localStorage に「名前付き回路」を保存する仕様

これは Circuit picker と共有される保存レイヤーの仕様。URL hash は共有・復元のために残し、localStorage は個人用の回路ライブラリとして使う。

Decision

MVP は localStorage

回路 JSON は小さく、同期的に扱える。保存タイミングは明示操作だけに限定し、描画フレームやドラッグ中には触らない。

01

責務境界

保存レイヤーは「名前付き circuit JSON の永続化」だけを担当する。エディタ状態・URL・GPU plan への反映は呼び出し側が明示的に行う。

Storage

localStorage から versioned document を read/write。失敗時は typed error を返す。

Codec

回路本体は既存 URL と同じ {"cols":[...]}。別表現を増やさない。

Consumer

将来のメニューや command が API を呼ぶ。保存仕様は UI を知らない。

02

保存・読み込みフロー

localStorage は起動時 hydrate と picker / undo / redo / clear の commit 境界で読む / 書く。Quirk 由来の undo/redo と同じく、ドラッグ中の一時状態は保存対象にしない。

SAVE 01

現在回路を JSON 化

circuit_to_json() で URL と同じ形式を得る。

SAVE 02

名前を受け取る

UI から渡された name を trim / validate。空はエラー。

SAVE 03

Document 更新

updatedAt と派生 meta を更新し、新しい順に並べる。

SAVE 04

localStorage 書き込み

qni.circuit_library.v1 へ 1 document として保存。

LOAD

JSON を返す

保存レイヤーは entry JSON を返す。エディタ適用は呼び出し側。

03

localStorage schema

1 key に versioned document を丸ごと保存する。個別 key を乱立させないため、移行と一覧表示が簡単になる。

JSON shape
{
  "version": 1,
  "activeId": "ckt_20260514_bell",
  "circuits": [
    {
      "id": "ckt_20260514_bell",
      "name": "Bell state",
      "json": "{\"cols\":[[\"H\"],[\"•\",\"X\"]]}",
      "createdAt": 1778726400000,
      "updatedAt": 1778727600000,
      "meta": { "qubits": 2, "columns": 2, "gateCount": 3 }
    }
  ]
}
Fields
versionschema migration 用。初期値は 1。
activeId最後に load / save した回路。URL payload がない起動時はこの entry を自動復元する。
idtimestamp + random suffix。rename しても変えない。
name表示名。空は禁止。重複は許可または suffix 付与。
jsoncanonical circuit JSON。保存対象の唯一の回路 source。
meta一覧用の派生値。保存時に JSON から計算し、読み込み時に整合性を確認する。
04

URL / Undo / GPU plan との同期

保存ライブラリは editor の source of truth ではない。load は JSON を返すだけ。適用時のポリシーは app 側で統一する。

Apply on load
対象推奨挙動
placed_gates選択 entry の JSON から全置換。
next_gate_iddecode 後に再採番して collision を防ぐ。
URL hash読み込んだ JSON へ更新。共有 URL は常に現在回路を表す。
gpu_plandirty にする。計算は既存 WebGPU path。
Undo policy
操作推奨理由
Save current履歴なし回路内容は変わらない。library 永続化だけ。
Save as履歴なし別名保存も editor 変更ではない。
Load circuit履歴リセット別ドキュメントへ移動する感覚。Quirk の URL load / clear に近い。
Delete saved履歴なしlibrary 操作のみ。現在回路が消えるわけではない。
05

制限・エラー・プライバシー

localStorage は十分大きいが、永続保証されたデータベースではない。失敗時の UX を仕様に含める。

Capacity

目安 5MB / origin。保存時に QuotaExceededError を捕まえる。

Persistence

サイトデータ削除、private browsing、別 origin では消える / 見えない。重要回路向けには将来 export/import。

Privacy

localStorage は同一 origin の JS から読める。サーバへ自動送信されない点では cookie より適切。

06

実装メモ

実装時は小さく分け、保存 adapter と呼び出し側を分離する。

結論: localStorage で MVP は十分。この文書は保存 API とデータ境界だけを定義する。URL は共有、localStorage は個人ライブラリ、将来の大規模化だけ IndexedDB / export-import に逃がす。
