Summary — egui-web 内だけの結論

結論: 大きな分割は進んでいる。次に効くのは render/circuit_picker.rs の coordinator 責務をさらに薄くすること、test hook を registry 化すること、visual spec の座標・色定数を Rust 側 source of truth へ寄せること。

今回の観点

  • apps/egui-web 以外の問題は除外
  • 500 行超ファイルと残った coordinator 責務
  • test-only readback / window hook の境界
  • Rust と TS visual spec 間の手動同期

Issues — egui-web 優先度順

Circuit picker は分割後も coordinator が厚い

High

action / chrome / constants / drag / rename へ分割済み。ただし本体 file は 561 行残り、dropdown orchestration と input handling がまだ密。

Evidence
  • render/circuit_picker.rs: module facade + picker orchestration。
  • render/circuit_picker/chrome.rs: footer / popover / geometry publish など 355 行。
  • app/circuit_picker_state.rs: picker state transition が 464 行。
Refactor
  • row layout / dropdown layout / submenu placement を pure layout helper 化。
  • paint から mutation を外し、PickerAction reducer を明示する。
  • debug geometry publish は test hook registry に移す。

window hook / debug geometry hook が散在している

High

テスト用 hook は必要だが、bootstrap、app、render 各所に __qni* / __egui* の公開が散る。production / debug / test の境界を読み取りにくい。

Evidence
  • bootstrap.ts が readback と circuit library hook を公開。
  • render/circuit_picker/chrome.rs, render/toolbar.rs, state_panel_popup/aspect.rs が geometry JSON を公開。
  • current source 上の window/test-hook 参照は 115 箇所。
Refactor
  • apps/egui-web/src/test_hooks.rs のような単一 registry に集約。
  • hook 名と型を TS declaration と Rust 側で共有する。
  • test-only readback と visual geometry hook を明確に namespace 化する。

Rust UI 定数と TS テスト定数が手動同期

Medium

visual specs は座標と色に強く依存する。Rust 側の constants.rs と TS helper/spec の値が別々に書かれ、UI 変更時に片側だけ更新されるリスクがある。

Evidence
  • features/support/egui-helpers.ts: QNI_CIRCLE_LAYOUT, DEFAULT_REM, palette geometry。
  • tests/egui-web-interaction.spec.ts: TEST_CIRCUIT_LINE_Y, LINE_LEFT_OFFSET など。
  • features/support/assertions.ts と tests/support/egui-web-spec-helpers.ts の color matcher 重複。
Refactor
  • Rust から test-fixtures/ui-constants.json を生成。
  • 座標は canvas pixel 推定より app の debug geometry hook を優先。
  • 色トークンは Flexoki 名から共有し、RGB literal を最小化。

列セマンティクスの解析が描画と GPU lowering に分散

Medium

control / swap / phase / QFT の列単位ルールを、connector 描画と simulation_plan が別々に解析している。仕様追加時に「見た目は接続されるが GPU op が違う」型のズレが起きやすい。

Evidence
  • simulation_plan/linearize.rs: control mask, swap decomposition, QFT expansion, measurement / Bloch order。
  • render/circuit_connectors/control.rs: control groups。
  • render/circuit_connectors/swap.rs and phase.rs: column grouping を別実装。
Refactor
  • ColumnAnalysis または StepIr を導入。
  • GPU ops と connector paint inputs を同じ解析結果から出す。
  • drag preview 用の仮配置も同じ analyzer に流す。

visual specs が座標と pixel 色に強く依存している

Medium

Playwright の visual specs は実描画確認に役立つ一方、magic number と pixel probe が増えると UI 微調整のたびに test 修正が膨らむ。

Evidence
  • egui-web-drag-visual.spec.ts 457 行。
  • egui-web-state-semantics.spec.ts 450 行。
  • features/support/egui-helpers.ts が screenshot decode、drag helpers、layout estimation をまとめて持つ。
Refactor
  • semantic helper と pixel helper を分ける。
  • 色の exact RGB assert は必要な箇所だけに限定する。
  • UI geometry は hook / snapshot から読む。

gate params は matrix / angle / POD が同居している

Low

現状は 400 行で破綻はしていない。ただし parametric gate や QFT 展開が増えると、matrix 定義と parser と GPU POD layout の責務を分けた方が安全。

Evidence
  • gate_matrix が fixed gate matrix を保持。
  • parse_angle_radians / pi_coefficient / parse_fraction が同居。
  • GateParams と各 *_params builder も同居。
Refactor
  • gates/matrix.rs, gates/angle.rs, gates/gpu_params.rs へ分割。
  • angle parser の unit tests を module-local に寄せる。
  • POD layout の変更は GPU shader と一緒にレビューする。

固定 GPU capacity は今後のスケールで詰まりやすい

Backlog

現在は validation で silent skip を避けているため緊急ではない。ただし large mode や QFT 展開で op 数が伸びると、定数調整だけでは保守しにくくなる。

Evidence
  • MAX_OPS_PER_RECOMPUTE = 256
  • MAX_BLOCH_SLOTS = 64
  • MAX_MEASUREMENT_SLOTS = 64
Refactor
  • buffer grow or explicit user-facing capacity error。
  • QFT 展開後 op 数を UI で見える化。
  • docs/gpu-plan.md の Dynamic GPU capacity 候補と連動。

Roadmap — egui-web 内での安全な実行順

Circuit picker coordinator を薄くする

分割済み module を活かし、layout pass と action reducer をさらに明示して本体 file を短くする。

render/circuit_picker.rsapp/circuit_picker_state.rs

test hook registry を作る

global hook 名、geometry JSON、dirty/repaint を一箇所へ集約。既存 Playwright / Cucumber の flaky 要因を減らす。

bootstrap.tssrc/test_hooks.rs

UI constants を生成物にする

Rust 定数から TS fixture を生成し、visual tests の magic number を削る。色は Flexoki token 名で扱う。

constants.rsegui-helpers.ts

ColumnAnalysis を導入

connector 描画と GPU op lowering の入力を共有し、gate 追加時の見た目/意味ズレを防ぐ。

simulation_planrender/circuit_connectors

visual specs を helper 層で整理

pixel probe、drag helper、semantic setup を分け、UI 微調整時の修正範囲を狭める。

tests/*.spec.tsfeatures/support

capacity 設計を前倒し

dynamic buffer grow か明示エラーを設計し、QFT / large mode の op 数増加に備える。
