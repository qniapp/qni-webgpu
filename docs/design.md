# Design

このドキュメントは、**このプロジェクトが何であり、誰のための何か**を、現時点の実装と既存ドキュメントからプロダクト視点で整理したものです。

技術の詳細は `docs/tech-stack.md`、構成の詳細は `docs/architecture.md`、個別仕様は `docs/decisions.md` / `docs/web.md` / `docs/tui.md` を参照してください。

## ひとことで言うと

このプロジェクトは、**量子回路を学ぶ人が、回路を置いて・結果を見て・状態を理解できるようにするための学習向け PoC** です。

ただ数式や振幅の配列を表示するのではなく、

- 回路を自分で組み立てる
- ゲートを置くと状態がどう変わるかを見る
- 状態ベクトルを視覚的に理解する

という体験を通じて、量子回路の基礎をつかめることを目指しています。

## 主な対象ユーザー

このプロジェクトの主な対象ユーザーは、**量子回路を学ぶ人**です。

特に向いているのは、次のような人です。

- 量子ゲート `H`, `X`, `Y`, `Z` などの働きを手を動かして理解したい人
- `|00>` からどう状態が変わるかを見ながら学びたい人
- Bell state や制御ゲートのような基本例を、視覚的に追いたい人
- 数式だけでなく、UI 上の変化として量子状態を理解したい人

一方で、開発者向けの実験要素も含まれていますが、それらは現時点では**学習体験を支える副次的な面**として捉えるのが自然です。

## このプロダクトが解決したいこと

量子回路の学習では、次のような難しさがあります。

- ゲートを置いた結果が頭の中でイメージしにくい
- 状態ベクトルが数値列だけだと直感的にわかりにくい
- CNOT や重ね合わせの結果が「なぜそうなるか」を追いにくい
- 既存の教材は静的な図か、逆に高機能すぎるツールに寄りがち

このプロジェクトはその間を埋めるために、**最小限の回路編集体験と、即時に更新される状態表示**を組み合わせています。

つまり目標は、

> **量子回路を読むだけでなく、触って理解できるようにすること**

です。

## プロダクトとしての中心体験

このプロジェクトの中心体験は、次の 5 ステップです。

1. 量子ビット線を持つ回路を見る
2. パレットからゲートを選ぶ
3. 回路に配置する
4. 左から右へ適用される回路として理解する
5. 結果の状態ベクトルを視覚的に確認する

重要なのは、**編集と理解が分断されていないこと**です。

- 回路を置く
- 状態が変わる
- 結果をその場で見る
- もう一度置き換えて比較する

この短いフィードバックループが、学習体験の核になっています。

## このプロジェクトの主価値

### 1. 手を動かして学べる

静的な教科書や図ではなく、自分でゲートを配置しながら学べます。

### 2. 状態の変化を見て学べる

状態ベクトルを単なる内部データではなく、学習対象そのものとして可視化します。

### 3. 最小限の回路題材に集中できる

最初から巨大な機能集合を持たず、基本ゲート・基本状態・基本操作に集中できます。

### 4. 複数の見方を持てる

Web と TUI という複数の入口がありますが、いずれも「量子回路を理解する」という同じ題材を別の形で支えています。

## 現在の 2 つの入口

### Web PoC (`apps/web`)

学習者にとって最も中心に近い体験です。

- ブラウザ上で回路を直接触れる
- ゲート配置と状態表示を一画面で扱える
- WebGPU を使って状態ベクトル計算・描画を行う
- 視覚的な理解を強く支える

現時点では、この Web 版が**もっとも「学習プロダクトらしい」顔**を持っています。

### TUI PoC (`apps/tui`)

TUI は、同じ題材をより軽量に試すための入口です。

- 端末上で回路操作や状態表示を試せる
- 表現や操作を素早く検証できる
- スナップショットや E2E による回帰確認がしやすい

学習者向けの完成 UI というより、**学習体験を育てるための試作・検証面**として重要です。

## このプロジェクトが目指している学習体験

repo 全体から見ると、このプロジェクトが目指しているのは、次のような学習体験です。

- **抽象概念を UI に落とす**
  - 重ね合わせ
  - 位相
  - 制御ゲート
  - 状態遷移
- **回路と結果を同時に見る**
- **少し変更して結果差分を見る**
- **基本概念を繰り返し試せる**

つまり、量子回路を「正解を与えられて理解する」のではなく、**操作と観察を通じて理解する教材的プロダクト**として読むことができます。

## これは何ではないか

このプロジェクトは、少なくとも現時点では次のものではありません。

- 汎用の本格量子 SDK
- 研究用途の大規模量子回路シミュレータ
- 本番向けの量子開発プラットフォーム
- 測定・古典レジスタ・最適化・実機接続まで揃った完成製品
- 学習コンテンツ一式を備えた完成教材サイト

つまり、**学習者向けの完成サービス**というより、**学習体験の核を検証している PoC** です。

## 現時点で強い設計方針

### 1. 学習上のフィードバックを速くする

ゲート配置の結果がすぐ状態表示へ反映されることが重要視されています。

### 2. 状態ベクトルを可視化の中心に置く

このプロジェクトでは、状態ベクトルは裏側の計算結果ではなく、学習者が見るべき中心情報です。

### 3. 高機能化より理解しやすさを優先する

今の repo は機能網羅よりも、基本体験が成立するかどうかに重心があります。

### 4. UI 実験を積極的に行う

WebGPU と TUI の 2 面構成からもわかる通り、単一実装を固定するより、学習体験に合う形を探る姿勢が強いです。

## 現時点での成熟度

このプロジェクトは完成品ではなく、**複数の PoC を並行して育てている段階**です。

- Web は学習体験の本命に近い
- TUI は検証・実験・回帰確認に強い

そのため `design.md` としては、現状を次のように捉えるのが適切です。

> **量子回路を学ぶ人のために、回路編集と状態可視化を結びつけた学習体験を作ろうとしている、その途中段階のプロダクト**

## 現時点の結論

このプロジェクトは、**量子回路を学ぶ人が、回路を置いた結果をすぐ見て理解できるようにするための学習向け PoC リポジトリ**です。

その中心には、次の考えがあります。

- 量子回路は、読むだけでなく触って学ぶべき
- 状態ベクトルは、隠れた内部状態ではなく学習の中心に置くべき
- 基本概念は、操作 → 反映 → 観察の短いループで理解できるべき

この意味で `qni-webgpu` は、単なる技術デモではなく、**量子回路学習のためのインタラクティブな理解装置を探っているプロダクト**です。

## まだ確認したい点

今の整理は「学習者向け」を主軸に寄せていますが、今後さらに精密化するなら次の点を確認したいです。

- 初学者向けなのか、中級者向けなのか
- Bell state などの基本例に絞るのか、より広い回路構築まで狙うのか
- 学習 UI そのものを主役にするのか、学習支援エージェント連携まで含めるのか

必要なら次に、`docs/design.md` を **より教材/学習プロダクト寄り** にして、

- 学習目標
- 典型ユースケース
- 学習シナリオ
- MVP で教える概念の範囲

まで踏み込んで追記できます。
