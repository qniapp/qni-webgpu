Probability display

Quirk の Probability / Probability2…16 相当の確率表示 ゲート。回路の任意の地点に置くと、その時点で span 内 量子ビットを測定した 場合の各 outcome 確率を、ゲート本体の中で横バー+%として可視化 する。状態ベクトルには影響しない (display gate)。span 1..16、いずれも 2span 行の横バーという同じ視覚モデルで統一 (Quirk の span 1 thermometer 形は採用せず、span 1 = 2 行に正規化)。

§ 02 d プロトタイプ — drag to resize span (= resizable-span handle)

ゲート下端の 紫のグリップを上下にドラッグすると、span (= 縦に伸びる 量子ビット数) が 1 → 2 → 3 → 4 → 5 と変わります。 integer span にスナップ。Quirk のように Probability / Probability2..16 を別アイコンとしてパレットに並べるのではなく、パレットには mini gate プレビューの 1 アイコンだけを出し、配置後にこのハンドルで span を調整 する UX (= resizable-span ゲートと同じ仕組み)。span 変化に合わせて行数 = 2span も自動更新されます (uniform distribution で seed)。

§ 04 実装仕様 (Codex 用リファレンス、暫定)

パイプラインの大枠

  1. compute shader (probability marginalize) ─ 既存の STATE storage buffer (vec2 amplitudes) を入力に、 
    // 1) amp → prob with control mask
prob[k] = dot(amp[k], amp[k]) * control_mask[k];

// 2) cycle bits so the spanned range starts at bit 0
prob = cycle_bits(prob, -range_offset);

// 3) sum-fold from n_total down to span: log2(register_size) − span 回
//    の half-and-sum を回して、後ろの bit を marginalize
while (n > span) { prob = sum_fold(prob); n -= 1; }

// 4) result: 2^span 要素の確率テクスチャ / storage buffer
    Quirk の probabilityStatTexture を WebGPU コンピュートシェーダに翻訳。 CPU 側に readback しない (CLAUDE.md 制約)。結果は STATE_PROB_BUFFER 的なストレージバッファに書き出す。
  2. render shader (gate body) ─ 既存の STATE_RENDER_SHADER パターンと同じく、フラグメントシェーダ内で probability バッファを直接 sample して バーと矩形を描画する。digit overlay (measure/digit.rs) と同じ要領で % テキストは digit_atlas を sample する別 pass で重ねる。 text 描画も GPU 完結 (CPU 側で text rasterize しない)。
  3. per-row layout:
    ・bar の高さ = gate_h / 2^span
    ・bar の幅 = prob[k] * gate_w
    ・行高 ≥ 8 px なら digit アトラスで "XX.X%" を右詰めで描画
    ・行高 < 8 px なら % は描画せず、tx-3 @ 70% の縦 1 px 線を x = (1 + log(prob) / log_scale) * gate_w の位置に置く
  4. state representation ─ GateKind::ProbabilityDisplay { span: u8 }。 既存の display 系 (ブロッホ表示等) と同じ trait に乗せる。has_no_unitary_effect = true 相当のフラグ立ててシミュレータは skip。
  5. URL serialization (Quirk 互換) ─ serialized id は Quirk と同じ語彙を採用 (将来の Quirk URL インポートを素直に取るため):
    ・"Probability" (span 1)
    ・"Probability2", "Probability3", ..., "Probability16" (span 2..16)
    URL fragment (#circuit=...) 内では JSON がそのまま生で入る (fragment 内は {}[]":, がエンコード不要): 
    # span 1、q0 に 1 個
#circuit={"cols":[["Probability"]]}

# span 3、q0..q2 に
#circuit={"cols":[["Probability3"]]}

# span 3、q1..q3 に (q0 を skip するため数値 1 を placeholder)
#circuit={"cols":[[1,"Probability3"]]}

# H × 3 → Probability3 で末尾の測定確率を見る回路
#circuit={"cols":[["H","H","H"],["Probability3"]]}
    ブラウザコピー時に percent-encode された %7B"cols"%3A%5B%5B"Probability"%5D%5D%7D 形式も等価に parse できるようにする (Quirk と同じ挙動)。
    Quirk の setSerializedId 該当ロジックは ProbabilityDisplay.js:280 / 294 (single = "Probability"、 multi = "Probability" + span) を参照。
  6. placement ─ パレットには mini gate プレビューの 1 アイコンだけを出し、配置後に resize ハンドルで span を 1..16 に変更 (§ 02 d の挙動)。Quirk 風に Probability / Probability2..16 を パレットに並べるよりアイコン数が削れ、UX も既存 resizable-span ゲートと一貫する。 ハンドルはゲート本体の下端中央に 16×4 px の purple-400 pill、hover/ドラッグで purple-600 + 20×5 px に拡大。ドラッグは cursor 縦移動 ÷ wire_pitch (= 52 px / 量子ビット) で integer span にスナップ。配置直後は span 1 で開始。
  7. tests:
    ・compute shader unit test ─ 既知の state (H|0⟩, Bell, GHZ) で結果が解析解と一致すること。
    ・visual snapshot ─ insta で span 1 / span 3 / span 5 の見た目を固定。
    ・Playwright ─ パレットから Probability Display を drop → 回路上で表示される → ゲートを動かすと値が更新される。

※ 数値 (gate footprint, バー色, テキストサイズ) は本モック上の値が "見た目の正解"。 Codex 向けプロンプトは別途このページを参照する形で発行します。

§ 05 ゲートパレット用アイコン

パレット (gate toolbox) 上で他のゲートと並べて表示するアイコン。 ゲート本体のミニチュア (Quirk 流儀) を採用 — 2 行 × 横バーで 「これは確率表示ゲートだ」が palette サイズでも瞬時に伝わる。 左 = 28 px (実寸)、右 = 96 px (拡大)。ストロークは tx (#100F0F)、 塗りは blue-300 (#66A0C8 — gate 本体のバー色と同じ)、背景透過。

Mini gate preview (= ゲート本体ミニチュア)

24×24 viewBox 内に (3, 4) → (21, 20) = 18×16 の外枠 (stroke tx #100F0F、1.4 px)、中央水平線 (1 px、行区切り) で 2 行に分割。 上段 = 1/3 長の bar、下段 = 7/9 長の bar (= 例示として「分布が偏っている」 見た目)。fill は blue-300 (#66A0C8) で gate 本体と完全一致。 実装は apps/egui-web/src/icons/ 配下に Lucide 風 SVG として 配置 (既存のゲートアイコンと同じ階層)。

span が 1 でも 5 でも、palette アイコンは 同じ 2 行 mini preview で OK (Quirk と同じ)。span 別の visual variant は不要 — パレット上では 「Probability Display 系ゲート」がひと目で識別できれば十分で、span は配置後のゲート本体が span 数を物理的に示すので。
