状態ベクトルパネル — ハンドルのデザイン案

現状のハンドルは、パネル上端にくっついた高さ 14px のグレーの帯と、その中央に置かれた白いピルでできています。下に並べた 3 案は、qni のデザイン言語 (rounded-xl + shadow-xl + zinc 系のグレー + sky-500) に寄せた代替案です。いずれも「ドラッグできる場所」だとひと目で分かることを残しつつ、パネル上の視覚的な重さを軽くする方向で考えました。

現状

幅いっぱいのグレー帯 + 白ピル

帯がパネルの上辺に密着し、中央の白いピルがグリップに見えるという構成。帯がパネル幅いっぱいに広がるぶん、視覚的な重さが大きいのが弱点です。

B 案

パネル一体型のヘッダー帯

ハンドルをパネルの一部として組み込む案。高さ 14px の zinc-100 のヘッダー帯 (パネルと同じ角丸) を上端に置き、中央に zinc-300 の小さなピルを乗せます。「タイトルバーつきのカード」としてひとつのまとまりに見えます。

C 案

パネル内側のドットグリップ

外側の帯をなくして、パネル上端の中央に zinc-300 のドット 6 個を並べる形。一番コンパクトで、パネル本体は円だけに集中させられます。代わりにパネル本体のクリックでもドラッグできるようにする前提です。

D 案

タブ型ハンドル (ブラウザタブ風)

56 × 16 px の小さな白いタブをパネル上端に貼り付ける形。パネルと同系統の角丸 + シャドウで、「カードに付いた取っ手」として読めます。ブラウザのタブや Figma の小さなパネルと同じ視覚的メタファーです。

移動 + リサイズができるハンドル案

後々パネルをリサイズもできるようにする前提で、移動とリサイズを同居させる案を 2 つ並べます。どちらもデスクトップウィンドウの語彙 (上端のヘッダー帯 = 移動 / 角 = リサイズ) を借りていて、「2D で動かす」と「縦横にリサイズ」が自然に共存します。

G 案

ヘッダー帯 + 四隅を囲うブラケット形ハンドル

移動はパネル上端のヘッダー帯。リサイズは各隅の「外側」に L 字 (⌜ ⌝ ⌞ ⌟) のブラケット形を置く案。パネルの角と同じ向きに丸まっているので、「角を一回り大きく囲んだ」自然な形。アイドル時は非表示、パネルにホバーした瞬間にだけフェードインし、円表示の邪魔をしません (下のモックアップでパネル上にカーソルを乗せて確認可)。

H 案

ヘッダー帯 + 右下コーナー (デスクトップウィンドウ風)

B 案のヘッダー帯を「タイトルバー = 移動」に流用しつつ、右下に E 案のコーナー斜線を置く構成。デスクトップウィンドウとほぼ同じ語彙なので、操作の予測がしやすい一方、視覚的な chrome は他より少し多めです。

ヘッダー帯に情報を載せる派生 (G 案ベース)

ヘッダー帯はパネル本体と無関係なら無駄な余白に見えますが、qubit 数や grid 形 / 状態数のような「いま何を、どう表示しているか」を載せると、空間を有効活用できます。G 案 (4 角リサイズ) をベースに、左右に情報を分ける案を 1 つ。フォントは qni 同様のモノスペース (Hack 系) を想定。

G-2 案

左右に分けて配置 (グリッド × グリッド = 状態数)

左に「qubit 数」、右に「グリッドの縦 × 横 = 状態数」。リサイズで縦横の grid 形を変えると右側の数値だけが変わり、左側の qubit 数 (回路で決まる量) はそのまま。リサイズハンドルは G 案と同じく、四隅の外に L 字 (⌜ ⌝ ⌞ ⌟) のブラケット形。アイドル時は非表示で、パネルにマウスが乗ったときだけ薄くフェードインし、ハンドル単体ホバーで sky-500 に変わります (下のモックアップでパネル上にカーソルを乗せて確認可)。例として 3 qubit (8 状態, 8 × 1 表示) と 16 qubit (65536 状態, 256 × 256 表示) を並べます。

3 qubits 8 × 1 = 8 states
16 qubits 256 × 256 = 65536 states

「移動だけ」の 3 案 (B〜D) について

  • B 案 — ヘッダー帯: 「タイトルバーつきのカード」として読めて、デスクトップウィンドウ的なメタファーに一番近い
  • C 案 — ドットグリップ: 円表示への集中度が最大。パネル本体クリックでもドラッグできるようにすれば最も自然
  • D 案 — タブ型ハンドル: 「カードに付いた取っ手」というメタファーが一番はっきりしている

「移動 + リサイズ」の 2 案 (G・H) について

  • G 案 — ヘッダー帯 + 四隅を囲うブラケット形: 四隅の外に L 字 (⌜ ⌝ ⌞ ⌟) を置く案。パネルの角と同じ方向に丸まるため、ぱっと見で「角」と認識できて装飾感が少ない
  • H 案 — ヘッダー帯 + コーナー斜線: 旧来の OS 流。chrome がやや少なめだが、リサイズが右下からしかできない

「ヘッダーに情報を載せる」派生 (G-2) について

  • G-2 案 — 左右に分けて配置: 左 = qubit 数 (回路で決まる)、右 = 「縦 × 横 = 状態数」。リサイズで grid 形を変えると右側だけが書き換わるので、いまの表示形がそのまま読めて便利

どの案も、パネル本体の qni 互換のスタイル (rounded-xl + shadow-xl + 16/20 のパディング) には手を入れていません。変更点はあくまで取っ手部分だけです。
