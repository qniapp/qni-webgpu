# サンプル表示ブロックとパリティ制御

## サンプル表示ブロック

URL トークンは `Sample1`〜`Sample8` (コード識別子は `GateKind::SampleDisplay`)。末尾の数字は覆う量子ビット数を表す。上限の 8 は `apps/web/src/gates.rs` の `SAMPLE_MAX_SPAN` で定める。描画シェーダの `SAMPLE_MAX_SPAN` と Qiskit バックエンドの `SAMPLE_DISPLAY_MAX_SPAN` も同じ値とし、Rust のテストで一致を確認する。`Sample9` 以上と `Sample0` は読み込まない。

- 状態を変えず、収縮もさせない読み取り専用の表示ブロック。覆った量子ビットの測定確率から 1 つのビット列をサンプリングして表示する。
- 覆う量子ビットごとに、ゲートと同じ 40px 角の角丸タイルを各ワイヤの中心に 1 枚ずつ置く。文字は表示しない。タイルどうしをつなぐ線はなく、タイルの間は透明で回路の背景が見える。
- 対応するビットが 1 のタイルは点灯する。点灯色は、0 を赤・1 を青で表す配色の規則に合わせて「1」の色 (`BLUE_600`、`semantic_on` と同じ) を使う。中心の明るい青 (`BLUE_100`) から外側の青 (`BLUE_200`) へ移るグラデーションで塗り、1px の青 (`BLUE_600`) で縁取る。縁の外側には同じ青の光がにじみ出る。
- 0 のタイルは消灯し、光のない平らな灰色 (`UI_2`) で塗り、1px の灰色 (`TX_3`) で縁取る。
- サンプリングとタイルの点灯の判定は GPU シェーダ内で完結し、本番経路で GPU → CPU リードバックは発生しない。
- サンプリングでは 2^n 通りの結果の確率を走査する。8 ビットでは 256 通りになるため、画素ごとではなく頂点シェーダで 1 回だけ抽出し、結果をフラグメントシェーダへ渡す。
- ドラッグ中は、配置位置に吸着するとその位置でサンプリングした結果でタイルを点灯する。吸着していない間は全タイルを消灯して仮表示する。
- QFT や確率表示ブロックと同じく、ホバーすると上下に出るリサイズハンドルをドラッグして 1〜8 本の範囲で縦に伸縮できる。縦レイアウトでは伸縮できず、2 本以上のサンプル表示ブロックはタイルを描画しない。伸縮すると URL トークンの末尾の数字が覆う本数に合わせて変わり、新しい範囲でサンプリングし直す。
- 乱数シードはブロックの ID から決まるため、同じ回路ではフレームごとに結果が変わらない。
- 同じ列に制御を置くと、その条件を満たす状態だけからサンプリングする (条件付きサンプル)。条件を満たす状態の確率が 0 のときは、全タイルを消灯する。

## パリティ制御

URL トークンは `zpar` / `xpar` (コード識別子は `GateKind::ZParityControl` / `GateKind::XParityControl`)。

- 同じ列のパリティ制御のうち、条件を満たすものが奇数個のときに列の操作を適用する。
- `zpar` は Z 基底、`xpar` は X 基底で条件を判定する。同じ列で両者を混ぜてもよく、すべてのパリティ制御の結果を XOR でまとめる。
- 通常の制御と反制御 (`•` / `◦`) とは AND で組み合わせる。
- 量子ビット a, b に `zpar` を置き t に X を置いた列は、CNOT(a → t) のあとに CNOT(b → t) を適用するのと等しい。
- `xpar` を置いた列は、`xpar` を `zpar` に置き換え、その量子ビットにだけ列の前後で H を適用した回路と等しい。
- Y 基底のパリティ制御 (`ypar`) は提供しない。

## 外部 GPU 実行 (Qiskit)

Qiskit 連携 API は `zpar` / `xpar` とサンプル表示ブロック (`Sample1`〜`Sample8`) に対応する。

サンプル表示ブロックは確率表示ブロックと同じ位置で条件付き周辺確率を保存し、既存の `outputs.probability` 要求と `probability` 応答を使う。要求にはブロックの ID、列、上端のビット、レジスタ下端で切り詰めた本数、列の制御条件を渡す。結果はその ID の外部確率スロットへ転送する。試行ごとのビット列は使わず、WebGPU と同じ描画シェーダがブロックの ID を種として 1 回抽出する。同じ確率と ID なら同じタイルが点灯し、再描画では変わらない。結果の待機中や条件の確率が 0 の場合は全タイルを消灯する。結果の bit 0 が上端のワイヤに対応し、bit 1、bit 2 はその下のワイヤに順に対応する。

測定・検出器・測定変数による分岐が先行する場合、Qiskit の確率は既存の確率表示と同じ試行平均であり、WebGPU の 1 回の収縮後の分岐とは異なる。有限試行数や浮動小数点の差によって、抽出結果も異なり得る。事後選択では、その列までの条件を通過した試行だけを使い、到達した試行がなければ全タイルを消灯する。詳しくは[事後選択の外部実行](postselection.md#外部-qiskit-実行)を参照する。

検証用の `read_sample_display_outcome` は外部実行でも同じ確率バッファとシェーダを使う。結果の転送と描画の完了後に呼び出す。本番描画では読み戻さない。

パリティ制御は WebGPU と同じ列単位の手順で実行する。

1. 同じ列の伸縮可能なブロックの範囲内にあるパリティ制御を除外し、残りを上から順に並べる。
2. `xpar` の量子ビットに H を適用する。一番上のパリティ制御の量子ビットを集約先とし、ほかのパリティ制御から集約先への CX で XOR を求める。
3. 集約先が 1 という条件を通常の制御・反制御と AND で組み合わせ、列の操作に適用する。
4. 列の処理後、CX と H を逆順に適用して集約を解除する。

既存の量子ビットを可逆的に集約先として使うため、パリティ制御用の補助量子ビットは不要である。パリティ制御を含み、ほかに操作のない列では、通常制御どうしの CZ を追加しない。

X 軸検出器・Y 軸検出器の基底変換はパリティ集約の後に行い、表示値は検出器の逆変換後、パリティ集約の解除前に保存する。通常の Measurement は列の制御を無視するが、パリティ集約と解除の間で実行する。Z Detect-Control-Reset の Z 基底測定は集約前に行い、表示値の保存後、集約の解除前に対象をリセットする。

事後選択、測定変数で条件付けた `X<a` などの操作とも組み合わせられる。通常制御と同じく、安全に変換できない制御付き書き込みや、Z Detect-Control-Reset と QFT の範囲が重なる場合などは拒否する。詳しくは[外部 GPU API 互換方針](implementation/external-gpu-api-compatibility.md#ゲート対応)を参照する。

## パレット

`zpar` / `xpar` は通常の制御と反制御の隣に、サンプル表示ブロックは確率表示ブロックの隣に並ぶ。サンプル表示ブロックのアイコンは、点灯した角丸タイル 1 枚で描く。タイルはパレットのセル中央に置き、光のにじみがセルからはみ出さない大きさにする。
