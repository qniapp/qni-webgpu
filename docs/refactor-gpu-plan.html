§06 段取り

  1. 準備 — gpu.rs → gpu/mod.rs に rename

    git mv apps/egui-web/src/gpu.rs apps/egui-web/src/gpu/mod.rs。 この時点で 1 ファイルから 1 ディレクトリへ。中身は手付かず、ビルドも通る。コミット小さく。

  2. Layer 0 を切り出す (shaders / params / digit_atlas)

    リーフモジュール 3 つを順に作る。中身は cut & paste。mod.rs から mod shaders; 等を宣言し、各種参照を self::shaders::STATE_COMPUTE_SHADER に置換。1 モジュールずつコミット。

  3. Layer 1 — resources.rs を切り出す

    StateVectorResources + new + update_render_pipeline をまるごと移動。use super::shaders::*; / use super::params::*; / use super::digit_atlas::*; で import 解決。

  4. Layer 2 — callbacks.rs

    3 個の Callback struct + impl を移動。Issue A の recompute ロジックも一緒に来る。

  5. Layer 2 — readback.rs

    test-only readback と thread_local を最後に切り出し。#[cfg(target_arch = "wasm32")] を維持。

  6. 掃除 — mod.rs を pub use 専用に

    pub(crate) use callbacks::*; 等で外部 API を維持。lib.rs 側 (read_state_vector など) の参照は変更不要。

  7. 検証

    各ステップごとに cargo build --target wasm32-unknown-unknown + Playwright suite を流す。最終ステップで Bell / GHZ のスクショと test:bdd を含むフルサイクル。

§07 リスク評価

● Low

振る舞いの変化

純粋な構造変更。識別子の引っ越しのみで、ロジックは触らない。Playwright suite (28 件) が回帰検出器。

● Medium

可視性の調整

pub(crate) が増えるかもしれない。StateVectorResources のフィールドを別モジュールから読むため。最小限に留める。

● Low

diff の大きさ

差分は大きいが git mv + cut/paste 中心。レビュアは構造を見るだけで済む。各 step を別コミットにすれば bisect も効く。

● Low

循環依存

DAG が決まっているので機械的に防げる。cargo build が即座にエラーで教えてくれる。

● Medium

resources.rs が依然として大きい (~1,180 行)

new() が膨大だから。Phase 2 として buffers.rs / pipelines.rs / bind_groups.rs に細分化することは可能。今回は Phase 1 のスコープ外。

● Low

roll back 容易性

各 step が独立コミット。問題があれば該当 step だけ revert。
