リサイズハンドル

span を持つ表示ブロック (確率表示ブロック / 振幅表示ブロック / 密度行列表示ブロック / QFT / QFT† 等) が共有する「上下ドラッグハンドル」 primitive。ゲートの上下 2 ヶ所に出る cyan-400 ピル形 (24 × 6 px) で、ホスト ホバーで「奥から飛び出してくる」マイクロインタラクションを伴って出現する。 クロム (色 / 寸法 / 状態遷移 / マイクロインタラクション) は本ページ + design-system.css に集約し、各コンポーネントは ポリシー (幅算出 / span 上限 / 配置主体) だけを定義する。

§ 01 概要 (見た目と用途)

span を持つ表示ブロック (確率 / 振幅 / 密度行列 / QFT 等) のホスト要素の上下にドラッグハンドルを出し、span を伸縮可能にする横断 primitive。 通常時は invisible で UI を圧迫せず、ホスト hover で「奥から飛び出してくる」バウンス出現を伴って visible になる。 下のモックで挙動と典型的な見た目を確認できる。

色族の選定根拠: qni-webgpu のホバー枠 / 行ホバー枠 / drag preview は purple-400 / purple-600 を使う。 ハンドルも同じ purple 系統にすると 2 px 背景の空き という防御策で「リングの突起 ?」誤認を回避する必要があった (当初設計)。 別色族 (cyan) にすると隣接していても 2 オブジェクトとして読めるので、空きは視覚的な余白として残すだけで十分。 cyan-400 は Flexoki Light で blue (確率バー) / purple (hover) のどちらとも干渉せず、ハンドルが「操作可能な別物」だと一目で分かる。

ホバー枠との位置関係

ホスト上辺を基準 (y = 0) に、ホバー枠は y = -4 .. 0 に purple-400 2 px + paper 2 px を描く。 ハンドル top は y = -12 .. -6 なので、ホバー枠の外端 (y = -4) との間に 2 px の背景の空き が確保される。 bottom 側も同様に対称。色族が異なる (purple ホバー枠 / cyan ハンドル) ため隣接していても誤認されないが、 空きは視覚的な余白として残す (色族分離だけでなく、ハンドルがホスト本体から「浮いて」見える効果も狙う)。

★ 批評 · § 03 レイヤ図がない
5 層の積層を表だけで伝えている

「ホスト本体 → 背景の空き → ホバー枠 → 背景の空き → リサイズハンドル」と y 軸方向に 5 層が積層する話は、 表で読むと毎行 0..2 px 外側 / 2..4 px 外側 を暗算で繋ぐ必要があり、 頭の中で図を再構成しないと位置関係が掴めない。

対案: 幅 6 px · 高さ 60 px 程度の annotated 側面図 (SVG) を表の右に置く。色付き矩形 5 個 + 寸法線 + ラベルだけで、表は単なる数値リファレンスに格下げできて、 図が主たる伝達手段になる。

§ 04 状態とマイクロインタラクション

状態opacitytransformbackgroundtransition
default (ホスト非ホバー時) 0 scale(0.7) cyan-400 —
visible (ホスト hover、モックでは常時表示) 1 scale(1.0) cyan-400 opacity 200 ms ease-out / transform 250 ms cubic-bezier(0.34, 1.56, 0.64, 1) ← 軽いオーバーシュート / background 120 ms ease-out
hover (ハンドル単独 hover) 1 scale(1.15) cyan-600 即時切替 (transition: none)
active (ドラッグ中) 1 scale(1.25) cyan-600 即時切替

バウンスの理由: cubic-bezier(0.34, 1.56, 0.64, 1) は最終値を 1.56 倍まで一瞬オーバーシュートするイージング。 scale(0.7) → scale(1.0) の変化が「奥から飛び出してきて、ちょっと弾む」マイクロインタラクションとして読める。 気付きやすさ + ゲート操作の遊び心を狙う。opacity と background は通常の ease-out にして、scale だけが弾む。

★ 批評 · § 04 動きの仕様が動かない
バウンスを語るページにバウンス曲線も on-page demo もない

このページの存在意義の半分は cubic-bezier(0.34, 1.56, 0.64, 1) の 「ちょっと弾む」表現。だがその曲線そのもの (グラフ) も、ホスト hover で発火する live demo も、 どこにも描かれていない。読者は数値を読んで頭の中でカーブを想像する。

対案: (a) 60 × 60 px の SVG で cubic-bezier(0.34, 1.56, 0.64, 1) を描いて表の右に置く。0..1 を超える 1.56 の山が一目で見える。 (b) その下に「ホスト hover で発火する live demo」用の .rh-mock を 1 つ置き、 仕様の核を spec が体現する。

★ 批評 · § 05 default モックが wireframe に読める
「invisible が正しい状態である」ことを示す affordance がない

① default (non-hover) モックは ui-2 1 px 枠だけの完全な空矩形。 opacity 0 の handle は当然見えない。隣の ②③④ と並べたとき、 「未実装の placeholder」「描画失敗」「無効状態」のいずれかに読めてしまう。 意味は caption の「ハンドル非表示」が運んでいて、モック単体では仕様を伝えていない。

対案: 薄破線 outline + opacity 0 注釈、 もしくは薄い位置ガイド (opacity: 0.15 の cyan-400 ピル) を入れて、 「ここに何があるはずか」を視覚的に示す。

§ 06 設計判断

色

  • ホバー枠 (purple) と別色族 (cyan) にする: 同色族にすると 2 px 背景の空き という防御策で「リングの一部 ?」誤認を回避する必要があった。別色族なら隣接していても 2 オブジェクトとして読めるので、空きは視覚的な余白として残すだけで十分。cyan-400 は Flexoki Light で blue / purple のどちらとも干渉せず、ハンドルが「操作可能な別物」だと一目で分かる
  • cyan-400 → cyan-600 で深さの変化: ハンドルが「触れる対象 → 操作対象」に遷移したことを色濃度で示す。彩度ではなく明度の変化なので、認知負荷が低い。同色族での 400 → 600 という濃度遷移パターンはホバー枠 (purple-400) / ドラッグプレビュー (purple-600) と同じ規則性

形状とジオメトリ

  • 上下 2 個にする: span は両方向に変化させたいので、片側のみだと拡張方向が片寄って感じる。確率表示ブロック / 振幅表示ブロック / 密度行列表示ブロック / QFT は同じ「縦方向に伸びる回路要素」なので、上下対称な配置に統一する
  • 4 px ホバー枠の外側 + 2 px の空きで配置: 空きは色族分離の防御ではなく、ハンドルがゲート本体から「浮いて」見える効果を狙う。色族分離があるので空きを更に詰めることも可能だが、視覚的な余白として 2 px (spacing-0.5) を保つ
  • 形状はピル (capsule): 矩形だと「点」、円だと「ボタン」、ピルだと「つまみ」に読める。span を 引き伸ばす動作とピル形の横長が一致して、操作のメタファとして馴染む

アニメーション

  • opacity / background は ease-out、transform だけバウンス: opacity の bounce は「透明度が一瞬戻る」現象になり不自然。background は色変化なので即時 (transition なし) または短い ease-out。scale だけが「奥から飛び出してきて、ちょっと弾む」表現を担う
  • scale(0.7) → 1.0 → 1.15 → 1.25 の連続スケール: 1 軸の連続変化なので状態遷移が自然に読める。サイズ差は +15 %, +25 % と明確に体感できる程度。10 % 以下だとほぼ気づかない

アフォーダンスとポリシー分離

  • 幅ポリシーは呼び出し側に委ねる: 確率表示ブロックは本体幅 40 px 固定なのでハンドル幅も固定 24 px。振幅 / 密度行列は span が大きいほど本体が広くなるので canvas × 0.6 で追従する
  • cursor: ns-resize: 「上下方向にドラッグできる」を OS のカーソル変化でも伝える (ハンドルの形だけに頼らない)
