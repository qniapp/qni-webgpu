ゲートクロム共通仕様

1 スロットゲートの基準本体、span を持つゲートにも共通する 56 px ピッチ、ホバー枠、配色ロールを定義する親仕様。 塗りつぶし本体を持つゲートは本体色とドラッグプレビューもここから継承し、透明マーカや非ユニタリ操作は hit 領域と配置方針だけを継承する。

§ 01適用範囲

本仕様は「回路上で 1 つの配置単位として扱うゲートの外装」を扱う。対象は、角丸正方形 / 真円 / 透明マーカ / span 付き本体を持つ操作要素である。 ただし box_fill / drag_fill は塗りつぶし本体を持つゲートだけの共通仕様とし、Spacer / Measurement / Write 系や透明マーカは個別仕様の色とドラッグ表示を優先する。 表示ブロック (確率 / 振幅 / ブロッホ球 / 密度行列) は状態を変えない読み取り要素なので、各表示ブロック仕様を正とする。

このページで定義する 1 スロットゲートの基準本体サイズ、スロットピッチ、塗りつぶし本体の色ロール、ホバー枠、z-index の層。
個別ゲート仕様で定義する 字形、量子操作の意味、形状分岐、span 範囲、例外的なコネクタやリサイズハンドル。
再定義してはいけない 1 スロットゲートの 40 px 基準本体、56 px ピッチ、ホバー枠の 4 px 外側展開。塗りつぶし本体の状態色もここを正とする。

§ 02配色ロールと状態

配色は「ロール」と「状態」を分けて読む。ロールはデザイントークン上の意味、状態は表示中にどのロールへ切り替えるかを示す。 これにより、個別ゲートページが 本体 fill (default) と 本体 fill (drag) を別判断として重複記述する必要がなくなる。

ロール状態Flexoki トーン使い方
box_fill default / hover cyan-400 確定配置済みの塗りつぶしゲート本体。形状は個別ゲートが決めるが、塗りはこの系統で共有する。
label default / hover / drag bg / paper 塗りつぶしゲート上の反転字形。SVG path は currentColor で受け、stroke を足さない。
gate_hover_border hover purple-400 本体外側 4 px に出るホバー枠の外周 2 px。詳細は hover-frame.html と一致。

drag_fill drag preview purple-600 塗りつぶし本体を持つゲートの仮配置中の本体色。半透明にはせず、確定済みの cyan-400 と不透明色で区別する。
line 常時 ui-2 量子ビットワイヤ。ゲート本体より背面に置き、ゲートがワイヤ上に載っている関係を保つ。

cyan-400 + paper の相対輝度比は約 2.8。通常テキストの WCAG AA 基準には届かないため、 本仕様では「文字」ではなく 40 px アイコン内の字形として扱う。将来の高コントラスト表示では label を tx 系へ切り替える余地を残す。透明マーカ / Spacer / Measurement / Write 系は、ここで定義する box_fill と drag_fill を継承しない。

§ 03寸法と形状

スロット56 × 56 px (SLOT_SPACING = LINE_GAP = 56 / Tailwind spacing-14)
スロット内余白上下左右 8 px (Tailwind spacing-2)。40 px 本体を 56 px スロットの中央に置く。
角丸正方形border-radius: 6 px (Tailwind rounded-md)。H / 位相 / 回転ゲートなどの標準形。
真円border-radius: 50%。X / CNOT ターゲットなど、Quirk の plus-in-circle 慣例を保つゲートで使う。
透明マーカControl / AntiControl / Swap などは 40 px の hit 領域を保ちつつ、本体塗りではなく円・線・× で描く。色とドラッグ表示は個別仕様を正とする。
span 付き本体QFT などは幅 40 px と 56 px ピッチ、状態色を継承する。高さ、span 範囲、リサイズハンドルは個別仕様で定義する。
z-indexwire = 0、ゲート本体 = 10、ホバー枠 / ハンドル = 20。個別仕様が新しい層を足す場合もこの順序を崩さない。

§ 04状態バリアント

個別ゲートは同じ 3 状態を実装する。状態名と色の切り替えは本仕様を正とし、個別ページは字形が各状態で読めることだけを確認する。

2 px 背景の空き

purple-600 本体
既定確定配置済み。box_fill = cyan-400、label = paper。
ホバー本体色は変えず、外側に gate_hover_border の枠を足す。パレットや仕様モックでは surface の空きも見せる。
ドラッグプレビュー塗りつぶし本体を持つゲートでは、本体色だけを drag_fill = purple-600 に置き換える。ホバー枠とは重ねない。本体塗りを持たないゲートは個別仕様に従う。

§ 05回路グリッド上の配置

1 スロット幅のゲートは 56 px ピッチで並び、本体同士の間には常に 16 px の余白が残る。 ホバー状態を隣接させても purple-400 の枠が接触しないよう、余白を次の層に分けて確保する。

16 px = 背景 2 + 枠 2 + 視覚的な余白 8 + 枠 2 + 背景 2

上図の点線は説明用のスロット境界で、実 UI には描画しない。横ピッチ・縦ピッチとも 56 px にそろえるため、 ワイヤ間の縦方向にも同じ余白政策が適用される。

§ 06個別仕様への委譲

各ゲート仕様は、共通クロムを参照したうえで差分だけを書く。次のように責務を分けると、角丸正方形の 1 スロットゲート群が 同じ配色表や 56 px 配置図を繰り返さなくてよい。透明マーカや非ユニタリ操作は、共通の配置方針を参照しつつ固有の色と状態表示を定義する。

書く場所書く内容例
gate-chrome.html 40 px 基準本体、56 px ピッチ、塗りつぶし本体の状態色、ホバー枠、隣接余白。 box_fill / drag_fill (塗りつぶし本体のみ) / 隣接余白。
個別ゲートページ 量子操作の意味、字形、形状分岐、span、固有の設計判断。 H のアダマール変換、X の真円、QFT の縦長本体。
関連 primitive ゲート以外にも使う UI 部品の細部。 ホバー枠、リサイズハンドル。
