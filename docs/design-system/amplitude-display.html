振幅表示ブロック

span 内の量子ビットを測定せずに、状態ベクトルの複素振幅 (大きさ + 位相) を可視化する振幅表示ブロック (`表示ブロック` の定義は AGENTS.md 用語集と design-system §01 参照)。 確率表示ブロックが |α|² (周辺確率) を線形バーで描くのに対し、本表示ブロックは α = re + i·im を 横断プリミティブ 振幅円 (輪郭円 + 振幅円盤 + 円盤境界線 + 位相針) で描く。 span 上限は 16 量子ビット (Quirk と同じ。216 = 65 536 outcomes、状態ベクトル ≈ 512 KB を GPU storage で扱う上限)。 配色 (blue-200 fill / blue-400 disk border / tx-2 outline / tx needle) は状態ベクトルパネルと完全に揃える (state.rs の cell_contribution)。 Quirk の AmplitudeDisplayFamily (src/gates/AmplitudeDisplay.js) を Flexoki + WebGPU へ移植する仕様書。

★ 批評 · 全体所見
「振幅をどう描くか」の根本判断が § 06 まで遅延し、複素数表示の trade-off が言語化されていない

Flexoki Light 準拠、cellPx 帯ごとのレイヤ抑制、GPU パイプラインの 10 stage まで網羅性は高く、 probability-display.html / bloch-display.html と同じ「視覚仕様 + 実装仕様」の二重責任を踏襲している (全体構造は probability-display.html § 全体所見と同じ問題)。 一方で本仕様固有の論点として、「複素振幅 (実数 + 虚数の 2 自由度) を 2D 平面にどう写すか」という根本判断が § 06 のセル描画モデルまで持ち越されており、§ 01〜§ 05 では「disk + needle」が天下り的に登場する。 Quirk オリジナルは 確率正方形 + 対数強調円 + needle の 3 表現を併用、本仕様は outline 円 + 振幅 disk + 位相 needle に統一しているが、 なぜこの統一が振幅表現として優れているか (極座標 [mag, phase] が直交座標 [re, im] より読みやすい理由 / phasor 表現の代替案を退けた根拠) が 明示されていない。state panel と揃えるという 系内一貫性の根拠だけが書かれていて、表現選択そのものの妥当性は読者の信頼に依存する。

確率表示ブロックとの差別化が「位相情報の有無」だけに集約されている: lede / § 01 / § 04 で「確率表示ブロックは |α|²、本表示ブロックは α」と繰り返されるが、 α を見れば |α|² も読める(disk 面積 ∝ mag² = prob) のだから、振幅表示ブロックが存在する以上は「確率表示ブロックの上位互換」とも解釈できてしまう。 にもかかわらず両者が別表示ブロックとして並存している根拠 (大量 span での縦バー読みやすさ / hover popup の文言の違い / production cellPx 帯の限界) は仕様書全体で散発的に触れられているだけで、 「いつ確率表示ブロックを、いつ振幅表示ブロックを選ぶか」の意思決定ガイドが章として無い。これは Codex / 人間が両方の仕様ページを行き来する動機を弱める。

★ 批評 · Top Opportunities
影響度の大きい改善候補 (各論は本文中の批評ブロックに展開)

  2. 確率表示ブロックとの使い分けガイドを § 01 末尾に明記 — 「位相が見たい → 振幅表示ブロック」「測定結果を縦に多数並べたい → 確率表示ブロック」「span 16 を fit して全体形状を見たい → 確率表示ブロック」など decision matrix を 1 表で (全体所見 / § 01 参照)。
  3. § 02 のサイズ別レンダリングを「production cellPx」と「mock cellPx」の 2 軸に分離 — 現状は「mock span 13〜16 は heatmap」と注記があるが、production では heatmap が発生しないこと (cellPx 最小 3 px) が読み流されやすい (§ 02 参照)。

  5. § 09 GPU パイプラインの 10 stage と § 10 決定事項の重複を整理 — phase lock / quality / control_mask の決定値が両セクションに分散し、追跡が難しい (§ 09 / § 10 参照)。

★ 批評 · § 01 概要
「振幅表示ブロックがあれば確率表示ブロックは要らない」と誤読される設計提示

本文は span 1 / span 2 の見本だけで本表示ブロックを「複素振幅を見せる」と紹介するが、 振幅 disk の面積 ∝ mag² = 確率 なので、振幅表示ブロックは原理的に確率情報も内包する。 にもかかわらず確率表示ブロック (sibling) が独立して存在することは「単なる位相情報の有無」では正当化しきれない。 実際の使い分け軸は(a) span が大きい時の縦バーの読みやすさ (span 16 では 65 536 行を縦 880 px に詰める確率表示ブロックの線形バーが圧倒的に読みやすい)、 (b) 1 セルから何の量を読みたいか (確率は「ラベル数値」で正確に読む、振幅は「needle 方向で位相パターン」を視覚で読む) の 2 点。

この使い分けを § 01 末尾に「位相を読みたい → 振幅表示ブロック / 大きな span の確率分布形状を見たい → 確率表示ブロック」の 1 表で示すと、 Quirk から移行した学習者が両表示ブロックを取り違える事故が減る。Quirk もこの decision matrix を持たないが、qni-webgpu は state panel + 3 表示ブロックを併用するので、本仕様が canonical な使い分けガイドの場として適する。

§ 02 サイズ別の見た目 (1〜16 量子ビット、動くモック)

span を 1〜16 (上限) 全部並べた参考レンダリング。測定結果数 n = 2span を w × h グリッド (w = n === 2 ? 2 : 1 << floor(log2(n)/2)) に配置する。 位相の原点 (needle の向き) は state panel と同じ「phase = 0 = 真上」 (cell 中心からの方向 = (−sin(phase), −cos(phase)))。 各セルにマウスを乗せると、Quirk と同じ tooltip 内容 (ket、val、mag² と phase) をポップアップ表示する。 cell 寸法 (cellPx) が小さくなるにつれてレイヤを段階的に省略する。閾値 (§ 06 参照): cellPx ≥ 12 = needle + outline + disk / cellPx ∈ [3, 12) = outline + disk / cellPx < 3 = heatmap。cell 間の区切り線は描かず、matrix 全体の外枠だけを描く。 production の cellPx は § 05 表参照、span 16 でも最小 3 px なので heatmap は production では発生しない。下のモックは表示の都合で 320 px に scale down しているので、mock では span 13〜16 が cellPx ≤ 2 となり heatmap mode に入る。

実行前プレースホルダ (シミュレーション未実行の状態)

回路に振幅表示ブロックを配置しただけで、まだシミュレーション (▶ Run) を実行していない段階で表示する仮の見た目。 GPU 経路の amplitude_result storage buffer がまだ書き込まれていないので振幅値は存在せず、 従来の実装ではセル領域が真っ白の四角で抜けて見えていた (背景 bg-2 と同色になり「壊れているのか配置できていないのか」が判別できない問題)。 この空白を「実行待ちであることを伝えるプレースホルダ」として明示的にデザインする。

  • 背景 (placeholder fill) — purple-100 (#ECE1F3) の薄い紫で塗る。 本デザインシステムでは「未確定 / 進行中」を表現する色として紫を採用しており (drag preview = purple-600、ホバー枠 = purple-400)、 実行前の振幅も 0 (赤系) と 1 (青系) の中間に位置する未確定な値として同じ紫系統で表す。 色相は drag/hover で使う濃い紫よりさらに淡くして、「進行中アクション」と「結果待ちの静止状態」を区別する。
  • outline 円 — ui-2 (#DAD8CE) の薄いグレー。これは「振幅 ≈ 0」のときの既存配色 (state panel state_outline_zero) と同じ token を流用するので、追加の色定義は不要。stroke 太さ・半径は通常時と同じルール (cellPx ≥ 24 で 2 px、それ未満で 1 px、半径 = cellPx/2 − stroke/2 − 1.5 px)。
  • disk / needle — 描かない。振幅値そのものを持たないので、disk (大きさ) も needle (位相) も意味を持たない。
  • frame — 通常時と同じ ui-2 1 px の外枠を引く。これにより「ゲートとしての箱の輪郭」が背景 bg-2 と区別できる。
  • hover / tooltip — 実行前は cell 単位 popup を出さない (表示すべき数値が無い)。ゲート全体のホバー枠 (purple-400 4 px) と上下リサイズハンドルは通常時と同じく出す。
  • 遷移 — Run を押した瞬間、placeholder layer (薄紫背景 + グレー outline) を 150 ms ease-out でフェードアウトしつつ、通常の disk + needle 描画にクロスフェードする。フェード中は cellPx の判定 (§ 06) も通常通り適用する。

★ 批評 · § 02 production と mock の見た目が一致しない
「mock 限定の heatmap」がページの 1/4 を占めるのに、production では発生しない

§ 02 は「mock span 13〜16 (mock cellPx ≤ 2、heatmap、alpha = √(mag/max_mag)) — mock 限定の rendering」というセクションで 16 個中 4 個の見本を並べているが、 本文中に「production の cellPx は § 05 表参照、span 16 でも最小 3 px なので heatmap は production では発生しない」と注記されている。 これは 仕様ページの 1/4 が production と一致しない見本に費やされている状態で、 実装根拠としてこのページを開いた読者は「heatmap モードは実装すべきか?」と判断に迷う。

改善案: (a) production / mock 両方の cellPx を表に追記する (§ 05 表に「production cellPx」「mock cellPx」の 2 列を作る) と、見本がどちらのスケールで描かれているかが章を跨いでも追跡できる。 (b) heatmap mock を「もし production cellPx が将来 3 px 未満になったらこう描く」という仮想 fallbackとして明示する 1 段落を入れる。 現状は「mock 限定」の注記が太字ではなく文末に押し込まれているので、最初の読み流しでは見落とされる。

2N セルの面積スケーラビリティが span 8 で破綻している

確率表示ブロックは縦バーなので 65 536 行を縦 880 px に圧縮できる (行高 ≈ 0.013 px、対数ヒント線で形だけ伝える)。 振幅表示ブロックは 2D matrix (w_grid × h_grid) なので 65 536 セルを正方形に並べ、本体寸法が 880 × 880 px まで膨らむ。 これは確率表示ブロックの 40 px 幅と比べて面積で 484 倍。回路エディタの 1 つのゲートとしては大きすぎ、ユーザーが span を 16 まで上げると画面の大半を占有する。 Quirk も同じ問題を持つが、qni-webgpu の Flexoki + WebGPU 描画では 本体が大きい = "高価な情報を持つ"という錯覚が強まり、初学者は「振幅表示ブロックは高機能」と過大評価しがち。 § 01 の使い分けガイドに「span が大きい場合は確率表示ブロックを推奨」と書くと、この錯覚を初期段階で打ち消せる。

§ 03 パレットアイコン (mini preview)

パレットに並ぶ AmplitudeDisplay アイコンは 40 × 40 px の静的 mini preview。 単一 cell (1×1) に mag² ≈ 50% の disk + 右下向き needle (phase = 5π/4) で Qni の "Q" 風シルエットを作る (円胴 + 右下に伸びるテール)。 matrix の四角い外枠は描かず、円胴 + 右下テールだけを表示する。 ホバー時は外側のホバー枠だけ表示 (静的なので個別 cell ポップアップは出さない)。

★ 批評 · § 03 パレットアイコン
「Q の右下テール」が本体 (matrix grid) と意味的に切れている

パレットアイコンは 単一セル (1×1) + 右下向き needle で Qni の "Q" 風シルエットを狙う、と本文に書かれている。 ブランディングとしては効くが、配置後の本体は最低でも 2×1 grid (span 1)、典型的には 2×2 grid (span 2)になる。 つまり「アイコン = 1 セル / 配置後 = 複数セルの matrix」という形状ジャンプが起きる。 これは sibling の probability-display.html § 03 で指摘されている「アイコンの 4 行 vs 配置後 span 1 の 2 行」と同じ構造の問題で、 ユーザは「振幅表示ブロック = 単一 cell のゲート」と最初に学習し、リサイズハンドルで広げるという正しい操作モデルに到達しにくい。

改善案: span 1 の初期状態 (2×1 grid に |0⟩ と |1⟩ の振幅 disk を 2 つ並べる) をアイコン化し、 2 セル + 中央分けの線で「複数測定結果を 2D matrix で見る」というメンタルモデルを最初から伝える。 "Q" 風シルエットの ブランディングは犠牲になるが、機能を優先する。 density-matrix-display.html § 03 はアイコンに 2×2 grid (span 1 の |+⟩⟨+| を 4 セル)を採用しており、密度行列表示ブロックの形を最初から正しく示している。本表示ブロックも同じ哲学に揃える価値がある。

現行 qni-webgpu のゲートは resizable span でも幅 40 px 固定 (例: 確率表示ブロックも 40 px)。本仕様の振幅表示ブロックは 2D 行列の縦横バランスを保つため span に応じた可変幅 (cols = 2〜16、width_px = (cols − 1) × SLOT_SPACING + GATE_SIZE = 56 × cols − 16、96 〜 880 px) を採用する。 これは現行 gate_visible_rect() / hit-test / drag-drop / ホバー枠 と整合しないので、以下を併せて実装する:

  • gate_visible_rect() — gate の width_cols を返すよう拡張、x..x + width_px を bounding rect とする (width_px = (cols − 1) × SLOT_SPACING + GATE_SIZE)。振幅表示ブロック以外は cols = 1 を返して既存挙動 (width_px = GATE_SIZE = 40) を維持。
  • hit-test (palette → circuit drop) — drop 時に新規 amplitude の gate_rect (width = 56 × cols − 16) と既存 gate rect が幾何交差しないかを確認、交差なら drop 拒否 (詳細は下の「placement / 衝突検出」参照、probability / QFT の resizable と同じセマンティクス)。
  • drag / drop preview — drag 中の影 / プレビューも width_px × height_px で描く。drag 中の matrix 背景は他ゲートの drag preview と同じ purple-600 にするが、outline 円の内側の白地は bg のまま残し、振幅 disk / outline / needle の色も通常時のまま変えない。回路 slot に snap して GPU の live 値が出る前も、palette から出した Amps1 は同じ GPU 表示シェーダの強制ゼロ描画インスタンスとして mag = 0 の空セル 2 つを描く。drop target highlight も同寸。
  • ホバー表示 — Amplitude の cell hover は正方形枠を描かず、対象 測定結果の outline 円周だけを purple-400 に置き換える。ゲート全体の矩形ホバー枠は cell hover 中には出さない。
  • resize handle — 上下のみ (height = span を変える)、左右の幅は span の関数なので separate な width handle は不要。
  • 列衝突検出 — gate の右端列まで衝突判定を広げる。width_px 範囲内の他ゲートと gate_rect ∩ gate_rect 幾何交差で重ならない位置にのみ配置可。
  • URL round-trip (Quirk 互換) — JSON は {"cols":[["Amps3"]]} のように単一 token。setWidth は表示列幅であって JSON 上の列消費ではない。 採用モデル: 「JSON col index = qni 内部 slot index」 (1:1 対応、shift 一切なし)。 decode:
    1. JSON の各 col 配列を読み、wire k の cell が "Amps3" なら span = 3 を正規表現で抽出
    2. cols = (span === 1 ? 2 : (span % 2 === 0 ? span : ceil(span/2))) で表示列幅を導出
    3. amplitude gate は qni 内部で JSON col index 1 つ分の slot を占有するエントリとして登録する。後続 slot を予約しない、shift しない
    4. 表示時に「右側 cols − 1 個の slot 範囲」に視覚的にはみ出すが、これは描画レイヤだけの話で slot 構造には反映しない
    encode:
    1. 各 qni slot を順に走査して JSON col 配列を出す。amplitude gate は "Amps<span>" の単一 token を該当 col に書くだけ
    2. shift / 圧縮なし。slot index がそのまま JSON col index になる
    衝突検出は decode/encode の責務ではなく、placement 時に幾何的に行う (次項)。
  • 水平 slot 占有モデル — qni の水平 slot pitch は SLOT_SPACING = 56 px (確率表示ブロックと同じ。40 px ではない)。amplitude の幾何幅は垂直の (span − 1) × LINE_GAP + GATE_SIZE と対称に width_px = (cols − 1) × SLOT_SPACING + GATE_SIZE = 56 × cols − 16。slot 構造としては 1 列消費 (上記 decode/encode と一致)、視覚的には cols slot 分の幅を覆う。
  • placement / 衝突検出 (幾何ベース) — slot index の比較ではなく、gate_rect の幾何交差で判定する: 新規 gate を slot N に置くとき、その gate_rect (x_left..x_left + width_px, y_top..y_top + height_px) と既存 gate の rect が交差していたら drop 拒否。amplitude の場合 width が広いので、右側 cols − 1 個分の slot 範囲に既存 gate があれば交差で検出される。
    この方式なら cols 可変 × cols=1 ゲート混在も、矩形交差だけで一貫して扱える。逆に slot index 単純比較は wide gate に対して破綻するので採用しない。

上記が困難なら fallback: 幅 40 px 固定 × 高さ可変 (確率表示ブロックと同じ) にして、2D matrix を 1 列の縦並び に潰す。情報は保持されるが Quirk のような bit-pattern 視覚化は失う。本仕様はまず可変幅で実装することを推奨、難しければこの fallback に切り替える。

cols 算出式 span === 1 ? 2 : (span % 2 === 0 ? span : ceil(span/2)) の根拠不明

span 別表で cols = 2, 2, 2, 4, 3, 6, 4, 8, 5, 10, 6, 12, 7, 14, 8, 16 となるが、奇数 span (3, 5, 7, ...) が ceil(span/2) で偶数 span より狭くなる非単調性がある。 例: span 4 = cols 4 (208 px 幅)、span 5 = cols 3 (152 px 幅) と span が増えたのに幅が縮む。grid を正方形に近づける Quirk オリジナル式と一致するが、 ユーザーが span を上げたら本体は単調に大きくなるという期待と逆に動くので、リサイズ操作中に「ハンドル動かしてるのに本体が縮んだ?」という混乱を生む。 この非単調性が意図的 (matrix grid の縦横バランス優先) なら、リサイズハンドル仕様 (§ 09 相当) のところで「span を上げると幅が増えたり減ったりする」と明示する余地がある。

§ 06 セル描画モデル (state panel と同じ 4 層)

qni-webgpu の状態ベクトルパネル (apps/web/src/gpu/shaders/state.rs) と 同じ 4 層モデルを 1:1 で踏襲する: outline 円 + 振幅 disk + disk 境界線 + 位相 needle。 Quirk の確率正方形 / 対数円は冗長 (disk の半径 = mag、面積 ∝ mag² で確率値も読める) なので不採用。 α = re + i·im, mag = |α| = √prob。

(1) back fill — セル背景。通常時は bg (#FFFCF0)。drag preview 中だけ円の外側を purple-600 (#5E409D) に差し替え、outline 円の内側の白地と disk / outline / needle 色は維持する
(2) outline 円 — セル中央、半径 = cellPx/2 − stroke/2 − 1.5 px (matrix 外枠へ触れない範囲で最大化する)。stroke は cellPx ≥ 24 で 2 px、それ未満で 1 px。描画条件: cellPx ≥ 3。 mag > 1e-6 なら tx-2 (state panel の state_outline)、≈ 0 なら ui-2 (state_outline_zero)。cell hover 時は正方形枠ではなく、この outline 円周を purple-400 で上書きする。
(3) 振幅 disk — 中心 = セル中心、半径 r = mag × inner_radius (= mag × (outline_radius − stroke/2)、mag = 1 で outline の内側ギリギリまで広がる)。 blue-200 fill (state panel の state_fill、Quirk #8FF と等価)。 加えて blue-400 (確率表示ブロックのバー右端と同じ) でinset の 1 px 境界線を引く: ① 半径 r で fill ② 半径 r − 0.5 で stroke。stroke の外端が r に一致するので視認性は上がるが disk 面積は変わらない。閾値: r > 0.3 で fill、r ≥ 1.5 で stroke も追加
(4) phase needle — セル中心から方向 (−sin(phase), −cos(phase)) = (−im/mag, −re/mag) へ長さ inner_radius の線分。 tx stroke (outline と同じ太さ: cellPx ≥ 24 で 2 px、それ未満で 1 px)。 描画条件: cellPx ≥ 12。それ未満では省略 (cellPx ∈ [3, 12) は outline + disk、cellPx < 3 はモック限定 heatmap)。 位相 0° = 真上、反時計回りに π/2 (= 左)、π (= 下)、−π/2 (= 右)。 state panel cell_contribution wgsl と一致 (let dir = vec2(-sin(phase), -cos(phase)))
(5) frame — matrix 全体の外枠だけを ui-2 1 px で描く。cell 間の区切り線は描かない (円と円の間は bg のまま)

state panel との差分: 色トークン (blue-200 fill / blue-400 disk border / tx-2 outline / tx needle) と disk 半径計算式 (mag × inner_radius) は state.rs の cell_contribution() と同一。ただし以下の点で異なる:

  • cell を矩形 grid で密に並べる (state panel は cell 間に 3 px gap あり)
  • outline 表示条件: mag > 1e-6 で tx-2 / ≈ 0 で ui-2。10 量子ビット 一様振幅 (prob = 1/1024) のような小さいが非ゼロの振幅も non-zero outline として扱う
  • layer 合成順序: 本仕様は frame → outline → disk → disk border → needle (state panel は fill → disk border → needle → outline 合成)。cell 間の区切り線は描かない
  • phase lock cell の別マーカーは引かない (state panel は phase lock 概念がない、本仕様も Quirk の赤マーカーを不採用)

擬似コード (Rust + wgsl 構造)

// shader (fragment) — 1 cell につき (state.rs の cell_contribution と同形)
const STROKE: f32 = 2.0;
const half_stroke: f32 = STROKE / 2.0;
fn render_cell(re: f32, im: f32, cell_uv: vec2<f32>, cell_size: f32) -> vec4<f32> {
    let mag = sqrt(re*re + im*im);
    let p   = re*re + im*im;
    let outline_clearance = 1.5;
    let r_outline = cell_size / 2.0 - half_stroke - outline_clearance;
    let r_inner   = r_outline - half_stroke;
    let r_cell    = distance(cell_uv * cell_size, vec2(cell_size/2.0));
    var col = BG;                                                      // (1) back

    // (2) outline (常時描画、mag で stroke 色だけ切替)
    let outline_color = select(UI_2, TX_2, mag > 1e-6);
    if (abs(r_cell - r_outline) < half_stroke) { col = outline_color; }

    // (3) disk (mag > threshold なら塗る)
    let r_disk = mag * r_inner;
    if (r_disk > 0.3 && r_cell <= r_disk) {
        col = BLUE_200;
    }
    // (3.5) disk border — 半径 r_disk - 0.5 の 1 px stroke。外端は disk 外周と一致。
    if (r_disk >= 1.5 && abs(r_cell - (r_disk - 0.5)) <= 0.5) {
        col = BLUE_400;
    }
    // (4) needle: 同じ fragment shader 内で SDF。cell center から (-sin(phase), -cos(phase)) × inner_radius
    //     への線分との signed distance を計算、stroke 幅以下なら TX で塗る (§ 09 参照)。
    // (5) frame: matrix 全体の外枠だけを ui-2 1 px で塗る。cell 間の区切り線は描かない。
    //     全レイヤ CPU vertex buffer は不要、すべて fragment shader 完結。
    return vec4(col, 1.0);
}
★ 批評 · § 06 セル描画モデル
極座標 (mag + phase) を採用した根拠が「state panel と統一」で止まっている

本ページは複素振幅 α = re + i·im を 「disk 半径 = mag = √prob」「needle 方向 = phase」の極座標で描く決定をしているが、 この decision の根拠は「state panel cell_contribution() と同じ語彙」「Quirk の確率正方形 / 対数円は冗長」とだけ書かれている。 振幅を 2D 平面に写す方法は他にもある:

  • (A) 直交座標: 2 つの bar (re と im) を縦に並べる。実部 / 虚部の符号と大きさが直接読める。位相回転による re ↔ im の swap が見える。
  • (B) phasor (arrow): 中心から (re, im) 方向へ長さ mag の矢印 1 本。極座標 (本仕様) は半径 + needle の 2 オブジェクトだが phasor は 1 オブジェクトに統合できる。
  • (C) HSV / color wheel: 位相を色相に、大きさを彩度 / 明度にマッピング。1 cell が 1 つの色で済むので heatmap モードに自然移行できる (Quirk の oss/QuirkAlternate 拡張に類似)。

本仕様は (C) を「Flexoki トーンに馴染まない」(§ 10) と明示退ける一方、(A) (B) を退ける明示的な議論がない。 極座標 (mag + phase) の利点は「needle が真上 = 位相 0」という幾何的アンカーを持ち、位相パターンを目で追えること、 欠点は「mag = 0 のとき位相が定義できない」「needle と disk が cell 内で 2 オブジェクト = cellPx が小さい時に潰れる」こと。 この trade-off を § 06 冒頭で 1 段落言語化すると、phasor (B) を採用しない理由 (mag が小さい時に矢印が見えない / 同心円的な disk のほうがスケール感を読みやすい) が明確になる。

「mag > 1e-6」と「r > 0.3」「r ≥ 1.5」の閾値群がマジックナンバー

outline の色切り替え (mag > 1e-6) / disk fill (r > 0.3) / disk border (r ≥ 1.5) と 3 つのマジックナンバーが本文中に散在する。 1e-6 は f32 epsilon の経験値、0.3 px は anti-alias で sub-pixel 描画した時に視認できる最小半径、1.5 px は inset 1 px stroke が disk fill に潰されない最小半径、とそれぞれ異なる物理的根拠を持つが、§ 06 ではフラットに並べられている。 コメントに「(a) f32 noise の閾値 / (b) sub-pixel 視認限界 / (c) inset border 視認限界」と分類して書くと、将来 cellPx を変えたり anti-alias を変更したりするときの再評価が容易になる。

§ 07 phase lock + incoherent state

phase lock — 主要振幅を位相基準に

GPU パイプライン (§ 09) は最大振幅を持つ測定結果の index (phaseLockIndex) を返す。 その index の振幅の位相 θ = atan2(im, re) を全 ket から e−iθ で打ち消し、 phase lock 後の振幅は実数正 + 虚部ゼロに正規化される。これで「全体に同じ位相を掛けたとき見た目が変わらない」 = 量子状態の物理的等価性を視覚化に反映する。

phase lock cell に別マーカーは引かない。state panel と同じく needle が真上 (位相 0) を向いている cell を見れば自然に lock 位置がわかる、というのが基本方針。 Quirk 原版の赤い水平線 + 'fixed' ラベルは (a) needle 方向との視覚的衝突 (Quirk は phase 0 = 右、本仕様は phase 0 = 上)、(b) state panel に同等マーカーが無いため UI が分散する、の 2 点で不採用。 span == 回路全体の量子ビット数 のときだけは phase lock を無効にする (「全体相」を持つ意味がないため、Quirk 同挙動)。 実装は AmplitudeCapture uniform の phase_lock_enabled flag で制御する: ColumnAnalysis が span == total_qubits を検出して phase_lock_enabled = 0 に set し、shader 側は phase_lock_index = sentinel を書き、stage 8 で θ = 0 扱い (正規化のみで位相回転なし)。詳細は § 09 stage 7/8 参照。

incoherent state — entangled で振幅未定義

span 内の量子ビットが span 外と entangled しているとき、純粋状態としての振幅は定義できない (reduced density matrix のみ計算可能)。 Quirk は coherence 指標 quality = denormalizedQuality / unity / incoherentUnity を計算し、 quality < 0.99 で incoherent と判定する。

  • matrix は ket ではなく incoherentKet = sqrt(reduced_diag) (実数のみ) を描く
  • outline 円は通常通り描く (情報量を保持)、disk は alpha 0.45 で薄塗り「振幅未定義 / 確率のみ」を示す
  • phase needle は描かない (虚部が無いので位相は 0、線が意味を持たない)
  • ゲート下に "incoherent" を red-600 でフェードイン (1 − indicatorAlpha 透明度)
  • ホバー popup は "Probability of |ket⟩ [entangled with other qubits]" と raw % / log dB のみ (val / phase は出さない)

measure 済み列での挙動 (Quirk と仕様が異なる)

qni と Quirk で capture 順序が異なる:

  • Quirk: 列処理の前に display capture → measure された量子ビットがあっても collapse 前の純粋振幅を表示。「deferred measurement」の解釈で、ゲート下に "(w/ measure defer)" / "(assuming measurement deferred)" を red-600 でフェードイン。
  • qni: 列処理の後に display capture (既存 CaptureProbability と同じパス) → measure された量子ビットは collapse 後の古典状態として扱われる。表示される ket は post-measure 状態の振幅 (=ある測定結果に collapse した後の確定状態、span 内に measured wire があれば確率 1 の単一の測定結果になる)。

本仕様では「post-measure state を素直に表示する」を採用。ゲート下の "incoherent" 以外の補足テキストは出さない (Quirk の "(w/ measure defer)" 系を真似ない)。Quirk と数値再現性を取る場合は別途 capture 順序の入れ替え (lowering で display を column 先頭に移動) が必要だが、本仕様では未採用。

★ 批評 · § 07 phase lock + incoherent state
quality < 0.99 閾値の根拠が Quirk 互換のみで、誤判定リスクが定量評価されていない

本文は「f32 丸め誤差で false-incoherent は通常出ない」とだけ述べるが、 実際には 量子ビット数が増えると累積誤差が 1e-3 オーダーに達することがあり、span 8 を超える pure state でも quality = 0.98 程度になり incoherent と誤判定される可能性がある。 Quirk は WebGL float32 で同じ閾値を使うが、qni-webgpu は WebGPU 経由でより数値安定な実装が可能 (compute shader で f64 エミュレートも選択肢)。 単に Quirk と同じ 0.99 を継承するのではなく、span × 回路深さ × Flexoki 表示でユーザに違和感を与えるしきい値を実測した結果として閾値を採用するほうが防衛的。 最低限、「閾値は将来 0.95 や 0.999 に変更する可能性がある」と注記すると、後続改良の自由度が確保される。

incoherent 表示の alpha 0.45 が「振幅未定義」を直感的に伝えない

incoherent 状態では disk を alpha 0.45 で薄塗りし needle を消す、と仕様化されている。 しかし「薄い = 確率が低い」と読み取る初学者は多く、「薄い disk = 振幅が定義できない」という意図が伝わりにくい。 coherent state でも mag が小さい disk は薄く見える (anti-alias で sub-pixel 描画されるため) ので、alpha 半透明だけでは coherent と incoherent の区別がつかない場面が出る。 改善案: incoherent disk には disk 内側に diagonal hatch (45° の斜線パターン) を入れる / 色を blue-200 から purple-200 に変えて「位相情報が無い」ことを示す、など視覚的に異なる texture を採用する余地がある。 ゲート下の "incoherent" 赤テキストは補助だが、widget サイズが大きい (span 5+) と離れすぎて関連性が読みにくい。

post-measure 挙動の Quirk 非互換が「決定事項」になっているが影響範囲が不明

qni では「列処理の後に display capture」、Quirk では「列処理の前」と仕様が異なる、と決定事項として明記されている。 これは Quirk URL から import した回路で 振幅表示ブロックの値が Quirk と一致しないという重大な互換性違反だが、本仕様では「Quirk と数値再現性を取る場合は別途 capture 順序の入れ替えが必要 (本仕様では未採用)」と 1 行で済まされている。 影響範囲 (measurement gate を含む Quirk 例題回路の何 % が再現不能か / ユーザがどんなケースで気付くか) の定量評価か、少なくとも「Quirk 互換性スコア」の現状値があると、将来 Quirk-compat モードを実装する判断材料になる。

§ 09 GPU パイプライン (GPU-only、毎フレーム readback 無し)

Quirk の amplitudeDisplayStatTextures() + JS 側 processOutputs() を WebGPU compute shader 列に完全移植する。Quirk が JS で行う unity 正規化 / quality 計算 / phaseLockIndex 選択 / phase 回転 も全部 GPU compute pass にする (AGENTS.md の GPU-only ルールに従い、毎フレームの readback は禁止)。 入力: state_ket: storage<vec2<f32>> (state vector、各要素 = 複素振幅)、capture: AmplitudeCapture uniform (下記)。 出力: すべて GPU storage buffer に書き込み、render shader が直接 sample する。

capture uniform (CaptureProbability の amplitude 版)

現行 CaptureProbability は base_bit / span / output_slot のみで control 情報を持たない。 Amplitude では Quirk と同じ control-conditional 表示を行うため、capture uniform を拡張する: 

struct AmplitudeCapture {
    base_bit:           u32,   // span 内の量子ビットの起点 (CaptureProbability と同じ)
    span:               u32,   // 1..=16
    output_slot:        u32,   // 結果 buffer の書き込み slot
    control_mask:       u32,   // どの state_index bit が control 条件の対象か
    control_value:      u32,   // 期待値 (該当 bit が 1 なら |1⟩ 期待、0 なら |0⟩ 期待)
    phase_lock_enabled: u32,   // 0 = 無効 (θ=0、回転なし) / 1 = 有効 (Quirk 互換、決定論的 max)
    total_qubits:       u32,   // 回路全体の量子ビット数。span == total_qubits なら ColumnAnalysis で
                                // 自動的に phase_lock_enabled = 0 にセット (§ 07 「span == 全量子ビット」例外)
};

bit 順序: control_mask / control_value はqubit_bit (= state_index の bit position) 単位で指定。 qni-webgpu の state_index は qubit big-endian (state_index = bq−1 bq−2 ... b1 b0、wire 0 が top wire) なので、 wire 番号と bit position は qubit_bit = qubits − 1 − wire で変換する (qni 既存の変換と一致)。 uniform に書く値は wire 番号ではなく変換後の qubit_bit: 

// ColumnAnalysis 側で wire → qubit_bit 変換してから uniform を組む。
// 例: qubits = 5、wire 1 を |1⟩ control にする場合:
//   qubit_bit = 5 - 1 - 1 = 3
//   control_mask  |= 1 << 3;
//   control_value |= 1 << 3;   // |1⟩ 期待
// wire 1 を |0⟩ control (anti-control) にする場合:
//   control_mask  |= 1 << 3;
//   control_value |= 0 << 3;   // (= no-op)、|0⟩ 期待

shader 内では既存 base_bit と同じセマンティクスで (state_index & control_mask) == control_value な要素のみを集約対象とする。 control_mask = 0 なら無条件 (現行 確率表示ブロック同等)。controls 統合はこの uniform 1 つで完結する。

phaseLockIndex の選び方 (Quirk 互換: 決定的最大)

Quirk の _processOutputs_pickPhaseLockIndex() は m > best * 10000 な「10000 倍ジャンプしないと更新しない」探索を行う: 

var best: f32 = 0.0;
var result: u32 = 0u;
for (k = 0u; k < n; k++) {
    let m = dot(ket[k], ket[k]);
    if (m > best * 10000.0) { best = m; result = k; }
}

真の最大ではなく「圧倒的に大きい最初の outcome」を選ぶ。利点は (a) 振幅が拮抗するときは index 0 を保ち画面のチラつき (異なるフレームで lock 先がコロコロ変わる) を抑える、(b) 浮動小数の僅差を安定して扱える、こと。 qni でもこの Quirk-compatible な決定論的探索を採用する (真の argmax は意図的に使わない)。

Render shader (毎フレーム描画、readback 無し)

矩形 cell grid を fragment shader で描く (確率表示ブロックの STATE_RENDER_SHADER と同じパターン)。 入力 storage buffer (ket / incoherent_ket / quality / phaseLockIndex) を直接 sample。 quality < 0.99 の判定も fragment shader 内で行う (incoherent fallback 切替) — CPU 分岐ではない。 needle 線・matrix 外枠・outline 円・disk・disk 境界線はすべて1 dispatch の draw call で出す:

  • outline 円 / disk / disk 境界線: fragment shader で SDF (signed distance) 計算、ブレンド合成
  • 背景 / matrix 外枠: 同じ fragment shader 内で背景 layer として塗る。cell 間の区切り線は描かない
  • needle: fragment shader 内で SDF で描く。各 fragment で「自分が属する cell の amp = (re, im) を amplitude_result.ket[k] から sample」→「needle 線分 (center → (-sin(phase), -cos(phase)) × inner_radius) との signed distance を計算」→ stroke 幅以下なら TX 色で塗る。専用 vertex buffer は持たない ので、振幅 / 位相が変わるたび rebuild する必要がない (毎 recompute で amplitude_result が更新されれば、render shader が自動的に新しい needle を描く)。

CPU は vertex バッファを作らない。ゲート配置 (cell サイズ) が変わったときに更新する vertex は cell quad の四隅と uv だけ (各セル fragment shader が cell index を知るための instance buffer 相当)。これは ゲート placement / resize 時だけ rebuild。

Popup の値も GPU 描画 (readback 無し、glyph atlas + overlay shader)

ホバー popup の数値 (coherent では val / mag² / phase の 3 行、incoherent では raw / log の 2 行) は本番 UI 経路なので、GPU-only ルールに従いreadback しない。 代わりに glyph atlas + overlay render pass で GPU 上で文字を直接合成する (確率表示ブロックのポップアップと同じ方針)。 coherent / incoherent の分岐は overlay fragment shader 内で quality < 0.99 を判定して切り替える (擬似コードは下記)。

必要なリソース

  • glyph_atlas: texture_2d — pre-rendered grid: ASCII 数字 0..9、記号 + − . i %、単位 °、ラベル val / mag² / phase (coherent 用)、raw / log (incoherent 用、確率表示ブロックのポップアップと完全共有) と dB 単位。Geist Mono で 1 行高 16 px、各 glyph 16×16 px の正方 grid に焼く (起動時 1 度のみ)
  • amplitude_result — § 09 の compute pass 出力 storage buffer (ket / incoherent_ket / quality / phase_lock_index)。fragment shader は quality < 0.99 で incoherent_ket を読み、それ以外は ket を読む
  • popup_uniform: PopupRenderInput — hovered cell の index hovered_k: u32、popup screen 位置 popup_pos: vec2<f32>、表示 / 非表示 flag

overlay render pass

ホバー判定は CPU で行う (マウス座標 → cell index)、その index を popup_uniform に書くだけ。値そのものは GPU 内のまま: 

// fragment shader (popup overlay) — coherent と incoherent で表示内容を切替
@fragment
fn fs_popup(@location(0) uv: vec2<f32>) -> @location(0) vec4<f32> {
    if (popup.hovered_k == 0xffffffffu) { discard; }
    let k: u32 = popup.hovered_k;
    let q: f32 = amplitude_result.quality;

    var glyph_uv: vec2<f32>;
    if (q < 0.99) {
        // incoherent: raw % と log dB の 2 行のみ (val / phase は出さない)。
        // incoherent_ket[k] は sqrt(prob) なので raw_prob = (incoherent_ket[k])².
        let sqrt_p: f32 = amplitude_result.incoherent_ket[k];
        let raw_p: f32 = sqrt_p * sqrt_p;                       // 0..1
        // log10(x) = log(x) * 0.4342945。raw_p = 0 のときは log(0) = -inf になるので、
        // 専用 sentinel (NEG_INF: f32 = -3.4e38) を渡し、compute_glyph_uv_incoherent 側で
        // "−∞ dB" の glyph 並びへ分岐する。
        let log_db: f32 = select(log(raw_p) * 4.342945, NEG_INF, raw_p <= 0.0);
        glyph_uv = compute_glyph_uv_incoherent(k, uv, raw_p, log_db);
    } else {
        // coherent: val (re / im) / mag² / phase の 3 行。
        let amp: vec2<f32> = amplitude_result.ket[k];
        let mag2: f32 = dot(amp, amp);
        let phase_deg: f32 = atan2(amp.y, amp.x) * 180.0 / PI;
        glyph_uv = compute_glyph_uv_coherent(k, uv, amp, mag2, phase_deg);
    }
    return sample_glyph_atlas(glyph_uv);
}

compute_glyph_uv_coherent / compute_glyph_uv_incoherent は同じ glyph atlas を sample するが、 ラベル glyph (val / mag² / phase vs raw / log) と行レイアウトが異なる。incoherent 側の raw / log ラベルと整形ロジックは 確率表示ブロックのポップアップと完全共有 (shaders/glyph_format.wgsl)。

確率表示ブロックのポップアップとの共有

確率表示ブロックのポップアップの既存 glyph atlas + format callback パターンを再利用する:

  • glyph atlas 本体 — 既に 確率表示ブロックのポップアップで実装済み (shaders/glyph_atlas.wgsl)。ASCII 数字・+ − . i % °・固定ラベル文字を共有。Amplitude 用に追加するのは val / mag² / phase のラベル glyph のみ。
  • format helper — 確率表示ブロックのポップアップで format_percent(p, decimals) / format_db(p) 等が既にある。Amplitude は 新規に 以下を追加:
    • format_complex(re, im, decimals) — "0.50000 + 0.30000i" 形式。sign / 整数桁 / 小数桁 / "i" 記号 を順に glyph に逆引き。
    • format_signed_deg(deg, decimals) — "+30.96°" 形式。format_percent に sign prefix を足したものと同等構造。
  • log10 の WGSL fallback — WGSL には log10 が無いので log10(x) = log(x) / log(10.0) (= log(x) * 0.4342945) を glyph_format.wgsl 内に inline 定義。確率表示ブロックのポップアップの dB 表示でも同じ式が必要なので、Probability/Amplitude 共有 helper として置く。
  • atan2 は WGSL builtin なので追加実装不要。

確率表示ブロックのポップアップが既に動いていれば、振幅表示ブロックのポップアップの glyph 描画は「format 関数 2 つ追加 + label glyph 3 つ追加」だけで済む見込み。 fragment shader 内で完全な printf を実装するわけではなく、確率表示ブロックのポップアップの既存パイプラインに乗せる前提。

readback はテスト専用 API に限定: read_amplitude_cell(gate_id, k) は #[wasm_bindgen] で JS テストから呼ぶ async API としてのみ提供 (Playwright で val / mag² / phase の正しさを確認する用途)。本番 UI 経路からは一切呼ばれない。 これは AGENTS.md の例外条項 (テストハーネス向けの on-demand readback) に該当。

Quirk の探索ロジック m > best * 10000 は「明らかに大きい測定結果だけ採用、拮抗時は index 0 を保つ」。 これは振幅が小数点 4 桁オーダーで揺らぐ場合に lock 先が安定するメリットがある一方、span が大きいときに「実質的な最大値」を見逃すケースが出る。 例えば span 8 の QFT|001⟩ では全 256 測定結果が mag² = 1/256 ≈ 0.39% で均等になり、best × 10000 条件を満たす測定結果は存在せず lock index = 0 で固定される。 これは「均等位相分布では位相回転をしない」という意味になるが、ユーザは「lock index が真に最大の測定結果を指している」と期待する。 テスト計画 § 11 にこのケースが含まれているのは良いが、本セクションでは Quirk 互換であるという根拠だけで採用されている。qni-webgpu 独自の制約 (cellPx ≥ 12 で needle が見える span 1〜8)に対して最適化された探索ロジックを検討する余地はある (例: m > best × 1.1 など 10 % 程度の差で更新)。
