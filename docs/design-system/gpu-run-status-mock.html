Run GPU button & status pill

GPU モードで Run on GPU を押した直後・実行中・完了・失敗の 4 状態を toolbar 内に収める提案。失敗時は理由 (backend offline / unsupported gate / HTTP error) を pill の右側に · 区切りで足す。CPU fallback を匂わせる文言や generic な Loading… は使わない。

§ 01 6 状態 — toolbar 一直線で

全状態を縦に並べる。toolbar は paper bg + shadow (下方向のみ) の フルワイド header strip。ウィンドウの top / left / right 3 辺すべてに密着するので 4 角すべて square (角丸を入れるとフチが切れて「タブ」っぽくなる)。 下に spacing-6 (24 px) 空けてゲートパレットを置き、さらに palette と回路 1 段目ゲートの間は spacing-12 (48 px) 空ける (palette と回路はどちらも cyan-400 ゲートが並ぶ同質要素なので、より強い境界が必要)。 レイアウトは [↶ undo] [↷ redo] [🗑 trash] | [▶ run] [status pill] … [spacer] … [Local | GPU] の 3 ゾーン構成:
・edit cluster (左): undo / redo / trash — 回路編集の utilities。Local / GPU 両モードで常時表示。
・execute cluster (中): run + status pill。Run はアイコンのみ ▷、edit と同じ neutral gray ボタンで揃え、1 px hairline divider で intent group の境を見せる。
・mode (右): Local | GPU セグメント。
button は 常に ▷ アイコン 固定 (running 時は tx-3 に dim するだけで形は変わらない)。位置・幅も不変。 動的アクセントは pill の脈動ドット 1 点に集約。 Local モード時は execute cluster (run + pill) が消え、edit + spacer + toggle だけになる。

§ 03 Run button — 文字 vs アイコンの 2 案

押下後に起こる動作は どの状態でも同じ「現回路を GPU で実行する」 なので、ラベルは Run on GPU で統一し、見た目も全状態で 同じ neutral グレー に揃える (押せるアクションは何度押しても同じ)。 唯一の差は running ─ tx-3 に dim して cursor: not-allowed。 動的アクセントは pill の脈動ドット 1 点に集約。
その上で button のラベルを文字にするかアイコンにするか を比較する: A · text-led (常に Run on GPU と書く) と B · icon-led (常に ▷ — pill が文字を全部担当)。

A · text-led 状態ごとに最も意味の濃い文字を出す

規則

全状態で Run on GPU をベタ書き。色は全状態 neutral グレー。Running は tx-3 に dim して disabled を伝える (テキスト内容は変えない)。状態の語りは pill 側が完全担当。

長所

  • 初見で何が起きるか button だけで読める (`Run on GPU` で動詞 + 対象が完結)
  • screen reader は visible caption をそのまま読むので a11y 対応がシンプル
  • 右隣の Local | GPU セグメント (文字) と視覚リズムが揃う

短所

  • on GPU 部分は隣のトグルが既に語っており、厳密には冗長
  • 同じテキストが 3 状態で並ぶので画面情報量がやや高い (pill + button が両方文字)
B · icon-led context が既に語っている部分はアイコン化する

規則

全状態で ▷ (play) アイコン 1 種類のみ。idle / completed / failed は tx-2、running は tx-3 に dim して disabled を表現。形は不変、色だけ落ちる。状態は pill 側でだけ語る。

長所

  • button 内に文字がない分 toolbar 全体の情報密度が下がって calm
  • pill (文字) と button (アイコン) で役割が完全に分離 — pill = 何が起きた、button = run できる
  • ▷ アイコン 1 種類だけが画面に出続けるので形・幅・位置の揺らぎがゼロ
  • ▶ は Jupyter / VSCode / 一般メディアプレイヤーで universal な execute affordance

短所

  • 初見ユーザーに「これは何のボタン？」と問われた場合、tooltip / aria-label がないと答えられない
  • 右隣の Local | GPU セグメント (文字) と並ぶと button だけアイコンで視覚スタイルがやや浮く
  • failed の attention は pill だけが担うので、button が calm すぎて見落とされないか確認が要る (pill の red dot + 文言が十分なら問題ない見込み)

採用: B (icon-led)。 押下後の動作は Run on GPU 一択で同じ、状態は pill 側でだけ語る、 という前提が固まったので button にテキストを持たせる意味が薄い。
A は文字 + 色だけで状態を語る代替案として残してあるが、§01 ギャラリー / §04 プロトタイプ / §05 impl spec は B (icon-led) で揃えている。 button は ▷ アイコン 1 種類で固定、running 時は tx-3 に dim するだけ。spinner も不要なので追加タイマーは要らない。

§ 05 導入要件

ツールバー表示要件

  1. ツールバーのパネルコンテナ — paper 背景、角丸なし、下方向だけの影。ウィンドウの上端 / 左端 / 右端に密着し、stroke は入れない。
  2. 縦方向の余白 — toolbar 下 → palette 上 = 24 px (spacing-6)、palette 下 → 回路 1 段目ゲート上 = 48 px (spacing-12)。
  3. 並び順 — undo → redo → trash → divider → run button → status pill → spacer → execution mode toggle。Local モードでは run button + status pill を表示しない。
  4. 編集ボタン — 32×32 px、icon 18 px / stroke 2 px。hover は ui 塗り、disabled は tx-3。
  5. Run button — ▷ アイコン 1 種類で固定。running 中は tx-3 に dim し、button 自体は静止させる。
  6. 状態ピル — running / completed / failed のときだけ表示する。dot 6 px + text-sm label + 必要な詳細値を横並びにし、bg は transparent。
  7. dot 脈動 — running 中だけ dot が 1.2 s 周期で脈動する。spinner は使わない。
  8. 文言 — Backend unreachable / Unsupported gate / Backend error / Completed を §02 の表記どおりに使う。
  9. focus 表示 — Local / GPU トグルは active 側の塗りで選択状態を示す。クリック後に青い focus outline を残さない。

Acceptance

  1. toolbar が §01 の 6 状態と色・寸法・位置で一致する。
  2. toolbar / palette / circuit の 24 px / 48 px リズムが維持される。
  3. GPU モードで Run を押すと running → completed / failed へ遷移し、状態ピルの文言が §02 と一致する。
  4. Local モードでは run + pill が消え、edit utilities と toggle はそのまま。
  5. Local / GPU トグルをマウスで切り替えても、seg の周りに青い focus outline が出ない。

避ける文言

  • CPU で代わりに計算します / Switching to CPU / Local モードで実行 — GPU を求めた行為に CPU 救済を匂わせない。
  • Loading… — 何を loading してるか不明。Running on GPU… で具体に。
  • Try again 単独 — 理由を pill 側で必ず示す。
  • 生 stacktrace / JSON dump — pill に出さない。
  • 顔文字 / 励まし語尾 — トーンに合わない。
