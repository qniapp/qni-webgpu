Run GPU button & status pill

GPU モードで Run on GPU を押した直後・実行中・完了・失敗の 4 状態を toolbar 内に収める提案。失敗時は理由 (backend offline / unsupported gate / HTTP error) を pill の右側に · 区切りで足す。CPU fallback を匂わせる文言や generic な Loading… は使わない。

§ 01 6 状態 — toolbar 一直線で

全状態を縦に並べる。toolbar は paper bg + shadow (下方向のみ) の フルワイド header strip。ウィンドウの top / left / right 3 辺すべてに密着するので 4 角すべて square (角丸を入れるとフチが切れて「タブ」っぽくなる)。 下に spacing-6 (24 px) 空けてゲートパレットを置き、さらに palette と回路 1 段目ゲートの間は spacing-12 (48 px) 空ける (palette と回路はどちらも cyan-400 ゲートが並ぶ同質要素なので、より強い境界が必要)。 レイアウトは [↶ undo] [↷ redo] [🗑 trash] | [▶ run] [status pill] … [spacer] … [Local | GPU] の 3 ゾーン構成:
・edit cluster (左): undo / redo / trash — 回路編集の utilities。Local / GPU 両モードで常時表示。
・execute cluster (中): run + status pill。Run はアイコンのみ ▷、edit と同じ neutral gray ボタンで揃え、1 px hairline divider で intent group の境を見せる。
・mode (右): Local | GPU セグメント。
button は 常に ▷ アイコン 固定 (running 時は tx-3 に dim するだけで形は変わらない)。位置・幅も不変。 動的アクセントは pill の脈動ドット 1 点に集約。 Local モード時は execute cluster (run + pill) が消え、edit + spacer + toggle だけになる。

§ 02 Status pill の解剖

§ 03 Run button — 文字 vs アイコンの 2 案

押下後に起こる動作は どの状態でも同じ「現回路を GPU で実行する」 なので、ラベルは Run on GPU で統一し、見た目も全状態で 同じ neutral グレー に揃える (押せるアクションは何度押しても同じ)。 唯一の差は running ─ tx-3 に dim して cursor: not-allowed。 動的アクセントは pill の脈動ドット 1 点に集約。
その上で button のラベルを文字にするかアイコンにするか を比較する: A · text-led (常に Run on GPU と書く) と B · icon-led (常に ▷ — pill が文字を全部担当)。

A · text-led 状態ごとに最も意味の濃い文字を出す

規則

全状態で Run on GPU をベタ書き。色は全状態 neutral グレー。Running は tx-3 に dim して disabled を伝える (テキスト内容は変えない)。状態の語りは pill 側が完全担当。

長所

  • 初見で何が起きるか button だけで読める (`Run on GPU` で動詞 + 対象が完結)
  • screen reader は visible caption をそのまま読むので a11y 実装がシンプル
  • 右隣の Local | GPU セグメント (文字) と視覚リズムが揃う

短所

  • on GPU 部分は隣のトグルが既に語っており、厳密には冗長
  • 同じテキストが 3 状態で並ぶので画面情報量がやや高い (pill + button が両方文字)
B · icon-led context が既に語っている部分はアイコン化する

規則

全状態で ▷ (play) アイコン 1 種類のみ。idle / completed / failed は tx-2、running は tx-3 に dim して disabled を表現。形は不変、色だけ落ちる。状態は pill 側でだけ語る。

長所

  • button 内に文字がない分 toolbar 全体の情報密度が下がって calm
  • pill (文字) と button (アイコン) で役割が完全に分離 — pill = 何が起きた、button = run できる
  • ▷ アイコン 1 種類だけが画面に出続けるので形・幅・位置の揺らぎがゼロ
  • ▶ は Jupyter / VSCode / 一般メディアプレイヤーで universal な execute affordance

短所

  • 初見ユーザーに「これは何のボタン？」と問われた場合、tooltip / aria-label がないと答えられない (実装ではどちらにせよ付ける)
  • 右隣の Local | GPU セグメント (文字) と並ぶと button だけアイコンで視覚スタイルがやや浮く
  • failed の attention は pill だけが担うので、button が calm すぎて見落とされないか確認が要る (pill の red dot + 文言が十分なら問題ない見込み)

採用: B (icon-led)。 押下後の動作は Run on GPU 一択で同じ、状態は pill 側でだけ語る、 という前提が固まったので button にテキストを持たせる意味が薄い。
A は文字 + 色だけで状態を語る代替案として残してあるが、§01 ギャラリー / §04 プロトタイプ / §05 impl spec は B (icon-led) で揃えている。 button は ▷ アイコン 1 種類で固定、running 時は tx-3 に dim するだけ。spinner も不要なので実装側も async タイマー要らず。

§ 05 実装仕様 (Codex 用リファレンス)

差分は toolbar だけ。結果 panel・banner は別 PR。

  1. 状態 enum ─ apps/web/src/app/external_gpu.rs に 1 本化:
    enum ExternalGpuStatus { Idle, Running, Completed { duration: Duration }, Failed(GpuFailure) }
    enum GpuFailure { BackendOffline, UnsupportedGate(String), Http(u16), Other(&'static str) }
    既存の completed: bool / error: Option<String> は廃止 (後方互換レイヤーは残さない)。
  2. Runner のエラー分岐 をこの 4 variant にマップ:
    ・fetch error / ECONNREFUSED → BackendOffline
    ・gate validator → UnsupportedGate(name)
    ・response.status != 2xx → Http(code)
    ・それ以外 → Other(short_label)。詳細は tracing::warn! で吐く。
  3. Toolbar panel container ─ render/toolbar.rs で egui::Frame を: fill = paper (bg) / stroke = none / corner_radius = CornerRadius::ZERO (full-width header strip、4 角すべて square) / shadow = Shadow { offset: vec2(0, 4), blur: 24, spread: 0, color: tx \w/ alpha 15 } / inner_margin = Margin::symmetric(12, 6) で組む。 ウィンドウの top / left / right 3 辺に密着するので、stroke も角丸も入れない。shadow は下方向だけ。
  4. 縦方向の余白 (toolbar / palette / circuit の 3 段) ─ toolbar 下 → palette 上 = 24 px (spacing-6)、 palette 下 → 回路 1 段目ゲート上 = 48 px (spacing-12)。 24 / 48 の 2 倍リズムが「異なるレイヤー」と「同質要素間の境界」を伝える。 後者を 24 px と同値にすると palette と回路のゲートが視覚的に近接しすぎる (どちらも同じ cyan-400 32×32 の body で、同質性が高いため通常以上のセパレーションが要る)。
    実装:
    ・toolbar は full-width Area で描き、palette 側は PALETTE_ROW_Y から PALETTE_PADDING_Y を引いた top が toolbar bottom + 24 px になるよう固定する
    ・constants.rs に pub(crate) const PALETTE_CIRCUIT_GAP: f32 = 48.0; を追加
    ・LINE_Y は実数値ではなく次の式で組む (旧 6.5 * REM = 208 から 236 に変更): 
    pub(crate) const LINE_Y: f32 =
    PALETTE_ROW_Y                                 // 80
    + (PALETTE_SIZE * 2.0 + PALETTE_ROW_GAP)      // 72
    + PALETTE_PADDING_Y                           // 20  → palette bottom = 172
    + PALETTE_CIRCUIT_GAP                         // 48
    + GATE_SIZE / 2.0;                            // 16  → 236
  5. Toolbar の並び順: undo → redo → trash → divider → run_button → status_pill → spacer → exec_mode_toggle。 edit utilities は Local / GPU 両モードで常時表示。 GPU モード時のみ run_button + status_pill を edit と spacer の間に挿す。 Local モード時はその位置を抜いて edit → spacer → toggle の 3 ゾーン。
  6. Edit utility ボタン ─ undo / redo / trash は同じ ToolButton widget で描く: サイズ 32×32 px、icon 18 px / stroke 2 px、bg transparent、hover で ui 塗り、disabled は tx-3 + 押せない。 アイコンは Lucide スタイル (24 viewBox / 2 px stroke) を painter.add(Shape::Path { ... }) で描く。 Lucide の polyline 座標をそのまま採用すれば良い (アセット追加なし)。 action handler の対応: ・undo / redo は履歴スタック (まだ無ければ tracing::info!("undo") でスタブし、別 PR で実装)
    ・trash は placed_gates.clear()。
  7. 1 px の縦 divider ─ trash と run の間。painter.line_segment([top, bottom], Stroke::new(1.0, ui_2))、 高さ 18 px、左右の margin 2 px。
  8. Run button ─ ToolButton と同じ寸法 (32×32 px、icon 18 px / stroke 2 px) で ▷ アイコンを 1 種類だけ描く。色だけ状態で切替: idle / completed / failed = tx-2 / hover で tx、 running = tx-3 + cursor: NotAllowed (hover なし)。 spinner は不要 — pill の脈動ドットがアクティブ感を担当する。 response.on_hover_text("Run on GPU") を全状態で付ける (egui の tooltip; running も同じテキストでよい)。 三角形は Shape::convex_polygon で 3 頂点 (例: (0, 0), (10, 5.5), (0, 11)) を stroke 描き、 stroke: Stroke::new(2.0, color) / linejoin: round 相当 (PathShape::stroke + closed: true)。
  9. Status pill ─ 新規 apps/web/src/render/gpu_status_pill.rs。 signature: pub fn gpu_status_pill(ui: &mut Ui, status: &ExternalGpuStatus) -> Option<Response>。 Idle は None を返して呼び出し側で ui.add をスキップ。
    構造: ● dot (6 px circle) + label (text-sm) + (option) " · " + code (text-sm mono) を ui.horizontal 内に並べる。bg は transparent、padding 2 / 8 px。
    色トークン:
    ・running = blue (dot 脈動 1.2 s)
    ・completed = green
    ・failed = red
    ・ · セパレータは tx-3。
    本文は §02 の文言 (Backend unreachable / Unsupported gate / Backend error / Completed) を厳守。 詳細値 (URL / gate 名 / HTTP code / duration) は RichText::new().monospace() で右側に。
  10. Dot 脈動 (running のみ) ─ let opacity = ctx.animate_bool_with_time(id, ctx.frame_nr() % 2 == 0, 0.6); で 0.35 ↔ 1.0 を行き来。running 中だけ ctx.request_repaint_after(Duration::from_millis(600)) を予約し、他状態では tick しない。 最も簡単な実装は ui.ctx().animate_value_with_time で sin 波相当の係数を入れる方式。
  11. Snapshot / interaction tests ─ apps/web/tests/web-toolbar-gpu-pill.spec.ts を新規。 test-only hook を QniApp::wire_test_hooks() から生やす: window.__setExternalGpuStatus = (json) => { app.borrow_mut().exec.status = ... }。 Playwright で 4 状態 + 3 failure variant を直接挿し、palette 領域含めた canvas pixel を比較。 実 backend を落とす test は flaky になるので避ける。
  12. Local モード ─ exec mode が Local の時:
    ・run_button + status_pill は描かない (空のスロット)
    ・edit utilities + spacer + toggle はそのまま
    Local では auto-recompute なので Run の概念が無い。状態は state-vector パネルが直接表示する。
  13. exec_mode_toggle の focus 表示 ─ seg の外側コンテナに egui デフォルトの青い focus outline を出さない。アクティブ側の塗り (Local = tx-2 / GPU = blue-600) で「どっちが選ばれているか」 は既に明確で、focus ring と二重表現になる上に、クリック後も outline が残って "光る → 残る" のノイズを生む。
    実装:
    ・seg の outer 容器は egui::Frame のみで作り、自身が Sense::click() を持たない (= focusable じゃない)
    ・個別の opt (Local / GPU) は focusable のままだが、その widget の visuals.widgets.focused.bg_stroke = Stroke::NONE を局所オーバーライドして 2 px 青ストロークを抑制
    ・キーボード a11y は確保: Tab で seg に到達 → 矢印キーで Local ↔ GPU 切替 (これは既に動いてるはず)。 focus 視覚は塗り (active opt の bg 色) で十分。

Acceptance

  1. toolbar が §01 の 6 状態と pixel-by-pixel で一致 (色・寸法・位置)。4 角すべて square で window edge に密着。
  2. toolbar の bottom と gate palette の top の間に 24 px の余白がある。
  3. gate palette の bottom (panel 下端) と回路 1 段目ゲートの top の間に 48 px の余白がある。 実測手順: LINE_Y - GATE_SIZE/2 - (PALETTE_ROW_Y + PALETTE_SIZE*2 + PALETTE_ROW_GAP + PALETTE_PADDING_Y) == 48.0。
  4. backend を落とした状態で Run を押す → 1 秒以内に "Backend unreachable · {url}" pill が出る。
  5. 未対応 gate (例: Spacer) を含む回路で Run → "Unsupported gate · Spacer" pill が出る。
  6. backend が 502 を返す → "Backend error · HTTP 502" pill が出る。
  7. 成功 run 後、duration が小数点 1 桁の秒表示 (例: "1.4 s"; 1 秒未満は "ms" 単位、例 "420 ms")。
  8. running 中、button 全体は静止画。pill 内の dot だけが 1.2 s 周期で脈動。
  9. Local モードで toolbar を見ると run + pill が消える。edit utilities と toggle はそのまま。
  10. Local / GPU トグルをマウスで切り替えても seg の周りに青い focus outline が出ない。アクティブ側の塗りだけが selected を語る。
  11. cargo clippy --all-targets -- -D warnings と cargo fmt --check 通過。
  12. snapshot tests が CI で flaky にならない (実 backend に依存しない)。

避ける文言

  • CPU で代わりに計算します / Switching to CPU / Local モードで実行 — GPU を求めた行為に CPU 救済を匂わせない。
  • Loading… — 何を loading してるか不明。Running on GPU… で具体に。
  • Quantum simulation in progress — 文脈で自明。修飾は省く。
  • Try again 単独 — 理由を pill 側で必ず示す。button だけ Retry にしても直らない。
  • Crashed / Fatal / Disaster — 過剰。Failed / Unreachable で十分。
  • Working on it… / Please wait — 体感ゼロ。dot 脈動と 1 文で。
  • 生 stacktrace / JSON dump — pill に出さず tracing へ。
  • 顔文字 / 励まし語尾 — トーンに合わない。
