コメントブロック

回路の連続した列を囲み、コメントを付ける要素。シミュレーションには影響しない。 qni の circuit-block と同じ見た目と URL 形式 (["{コメント"] … ["}"]) を使い、 エディタではパレットから置いて、ラベルをその場で編集し、左右のハンドルで囲む列を変える。 コード上の型は CircuitBlock / CircuitBlocks、パレットの項目は PaletteItem::CircuitBlock。

§ 04 挙動

置く

  • パレットの表示ブロック欄の末尾 (通し番号 36、3 列 × 2 行では右下) からドラッグし、ゲートのある列に落とす。ツールチップの名前は Comment Block。
  • スナップ先はポインタに最も近い列。その列が複数の列を占めるゲートの一部なら、ゲート全体の列にする。縦方向は本体の上端から下端までならどこでもよい。スナップ先があれば、その列に本体の背景だけをプレビューし、ポインタのアイコンは消す。
  • ゲートの無い列 (右端の操作領域を含む) と、すでにブロックに含まれる列にはスナップしない。離しても何も起きない。
  • 確定すると既定のコメント「comment」でブロックを作り (元に戻す操作 1 回分)、すぐに上のラベルの編集を全選択の状態で開く。

列の境界

  • ブロックの端は、どのゲートにも横切られない列の境界にだけ置ける。振幅表示ブロックなど複数の列を占めるゲートの途中には端を置かない。
  • ブロックは少なくとも 1 つのゲートの列を囲む。ゲートの無い列だけのブロックは次の編集で消えるため作らない。
  • 入れ子と重なりは作らない。隣接は許す。

リサイズ

  • ブロック (本体・ラベル) にホバーすると左右のハンドルを出す。ハンドルのドラッグで、ポインタに最も近い境界へスナップしながら端を動かす。
  • 最小 1 列。隣のブロックの端を越えない。最後のゲートより右の空の操作領域には広げない。
  • ゲートは動かさず、囲む列だけを変える。離したときに 1 回だけ、元に戻す履歴の区切りを作る。

移動と削除

  • ラベルをドラッグ (クリックのしきい値を超えたもの) すると、幅を保ったまま境界にスナップして移動する。重なる位置やゲートの無い列には動かない。
  • ラベルを上下方向にラベルの帯より外へ運ぶと、ブロックを消してラベルだけがポインタに付く。そのまま離すとブロックを削除する。囲んでいたゲートは残る。左右へ運んでも削除しない。
  • ブロックのドラッグ中 (置く・リサイズ・移動・削除) に Esc を押すと、ドラッグを始める前の状態に戻す。

コメントの編集

  • ラベル (上下どちら) をクリックすると、その位置に 1 行の入力欄を重ねる。下書きはもう一方のラベルにもその場で反映する。
  • Enter またはフォーカスを失うと確定、Esc で取り消し。編集中にほかの場所を押すと確定するだけで、ほかの操作は始めない。
  • 下書きが元のコメントと同じなら何もしない (URL に前後の空白があるコメントも書き換えない)。違う場合は前後の空白を除き、空になったら変更しない。値が変わったときだけ、元に戻す履歴の区切りを 1 つ作る。
  • 入力は 32 文字まで。改行は入らない (貼り付けた改行は空白になる)。URL の読み込みでは長さを制限しない。
  • 日本語入力の変換を確定する Enter は eframe の Web 入力処理が捨てるため、コメントの確定にならない。
  • 日本語は Noto Sans CJK JP の CP932/JIS 部分集合で描くため、範囲外の字 (一部の人名漢字や絵文字) は □ で表示される。入力は拒否しない。

編集できる条件

  • 回路がロックされていないこと。
  • パレットにコメントブロックがあること。つまり全ゲートのパレット、または埋め込みの制限パレットに "{}" があること。既存のチュートリアルの埋め込みでは、ブロックは今までどおり読むだけの要素として残り、ホバー表示もしない。

§ 05 URL 形式

URL と回路 JSON の形式は変えない。エディタで作ったブロックも ["{コメント"] の列と ["}"] の列で前後を囲んで書く。 空のコメントは不正な印 "{" になるため、エディタは空のコメントを確定せず、書き出し側でも debug_assert! で止める。
