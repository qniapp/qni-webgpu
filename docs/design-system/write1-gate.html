|1⟩ オペレーション (Reset to |1⟩)

対象量子ビットを 状態 |1⟩ に強制的に再初期化する非ユニタリ操作。 H / X / Rz のような操作ゲートとは違い、cyan-400 角丸正方形の本体を持たず、 透明な 40 × 40 の hit 領域に tx-2 のケット括弧 |⟩ と中央の blue-600 のディジット "1" だけを描く。同色対の |0⟩ オペレーション と陣形を共有する。

★ 批評 · 全体所見
「|0⟩ オペレーションの 1 文字差分」というページとしての存在意義

H ページの全体所見と同じく、本仕様は配色・寸法・字形を Flexoki Light に厳密に従って網羅している。 |0⟩ オペレーション と sibling 関係にあり、本文中でも「red-600 → blue-600」と ディジット 1 文字 + 色 1 つの差分しかないことが明示されている。クロム / 寸法 / 状態挙動はすべて共通で、 実際 § 02 / § 03 / § 04 のテーブルは |0⟩ ページとほぼ 1:1。

この構造は 「sibling ページが同じ template の写経で 95 % 同一になる」問題を抱え、 h-gate.html § 02 全体所見が指摘した「ユニタリゲート族の親仕様を抽出すべき」議論と完全に並行する。 |0⟩ / |1⟩ は意味論的にも「on / off の対」として並んで初めて意味があるので、 1 ページ (例: ket-operations.html)に「|0⟩ と |1⟩ の差はディジットと色だけ」として並列に書くほうが、 template 重複を解消できる。本ページ単独で読むと「|0⟩ の文書を見なくても完結する」が、 その独立性が逆に「差分が分かりにくい」というデメリットを生む。

§ 01概要 (見た目と用途)

|1⟩ オペレーションは、入力状態に関わらず対象量子ビットを |1⟩ に置き換える 状態準備 (state preparation) ゲート。 ユニタリ変換ではないため、厳密には「ゲート」ではなく operation に分類する。 コード上の識別子は Write1、シリアライズ ID は Quirk 互換の "|1>"。 H / X / Y / Z / Rz など状態を回転させる cyan-400 ゲートと混同しないよう、 本体 fill を持たない透明マーカ + ケット記号で「読み書き系」であることを示す。 色配分は tx-2 = クロム (括弧)、blue-600 = データインク (ディジット) の 2 段だけで、 意味は「|1⟩ の 1 = on ビット」を semantic_on ロールにマップして伝える。

★ 批評 · § 02 配色

補足: 「blue-600 は WCAG コントラスト比 6.8 で paper に乗り、red-600 と同等の視認性を保つ」と 設計判断 § 07 にあるが、red-600 のコントラスト比 (実測値) と並べて書かれていないので、 「同等」の根拠が読者に渡らない。Probability ページの contrast 仕様を併記すると、UI 全体での読解性が増す。

★ 批評 · § 04 字形
Geist Mono "1" の左上セリフと横長 foot が、光学的中心と幾何中心をずらす

本仕様は「外形サイズ "1" 単体が約 13.4 × 19.8」「"0" と同じ origin を使うため、|0⟩ ↔ |1⟩ の差し替えで ベースラインが動かない」と書いている。しかし Geist Mono の "1" は 左上セリフ + 横長 foot (x = 60 〜 540)を持つ字形で、 幾何中心 (bbox 中央) と光学中心 (人の目が "中心" と感じる位置) がずれやすい ("1" は左上のセリフのせいで光学中心が幾何中心より右下にある)。

|0⟩ の "0" は左右対称な楕円形で幾何中心 ≒ 光学中心だが、"1" は非対称なので、 同じ origin に置くと "1" がやや左に寄って見える可能性がある。 本仕様の 3× zoom で目視するとこの差は微小だが、palette や複数の |1⟩ を縦に並べた回路では累積的に違和感を生む。 改善案: "1" だけ translate の x 成分を +0.5 〜 +1 px (viewBox 上) 程度オフセットして 光学センター補正をかける。これは Geist Mono の Type Specimen で公式に「foot の張り出しによる光学補正」が 言及されているなら、その値をそのまま借用するのが正当。

補足: |0⟩ ページの § 04 では「X は左括弧 (x=6) と右括弧の尖端 (x=43.5) の中点に近づくよう微オフセット」と書かれていたが、 |1⟩ ページにはこの「微オフセット」の根拠説明がなく、"0" と "1" で同じ transform を共有することの 副作用がそもそも意識されていない可能性がある。

§ 05状態バリアント (常時表示モック)

既定に加え、ホバー / ドラッグ状態を state 属性で強制したモック。 |1⟩ オペレーションは本体 fill を持たないため、ドラッグ時も括弧とディジットの色は変えない。 ドラッグ状態の識別は cursor (grabbing) が担う。回路セル外でドラッグカーソル下に出る プレビューも色は変えず、配置先候補スロットのハイライトと組み合わせて位置を伝える点が、cyan-400 系のゲート (H / Rz など) との大きな違い。

§ 06回路グリッド上の配置

|1⟩ オペレーションは 1 本の量子ビットワイヤ上の単一スロットに置く。スロットは 56 × 56 px 等間隔、 hit 領域 40 px は中央配置で上下左右に 8 px の余白を持つ。 回路頭 (列 = 0) に置けば |1⟩ での初期化 (X ゲートと等価だが意味的に「強制書込み」を明示)、 途中に置けば |1⟩ への部分リセットを表す。 非ユニタリ操作なので、コンパイル時には measurement + 条件付き X を組み合わせた 動的回路にしか写像されない (純粋にユニタリな回路シミュレータでは別経路で実装される) ことに注意。

うっすら入っているスロット境界の ui 線は説明用で、実 UI には描画されない。 隣接スロットへ連続配置しても、hit 領域同士には 16 px の余白が残り、ホバー枠同士が重ならない。

★ 批評 · § 06 回路グリッド配置
「X ゲートと等価だが意味的に「強制書込み」を明示」は UI 配置仕様の章で扱う論点ではない

本文に 「回路頭 (列 = 0) に置けば |1⟩ での初期化 (X ゲートと等価だが意味的に「強制書込み」を明示)」と書かれているが、 これは「UI 上の配置寸法仕様」ではなく「X と |1⟩ の意味論的差異」の論点で、§ 07 「意味論と設計判断」で扱うべき内容。 加えて、|0⟩ ページの § 06 でも同じく「コンパイル時には measurement + 条件付き X」と書かれており、 2 ページとも UI 配置の章に semantics が混入している。

改善案: § 06 は 「スロットに置くと何 px の余白が確保されるか」「隣接ゲートと枠が重ならないか」に集中させ、 意味論 (X ゲートとの等価性、コンパイル時の分解) は § 07 へ移す。 UI レイヤと意味論レイヤの章境界が曖昧だと、本仕様を実装する Codex が「絵をどう描くか」と「動かしたらどうなるか」のどちらの仕様を参照すべきか迷う。

  • cyan-400 角丸正方形を使わない: H / X / Y / Z / Rz と同じクロムを流用すると「ユニタリ回転」と誤解される。状態を回す操作ではなく「強制的に書き込む」操作なので、ケット括弧 + ディジットという「状態ラベルそのもの」を見せる字形を採用する。|0⟩ オペレーションと同じ陣形を共有することで、palette 内で「状態書込み系」として隣接配置できる
  • ケット括弧を tx-2 にする: 括弧自体は意味を持たないただのクロム (区切り記号)。tx-2 で目立たせず、データインクであるディジットを際立たせる。X ゲートの "+" や Rz の文字グリフが paper = #FFFCF0 で本体上にコントラスト 3.4 で乗るのと違い、|1⟩ は背景 (paper) に乗るので、stroke 色は paper にできず、可読な中性トーン tx-2 を選ぶ
  • ディジット "1" を blue-600 にする: 色対 red-600 = 0 / off と blue-600 = 1 / on を UI 全体 (確率表示 / Measurement / |0⟩/|1⟩ operation) で 1 つに固定する。緑 / 紫 / 黒など他の色を試すと、「on/off の対」という意味が崩れる。blue-600 は WCAG コントラスト比 6.8 で paper に乗り、red-600 と同等の視認性を保つ
  • ホバー枠を内側 bg ギャップなしの単線にする: cyan-400 ゲートでは「本体 + paper 2 px + purple 2 px」の 2 重 box-shadow を使うが、本体が透明な |1⟩ では内側ギャップを取ると ket 括弧と枠の間に余計な隙間が生まれ、可読性が落ちる。純粋な外側 purple-400 単線にする (|0⟩ オペレーションと共通)
  • ドラッグ時に色を変えない: cyan-400 ゲートは本体 fill を cyan-400 → purple-600 に差し替えてドラッグを示すが、本体 fill のない |1⟩ ではこの方法が使えない。色を変えない代わりに、drag preview がうっすらしか目立たないため、cursor: grabbing と配置先候補スロットのハイライト (回路グリッド側で別途定義) で位置を伝える
  • X ゲートと分けて持つ: 「|0⟩ から |1⟩ へ反転する ユニタリ」が X ゲート、「任意状態を |1⟩ に 強制書込み する非ユニタリ」が |1⟩ オペレーション。回路頭での見た目は同じ結果になるが、回路の途中での挙動と量子情報的意味 (情報の破棄を伴うかどうか) が違うため、別ゲートで明示する
  • パラメタを持たない: Rz / P のような連続パラメタが無く、配置即確定。|0⟩ ↔ |1⟩ の切替は別ゲート (|0⟩ オペレーション) として独立に並べる方が、palette / 回路上での識別が早い
  • span = 1 固定: 多量子ビット同時リセットは複数 |1⟩ オペレーションを縦に並べて表現する。表示ブロックや QFT のような span リサイズは持たない
★ 批評 · § 07 意味論と設計判断
「X ゲートと分けて持つ」が文章だけで、視覚的並列比較がない

本章 6 項目目の「X ゲートと分けて持つ」は、|1⟩ オペレーションの存在意義を語る最重要の論点 (回路頭での見た目は同じ結果になるが、回路の途中での挙動と量子情報的意味が違う)。 にもかかわらず並列比較ダイアグラムや配置例が一切なく、文章だけで X = ユニタリ反転 / |1⟩ = 強制書込み を区別している。 Qiskit / Cirq / Quirk の他の量子回路エディタを使ったことのある読者には自明だが、 本仕様だけ読む人にとっては「なぜ X があるのに |1⟩ を別ゲートで持つ?」が即座に理解できない。

改善案: § 07 末尾に 「初期状態 |0⟩ → X」と「任意状態 → |1⟩」の 2 つの mini-circuit モックを並べる。 前者は単純な状態反転、後者は中間のもつれを破壊して |1⟩ に強制する操作で、回路として明らかに違う挙動を示すことが、 実際の SVG モックで一目で伝わる。これは |0⟩ ページの同じ位置にも同様に追加する価値がある共通課題。

補足: 8 項目が平等に並んでいる問題は |0⟩ ページ § 07 / h-gate.html § 07 と完全に並行する。 透明マーカ系 (cyan-400 を使わない / ホバー枠単線 / ドラッグ色変えない / ケット括弧 tx-2) は |0⟩ と共有、 Write1 単独は「ディジット "1" を blue-600 / 南極へ強制移動」だけ、と階層化したい。
