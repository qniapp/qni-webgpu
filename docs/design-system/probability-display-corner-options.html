確率表示ブロックの角丸案

現状 ProbabilityDisplay ゲートだけは本体が角ばり (border-radius: 0) で描画されている。他の unitary 系ゲート（H / X / Y / Z 等）は 6 px の角丸付きだが、 確率表示ブロックだけ角ばりなのは「角丸 + overflow: hidden だと上下行のバーが 角でクリップされる」という設計判断の結果。 一方でパレットのホバー枠は内側角丸 8 px。角ばりの 確率表示ブロックがその枠に乗ると 外枠の角丸 / 中身の直角が不揃いで違和感が出る。 どう揃えるかの案をいくつか提示する。

§ 01 現状と問題

実コード

  • apps/egui-web/src/icons/gate_body.rs:84 — 通常 unitary 系は CornerRadius::same(6)
  • apps/egui-web/src/icons/gate_body.rs:119 — Probability preview は CornerRadius::ZERO
  • apps/egui-web/src/render/circuit_palette/panel.rs:51-56 — ホバー枠は外 10 px / 内 8 px の角丸

角ばりにしている根拠 (docs/probability-display-mock.html): 「角丸を付けると上下行のバーが角でクリップされ、Quirk と同じ sharp 矩形が崩れる」。 Quirk 互換と「100% = 端まで塗りつぶし」を保つ判断だった。

§ 02 案 A — 外枠は角丸 + バーを 2 px インセット

A · hover frame

ゲート本体に他の unitary と同じ border-radius: 6 px を入れ、 中のバーは外枠から 2 px 内側に詰める。バーは角丸領域を踏まないので クリップ不要。

「100% = 32 px 端まで」が「100% = 28 px」になり、視覚的に端まで塗らない バーが出る。ただし行間の divider 線は引き続き本体内に収まる。

ホバー枠と揃う○ 6 px の角丸が外枠と無理なく接続
「端まで = 100%」の意味△ 2 px ぶん詰まる（バー領域 28 px ÷ ゲート 32 px = 87.5%）
Quirk 互換性× Quirk は端まで塗る方式
実装コスト○ rect_filled の corner_radius + 内側矩形 shrink2

§ 03 案 B — 現状の角ばりを維持 + ホバー枠を角ばりに合わせる

B · sharp hover frame

確率表示ブロック 本体は今まで通り角ばり。代わりにホバー枠の方を Probability だけ角ばり寄り（例: 外 3 px / 内 1 px）に切り替えて、中身と外枠の 角度感を揃える。

ホバー枠が gate kind 依存のコンテキストロジックになるが、現状でも gate_body 内で kind 別分岐があるので相性は悪くない。

ホバー枠と揃う○ 角ばり同士で違和感なし
「端まで = 100%」の意味○ 維持
Quirk 互換性○ 本体は不変
実装コスト△ panel.rs のホバー枠描画に kind 別分岐が必要
他ゲートとの整合× 確率表示ブロックのホバー枠だけ角ばり、という別ルールができる

§ 04 案 C — 角丸 + バーを角丸に追従させてクリップ

C · rounded clip

外枠 6 px 角丸 + overflow: hidden でバーが自動的に角に追従して クリップされる方式。チェイス ゲートモック §03 で「クリップが起きるからやめた」 としたパターンを、あえて受け入れる選択。

バーが角でわずかに削れて見える（特に最上行 / 最下行が 100% に近いとき）。 実用上は 6 px の削れなので「角がほんのり丸い」程度で、Quirk より気持ち柔らかい 見た目になる。

ホバー枠と揃う○ 角丸同士で完全に揃う
「端まで = 100%」の意味△ 視覚的にはほぼ端まで（角ぶん 1–2 px 欠ける）
Quirk 互換性△ Quirk は sharp、こちらは柔らかい
実装コスト○ 既存 rect_filled に CornerRadius::same(6) を渡すだけ

§ 05 案 D — 角丸チップの中に角ばりの「データカード」を入れる

D · card-in-chip

外側は他ゲート同様 6 px 角丸のチップ。中身は3 px 余白を取って、その中に sharp なバー / 枠を描く。「角丸チップ = ゲート枠」「中の sharp 矩形 = データ可視化エリア」というメタ的な分離。

バー領域は 26 × 26 に縮むので、確率表示ブロック 本来の情報密度は落ちる。 別ゲートと並べたときの「確率表示ブロックだけ余白が多い」感が出るかも。

ホバー枠と揃う○ 外チップが角丸で揃う
「端まで = 100%」の意味△ チップ内の sharp 矩形では「端まで」だが、ゲート全体としては余白あり
Quirk 互換性△ 内側 sharp は維持、ただし外側に余白フレームが乗る
実装コスト△ 描画レイヤが 1 つ増える (外枠 + 内枠 + バー)
他ゲートとの整合△ 「確率表示ブロックだけ二重枠」が意図的にデザイン言語として通用するか要レビュー

§ 06 推奨

推奨は 案 C（角丸 + バー追従クリップ）。理由：

  • 実装コストが最小（既存の rect_filled の CornerRadius を ZERO → same(6) に変えるだけ）
  • ホバー枠との段差が完全に解消
  • バーの角クリップは「6 px 半径 × 数 px の欠け」なので視覚的にはほぼ気にならない。 Quirk の sharp と比べてもむしろ柔らかく現代的に見える
  • 「端まで = 100%」の意味が大きく崩れない（案 A / D のような明確な内側余白がない）

次点は 案 A。Quirk の sharp バーを維持しつつホバー枠と揃えたい場合の選択。 ただし 87.5% しか塗らない「100%」は perceptual には小さい嘘なので、Quirk 互換を 捨ててでも案 C のほうがすっきりすると判断。

案 B は「確率表示ブロックのホバー枠だけ別ルール」を持ち込むコストが情報量に対して 高く、却下。案 D は二重枠のデザイン言語を新規導入する判断が要るため、 まずは案 C で十分。
