Rx ゲート (X 軸回転 θ)

単一量子ビットへ e−iθX/2 を適用する X 軸まわりのパラメタ可変回転ゲート。 回路エディタ上では 40 × 40 px の cyan-400 角丸正方形に Geist Bold 由来の 2 文字グリフ "Rx" を中央配置する。 回転角 θ は配置後にパラメタ編集ポップオーバで決め、見た目では H / Y / Z / S / T と同じ 1 量子ビットゲートのクロムを継承する。

★ 批評 · 全体所見
Rotation 族共通の論点は ry-gate.html に集約、本ページは「Rx / X / √X の三つ巴」に固有性がある

配色 (§ 02) / ジオメトリ (§ 03) / グリッド配置 (§ 06 前半) は h-gate.html と完全に共通、 字形 2 文字グリフ (§ 04) / θ パラメタ編集 (§ 06 後半) は ry-gate.html と共通の論点なので、 本ページの全体所見はそれらを参照するに留め、Rx 固有の論点だけを以下に展開する。

Rx の固有性は 「Rx / X / √X の 3 ゲートが palette に並列に存在する」こと。 数学的には Rx(π) ∝ X / Rx(π/2) ∝ √X で、Ry が「Y / Ry の 2 ゲートだけ」、Rz が「Z / S / T / Rz の 4 ゲートだけ」 なのに対し、Rx だけが固定角ハードコードの正方形ゲート (√X) を持つ。これは ハードウェア実装で √X が NISQ デバイスの ネイティブゲートになっている歴史的経緯による。結果として Rx ページでは 「ユーザーが Rx(π/2) と √X のどちらを置くか」 という意思決定支援が必要になり、§ 07 に bullet が 2 つ (Rx(π) と X / Rx(π/2) と √X) 並ぶことになる。 この決定樹を § 01 概要に小型 flowchart として置くと、初学者の認知負荷が下がる。

§ 01概要 (見た目と用途)

Rx は X = Pauli-X の連続版で、任意角 θ の ブロッホ球 X 軸まわりの回転を表す。 θ = π で Rx = −iX、θ = π/2 で √X (グローバル位相を除いて等価) に一致するため、X / √X の上位互換として ハードウェア実装に近い回路を組むときに使う。見た目では「固定角」「任意角」を別色にせず、 cyan-400 = ユニタリ操作ゲートという既存の色対応を守る。 Rx 固有情報は字形 "Rx" と説明文、そしてパラメタ編集ポップオーバの θ 値に閉じる。

★ 批評 · § 01 概要
「X / √X の上位互換」と書きつつ、ユーザーが Rx と X / √X のどちらを置くべきかの基準が無い

本文は θ = π で Rx = −iX、θ = π/2 で √X (グローバル位相を除いて等価) に一致するため、X / √X の上位互換として ハードウェア実装に近い回路を組むときに使う と書く。しかし palette には Rx / X / √X が並列に並んでいるので、 ユーザー視点では「ハードコード固定角を使うべきか、Rx で任意角にしておくべきか」という選択が常に発生する。 本仕様はこの選択の判断軸 (回路を hardware-aware に書くか / 高校〜大学初級の教科書回路として書くか) を spec していない。

提案: § 01 末尾に小型 flowchart (「角度を固定で動かす → X / √X、scan で変えたい → Rx」「IBM Q ターゲット → √X、汎用 → Rx」) を置く。Ry には別名固定角が 0 個、Rz には 3 個 (Z / S / T) で、Rx の 2 個 (X / √X) と同じ問題が Rz でも起きる。 この決定樹は Rotation 族 + Pauli / Phase の横断仕様に置く価値があり、ここでは Rx 固有の事例として サブセットを示すかたちでよい。

★ 批評 · § 04 字形 (Rx 固有)
2 文字グリフ全般の論点は ry-gate.html § 04 に集約、Rx 固有は「x が X ゲートのプラスとどう違って見えるか」

Rotation 族共通の論点 (字形の高さが H の 53 % に対し 33 %、kerning の出所、3× zoom の必要性、Rotation 族親仕様化) は ry-gate.html § 04 の批評を参照。本ページでは Rx 固有の論点だけ展開する。

  • "x" と X ゲートのプラス記号 "⊕" がパレット上で隣接する — palette 上では Rx (角丸正方形 cyan-400 + paper "Rx") と X (cyan-400 円形 + paper "+") がしばしば並ぶ。"x" 字形は X (大文字) と区別される字形だが、目を素早く動かしたときに混同するか / しないかは実描画で検証が必要。「R」が頭につくことで Rx と X の差別化が成立するとは書かれているが、ベースの "x" 自体は X ゲートの "⊕" よりも視覚的に弱い。
  • "x" path M14 0 250 356 16 710H143L318 440L490 710H616L382 358L619 0H492L316 274L140 0Z は対称形 — 上下対称 (descender なし) で、Ry の "y" (実は Y を縮小) や Rz の "z" (descender なし) と並べたとき、字形高さが揃いやすい。これは Geist Bold の偶然の恩恵で、もし Rotation 族親仕様で「字形高さの canonical」を決めるなら、Rx の "x" を基準にできる。
  • 外形 23.3 × 13.3 px は H ページの "H" (21 × 21 ≈ 53 %) と比べて高さ約 33 %。Ry / Rz と並べたとき視覚的に「軽い」印象になりやすい。実装で本体の中央 (y = 20) に来るかどうかの検証スクショが本仕様にはない。

§ 06回路グリッド上の配置と θ パラメタ編集

Rx ゲートは 1 本の量子ビットワイヤ上の単一スロットに置く。スロットは 56 × 56 px 等間隔、 本体 40 px は中央配置で上下左右に 8 px の余白を持つ。配置後にクリックすると θ 値編集ポップオーバが開く。

うっすら入っているスロット境界の ui 線は説明用で、実 UI には描画されない。 隣接スロットへ連続配置しても、本体間には 16 px の余白が残り、ホバー枠同士が重ならない。

θ パラメタ編集ポップオーバ (モック)

Rx は配置後に回転角 θ を編集する。ポップオーバは cell の右下から 8 px のオフセットで開き、 自由入力 (ラジアン / 数式) と π 系プリセット (0 / π/4 / π/2 / π / 3π/2) の併用を許す。 値編集中もゲート本体の色 / サイズは変えず、現在の θ はセル下に数値ラベル (例: π/2) として描く。

  • H / Y / Z と同じ角丸正方形にする: Rx は文字グリフで識別する通常の 1 量子ビットゲート。X だけは CNOT ターゲットと同じ ⊕ 記号を共有するため円形にする
  • 2 文字グリフ "Rx" を採用する: 大文字 R で「Rotation」、小文字 x で「軸ラベル」を表す。これは Qiskit / Cirq / Quirk と一致するアカデミック表記。すべて大文字 "RX" は palette の他のゲート (H / Y / Z / S / T) と並べたとき視覚的に重く、字形バランスが崩れる
  • 回転角 θ を色で表現しない: θ は連続パラメタなので色相 / 明度マッピングは不安定 (θ = π と θ = π + 0.001 が同色)。θ の現在値はセル下の数値ラベルとポップオーバ (§ 06) に閉じる
  • Rx(π) と X を別カードとして残す: 数学的には大域位相を除いて等価だが、ハードウェア / 教育文脈では「X = 固定 NOT」「Rx = 連続パラメタ」と役割が違うため、palette でも UI でも別ゲートとして並べる
  • Rx(π/2) と √X を別カードとして残す: 同様に、√X は固定角の「半 NOT」ゲートとして使う場面 ("half-X" や Clifford 系列の説明) があるため、Rx(π/2) とは別アイコンを持つ
  • stroke を持たない: 本体色 cyan-400 が wire (ui-2) や背景 (bg-2) と十分区別できるため、枠線は足さない
  • span = 1 固定: Rx は単一量子ビットだけに作用するため、表示ブロックや QFT のような span リサイズを持たない
★ 批評 · § 07 意味論と設計判断
「Rx(π) と X」「Rx(π/2) と √X」を別カードにする根拠が「ハードウェア / 教育文脈」止まりで spec として弱い

bullet 4 と 5 (Rx(π) と X / Rx(π/2) と √X を別カードに残す) は本ページ最大の Rx 固有判断だが、根拠が 「ハードウェア / 教育文脈では役割が違う」という一般論で済まされている。 spec として記述を強化するなら、もう一段下りた根拠が要る:

  • ハードウェア: IBM Q / Rigetti / IonQ などの NISQ デバイスは √X + virtual-Z をネイティブゲートとして公開し、任意角の Rx は Ry / Rz / √X の合成で実現される。「Rx(π/2) を置く」と「√X を置く」では transpile 後のゲート数が違うので、別カードである必然性がある。
  • 教育文脈: X = NOT は古典論理と直接対応し、「ビット反転」というクラシカル直感が効く。Rx(π) = −iX は同じ操作だが大域位相 −i が付くため説明の文脈が違う (「グローバル位相は観測できない」という別話題)。

補足: Y / Z 族との非対称も spec で言及する価値がある — Ry には対応する「√Y」が palette に無く、 Rz には S = √Z として既に存在する。Rx 族の「X / √X / Rx」だけが 3 つ揃うのは、ハードウェアで √X (= sqrt-NOT) がよく出てくる歴史的経緯による。これは Rotation 族親仕様または Pauli / Phase 親仕様で言及すべき横断的特徴で、 本ページからリンクするだけでも読者の理解が深まる。

補足 2: bullet 1 (角丸正方形) / bullet 6 (stroke なし) / bullet 7 (span = 1) はユニタリゲート族共通の話で、 h-gate.html § 07 の批評と同じ「(a) 族共通 / (b) Rotation 共通 / (c) Rx 固有」の階層化が必要 (詳細は ry-gate.html § 07 参照)。
