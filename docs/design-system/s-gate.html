S ゲート (位相 π/2)

単一量子ビットへ diag(1, i) を適用する位相ゲート。回路エディタ上では 40 × 40 px の cyan-400 角丸正方形に Geist Bold 由来の字形 "S" を中央配置する。 位相量 (π/2) を色やバッジで区別せず、H / Y / Z / T と同じ 1 量子ビットゲートの見た目を継承する。

★ 批評 · 全体所見
「位相族の代表」としての責務が S ページに振られているが、機能の意味論が字形 "S" に乗っていない

40 px + 56 px ピッチ、ホバー枠 4+2、cyan-400 同族同色、Tailwind スケール厳守、stroke なし、角丸 6 px、 drag preview = purple-600 といったユニタリゲートクロムに関する論点は h-gate.html の全体所見で展開済みで、S ページにも同じ批判 (ユニタリゲート族の親仕様がなく 6 ページが重複する) が当てはまる。 S ページ固有の核心は 「Phase 族 (S / T / P / S† / T†) の代表として位相という機能の意味論を伝える責任」を 負っていることだが、現状の本文は H / X / Y / Z と並ぶ「同族の 1 ゲート」として均質に書かれ、 位相族の親としての視点が薄い。

機能面では、S は diag(1, eiπ/2) という対角行列で複素位相を進めるゲートだが、 字形 "S" にはその意味が一切乗っていない。"S" は Geist 700 の単なる文字グリフで、Pauli (X / Y / Z) や Hadamard (H) と本質的に区別がつかない。Quirk の歴史的経緯で確立した文字グリフ表記を踏襲しているとはいえ、 「視覚的に同族 / 機能的に独自」の隔たりが Phase 族全体に通底する論点として S ページに残されている。 ここを「字形が機能を表していない」という Phase 族共通の課題として明示しておくと、T / S† / T† / P 各ページが 参照できる根拠になる。

★ 批評 · Top Opportunities
影響度の大きい改善候補 (各論は本文中の批評ブロックに展開)
  1. Phase 族 (S / T / P / S† / T†) の親仕様を抽出 — 「位相とは何か」「字形で位相量を区別する規約」「dagger 表記の組版」「色を位相量に使わない」など Phase 族共通の判断を phase-gates.html (仮) に集約し、S ページは「S 固有 = 位相 π/2 / Clifford 階層の中核 / S2 = Z という代数関係」だけに絞る (全体所見参照)。
  2. § 02 配色テーブルに記載された相対輝度比 2.8 を見直す — § 02 は「cyan-400 上で相対輝度比 ≈ 2.8」と書くが、h-gate.html や x-gate.html では「≈ 3.4」と書かれている。同じ cyan-400 + paper の組み合わせなのに数値が割れているのは矛盾で、どちらかが誤り (§ 02 参照)。
  3. § 04 の 3 倍拡大が「位相を進める」という機能の伝達に貢献していない — 字形 "S" を 3 倍に拡大しても、見えるのは「より大きな S」だけで、π/2 位相という本質は読み取れない。ブロッホ球上の Z 軸 π/2 回転のミニ図解を併置するほうが、字形拡大より情報価値が高い (§ 04 参照)。
  4. § 07 の S2 = Z / T2 = S を視覚化 — 現状はリンク先テキストとして書かれているが、Phase 族のメンバ関係 (Z = π → S = π/2 → T = π/4) を 1 つの数直線 / 階段図にすると、ユーザが「どの位相量を選ぶか」を直感で決められる (§ 07 参照)。
  5. S と S† の見分けの困難さを Phase 族の課題として明示 — S と S† は字形 (右上の †) のみで区別される。40 px の本体上で † グリフは約 5 × 9 px と小さく、低視力ユーザや遠目では判別困難。「dagger ペアの判別可能性」は s-dagger-gate.html で深掘りされるが、本ページの § 07 にも「順 / 逆を字形差で示す」設計判断の代償として一言残しておくと、設計責任が明確になる (§ 07 参照)。

§ 01概要 (見た目と用途)

S は |1⟩ 成分にだけ位相 i (= eiπ/2) を加える基本ゲートで、Z 軸まわりの π/2 回転に対応する。 見た目では「位相」を別色にせず、cyan-400 = ユニタリ操作ゲートという既存の色対応を守る。 S 固有情報は字形 "S" と説明文に閉じ、H / Y / Z / T と横並びに置いたときの同族感を優先する。

★ 批評 · § 01 概要
「同族感」優先の判断が、π/2 位相という機能の唯一性を消している

本文は「H / Y / Z / T と横並びに置いたときの同族感を優先する」と書くが、これは Quirk 由来の同族同色原則を 踏襲した結果であり、S の機能 (Z 軸 π/2 回転) を字形 "S" が表現しているわけではない。 ユーザにとって "S" という記号は「Pauli の続きにある文字」程度の意味しか持たず、 diag(1, i) という対角行列との対応はヘルプ文か量子計算の知識に依存する。 この trade-off は本文でも 「同族感を優先」とだけ書かれ、代償が何かは明示されていない。

同族感の対案として、たとえば本体内に微小な位相インジケータ (Z 軸を中心とした扇形の角度マーカ) を 重ねる選択肢もあり得る。これは Phase 族 (S / T / P) で「位相量を視覚化する小さなクロム」を 共有する設計余地として残してよい。本ページでは採用しないが、「採用しなかった理由」を § 07 に 書いておくと、後続の P ページ (パラメトリック角度) でも判断の根拠を再利用できる。

★ 批評 · § 02 配色
「相対輝度比 ≈ 2.8」は h-gate.html / x-gate.html の「≈ 3.4」と矛盾している

§ 02 の「字形 "S" + paper」行には cyan-400 上で相対輝度比 ≈ 2.8 と書かれているが、 cyan-400 (#3AA99F) + paper (#FFFCF0) というまったく同じ前景・背景の組み合わせに対し h-gate.html § 02 と x-gate.html § 02 では ≈ 3.4 と記載されている。物理的に同じ色対の輝度比が 2.8 と 3.4 で割れているのは矛盾で、 どちらかが誤計算 (もしくは異なる仕様での測定値の流用)。

本プロジェクトは WCAG AA を意識した配色設計が前提なので、輝度比は 1 か所で計算し、 全ゲート仕様で同じ数値を参照する design-system-colors.html に一元化したい。 現状の数値ばらつきは「各ページが独立して計算した結果」を示唆するが、それなら h-gate.html / x-gate.html / s-gate.html の 3 ページで値が違うこと自体がドキュメント品質の品質指標として黄信号。

★ 批評 · § 04 字形
3 倍拡大では位相 π/2 という機能の意味が読み取れない

本セクションは字形 "S" を 3 倍拡大して「字形の位置確認」を行うが、見えるのは 「より大きな S 文字」だけで、S ゲートの本質である「Z 軸 π/2 回転 = |1⟩ に位相 i を加える」 という機能はまったく伝わらない。これは h-gate.html § 04 の批評 (「3× zoom 単体の情報価値は低い」) と 構造的に同じ問題で、Phase 族全体に共通する。

改善案: 拡大字形の隣にミニブロッホ球図 (Z 軸まわりの π/2 円弧 + |+⟩ → |+i⟩ への矢印) を併置し、 「S は文字 S だが、機能は Z 軸 π/2 回転」という対応関係を 1 つの図で見せる。 ブロッホ球は bloch-display.html の表示ブロックと同じ SVG プリミティブを 流用できるので、設計コストは小さい。同じ手法は T (π/4) / S† (−π/2) / T† (−π/4) でも再利用できる。

§ 06回路グリッド上の配置

S ゲートは 1 本の量子ビットワイヤ上の単一スロットに置く。スロットは 56 × 56 px 等間隔、 本体 40 px は中央配置で上下左右に 8 px の余白を持つ。

うっすら入っているスロット境界の ui 線は説明用で、実 UI には描画されない。 隣接スロットへ連続配置しても、本体間には 16 px の余白が残り、ホバー枠同士が重ならない。

§ 07意味論と設計判断

行列
S = [[1, 0], [0, i]]
基底状態
S|0⟩ = |0⟩
S|1⟩ = i|1⟩
ブロッホ球
Z 軸まわりの π/2 (90°) 回転。確率を変えず相対位相だけを進める。
関係
S2 = Z / S4 = I / T2 = S。Clifford ゲートの一種。
  • H / Y / Z / T と同じ角丸正方形にする: S は文字グリフで識別する通常の 1 量子ビットゲート。X だけは CNOT ターゲットと同じ ⊕ 記号を共有するため円形にする
  • 位相量を色で表現しない: S (π/2) と T (π/4) を別色にすると、ホバー / ドラッグなどの状態色と衝突する。位相系列のメンバー識別は字形 (S / T) とヘルプ文に閉じる
  • S† は別カードとして扱う: S (順回転 π/2) と S† (逆回転 −π/2) は意味が逆なので、見た目も "S" 単独と "S†" を区別する。色やサイズは共通、字形だけが異なる
  • RZ と混同させない: S は固定角 π/2 の位相、RZ(θ) は任意角の回転ゲート。S は単独文字、RZ は 2 文字グリフで描き分ける
  • 枠線を持たない: 本体色 cyan-400 が wire (ui-2) や背景 (bg-2) と十分区別できるため、枠線は足さない
  • span = 1 固定: S は単一量子ビットだけに作用するため、表示ブロックや QFT のような span リサイズを持たない
★ 批評 · § 07 意味論と設計判断
「Z = S2」「T2 = S」を文字情報だけで提示しており、Phase 族の階層構造が見えない

matrix-card 内に S2 = Z / T2 = S / S4 = I が列挙されているが、これらは Phase 族の階層構造 (π → π/2 → π/4 → ... を 2 で割っていく系列) を 示すもっとも重要な関係。文字列で並べるよりも、Z 軸まわりの単位円を 4 等分した図 (Z=π / S=π/2 / T=π/4) で 見せたほうが「S は Z の半分」「T は S の半分」が一目で伝わる。Clifford 階層を初めて学ぶユーザにとって、 この階層図は記号操作より遥かに認識負荷が低い。

さらに、§ 07 のリストには 「S と S† の判別性」への言及がない。S と S† はパレット上で隣接配置され、 クロム (cyan-400 / 角丸正方形 / 文字 "S") を共有し、差分は右上の小さな † グリフだけ。これは Phase 族で 繰り返される設計判断 (T / T† でも同じ) で、s-gate.html / t-gate.html の両方で「字形差で順 / 逆を示す」 ことの代償 (低視力 / 遠目での判別困難) を明示しておくと、ハイコントラストモードや拡大鏡支援の根拠になる。
