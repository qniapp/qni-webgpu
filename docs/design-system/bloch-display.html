ブロッホ球表示ブロック

単一の量子ビットの換算密度行列から求めた ブロッホベクトル (x, y, z) を、 本体内に 3D 球の透視投影 + 矢印 として可視化するブロッホ球表示ブロック (`表示ブロック` の定義は AGENTS.md 用語集と design-system §01 参照)。 状態ベクトルには影響しない。span は 1 量子ビット 固定でリサイズ不可。 密度行列の縮約 (reduce) → 矢印描画 (overlay) まで GPU パイプライン内で完結し、 CPU リードバックは発生しない。本ドキュメントは描画仕様 (寸法 / 配色 / 投影 / 挙動 / 実装参照) を 1 ヶ所にまとめたリファレンス。

§ 01 標準状態の見た目 (|0⟩, |1⟩, |±⟩, |±i⟩, 混合)

代表的な 1 量子ビット 状態を実寸 (40 × 40 px) で並べた参考レンダリング。 ゲート本体は 半径 19 px の円 (内塗り bg-2、外周 1.5 px tx-3) で、 その上に軸線 / 細楕円の wireframe (1 px tx-3) を重ねる。 透視投影は perspective-origin = top-right、p = 4 (§ 07 投影)。 矢印は中心からブロッホベクトルの先端へ伸び、先端には半径 3 px の色付き丸を置く。 先端ドットの色は z 成分による gradient: |0⟩ (z = +1) = red-600、|1⟩ (z = -1) = blue-600、equator (z = 0) は中点 #684768。 ブロッホベクトル長が 0 のとき (完全混合) は中心にグレーの丸 (tx-3、非アクティブを示唆) のみを描く。 マウスカーソルを乗せると、ゲート右 +8 px の位置にブロッホベクトル詳細 popup が出る (§ 10 ポップアップ仕様)。 hover 枠 / popup ともに実装済み (2026-05-18)。 モックは「実装済み挙動の常時表示プレビュー」として読む。

§ 02 パレットアイコン (mini preview)

パレットの BlochDisplay アイコンは 40 × 40 px の静的 wireframe sphere + 中央の |v|=0 グレードット (非アクティブ表示)。 まず icons/bloch_display.rs の draw_bloch_sphere で軸線・対角・楕円を tx-3 1 px で描き、続いて circuit_palette/panel.rs:73-75 が draw_bloch_vector(rect, [0, 0, 0]) を呼び出して 中心に tx-3 半径 3 px のドットを置く。 パレット項目はドラッグ起点としてのみ機能し、ホバーでもベクトル形状は変化しない。 旧仕様では blue-600 (qni オリジナルの "d=0 blue center dot") を使っていたが、 「弱い |1⟩」と誤読されうるため本仕様で tx-3 へ差し替え (§ 06 視覚要素)。

§ 03 概要

役割単一の量子ビットのブロッホベクトル (x, y, z) を可視化する表示ブロック (状態に影響しない)
span1 量子ビット 固定 (resizable_span: false)。リサイズハンドルなし、QFT / Probability のような可変 span はない
出力ブロッホベクトル (x, y, z) ∈ [−1, 1]3。長さ |v| ≤ 1 (純粋状態 |v| = 1、完全混合 |v| = 0)
算出1 量子ビット 換算密度行列 ρ から GPU コンピュートシェーダで計算 → bloch_output_buffer に書き出す。CPU リードバックなし
表示式x = 2·Re(ρ01)、y = −2·Im(ρ01)、z = ρ00 − ρ11 (qni convention)
シリアライズ ID"Bloch" (Quirk の "ブロッホ球表示ブロック" と互換)
配置パレット 1 アイコンから drag-and-drop。配置直後 (GPU dispatch 前) は |v|=0 状態のグレードットを egui で暫定描画 (§ 09)
nesting禁止 (表示ブロックを表示ブロックの中には置けない、Quirk と同じ)

§ 06 視覚要素

球本体 (外周)

  • 中心 (20, 20)、半径 sphere_radius = 19 の円
  • 内塗り bg-2 (painter.circle_filled)、外周 stroke 1.5 px tx-3 (painter.circle_stroke)
  • 本体はこの円だけ。占有矩形 40 × 40 の四隅は塗らない (他のゲートにある角丸 6 px の矩形本体は出さない、ブロッホ球表示ブロック専用の挙動)

内側 wireframe (軸線と楕円)

  • 水平軸: 中心から左右に sphere_radius 伸ばす 1 px tx-3 直線
  • 垂直軸: 中心から上下に sphere_radius 伸ばす 1 px tx-3 直線
  • 対角線: 左下 → 右上に 0.30 × sphere_radius 分だけ伸ばす 1 px tx-3 直線 (y 軸方向の擬似遠近マーカー)
  • 細楕円 (縦): 中心、短径 0.36 × sphere_radius、長径 sphere_radius の 1 px tx-3 楕円 (子午線)
  • 細楕円 (横): 中心、短径 sphere_radius、長径 0.36 × sphere_radius の 1 px tx-3 楕円 (赤道)

qni オリジナルの bloch-display-element.ts の 静的 SVG wireframe と レイアウト互換 (axis %、ellipse rx/ry 比は qni から継承)。

動的な矢印

  • 始点: 球の中心 (20, 20)
  • 終点: bloch_project(x, y, z) × sphere_radius を中心からのオフセットとして加算
  • 終点が球面外 (raw_tip_len > sphere_radius) の場合は球面に投影してクリップ: tip = raw_tip × (sphere_radius / raw_tip_len) (純粋状態が 透視で枠外に出るのを防ぐ)
  • 線描画は |v| > 10−3 のときのみ (ゼロベクトルでは線を出さない)

先端ドット (z 成分による色 gradient + 非アクティブ gray)

  • 位置: 矢印の終点 tip (純粋寄りの状態)、または中心 (20, 20) (完全混合)
  • 半径: 3 px (= 直径 6 px)
  • 色は z 成分 (緯度) のリニア gradient: |0⟩ (z = +1) = red-600 (semantic_off) から |1⟩ (z = −1) = blue-600 (semantic_on) まで、sRGB 空間で連続補間。 equator (z = 0) は両者の数値的中点 #684768。 Write0 / Write1 / ket digit / measurement 結果と同じ「0 = 赤 / 1 = 青」コンベンション
  • |v| < 10−3 (完全混合) は非アクティブを示唆する tx-3 (gray) を中心 (20, 20) に描く。 旧仕様の blue-600 は「弱い |1⟩」と誤読されうるため避ける
  • shader 側は 1.0 − smoothstep(tip_radius − edge, tip_radius + edge, dist_tip) の SDF アルファでアンチエイリアス

色補間の計算式

WGSL 擬似コード (BLOCH_OVERLAY_SHADER fs_main 内、実装ターゲット): 

// 緯度を [0, 1] に正規化: t = 0 が |1⟩ 寄り、t = 1 が |0⟩ 寄り。
let t: f32 = clamp((bloch.z + 1.0) * 0.5, 0.0, 1.0);

// |0⟩ 寄り (red) ⇄ |1⟩ 寄り (blue) の sRGB lerp。
// WGSL の mix(a, b, t) は a*(1-t) + b*t なので、blue を a、red を b にする。
let active_rgb: vec3<f32> = mix(params.blue_color.rgb, params.red_color.rgb, t);

// |v| ≈ 0 のときは非アクティブの gray に切り替え。
let tip_rgb: vec3<f32> = select(active_rgb, params.inactive_color.rgb, mag < 1.0e-3);

§ 07 投影 (透視 + 軸 swap)

qni の bloch-display-element.ts は CSS の transform: rotateY(phi) rotateX(−theta) + perspective: 4rem + perspective-origin: top right で 3D 描画している。 egui-web では同じ視覚を 2D で再現するため、以下の固定変換を使う。

1. Bloch → CSS の軸 swap

初期 up ベクトルを rotateY(phi)·rotateX(−theta) で回した結果として、Bloch (x, y, z) を CSS (X, Y, Z) に置き換える:

x_3d =  bloch.y      // CSS X (right)
y_3d = -bloch.z      // CSS Y (down)
z_3d =  bloch.x      // CSS Z (out of screen)

2. ピンホール透視

カメラを p = 4 (radius 単位)、viewing origin を球の右上 (px, py) = (1, −1) に置いた透視投影:

factor = p / (p − z_3d)            // z_3d > 0 で拡大、z_3d < 0 で縮小
sx = px + factor · (x_3d − px)
sy = py + factor · (y_3d − py)

最終的にスクリーン座標は tip = center + (sx, sy) × sphere_radius。 perspective-origin: top right なので、観測者から見て手前にあるベクトル (bloch.x > 0) は 左下寄り、奥にあるベクトル (bloch.x < 0) は 右上寄りに投影される。

§ 08 ブロッホベクトル算出 (GPU compute)

BLOCH_REDUCE_SHADER (gpu/shaders/bloch_display.rs:3-80) は対象量子ビット qubit_bit を消去した 1 量子ビット 換算密度行列 ρ の 3 成分を計算し、bloch_output_buffer の output_slot に vec4<f32>(x, y, z, 0) として書き出す。 シェーダは workgroup_size 64 + ツリー縮約 (64→32→16→8→4→2→1) で 2n 個の状態振幅を 1 つの workgroup でまとめ上げる。

入力 / 出力

入力 (storage, read)state: array<vec2<f32>> (状態ベクトル、各成分 = (Re, Im))
入力 (uniform)BlochParams { qubit_bit, state_count, output_slot }
出力 (storage, read_write)bloch_out: array<vec4<f32>>、 bloch_out[output_slot] = (x, y, z, 0)

計算式

対象 量子ビットのビットが 0 の状態 i と、それに qubit_bit を足した状態 j = i | qubit_mask の振幅を組にして、ρ00 / ρ11 / ρ01 を累積する: 

ρ_00     = Σ_{bit(i)=0}  |amp[i]|²
ρ_11     = Σ_{bit(i)=1}  |amp[i]|²
ρ_01_re  = Σ_{bit(i)=0}  Re( amp[i] · conj(amp[j]) )
ρ_01_im  = Σ_{bit(i)=0}  Im( amp[i] · conj(amp[j]) )

x =  2 · ρ_01_re
y = -2 · ρ_01_im      // qni convention (符号注意)
z =  ρ_00 − ρ_11

y のマイナス符号は qni の packages/simulator/src/matrix.ts 由来の convention。Quirk と数値が一致するよう、シェーダ側でこの符号を保つ。

GPU-only 保証

本番経路で CPU リードバックは発生しない。bloch_output_buffer は storage buffer のまま BLOCH_OVERLAY_SHADER の @binding(0) に渡され、 fragment shader が bloch_data[slot] を直接サンプルする (確率表示ブロックの STATE_PROB_BUFFER と同じパターン)。 これは AGENTS.md の「最重要ルール: GPU-only」に準拠する設計。

§ 09 ホバー挙動と暫定描画

ホバー枠

  • 実装: gate_rect.expand(4.0) に対して 角丸 10 px (= 本体 6 px + 4 px) の 2 px stroke を Inside で描く (circuit_gates.rs:73-91)。 内側 2 px (gate edge から外 2 px) は塗らず、背景の paper / 配線がそのまま透ける
  • 本体は円だが、ホバー枠は他のゲートと統一して角丸矩形。 content (球) と affordance (gate hover) を分離する設計で、ユーザは hover 文法を 1 つだけ覚えればよい
  • 確率表示ブロックは本体が角ばり矩形なのでホバー枠も角ばり (corner radius 0)、 Bloch / その他のゲートは本体 6 px + 外 10 px の 2 種類だけが存在
  • 確率表示ブロックと異なり 行ホバー枠は存在しない (描画要素が単一なので行の概念がない)
  • リサイズハンドルなし (resizable_span: false)。span を変える UI は出さない

ポップアップ

  • ゲート hover で右側 +8 px の位置にブロッホベクトル詳細 popup が出る (§ 10 ポップアップ仕様)
  • 表示内容: タイトル + 球座標 (r / ϕ / θ) + 直交座標 (x / y / z)
  • Quirk の BlochSphereDisplay.js:31-58 paintDeferredValueTooltip と同等の情報量を、 probability-display popup と同じ Geist 系のタイポグラフィで再構成
  • 実装ステータス: 本体表示 + GPU overlay 実装済み。popup の値表示は別作業で整理する

暫定描画 (snap 前 / GPU dispatch 前)

  • ドラッグ中 / 配置直後で gpu_plan.bloch_slot(gate.id) が None のときは GPU overlay を出せない
  • このとき egui 側で draw_bloch_vector(rect, [0, 0, 0]) を呼び、中心にグレードット (tx-3) のみを描く (静的 wireframe + 非アクティブ示唆の中央ドット)
  • 次フレームの GPU dispatch で値が確定し次第、egui 描画から GPU overlay 描画にシームレスに切り替わる
  • egui 暫定描画と GPU overlay の見た目を完全に揃えるため、両者は同じ bloch_project 式を使う (§ 07)

§ 10 ポップアップ仕様

§ 11 描画パイプライン (3 段)

ブロッホ球表示ブロックは compute (reduce) → render (overlay) → egui callback の 3 段で完結する。CPU は形状とスロット番号だけを GPU に渡し、ブロッホベクトル値は GPU の ストレージバッファをまたいで完結する。

Stage 1: Reduce (compute)

  • shader: BLOCH_REDUCE_SHADER (gpu/shaders/bloch_display.rs:3-80)
  • pipeline: gpu/resources/bloch_display/reduce.rs
  • workgroup: 64 スレッド、ツリー縮約 (workgroupBarrier 付き)
  • 入力 binding: 状態ベクトル (storage, read) + BlochParams uniform
  • 出力 binding: bloch_output_buffer (storage, read_write)、各 BlochDisplay に output_slot を割り当て

Stage 2: Overlay (render)

  • shader: BLOCH_OVERLAY_SHADER (gpu/shaders/bloch_display.rs:81-190)
  • pipeline: gpu/resources/bloch_display/overlay.rs
  • 頂点: common.unit_quad_vertex_buffer (Probability / その他と共有の単位 quad)
  • インスタンス: BlochOverlayInstance { center, radius, outer, slot }
  • fragment: bloch_data[slot] から (x, y, z) を直接サンプル → bloch_project → SDF で線とドットを描く
  • NDC 変換: egui_wgpu が callback rect に viewport をセットするので、viewport_min / viewport_size uniform で world 座標を NDC に変換

Stage 3: egui callback

  • callback: gpu/callbacks/bloch_display_overlay.rs (BlochOverlayCallback)
  • prepare: パラメータ / インスタンスを GPU バッファに書き込む (CPU → GPU)
  • paint: pipeline + bind group をバインドし draw_indexed(0..6, 0, 0..N)
  • 呼び出し元: render/circuit_gates.rs:210-249 (placed_gates から BlochDisplay を抽出してインスタンス化)

SDF 描画パラメータ (BLOCH_OVERLAY_SHADER fs_main): line_half = 0.75、tip_radius = 3.0、edge = 0.75。 1.0 − smoothstep(half − edge, half + edge, dist) でアルファを作るので、 線の実効幅 ≈ 1.5 px、ドット直径 ≈ 6 px (= 2 × tip_radius) になる。

バックエンド対応

  • Local WebGPU のみ対応。external GPU バックエンドでは未対応 (app/external_gpu/app_adapter.rs:97-115 の unsupported_external_gpu_gate に BlochDisplay → "Bloch" が列挙されている)
  • 回路に BlochDisplay が含まれる場合、external GPU 切替時に Unsupported エラーになる
  • 制約理由: external GPU 経路は ρ → (x, y, z) の reduce + GPU フラグメントへの直結という本仕様の経路を持たないため。 将来対応するなら BLOCH_REDUCE_SHADER 相当の reduce を external 側にも追加する

§ 12 URL シリアライズ (Quirk 互換)

BlochDisplay の シリアライズ ID は Quirk と同じ語彙を採用する (Quirk URL インポート / 双方向の URL 共有のため、gates.rs:73-77 で url_token: "Bloch")。 ただし下記の #circuit=... 形式は Quirk オリジナルの URL hash 構造であり、qni-webgpu 現行の URL 表現 (/#<percent-encoded JSON>) とは hash 内のキー名・構造が異なる。 本セクションは Quirk URL の語彙互換性を示すための参考であり、qni-webgpu 内部の URL 設計は別仕様 (TBD)。

spanserialized id
1"Bloch" (固定 — ブロッホ球表示ブロックは span 1 のみ)

URL fragment 内では JSON 生のまま (Quirk 形式):

#circuit={"cols":[["H"],["Bloch"]]}                          # H → Bloch
#circuit={"cols":[["H","H","H"],["Bloch","Bloch","Bloch"]]}  # 3 量子ビット、各 wire に Bloch
#circuit={"cols":[[1,"Bloch"]]}                              # q1 起点 (q0 placeholder)

percent-encode 済み (%7B"cols"%3A%5B%5B"Bloch"%5D%5D%7D) も等価に parse できる (Quirk と同じ挙動)。Quirk 側ロジックは ../oss/Quirk/src/gates/BlochSphereDisplay.js 参照。
