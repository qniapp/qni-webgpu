Z ゲート (Pauli-Z)

単一量子ビットへ Pauli-Z 行列を適用する位相反転ゲート。回路エディタ上では 40 × 40 px の cyan-400 角丸正方形に Geist Bold 由来の字形 "Z" を中央配置する。 X のような円形や位相専用色は使わず、H / Y / S / T と同じ 1 量子ビットゲートの見た目を継承する。

★ 批評 · 全体所見
「測定基底を変えない唯一の Pauli」という Z 固有の機能が前面に出ていない

ユニタリゲートクロム (40 px 本体 + 56 px ピッチ + cyan-400 + paper グリフ + 4+2 のホバー枠 + drag preview = purple-600) は h-gate.html の全体所見と同じ批判 (ページ間で内容が重複し、親仕様の抽出が望ましい) がそのまま当てはまる。 ここでは Z 固有の論点に絞ると、本ページの最大の特色は Pauli-Z 行列 diag(1, -1) が対角行列であり、 計算基底 |0⟩ / |1⟩ の確率分布を一切変えず位相だけを反転すること。これは X / Y にはない、Z 固有の機能で、 「測定結果からは Z が置かれたかどうか直接見えない」という非自明な振る舞いをもたらす。

にもかかわらず、§ 01 では「位相反転ゲート」と書くだけで、「測定では見えない」という特徴は § 07 の matrix-card の Z|0⟩ = |0⟩ / Z|1⟩ = -|1⟩ から読者が自分で気づくしかない。Z を初めて学ぶ読者には 「同じ見た目の H / Y と何が違うのか」が、本文中で明示的に述べられていない。

§ 01概要 (見た目と用途)

Pauli-Z は |1⟩ 成分の符号だけを反転し、確率を変えずに相対位相を変える基本ゲート。 見た目では「位相」を別色にせず、cyan-400 = ユニタリ操作ゲートという既存の色対応を守る。 Z 固有の情報は字形 "Z" と説明文だけで表し、H / Y と横並びに置いたときの同族感を優先する。

★ 批評 · § 01 概要
Z の核心 (測定基底を変えない / 対角行列) が前文に出てこない

本文は「|1⟩ 成分の符号だけを反転し、確率を変えずに相対位相を変える」と書いており、 ここに Z 固有の特異性が凝縮されている。だがすぐ次の段で「cyan-400 = ユニタリ操作ゲートという既存の色対応を守る」 という見た目の話に移ってしまい、機能と意味論を読者が掴む前に視覚同族論で覆ってしまう。

Z は X / Y と違って「ビット反転を起こさない」唯一の Pauli であり、量子コンピュータ初学者にとっては 「何をするゲートか」が直感的に分かりにくい代表格。「Z|0⟩ = |0⟩、Z|1⟩ = -|1⟩ なので、Z の前後で測定確率は変わらない」 という具体的な振る舞いを 1 段落で示すと、本ページ単独でも Z の存在意義が掴める。

★ 批評 · § 02 配色 / ホバー枠の幾何
ホバー枠の描画は <z-gate> の Shadow DOM に移し、個別ページ側の重複 CSS を解消した

以前のページ内 CSS は .z-gate::before の単層実装で、H / Y の 2 層構造と揃っていなかった。 現在は components/z-gate.js が .hover-frame と .hover-gap を持ち、 purple-400 外枠と 2 px の paper 空きを Shadow DOM 内で描く。これにより Z 仕様ページ / ゲートパレット / サムネイルが 同じ <z-gate> 実装を参照し、ホバー枠の幾何が 1 か所に集約された。

残る論点は、H / Y / Z 以外の 1 量子ビットゲートも同じ custom element 化を進め、 ページごとの本体 CSS と inline SVG を減らすこと。特に S / T / RZ は Z と同じ角丸正方形 + 文字グリフなので、 <z-gate> と同じ構造を再利用できる。

★ 批評 · § 04 字形 (Z)
字形 "Z" は意味論的に中立で、対角行列の特異性を伝える視覚要素を持たない

Pauli-Z 行列は diag(1, -1) という単純な対角行列で、計算基底ベクトル |0⟩ / |1⟩ を不変方向 (固有ベクトル) として持つ。これは X / Y が固有ベクトルを |+⟩, |-⟩ や |+i⟩, |-i⟩ という重ね合わせ状態に持つのと対照的で、Z だけが「計算基底と直接対応する Pauli」となる。

字形 "Z" 単独ではこの「対角性」「計算基底との一致」は伝わらず、たとえば対角線を強調した独自字形 (例: 太い斜線で対角行列を暗示) を採用する余地もあった。しかし本仕様は H / Y / √X / S / T と一貫させるため Geist Bold の "Z" を踏襲しており、その判断自体は妥当。視覚情報量 vs 同族感のトレードオフが 意識的になされていることを § 07 設計判断に追記すると、後続ゲートの字形選定時の議論基盤になる。

補足 (表記揺れ): h3 見出しは「3倍拡大」、本ページ § 03 凡例は日本語、SVG 内テキストは英語と、3 つの表記スタイルが混在している。 兄弟ページ (h / x / y / √X) はすべて「3× zoom」を採用しており、本ページの「3倍拡大」だけが異質。 どちらかに統一する (「3× zoom」推奨) ことで Pauli 4 ページ + sqrt-X が揃う。

§ 06回路グリッド上の配置

Z ゲートは 1 本の量子ビットワイヤ上の単一スロットに置く。スロットは 56 × 56 px 等間隔、 本体 40 px は中央配置で上下左右に 8 px の余白を持つ。

うっすら入っているスロット境界の ui 線は説明用で、実 UI には描画されない。 隣接スロットへ連続配置しても、本体間には 16 px の余白が残り、ホバー枠同士が重ならない。

§ 07意味論と設計判断

行列
Z = [[1, 0], [0, -1]]
基底状態
Z|0⟩ = |0⟩
Z|1⟩ = -|1⟩
ブロッホ球
Z 軸まわりの 180° 回転。X / Y 成分の符号を反転し、Z 成分は保つ。
  • H / Y と同じ角丸正方形にする: Z は文字グリフで識別する通常の 1 量子ビットゲート。X だけは CNOT ターゲットと同じ ⊕ 記号を共有するため円形にする
  • 位相を色で表現しない: 位相反転を紫や赤で示すと、ホバー / ドラッグなどの状態色と衝突する。Z 固有の情報は字形と説明文だけで表す
  • RZ と混同させない: Pauli-Z は固定角 π の操作、RZ は任意角 θ の回転ゲート。Z は単独文字、RZ は 2 文字グリフで描き分ける
  • 枠線を持たない: 本体色 cyan-400 が wire (ui-2) や背景 (bg-2) と十分区別できるため、枠線は足さない
  • span = 1 固定: Z は単一量子ビットだけに作用するため、表示ブロックや QFT のような span リサイズを持たない
★ 批評 · § 07 意味論と設計判断
「Z は π 位相反転」と「S / T は π/2 / π/4 位相回転」の連続性が示されていない

現状の bullet は Z と RZ の混同回避のみを扱うが、本ページが触れていない重要な関係として Z = S2 = T4 がある。S は π/2 位相回転、T は π/4 位相回転、 Z は π 位相回転で、3 つは「位相回転の階段」を形成している。Pauli-Z 単独で見ると「位相を π だけ回す離散ゲート」だが、 S / T と並べると「Z は位相回転族の最大角バージョン」という連続軸が見える。

bullet 3「RZ と混同させない」は単独で正しいが、S / T との関係を 1 行加えれば、Z が固定角 (π) の操作で、 RZ が任意角 (θ) の操作で、S / T はその中間の固定刻みという階層構造が一目で伝わる。 後続の S / T ページが揃ったタイミングで「位相回転族」セクションを 3 ページ横断で作る価値がある。

コントラスト面: § 02 配色表で cyan-400 + paper のコントラスト比を ≈ 2.78 と書いており、これは WCAG AA 大文字テキスト基準 (3.0) を下回る。§ 07 設計判断には妥協が明示されていないため、「色を意味に使わない」設計の代償として 色覚アクセシビリティが落ちる点を 1 行加えると、将来「ハイコントラストモード」の根拠になる。

補足: 用語ゆれ — § 03 のジオメトリ表で「枠線」と「stroke」が混在している (本ページの設計判断は「枠線を持たない」、 H / Y ページは「stroke を持たない」)。仕様横断で日本語 (「枠線」) に寄せるか、原文 (「stroke」) を統一するかを 決めるべき。CLAUDE.md のルー語ルールでは「stroke なし」「枠線なし」のどちらも許容されているため、 プロジェクト全体で 1 つに決めて prh.yml に追加するのが堅い。
