Circuit picker

回路ピッカーの 2 つの drag 操作をまとめて扱う:
・drag-to-reorder — 行をマウスで掴んで上下にドラッグして並び替える。 ハンドル無し、whole-row live reorder。submenu の Move up / Move down は据置 (キーボード代替)。
・separator resize — 上 (回路名リスト) / 下 (Create new circuit) 2 ペイン構成にして、 境界のセパレータをドラッグして items ペインの高さを可変にする。上ペインだけが独立スクロール、 下の Create new circuit は常に底に pinned で残る。
両者は連動する: items ペインが overflow している状態で行をドラッグして上端 / 下端付近に持っていくと、 ペインが edge auto-scroll して隠れている行を引き出せる。

§ 01 構造 — 2 ペイン構成

paper bg + ui-2 hairline + shadow-popover の panel クロムは既存ピッカーと pixel-by-pixel で一致。中身は 3 要素:
・items pane (上) — 高さ可変、内容が多ければ独立スクロール
・resize handle — separator、ドラッグで上下に動く
・footer (下) — Create new circuit、常に固定で見えている

§ 02 ドラッグ並び替えの解剖

Idle (普通) → Hover (掴める合図 = cursor: grab) → Dragging (掴んだ行そのものが pointer に追従、他の行は live-reorder で隣接 slot に瞬時に移動)。 複製行も drop indicator も elevated shadow も無し。 dragged 行は Flexoki ui グレーだけで示し、他の行は live-reorder されたあとの位置で静止する。

右端の例: GHZ state が「上に向かって動いてる途中」のスナップショット。 Bell state と QFT 4-量子ビットは既に live-reorder で位置が確定済み (QFT が 2 番目に上がっている)。 GHZ 行は ui グレーのまま pointer に追従。release した時点でその index が確定される。

part挙動 / トークン
drag start 行の mousedown + 移動距離 ≥ 4 px で drag 開始。閾値以下のクリックは選択 / kebab open など本来の挙動。
cursor 行 hover で grab、drag 中は grabbing。kebab hover では pointer。
dragged 行の描画 その行自身に translateY() を当てて pointer に追従させる。 background: var(--ui) + z-index: 5 で「これがいま掴まれている行」を示す。 elevated shadow は付けない、複製要素は作らない。
動きは Y 軸のみ: translateX は常に 0。
Y はドロップダウン内側にクランプ: pointer が dropdown の外に行っても 行は [panel_pad, dropdown_height - panel_pad - row_height] の範囲内に止まる。
他の行 drag 中は非 dragged 行はすべて paper bg。アイテムの bg は基本「ホバー時 = bg-2」 「ドラッグ中 = ui」のイベント由来の変化のみで、 アクティブ行も resting state では bg を持たない (font-weight 500 だけで「いま編集中」を示唆)。 これで dragged 行のグレーが視覚的に唯一のアクセントになる。
live swap 毎 mousemove で dragged 行の visual center を計算し、 1 つ上 / 1 つ下の行の center を跨いだら entries 配列で隣同士を swap し 再 render する。swap の瞬間に natural top が ROW_H ずれるが、 translateY を再計算して visual position は連続。
他の行 (FLIP) live swap で押し出される行は FLIP アニメーションで 旧位置から新位置へ 80 ms ease でスライドする。単純な snap だと「いま何が動いたか」が読みづらい。 FLIP: swap 前に rect を記録 (First) → swap + 再 render (Last) → 旧位置との差を translateY で打ち消す (Invert) → 次フレームで transition 有効 + transform 解除でアニメーション (Play)。 dragged 行は除外 (cursor 追従が遅延するため transition: none)。
kebab 除外 kebab 上の mousedown は drag を開始しない (event を kebab handler に渡す)。kebab は drag handle ではなく submenu trigger。
release data は drag 中に live swap で既に並び替え済み。mouseup では transform をクリアして state.drag = null するだけ。active_id は id で保持してるので index ズレなし。
Esc cancel drag 開始時に state.entries を snapshot し、Esc 押下で復元 + state.drag = null + 再 render。
submenu との両立 submenu の Move up / Move down は据置 (キーボード代替 / 1 段ずつ動かしたい時用)。drag は飛ばし移動の primary path。 別行の drag が始まったら開いている submenu は閉じる。同じ kebab trigger を再クリックしたときも閉じる。
auto scroll items ペインが overflow しているとき、カーソルが上端 / 下端 EDGE_ZONE = 36 px 圏内に入るとその方向に自動スクロール。 速度はゾーン深度に線形 (一番奥で 12 px / frame、ゾーン境界で 0)。 スクロール中も live-swap は継続、ペインが上端 / 下端まで到達済みのときは止まる。

§ 03 インタラクティブプロトタイプ — 並び替え + リサイズ

実際に separator (薄い水平線) をマウスで掴んで上下に動かせます。 items ペインの高さが変動し、内容が多ければペイン内で独立スクロール。 Create new circuit は底に pinned で常時見える。
カーソルは handle hover / drag 中は ns-resize。drag 中は document 全体に 強制するのでマウスがハンドルから外れてもカーソルは変わらない。

アイテム自体も drag-to-reorder 可能。さらにペインの高さを縮めて リストが overflow している状態で、ドラッグ中のアイテムをペインの上端 / 下端 36 px 圏内に近づけると、その方向へ自動的にスクロールします (edge auto-scroll, 速度はゾーン深度に比例)。

§ 04 導入要件

見た目と挙動の要件

  1. リサイズ — セパレータを上下にドラッグでき、items ペインの高さが 72 px (2 row) 以上、表示領域に収まる最大値以下で変動する。
  2. 固定フッタ — items ペインだけが独立スクロールし、Create new circuit フッタは常に底に固定する。
  3. ドラッグ並び替え — 行を上下にドラッグできる。dragged 行は Y 軸だけカーソルに追従し、ドロップダウン内側にクランプする。
  4. 視覚状態 — dragged 行は ui グレー塗りのみ。複製行、drop indicator、elevated shadow は出さない。
  5. 押し出しアニメーション — dragged 行の center が隣接行の center を跨ぐと、押し出される行は 80 ms ease でスライドする。dragged 行は cursor を 1:1 追従する。
  6. 自動スクロール — items ペインが overflow している状態で、ドラッグ中のアイテムをペイン上端 / 下端 36 px 圏内に近づけると、その方向へ自動スクロールする。
  7. キャンセル — Esc で drag をキャンセルし、順序を維持する。
  8. メニューとの両立 — kebab クリックでは drag を開始せず submenu を開く。同じ kebab を再クリックで閉じ、別行の drag 開始時には開いている submenu を閉じる。
  9. カーソル — 行 hover は grab、drag 中は grabbing、リサイズ中は ns-resize。
  10. 共通余白 — dropdown は topbar 直下に隙間なく開く。
