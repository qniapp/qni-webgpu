Circuit picker

回路ピッカーの 2 つの drag 操作をまとめて扱う:
・drag-to-reorder — 行をマウスで掴んで上下にドラッグして並び替える。 ハンドル無し、whole-row live reorder。submenu の Move up / Move down は据置 (キーボード代替)。
・separator resize — 上 (回路名リスト) / 下 (Create new circuit) 2 ペイン構成にして、 境界のセパレータをドラッグして items ペインの高さを可変にする。上ペインだけが独立スクロール、 下の Create new circuit は常に底に pinned で残る。
両者は連動する: items ペインが overflow している状態で行をドラッグして上端 / 下端付近に持っていくと、 ペインが edge auto-scroll して隠れている行を引き出せる。

・items pane (上) — 高さ可変、内容が多ければ独立スクロール
・resize handle — separator、ドラッグで上下に動く
・footer (下) — Create new circuit、常に固定で見えている

§ 02 ドラッグ並び替えの解剖

Idle (普通) → Hover (掴める合図 = cursor: grab) → Dragging (掴んだ行そのものが pointer に追従、他の行は live-reorder で隣接 slot に瞬時に移動)。 複製行も drop indicator も elevated shadow も無し。 dragged 行は Flexoki ui グレーだけで示し、他の行は live-reorder されたあとの位置で静止する。

右端の例: GHZ state が「上に向かって動いてる途中」のスナップショット。 Bell state と QFT 4-量子ビットは既に live-reorder で位置が確定済み (QFT が 2 番目に上がっている)。 GHZ 行は ui グレーのまま pointer に追従。release した時点でその index が確定される。

part挙動 / トークン
drag start 行の mousedown + 移動距離 ≥ 4 px で drag 開始 (egui だと response.drag_started() 相当)。閾値以下のクリックは選択 / kebab open など本来の挙動。
cursor 行 hover で grab、drag 中は grabbing。kebab hover では pointer。
dragged 行の描画 その行自身に translateY() を当てて pointer に追従させる。 background: var(--ui) + z-index: 5 で「これがいま掴まれている行」を示す。 elevated shadow は付けない、複製要素は作らない。
動きは Y 軸のみ: translateX は常に 0。
Y はドロップダウン内側にクランプ: pointer が dropdown の外に行っても 行は [panel_pad, dropdown_height - panel_pad - row_height] の範囲内に止まる。
他の行 drag 中は非 dragged 行はすべて paper bg。アイテムの bg は基本「ホバー時 = bg-2」 「ドラッグ中 = ui」のイベント由来の変化のみで、 アクティブ行も resting state では bg を持たない (font-weight 500 だけで「いま編集中」を示唆)。 これで dragged 行のグレーが視覚的に唯一のアクセントになる。
live swap 毎 mousemove で dragged 行の visual center を計算し、 1 つ上 / 1 つ下の行の center を跨いだら entries 配列で隣同士を swap し 再 render する。swap の瞬間に natural top が ROW_H ずれるが、 translateY を再計算して visual position は連続。
他の行 (FLIP) live swap で押し出される行は FLIP アニメーションで 旧位置から新位置へ 80 ms ease でスライドする。単純な snap だと「いま何が動いたか」が読みづらい。 FLIP: swap 前に rect を記録 (First) → swap + 再 render (Last) → 旧位置との差を translateY で打ち消す (Invert) → 次フレームで transition 有効 + transform 解除でアニメーション (Play)。 dragged 行は除外 (cursor 追従が遅延するため transition: none)。
kebab 除外 kebab 上の mousedown は drag を開始しない (event を kebab handler に渡す)。kebab は drag handle ではなく submenu trigger。
release data は drag 中に live swap で既に並び替え済み。mouseup では transform をクリアして state.drag = null するだけ。active_id は id で保持してるので index ズレなし。
Esc cancel drag 開始時に state.entries を snapshot し、Esc 押下で復元 + state.drag = null + 再 render。
submenu との両立 submenu の Move up / Move down は据置 (キーボード代替 / 1 段ずつ動かしたい時用)。drag は飛ばし移動の primary path。 別行の drag が始まったら開いている submenu は閉じる。同じ kebab trigger を再クリックしたときも閉じる。
auto scroll items ペインが overflow しているとき、カーソルが上端 / 下端 EDGE_ZONE = 36 px 圏内に入るとその方向に自動スクロール。 速度はゾーン深度に線形 (一番奥で 12 px / frame、ゾーン境界で 0)。 スクロール中も live-swap は継続、ペインが上端 / 下端まで到達済みのときは止まる。

§ 03 実装プロトタイプ — 並び替え + リサイズ

実際に separator (薄い水平線) をマウスで掴んで上下に動かせます。 items ペインの高さが変動し、内容が多ければペイン内で独立スクロール。 Create new circuit は底に pinned で常時見える。
カーソルは handle hover / drag 中は ns-resize。drag 中は document 全体に 強制するのでマウスがハンドルから外れてもカーソルは変わらない。

アイテム自体も drag-to-reorder 可能。さらにペインの高さを縮めて リストが overflow している状態で、ドラッグ中のアイテムをペインの上端 / 下端 36 px 圏内に近づけると、その方向へ自動的にスクロールします (edge auto-scroll, 速度はゾーン深度に比例)。

§ 04 実装仕様 (Codex 用リファレンス)

差分は picker 描画と state に絞る。永続化は別 PR。

  1. state ─ PickerState::Open に resize と reorder それぞれの drag sub-state を追加: 
    pub(crate) struct PickerOpen {
    // ... existing fields ...
    pub items_height: f32,    // px, default = 216 (6 rows)
    pub resize_drag_start: Option<{ pointer_y: f32, base_height: f32 }>,
    pub drag: DragState,
}

pub(crate) enum DragState {
    Idle,
    Pending { entry_index: usize, started_pos: Pos2 },
    Active  {
        entry_index: usize,         // dragged 行の現在の data index (live swap で変わる)
        pointer_offset_y: f32,      // pointer.y - row.top at drag start
        original_entries: Vec<CircuitEntry>,  // Esc cancel 用の snapshot
    },
}
    items_height default は 216 (= 6 row)。永続化は別 Codex (localStorage 層) で restore できるよう、field は #[serde] で skip しない。 DragState::Pending → Active への昇格は pointer 移動距離 ≥ 4 px。 Pending 中に mouseup なら通常の click (select) として扱う。
  2. panel 描画 ─ 既存の circuit_picker_dropdown.rs で:
    ・items ペインを egui::ScrollArea::vertical().max_height(items_height) 内に描く
    ・separator (9 px の Sense::click_and_drag() rect) を描く
    ・footer (Create new circuit、固定高 36 px) を描く
    順番は items → separator → footer。フッタは ScrollArea の外に置く。
  3. resize handle 描画:
    ・idle: 1 px ui-2 横線、handle rect 中央
    ・hover / drag: 2 px blue-600 横線に強調 (装飾なし、シンプル)
    ・cursor: ui.output_mut(|o| o.cursor_icon = CursorIcon::ResizeRow) を handle hover / drag 中に毎フレーム設定
  4. drag ロジック: 
    let response = ui.allocate_rect(handle_rect, Sense::click_and_drag());
if response.drag_started() {
    state.resize_drag_start = Some({
        pointer_y: pointer.y,
        base_height: state.items_height,
    });
}
if let Some(start) = state.resize_drag_start {
    let delta = pointer.y - start.pointer_y;
    state.items_height = (start.base_height + delta)
        .max(MIN_ITEMS_HEIGHT)   // 72 px
        .min(max_items_height(entries.len(), viewport_height));
}
if response.drag_released() {
    state.resize_drag_start = None;
    // bump_updated_at は不要 (高さは UI state、永続化レイヤーが別途 watch する)
}
  5. reorder drag — 各 row の sense ─ 各 item 行を egui::Sense::click_and_drag() で確保し、 response.drag_started() で DragState::Pending。 response.drag_delta().length_sq() > 16.0 (= 4 px 移動) で Active に昇格 (このとき entries を snapshot)。 response.drag_released() で Idle へ戻すだけ — data は live swap で確定済み。 ui.input(|i| i.key_pressed(Key::Escape)) で cancel (snapshot から復元)。 kebab 用の inner Response は Sense::click() のままにし、その上のクリックは行の drag を起こさない (egui は inner widget のクリックを優先する)。
  6. dragged 行の描画 ─ active.entry_index の行を描くとき:
    ・natural_top = row_rects[idx].top()
    ・wanted_top = clamp(pointer.y - pointer_offset_y, dropdown.inner_top, dropdown.inner_bottom - row_h) でドロップダウン内側にクランプ
    ・差を translateY 相当で吸収して描画。 egui では行の draw 時に ui.allocate_space を natural rect で取った後、 painter.add(Shape::translate(...)) で natural rect の中身を wanted_top - natural_top px Y シフトして描く方式、 またはその行だけ別 Area で描く (Area::new(...).order(Order::Foreground).fixed_pos(...)) 方式のどちらか。
    X 軸はロック: translateX は常に 0、pointer.x は無視。 背景は ui グレー: dragged 行だけ Frame.fill = colors.toolbar_hover_bg、他の行は colors.surface のまま。elevated shadow は付けない。
    他の行は全部 paper bg: drag 中は他の行の hover bg を transparent に抑制するだけ (active styling は font-weight 500 のみで触らない)。 egui だと if drag_active && !is_dragged { skip hover_bg paint } の 1 行で実現。
  7. FLIP swap アニメーション ─ live swap で押し出される側の行を即 snap せず、 80 ms ease で旧位置から新位置にスライドさせる。egui だと ctx.animate_value_with_time(row_id, target_y, 0.08) を行ごとに動かす方式:
    ・swap 直前に old_y[entry_id] = row_rect.top を記録
    ・swap 後の新位置を target_y として登録
    ・描画時に current_y = animate_value_with_time(target_y) を使って target_y - current_y 分の translateY シフトで描く
    ・dragged 行はこの animation 系から除外 (cursor 追従が遅れないように)
  8. live swap ロジック ─ 各フレームで dragged 行の visual center が隣接行の center を跨いだら entries 内で隣同士を swap し、active.entry_index を ±1 する: 
    let visual_center = wanted_top + row_height / 2.0;
let idx = active.entry_index;

if idx > 0 {
    let above_center = row_rects[idx - 1].top() + row_height / 2.0;
    if visual_center < above_center {
        library.entries.swap(idx - 1, idx);
        active.entry_index -= 1;
    }
}
if idx < entries.len() - 1 {
    let below_center = row_rects[idx + 1].top() + row_height / 2.0;
    if visual_center > below_center {
        library.entries.swap(idx, idx + 1);
        active.entry_index += 1;
    }
}
    基本は 1 swap / frame。高速 flick で複数 swap が必要なら while ループ版に。
  9. release / Esc cancel ─ drag_released() で DragState::Idle + library.bump_updated_at() を 1 回呼ぶ。 data は live swap で最終状態なので追加の reorder 処理は不要。active_id は id で保持してるので変わらない。 Active 中の Esc キーで library.entries = original_entries.clone() + Idle へ。dragged 行が元位置に jump で戻る。bump_updated_at() は呼ばない (実質変更なし)。
  10. submenu との両立 ─ submenu の Move up / Move down は据置 (キーボード代替 / 1 段ずつ動かしたい時用)。drag は飛ばし移動の primary path。 別行の drag を開始したら開いている submenu は閉じる。同じ kebab を再クリックしても閉じる。
  11. cursor アイコン:
    ・行 hover → CursorIcon::Grab
    ・DragState::Pending / Active 中 → CursorIcon::Grabbing
    ・kebab hover → CursorIcon::PointingHand
    ui.output_mut(|o| o.cursor_icon = ...) で設定。
  12. min / max 制約:
    ・MIN_ITEMS_HEIGHT = 72.0 (= 2 row)
    ・max_items_height = ((entries.len() as f32) * 36.0 + 12.0).min(viewport_height - 240.0)
    (= 全部見える分 cap + ビューポート内に収まる cap。240 は trigger / picker クロム / フッタの余白合算の概算)
  13. 独立スクロール:
    items ペイン内は ScrollArea::vertical() で完結。dropdown 全体はスクロール対象にしない。 Create new circuit フッタは ScrollArea 外なので常時ビューポートの底に見える。 マウスホイールが items ペイン内ならペインだけスクロール、外 (footer / separator / 隙間) なら何も起きない。
  14. scrollbar style (floating overlay) ─ egui の ctx.style_mut(|s| ...) で この ScrollArea 用に下記の調整を入れる: 
    style.spacing.scroll.floating = true;            // overlay 化 (gutter 予約しない)
style.spacing.scroll.bar_width = 6.0;            // 常時 6 px (ホバーで太らせない)
style.spacing.scroll.floating_width = 6.0;
style.spacing.scroll.floating_allocated_width = 0.0;
style.spacing.scroll.handle_min_length = 12.0;
    thumb の色は style.visuals.widgets.{inactive,hovered,active}.bg_fill で: ・idle (panel hover 中): tx-3 @ alpha 0.6
    ・hovered (バー直接): tx-2 @ alpha 0.7
    ・active (drag 中): tx-2 @ alpha 0.8
    track は描かない (egui のデフォルトは透明)。 フェードイン / アウトは egui が floating = true + 内部 animate_value_with_time で自動的にやる。
  15. tests:
    ・tests/egui-web-picker-resize.spec.ts 新規 — セパレータを 60 px 下にドラッグ → items_height が 60 px 増える / 上に大きくドラッグ → MIN (72 px) で停止 / 下に大きくドラッグ → MAX (viewport 制約) で停止 / 10 件 seed → items ペイン内でホイールスクロール、フッタは動かない
    ・tests/egui-web-circuit-picker-reorder.spec.ts 新規 — 3 件目を 1 件目の上にドラッグ → 順序が [3, 1, 2] に / 1 件目を末尾にドラッグ → 順序が [2, 3, 1] に / drag 中 Esc → 順序維持 / kebab クリックは drag を起こさず submenu を開く / 同じ kebab を再クリック → submenu が閉じる / submenu open 中に別行 drag を開始 → submenu が閉じる
    Playwright の mouse.down() / mouse.move() / mouse.up() で本物のマウス操作を実行。 スナップショットは drag 中の中間 frame をキャプチャしない (flaky 防止) ─ before / after だけ。
  16. edge auto-scroll (ドラッグ並び替えと組み合わせ) ─ items ペインが overflow している状態でアイテムをドラッグ中、カーソルがペインの 上端 / 下端 EDGE_ZONE = 36 px 圏内に入ったらその方向へ自動スクロール。 
    const EDGE_ZONE: f32 = 36.0;
const MAX_SCROLL_PX_PER_FRAME: f32 = 12.0;

// items_rect = ScrollArea の inner rect (screen coords)
let speed = 0.0;
if pointer.y < items_rect.top() + EDGE_ZONE {
    let depth = (items_rect.top() + EDGE_ZONE - pointer.y).clamp(0.0, EDGE_ZONE);
    speed = -(depth / EDGE_ZONE) * MAX_SCROLL_PX_PER_FRAME;
} else if pointer.y > items_rect.bottom() - EDGE_ZONE {
    let depth = (pointer.y - (items_rect.bottom() - EDGE_ZONE)).clamp(0.0, EDGE_ZONE);
    speed =  (depth / EDGE_ZONE) * MAX_SCROLL_PX_PER_FRAME;
}
if speed != 0.0 {
    // ScrollArea::show_rows / show_viewport は egui 側の API で
    // offset を毎フレーム動かす。egui の ScrollArea state を取り出して
    // `state.offset.y += speed` で進め、次フレーム ctx.request_repaint()。
    ui.ctx().request_repaint();
}
    スクロール中も live-swap (ドラッグ並び替えの入れ替え) は継続するように、 毎フレーム pointer.y と各 row の rect から target インデックスを再計算する。 ペインが上端 / 下端に到達済み (clamped offset が動かない) ときは何もしない。
  17. localStorage 永続化は別 Codex 案件。本 PR では state.items_height は in-memory のみ。 picker 閉じて開き直すと default (216) に戻って構わない。

Acceptance — resize

  1. セパレータをマウスで掴んで上下にドラッグでき、items ペインの高さが連動して変動する。
  2. セパレータの hover / drag 中、line が 1 → 2 px に太くなり blue-600 色に変わる。カーソルが ns-resize。
  3. items_height は 72 px (2 row) を下回らない。entries 全部見える以上 / ビューポートを超える以上に伸ばせない。
  4. items 件数が pane 高さを超えるとき、items ペインだけ独立スクロール。footer (Create new circuit) は常時底に固定。
  5. マウスホイールをフッタの上で回しても何も起きない。items ペインの上で回せばペインだけスクロール。
  6. drag 中はマウスがハンドルから外れても ns-resize カーソルを維持。
  7. items ペインが overflow している状態でアイテムをドラッグして上端 / 下端から 36 px 圏内に持っていくと、ペインがその方向に自動スクロールする。ゾーン中央 (深度ゼロ) ではスクロールしない。ペインがすでに上 / 下まで到達済みのときは止まる。

Acceptance — reorder

  1. 行を mouse で掴んで上下にドラッグできる。dragged 行そのものが cursor に追従し (ui グレー塗りのみ)、複製行や drop indicator や elevated shadow は出さない。
  2. dragged 行は Y 軸のみ追従。カーソルが横に動いても dropdown 列から外れない。
  3. dragged 行は ドロップダウン内側にクランプ。pointer が外に出ても row は panel 内に止まる。
  4. アイテムの bg が色付くのは hover 時 (bg-2) と drag 中 (ui) の 2 イベントだけ。active 行も resting state では paper のまま、font-weight 500 だけで識別。drag 中は他の行の hover も抑制され、dragged グレーが唯一のアクセント。
  5. dragged 行の center が隣接行の center を跨ぐと、押し出される行が 80 ms ease で FLIP スライド。dragged 行はこの animation から除外で cursor を 1:1 追従。
  6. release は単に drag state クリア (data は live swap で確定済み)。active な entry の id は変わらない。
  7. Esc で drag をキャンセル、順序維持。
  8. kebab をクリックしても drag は始まらず、submenu が開く。同じ kebab を再クリックで閉じる。
  9. submenu が開いている状態で別行の drag を始めたら submenu は閉じる。
  10. submenu の Move up / Move down は引き続き動く。
  11. cursor が行 hover で grab、drag 中で grabbing。kebab hover では pointer。

Acceptance — 共通

  1. dropdown は topbar 直下に隙間なく開く (state vector aspect dropdown と同じ接続感)。
  2. snapshot tests は drag 中の中間 frame をキャプチャしない (flaky 防止) ─ before / after だけ。
  3. cargo clippy --target wasm32-unknown-unknown --all-targets -- -D warnings 通過、cargo fmt --check クリーン、cargo insta test → review で全 snapshot accept。
