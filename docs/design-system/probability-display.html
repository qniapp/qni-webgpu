確率表示ブロック

任意の地点で span 内の量子ビットを測定した場合の各測定結果の確率を、 本体内に 横バー + XX.X% として可視化する確率表示ブロック (`表示ブロック` の定義は AGENTS.md 用語集と design-system §04 参照)。 状態ベクトルには影響しない。span は 1〜16 量子ビット (上限 16)、見た目は span 全体で同一視覚モデル。 本ドキュメントは描画仕様 (寸法 / 配色 / 挙動 / 関連仕様) を 1 ヶ所にまとめたリファレンス。

§ 01 概要 (見た目と用途)

span 内の量子ビットを測定したときの各測定結果の確率を、XX.X% ラベル付きの横バーで可視化する表示ブロック。状態ベクトルには影響しない。 下のモックで「シンプルな span 1」と「典型的な span 2」の見た目を確認できる。

span 16 (最大サイズ)

確率表示ブロックの上限は 16 量子ビット。測定結果の数 = 216 = 65 536、 高さ 880 px、行高 ≈ 0.013 px (サブピクセル)。 行高が極小のため XX.X% ラベルは描かず、対数ヒント線 (§ 09) のみで分布の形を表現する。 確率分布は中心 k = 32 768 に山を持つガウシアンプリセットで生成 (デモ用)。 実寸 40 × 880 px のため DOM 由来の 65 536 div を避け、<canvas> に直接描画している。

実行前プレースホルダ (シミュレーション未実行の状態)

回路に確率表示ブロックを配置しただけで、まだシミュレーション (▶ Run) を実行していない段階で表示する仮の見た目。 計算結果がまだ確定していないため各測定結果の確率値が無く、バー領域が背景と同化すると「未実行」なのか「壊れている」のかを判別しにくい。 この空白を「実行待ちであることを伝えるプレースホルダ」として明示的にデザインする。 振幅表示ブロックの「実行前プレースホルダ」(amplitude-display.html § 02) と同じ配色コンベンションに従う。

  • 背景 (placeholder fill) — purple-100 (#ECE1F3) の薄い紫で塗る。 本デザインシステムでは「未確定 / 進行中」を表現する色として紫を採用しており (drag preview = purple-600、ホバー枠 = purple-400)、 実行前の確率値も 0 (赤系) と 1 (青系) の中間に位置する未確定な値として同じ紫系統で表す。 色相は drag/hover で使う濃い紫よりさらに淡くして、「進行中アクション」と「結果待ちの静止状態」を区別する。
  • 行構造ガイド — ui-2 (#DAD8CE) の薄いグレーで行境界の水平線を 2span − 1 本引く (既存の行区切り線と同色)。 振幅表示ブロックの「outline 円」と同じ役割で、これから何行の確率値が並ぶかをプレースホルダ段階で示す。 rowH ≤ 2 px (span 8+) では線が重畳するので省略 (通常時の行区切り線と同じ閾値)。
  • バー / ラベル / 対数ヒント線 — 描かない。確率値そのものを持たないので、バー (幅) もラベル (数値) も対数ヒント線 (補助) も意味を持たない。
  • frame — 通常時と同じ ui-2 1 px の外枠を引く。これにより「表示ブロックとしての箱の輪郭」が背景 bg-2 と区別できる。
  • hover / tooltip — 実行前は行単位 popup を出さない (表示すべき数値が無い)。表示ブロック全体のホバー枠 (purple-400 4 px) は通常時と同じく出し、リサイズハンドル (§ 12) は端ごとの表示可否判定に従う。
  • 遷移 — Run を押した瞬間、placeholder layer (薄紫背景 + グレー行ガイド) を 150 ms ease-out でフェードアウトしつつ、通常の バー + ラベル / 対数ヒント線 描画にクロスフェードする。

§ 03 パレットアイコン (ミニプレビュー)

パレットに並ぶ確率表示ブロックアイコンは 40 × 40 px の静的なミニプレビュー。 ガウシアン風の 4 行プレビューで 「複数の測定結果を持つ確率分布の表示ブロック」を表す。バー / 区切り / 外枠は本体と同じルール (区切り線はバー領域に引かない、外枠は ui-2 1 px、本体角ばり)。 ホバー時は外側のホバー枠だけ表示 (行ホバー枠は出さない、静的なので行を選ぶ意味がない)。

§ 08 視覚要素

バー

  • 左から P(outcome k) × gate_w の幅で blue-200 を塗る
  • 右端 1 px は blue-400 の縦線で「確率境界」をマーク
  • 各行は同じ高さで分割される (= 全体高 ÷ 2span)

行区切り線

  • 隣接 2 行のうち広いバーの右端から行右端まで ui-2 1 px を引く
  • バー領域では「色の境界」自体が区切りになるので線は引かない (視覚的に冗長な線を排除)
  • 計算式: x_start = rect.left() + rect.width() × max(prob[i−1], prob[i])、x_end = rect.right()
  • 高密度表示では省略する。row_h ≤ 2 px のとき行区切り線を描かず、バー / 対数ヒント線 / ホバー位置だけを残す

テキストラベル

  • 各行の右端から 2 px 内側に右詰めで XX.X% を描画
  • バー領域に重なる場合もテキスト色は変えない (色境界 two-tone なし)。blue-200 上の tx 黒で十分なコントラスト
  • 条件: row_count ≤ 16 && row_h > 8.0。満たさないときは描かない (代わりに § 09 の対数ヒント線を描く)

§ 09 対数ヒント線 (logarithm hints)

行高が小さい場合 (row_h ≤ 8 px、span 5 以上) は XX.X% ラベルを出せない。 代わりに各測定結果の確率を対数スケールの補助線として薄い灰色で描き、 線形バーでは見分けにくい 極めて小さい確率 の差を視覚的に残す。

発動条件

判定式 showText = row_count ≤ 16 && row_h > 8
Probability1〜4 のみテキスト、Probability5+ は対数ヒント線。高密度表示で読みにくいラベルを避ける。
showText = trueXX.X% ラベルを描画。対数ヒント線は描かない (Probability1〜4)
showText = falseテキストを描かず、対数ヒント線を描画 (Probability5〜16)
線形バーとの重ね順対数ヒント線 → 線形バーの順で描き、バーの背後に補助線が残る

横位置の計算

スケール係数s = 1 / (4 + max(8, span))
横位置比x_ratio = clamp(0, 1, 1 + ln(p) × s) (ln は自然対数)
描画 xpx = rect.x + rect.w × x_ratio
境界挙動 p = 1 → x_ratio = 1 (右端) / p が小さいほど左へ寄る / p が極小または 0 なら clamp により x_ratio = 0 (左端) に潰れる
span 依存性 span が大きいほど s が小さくなり、ln(p) の効き目が緩やかになる (span = 8 → s = 1/12、span = 16 → s = 1/20)

描画形状 (連続ポリライン)

  • 1 本の連続ポリラインで描く。 各行の縦線 (px_i で長さ e = max(row_h, 1)) を、行境界で水平な接続線 (px_{i-1} → px_i) で繋ぐ。 全体として ECG / 階段状のシルエットになり、隣接行の確率差も視覚化される。
  • 線スタイル: tx-3 (#B7B5AC)、1 px
  • 行ごとに独立した縦線にはしない。水平接続を省くと、密な span (5〜) で隣接確率の上下関係が読めなくなる。

tooltip の log: ... dB との違い (重要)

行ホバー時の tooltip に出る log: (log10(p) × 10).toFixed(1) + " dB" は別仕様。 tooltip は 常用対数 (底 10) × 10 倍の dB 表示で、ユーザーへの数値情報提供が目的。 対数ヒント線は 自然対数 ベースでスケールした視覚的な補助線で、 数値そのものではなく「小さい確率同士の相対関係」を伝える。 両者は計算式 (ln vs log10) も用途 (描画 vs テキスト表示) も別。

GPU-only 描画要件

  • Probability1〜Probability4 (row_h > 8 px かつ row_count ≤ 16) は XX.X% ラベルのみ。対数ヒント線は描かない。
  • Probability5〜Probability16 は対数ヒント線のみ。% ラベルは出さない。
  • 本番経路で GPU → CPU 読み戻しをしない。GPU 上の確率値から線形バーと対数ヒント線を直接描く。
  • span ≥ 13 (row_count > 4096) は、画面上の 1 px に複数の測定結果が重なるため、各 y 位置の代表値で高密度表示する。行区切りやラベルは省略し、バー / 対数ヒント線 / ホバー位置だけを残す。
  • docs では「縦線」と呼ばず「対数ヒント線」または「対数スケールの補助線」と呼称統一する。

§ 10 ホバー挙動

外側ホバー枠本体外側 0..2 px = 背景の空き、2..4 px = purple-400 の枠 (合計 4 px 厚)。確率表示ブロック本体は角ばりなので、ホバー枠 § 02 に従い、外側ホバー枠の角丸も 0 px (90 度) にする
行ホバー枠ホバー中の行の内側に purple-400 2 px の枠を上書きする。行高が 4 px 未満の高密度表示では、上下ストロークが重なった 2 px 相当の水平帯として描き、Probability16 でもホバーしている測定結果の位置が消えないようにする
同時表示ホバー枠と行ホバー枠は同時に出る (回路上で行にカーソルを乗せたとき、外枠と内枠の両方が見える)
ポップアップ 行ホバー時、ポップオーバー共通仕様に従う tail 付きカードを表示する。通常は対象行の右側に出し、画面右端では左側へ反転する。表示内容: ket |bin(k)⟩ (主)、 Probability if measured · k = N (補足)、raw: (p × 100).toFixed(4) %、 log: (log10(p) × 10).toFixed(1) dB (p = 0 なら −∞ dB)。
ポップアップのタイポグラフィ ket = Geist Mono Regular 14 px (text-sm) / tx、 サブ = Geist Regular 12 px (text-xs) / tx-2、 ラベル (raw / log) = Geist Mono 12 px (text-xs) / tx-2 / UPPERCASE / letter-spacing 0.12 em、 数値 = Geist Mono 14 px (text-sm) / tx / tabular-nums。 tx-3 (#B7B5AC) は表示ブロック背景の paper 上で薄すぎるため使わず、tx-2 (#6F6E69) を二次テキスト色とする。 外装 (背景 / 枠 / 角丸 / 影 / tail / 画面端反転) は ポップオーバー共通仕様に従う。
パレットアイコン外側ホバー枠だけ受ける (行ホバー枠は出さない、静的プレビューなので)
リサイズハンドルホストホバー時に、操作できる端の cyan-400 ピル形ハンドルがフェードイン + 軽いバウンスで出現。ホバー枠 (purple-400) と別色族なので視覚的に独立したオブジェクトとして読める。詳細は § 12 参照

ポップアップ自体のデザイン仕様 (寸法 / 配色 / タイポグラフィ / 表示例 / 状態バリアント) は § 11 ポップアップ仕様、 リサイズハンドルの仕様 (寸法 / 状態遷移 / マイクロインタラクション) は § 12 リサイズハンドル を参照。

§ 11 ポップアップ仕様

行ホバー時に出るポップアップ内容の常時表示版。値ラベルと行構成を静的に並べ、 状態バリアントと構造をスクロールだけで確認できるようにする。 tail、輪郭、影、画面端反転は ポップオーバー共通仕様側で確認する。

設計判断

  • ket を最大の主役にする: 「どの測定結果の確率を見ているか」がポップアップの最重要情報。14 px Geist Mono Regular で視覚的に最も強い
  • raw を 4 桁 / log を 1 桁にする: raw は微小確率の比較、log は dB スケールの大まかな桁感を伝える
  • マイナス記号は U+2212 (−): hyphen-minus (-) より幅が広く、tabular-nums と同じ字幅に揃う
  • サブ・ラベルは tx-2: 当初 tx-3 を使ったが paper bg 上で読みにくかったため格上げ。tx-3 はポップアップ内では使わない
  • 角丸 10 px: ポップアップは別レイヤの情報カードとして ポップオーバー共通仕様へ揃える。確率表示ブロック本体は角ばりのままにし、外装の責務を分ける
  • 枠 + 影の二重表現: 枠 (popover_outline / Flexoki tx-3 1 px) は paper 背景との境界を明示し、0 10px 28px rgba(16, 15, 15, 0.14) の影は浮いていることを示す。どちらか片方では弱い
  • span 16 でも 1 行で収まる: 16 bit ket = 16 文字、補足 30 文字程度。white-space: nowrap で折り返しを防ぐ (最大幅は ~280 px)

§ 14 GPU バックエンド経路

確率表示ブロックはバックエンド種別に関わらず同じ見た目で描く。表示に使う確率値は、表示ブロックごとの span に対応する測定結果だけを対象にし、full statevector / full probabilities を UI 表示用に保持しない。

  • span 上限 = 16。1 つの確率表示ブロックが扱う測定結果は 216 = 65 536 が上限。
  • GPU-only。ブラウザローカル経路では本番 UI の毎フレーム読み戻しを行わない。
  • リモート GPU 経路。リモートから受け取った表示ブロック単位の確率値は GPU に渡し、以降の描画はローカル経路と同じにする。
  • 入れ子禁止。確率表示ブロックの中に確率表示ブロックは置けない (§ 04 概要参照)。
  • 未対応時。必要な確率値が得られない場合は NaN 相当の表示にし、CPU で代替シミュレーションしない。
