ポップオーバー

画面上のセル、行、ゲートなどに補足情報を結び付けて表示する吹き出し型の外装。 本仕様では、状態ベクトルセルの実装済みポップオーバーを基準形にし、 確率表示ブロック、振幅表示ブロック、ブロッホ球表示ブロック、パレットの説明表示へ展開するための共通寸法を定義する。

★ 批評 · 全体所見
primitive 仕様としては「実装ファイル参照禁止」ルール違反と、基準形が consumer の中身に寄りすぎている点が同居する

外装トークン (面 / 縁 / 角丸 / 影 / tail / anchor gap / 画面端処理) を 1 ページに集約し、 Flexoki トーンと Tailwind スケールへ準拠しつつ、状態セルのポップオーバー実装を「基準形」として置く構造は概ね適切。 § 02 / § 03 / § 04 が「規範はクロムだけ、内容は各コンポーネント」と書き分けるのも primitive 仕様として読みやすい。 4 方向の tail バリアントと「対象の右が基本、画面右端では反転」という配置原則も実装に直結する具体性を持つ。

最大の問題は、§ 07 関連仕様 / ソースと § 04 アイコン行、および § 02 / § 06 のトークン名 / 定数名引用が、 apps/web/src/render/popover.rs のような実装ファイルを直接参照していること。 デザインシステム配下のドキュメントから *.rs を指すと依存方向が逆転し、「実装が動くたびに primitive 仕様を書き直す」関係になる。 本来の依存方向は 実装→デザインシステムの一方向のみで、本ページ自体が「実装が参照される側」になるべき。

もう一つの問題は § 01 「基準形」が、状態セル ポップオーバーの 296 × 108 px / 3 行 (Amplitude / Probability / Phase) の中身を そのまま再掲してしまっていること。primitive ページの「基準形」が特定の consumer の中身で説明されていると、 確率 / 振幅 / ブロッホ / パレット説明で外装を共有する際、「3 行の表が無いとこのクロムは使えないのか」という誤解を招く。 外装だけで成立する抽象例を最初に出し、consumer 固有の中身例は § 06 ないし別ページへ寄せるとよい。

★ 批評 · § 01 基準形
「基準形」が状態セル ポップオーバーの 296 × 108 / 3 行をそのまま再掲してしまっている

§ 01 のデモは状態セル ポップオーバー実装そのもので、Amplitude / Probability / Phase の 3 行と各アイコン、phase の +0.00° まで含む。 primitive ページの「基準形」がこのまま consumer の中身を持つと、振幅表示ブロックや確率表示ブロックが本クロムを採用する際に 「3 行表が無いとこのクロムは使えないのか」と読まれかねない。

外装 (面 + 縁 + 角丸 + 影 + tail + anchor gap) だけを持つ空の本体を § 01 の「基準形」とし、 3 行を含む例は「§ 01b 状態セルでの利用例」または § 06 実装との対応の中に移すと、primitive と consumer の責任境界が読みやすい。 基準寸法 296 × 108 を持つ理由が「状態セル実装」だとすれば、それも § 06 側で書くべき (本ページの inline <style> コメントに残る POPUP_W / popup_height() も同じ理由で外せる)。

§ 02 外装トークン

surfacecolors.surface / var(--bg)。Flexoki bg (paper) を使う。
outline1 px inside stroke。colors.popover_outline / Flexoki tx-3。面と背景がどちらも paper になる場面でも tail の輪郭を読める濃さにする。
radius10 px。状態セル実装の CornerRadius::same(10) を基準にし、ゲート本体の角丸とは連動させない。
padding12 px 16 px。Tailwind spacing-3 / spacing-4。
shadowoffset [0, 10]、blur 28、spread 0、Flexoki tx alpha。実装上は colors.state_cell_popup_shadow を基準にする。
tail高さ 8 px、半幅 8 px の三角形。面は surface、対象へ向かう 2 本の斜辺だけを outline と同じ色の 1.5 px 線幅で描く。本体との接合辺には線を引かない。
anchor gap対象要素と tail 先端の距離は 4 px。Tailwind spacing-1。
viewport pad画面端との余白は少なくとも 4 px。狭い画面では本体位置を優先して内側へ寄せる。
★ 批評 · § 02 外装トークン
outline 行の「inside stroke」表記と、実装側 token 名 (colors.popover_outline 等) の混入

outline 行は「1 px inside stroke」と書くが、本ページの .popover 実 CSS は border: 1px solid var(--tx-3) で外側に伸びる通常ボーダー。 CSS で本当に inside stroke (= 面の内側へ縁を引く) を実装するには box-shadow: inset 0 0 0 1px ... または outline; outline-offset: -1px が必要で、 見た目は近いが用語としては誤導的。「1 px の外周線 (面と背景の境界に沿う)」のような表記に直すと CSS 実装と整合する。

同じ表で colors.surface / colors.popover_outline / colors.state_cell_popup_shadow / CornerRadius::same(10) は実装側 token 名で、 これを spec から指すと実装が改名するたびに仕様も書き直すことになる。 Flexoki トーン (bg / tx-3) と Tailwind スペーシング (spacing-3 / spacing-4) と数値 (radius 10 px, offset 0 / 10, blur 28) だけで十分。 viewport pad の「狭い画面では本体位置を優先して内側へ寄せる」も抽象的で、画面端での反転 (§ 03 で言及) との重複や手段の例示が無い点も改善余地。

§ 03 tail の向き

原則は「ポップオーバー本体を読みやすい位置に置き、tail だけで対象要素との関係を示す」。 状態セルのように上下に空きがある場合は下向き tail で対象の上に置く。 確率表示ブロックや振幅表示ブロックのセル詳細では、通常は対象の右側に置いて左端 tail を使い、画面右端では対象の左側へ反転して右端 tail を使う。

bottom tail 対象の上に置く
top tail 対象の下に置く
left tail 対象の右に置く
right tail 対象の左に置く
★ 批評 · § 03 tail の向き
caption の「対象の上に置く」が本体位置の話か tail 方向の話か一目で読めない

data-tail="bottom" の caption は「対象の上に置く」と書くが、これは「本体が対象の上、tail は下向き」を意味する。 初見ではこの 2 つの主語 (本体 / tail) が混在し、tail の名称 (bottom = tail が下向き) と本体位置 (= 対象の上) が直接結び付かない。 4 方向のサンプルに本体と対象アンカーを並べて表示し、矢印または視覚的位置関係を caption に併記すると、 primitive 仕様としての「向き」が初見で読める。

加えて、本文 p で「通常は対象の右側に置いて左端 tail を使い、画面右端では対象の左側へ反転して右端 tail を使う」と書くが、 この「右が基本 / 右端で反転」のルールは § 02 viewport pad と同じ画面端処理を別言葉で書いており、§ 02 と相互参照させると重複が減る。

§ 04 内容レイアウトの扱い

規範範囲本ページが規定するのは外装、tail、対象要素との距離、画面端処理まで。見出し、行数、区切り線、ラベル文言、数値の桁数は各コンポーネント仕様が持つ。
基準例状態セルは text-sm (14 px / 20 px) の等幅見出しと、text-xs (12 px) の 3 行値一覧を使う。区切り線や補足行は持たない。
状態セルのアイコンapps/web/src/render/state_panel_popup/icons.rs を正とする。Amplitude は Re/Im 軸 + 斜め矢印、Probability は外輪 + 内側ディスク、Phase は底辺 + 斜辺 + 角度弧で描く。
行ピッチ値の行間は 20 px を基準にする。ラベルと値の間は対象の最大文字数に合わせ、狭い表示で読みにくくしない。
GPU 値状態セル、確率表示ブロック、振幅表示ブロックなどの数値は GPU 上の値を直接描く経路を維持し、CPU へ読み戻さない。
★ 批評 · § 04 内容レイアウトの扱い
「規範範囲」が § 05 「適用範囲」と重複し、状態セルのアイコン行は実装ファイルを直接参照している

「規範範囲」行 (外装 / tail / 距離 / 画面端処理まで) は § 05 「適用範囲」(surface / outline / radius / shadow / tail / anchor gap / 画面端処理) と 同じ範囲を別言葉で 2 度書く。§ 04 から規範範囲行を抜き、内容レイアウトの個別ルール (基準例 / 行ピッチ / GPU 値) に集中させる。

「状態セルのアイコン」行は apps/web/src/render/state_panel_popup/icons.rs を正とする と書くが、 これは「デザインシステム→実装参照禁止」ルールに該当する (依存方向の議論は本ページ冒頭の全体所見を参照)。 Amplitude / Probability / Phase アイコンが「Re/Im 軸 + 矢印」「外輪 + ディスク」「底辺 + 斜辺 + 角度弧」で描かれている事実だけを残し、 ファイルパスは外す。ファイル参照を入れる位置は実装側の AGENTS.md / README から本ページを指す逆方向だけにする。

§ 05 適用範囲と非目標

適用範囲surface、outline、radius、shadow、tail、anchor gap、画面端処理を共通化する。
非目標値フォーマット、ラベル文言、表示ブロック固有の内容、ホバー対象の判定、選択用小窓、短文 tooltip の統合は本ページで規定しない。
不変条件本番経路で GPU から CPU へ状態値を読み戻さない。ポップオーバーは外装だけを共通化し、各表示内容の GPU 直接描画を壊さない。
戻してよい範囲確率 / 振幅 / ブロッホ / パレット側の採用で問題が出た場合は、各コンポーネント単位で既存クロムへ戻してよい。状態セルの基準挙動、GPU バッファ、シェーダ、値描画 callback、CPU 読み戻し禁止は戻さない。
検証採用時は 4 方向 tail の見た目、画面端反転、GPU 読み戻し非発生を確認する。

§ 06 実装との対応

場所現在の状態共通化方針
状態ベクトルセル本仕様の基準形。tail 付き、角丸 10 px、影 [0,10] / 28。共通クロム実装を使い、変更時は本ページも同時に更新する。
確率 / 振幅表示ブロック本仕様の共通外装へ移行済み。通常は対象セルの右側、画面右端では左側へ反転する。値の GPU 直接描画と表示ブロック固有の文言は維持する。

アスペクト選択クリックで開く選択肢リスト。情報表示ではなく選択用の小窓なので、本仕様をそのまま適用しない。
★ 批評 · § 06 実装との対応 — Resolved
ブロッホ球ポップオーバーも本仕様の共通外装へ移行済みと明記した

以前の記述は「詳細カード風の表示」「実装時は寄せる」という将来形で、実装済みの状態と用語がずれていた。 現在は「本仕様の共通外装へ移行済み」と完了形で統一し、個別の内容、数値形式、状態別の見本は ブロッホ球ポップオーバー仕様 へ委譲している。

残る運用上の注意は、外装トークンを変更したときに本ページだけでなく個別仕様も同時に更新すること。 これにより primitive 仕様と表示ブロック固有仕様の役割分担を保てる。

★ 批評 · § 07 関連仕様 / ソース
デザインシステム→実装参照禁止ルールへの正面違反 — 6 項目中 5 つが apps/web/src/render/*.rs

本リストの 5 項目 (popover.rs / state_panel_popup/cell/geometry.rs / state_panel_popup/icons.rs / circuit_gates.rs / circuit_palette/tooltip/layout.rs) はいずれも実装ファイル。 デザインシステムから実装を指すと依存方向が逆転し、実装が動くたびに primitive 仕様を書き直す関係になる。 本ページ自体が「実装が参照される側」になるべきで、本ページから実装を指す側にはならない。

*.rs リンクをすべて削除し、残すのは同じ design-system 配下の HTML (probability-display / amplitude-display / bloch-display) と、Flexoki / Tailwind の外部規約だけにする。 実装側からは apps/web/src/render/popover.rs などのドキュメンテーションコメントに本ページの URL を書く形で逆参照させる。

  • apps/web/src/render/popover.rs — 共通外装の面、縁、影、tail 描画。
  • apps/web/src/render/state_panel_popup/cell/geometry.rs — 状態ベクトルセル基準形の幅、余白、tail、画面端処理。
  • apps/web/src/render/state_panel_popup/icons.rs — 状態ベクトルセルの Amplitude / Probability / Phase 行アイコン。
  • apps/web/src/render/circuit_gates.rs — 確率表示ブロック / 振幅表示ブロックのホバー表示。
  • apps/web/src/render/circuit_palette/tooltip/layout.rs — パレット説明表示の余白と配置。
