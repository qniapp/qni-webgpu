P ゲート (位相 θ)

単一量子ビットへ diag(1, eiθ) を適用するパラメトリック位相ゲート。 回路エディタ上では 40 × 40 px の cyan-400 塗りつぶし円に字形 "P" を中央配置する。 S (= P(π/2)) / T (= P(π/4)) / Z (= P(π)) を 1 つの汎用形にまとめた位相系列の親で、 円形ボディを採用することで「角度パラメータを持つ位相ホイール」というメタファを字形と形状の両面で示す。

★ 批評 · 全体所見
「θ 可変パラメータ」というパラメトリックゲート性が本体の見た目に乗っていない

40 px + 56 px ピッチ、ホバー枠 4+2、cyan-400 同族同色、Tailwind スケール厳守、stroke なし、 drag preview = purple-600 はユニタリ共通論点で、h-gate.html 全体所見と同じ批判が当てはまる。 円形ボディの選定根拠 (X との形状共有 + 字形差で識別) は x-gate.html 全体所見の 議論の延長線上にあり、本ページでは「X = Plus, P = 文字 P で識別できる」と簡潔に扱われている。

P ページ固有の核心は 「パラメトリックゲート (θ 可変) の見た目をどう表現するか」。page-lede では 「円形ボディ = 位相ホイールのメタファ」とパラメトリック性を形状に込めようとしているが、 現状の 静的な円形 + 字形 "P" は θ の値や可変性をまったく示していない。S (P(π/2)) / T (P(π/4)) / Z (P(π)) と P(θ) を並べたとき、ユーザは「P は θ をいじれる」という機能をクロムから読み取れない。 § 02 / § 05 の本文に「θ の現在値はホバーポップアップやパレットの数値入力など別チャネルで提示する」と 書かれているが、それは 設計判断としては有効でも パラメトリック性の視覚的シグナルが本体にないという 課題は残る。Phase 族 (S / T / S† / T†) と並んだとき、「P だけが特別」を伝えるクロム上の差別化が円形以外にない。

★ 批評 · Top Opportunities
影響度の大きい改善候補 (各論は本文中の批評ブロックに展開)
  1. パラメトリック性の視覚的シグナルを本体に追加する余地を検討 — 円周上に微小な θ マーカ (時計の針 / 扇形の角度インジケータ) を重ねる、あるいは P 字形の右下にミニ角度バッジ (例: "π/4") を出すなど、θ の存在 / 現在値を本体に乗せる選択肢がある。採否は別だが、選択肢の検討が § 07 に含まれていない (全体所見 / § 07 参照)。
  2. X との形状衝突を緩和する設計余地を § 07 で明示 — § 07 リスト 1 で「円形は X と共有するが、X = Plus / P = 文字 P で識別できる」と書くが、これは X (CNOT ターゲット) と P (パラメトリック位相) という意味的にまったく異なる 2 つのゲートに同じ形状を使う設計判断。 Plus とアルファベット P はパッと見ても識別性が低くないが、初心者にとって「丸 = CNOT のターゲット」と「丸 = パラメトリック位相」の二重対応は学習負荷になる (§ 07 参照)。
  3. § 05 状態バリアントに「θ パラメータ編集 UI 開閉中」状態を追加 — 現状は default / hover / drag の 3 状態だが、パラメトリックゲートには「θ 編集 popover が開いている状態」も実シナリオで存在する (P 固有の状態)。これを §05 で扱わないと「θ をどう編集するか」の動線が仕様ページに残らない (§ 05 参照)。
  4. § 07 「S / T / Z と冗長させる」設計判断の代償が議論されていない — P(π/2) = S / P(π/4) = T / P(π) = Z と意味的に同じゲートを別々に提供することは、UI 上「同じことが 4 通りで実現できる」という冗長性を生む。利点 (短い字形で読みやすい) は書かれているが、代償 (新規ユーザの「どれを使えばいいか」の判断負荷) は触れない (§ 07 参照)。
  5. RZ / RX / RY との位置づけを matrix-card に追加 — 「RZ(θ) と P(θ) は大域位相を除いて等価」「P は Z 軸のみ / RZ は Z 軸の物理回転 (大域位相込み)」など、回転ゲート族との関係が本ページではほとんど扱われていない。matrix-card に「回転族との関係」セルを追加すると、ユーザが「いつ P を使い、いつ RZ を使うか」を判断できる (§ 07 参照)。

§ 01概要 (見た目と用途)

P(θ) は |1⟩ 成分にだけ位相 eiθ を加える 1 量子ビットゲートで、 θ を可変パラメータとして持つ。固定角の S / T / Z はすべて P の特殊例 (θ = π/2 / π/4 / π) として扱える。 見た目では「位相量」を別色で示さず、cyan-400 = ユニタリ操作ゲートという既存の色対応を守る。 P 固有情報は字形 "P" と円形ボディ (= 位相ホイール) で識別し、回路上に置いたときには パレットや状態パネルで現在の θ 値を別途表示する想定。

★ 批評 · § 01 概要
「円形 = 位相ホイール」のメタファが page-lede の文字情報だけで、視覚に乗らない

page-lede では「円形ボディを採用することで角度パラメータを持つ位相ホイールというメタファを字形と形状の両面で示す」と 書かれているが、実際のクロムは cyan-400 の塗りつぶし円 + 文字 "P"で、円周上に角度指標は何もない。 位相ホイールとはユーザの連想に依存するメタファで、円形ボディだけからホイール性を読み取るのは 量子計算の素養が要る (RZ 回転ゲートのブロッホ球上の動きを知っているユーザ向け)。

改善案: § 01 概要のモックに「現在の θ 値を持つ P ゲート」のバリアントを追加し (例: 円周の一部に θ 角度マーカ、 または P 字形右下にミニ "π/4" バッジ)、位相ホイールという主張が単なる隠喩でなく視覚的シグナルとして 成立しうることを示す。採用しないとしても、「採用しなかった理由」を § 07 に明示しておくと、 後続の RX / RY / RZ ページがパラメトリックゲートの可視化を再検討するときの根拠になる。

★ 批評 · § 05 状態バリアント
「θ パラメータ編集 UI 開閉中」は P 固有の重要な状態だが、別仕様として外部化されている

P はパラメトリックゲートで、ユーザは θ を編集するために必ず「編集モード」を経由する。これは default / hover / drag と並ぶ P 固有の第 4 状態だが、本文末尾の note では 「未着手 / 別仕様」として外部化されている。仕様ページとしては「P の状態空間 = 3 つ (他のゲートと共通)」と ミスリードしうる構成で、P 固有の重要性 (パラメトリック性) が § 05 から欠けている。

改善案: § 05 に「④ θ 編集 popover が開いた状態 (placeholder)」を追加し、本体の上に 小さな数値入力 + スライダの仮スケッチを乗せる (実装は未着手で問題ない)。これがあれば、 「P は他のゲートと違って 4 状態目を持つ」が仕様レベルで明示され、別仕様のリンク先 (未着手) が いつまで未着手で残るかの責任も明確になる。

§ 06回路グリッド上の配置

P ゲートは 1 本の量子ビットワイヤ上の単一スロットに置く。スロットは 56 × 56 px 等間隔、 本体 40 px は中央配置で上下左右に 8 px の余白を持つ。

うっすら入っているスロット境界の ui 線は説明用で、実 UI には描画されない。 隣接スロットへ連続配置しても、本体間には 16 px の余白が残り、ホバー枠同士が重ならない。

§ 07意味論と設計判断

行列
P(θ) = [[1, 0], [0, eiθ]]
基底状態
P(θ)|0⟩ = |0⟩
P(θ)|1⟩ = eiθ|1⟩
ブロッホ球
Z 軸まわりの θ 回転。確率を変えず相対位相だけを進める (大域位相を除けば RZ(θ) と等価)。
特殊化
P(π) = Z / P(π/2) = S / P(π/4) = T / P(0) = I。Clifford 階層を θ で連続化したもの。
  • 円形ボディを採用する: P は θ を可変に持つ「位相ホイール」であり、固定角の S / T (角丸正方形) と視覚的に区別する。円形は X (CNOT ターゲット) と共有するが、X は Plus グリフ、P は文字 "P" グリフで識別できるため衝突しない
  • パラメトリック回転 (RX / RY / RZ) とは違う見た目にする: RX / RY / RZ も θ を持つが、字形が 2 文字 (R + 軸) であり、角丸正方形ボディを使う。P は単独文字 + 円形で「単一軸 (Z) の位相のみ」「Clifford 階層の連続化」という固有の位置づけを示す
  • 位相量 θ を色で表現しない: θ = π/2 と π/4 で色を変えると、ホバー / ドラッグなどの状態色と衝突する。θ の現在値はホバーポップアップやパレットの数値入力など別チャネルで提示する
  • S / T / Z と冗長させる: P(π/2) = S と P(π/4) = T は同じ作用だが、回路エディタ上では別ゲートとして残す。固定角は短い字形 ("S" / "T" / "Z") で読みやすく、ユーザの意図 (θ をいじりたいかどうか) が見た目から分かる利点を優先する
  • 枠線を持たない: 本体色 cyan-400 が wire (ui-2) や背景 (bg-2) と十分区別できるため、枠線は足さない
  • span = 1 固定: P は単一量子ビットだけに作用するため、表示ブロックや QFT のような span リサイズを持たない
★ 批評 · § 07 意味論と設計判断
3 つの設計判断 (冗長性 / X 形状衝突 / RZ との関係) が一面的にしか議論されていない

(1) 「S / T / Z と冗長させる」判断の代償: リスト 4 項目では「P(π/2) = S と P(π/4) = T を別ゲートとして残す」 利点 (短い字形で読みやすい / 意図が見た目から分かる) だけが書かれ、代償 (新規ユーザの「どれを使えばいいか」の判断負荷、 パレット上の冗長配置による情報密度の低下) は触れない。Phase 族 5 ページが提示する選択肢 (P / S / T / S† / T†) は実用上「ほとんど S と T で済む」ので、初心者には「なぜ P が独立して必要か」が伝わりにくい。

(2) X との形状衝突: リスト 1 では「円形は X と共有するが、X = Plus / P = 文字 P で識別できるため衝突しない」と 断定するが、これは 初心者が「丸 = NOT」と「丸 = パラメトリック位相」の二重対応を学ぶ負荷を考慮していない。 実 UI で X と P が同じ wire 上に隣接配置されたとき、字形 (Plus vs P) の判別性は本ページではモック検証されていない。

(3) RZ / RX / RY との関係: matrix-card の「ブロッホ球」セルに「大域位相を除けば RZ(θ) と等価」と書かれるが、 これは P と回転族の関係を理解するうえで根本的な情報。リストには「パラメトリック回転 (RX / RY / RZ) とは違う見た目にする」と あるが、「P と RZ(θ) は大域位相を除いて等価」が決定的な区別点。matrix-card に「回転族との関係」セルを独立で立てると、 ユーザは「P を使うべき場面」と「RZ を使うべき場面」(大域位相が観測に影響する場合) を判断できる。
