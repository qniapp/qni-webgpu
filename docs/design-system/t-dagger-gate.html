T† ゲート (位相 −π/4)

単一量子ビットへ diag(1, e-iπ/4) を適用する逆位相ゲート (T のエルミート共役)。回路エディタ上では 40 × 40 px の cyan-400 角丸正方形に Geist Bold 由来の字形 "T" + 右上の小さな † (dagger) グリフを中央配置する。 本体の色やサイズは T と完全に共有し、字形だけが T と異なる「順 / 逆」のペア表現を採用する。

T† ページ固有の核心は 「T† が non-Clifford ゲートのエルミート共役」であること。 § 07 の matrix-card に (T†)2 = S† / (T†)4 = Z / T† = T7 / 非 Clifford ゲートと書かれるが、これは T と同じ non-Clifford 性を引き継ぐ唯一の dagger という 重要な性質。一方で本ページの構成は s-dagger-gate.html をほぼテンプレート流用しており、 章ごとの内容も S† と均質。T† だけが non-Clifford である事実が page-lede や § 01 でも触れられず、 「位相系列の dagger ペアのうちの 1 つ」という同列扱いで終わっている。

§ 01概要 (見た目と用途)

T† は |1⟩ 成分にだけ位相 e-iπ/4 を加える基本ゲートで、Z 軸まわりの −π/4 回転に対応する。 T†·T = I という関係から、T が進めた位相を巻き戻す「逆向き T」として使う。 見た目では「順 / 逆」や「非 Clifford」を別色で表現せず、cyan-400 = ユニタリ操作ゲートという既存の色対応を守り、 字形 "T" の右上に小さな † を重ねることで T との違いを示す。

★ 批評 · § 01 概要
T† が「non-Clifford ゲートの唯一の dagger」である事実が一切触れられない

本文は「T が進めた位相を巻き戻す逆向き T」「色やサイズは T と完全に共有」と T との関係を述べるが、 Phase 族の中で T と T† だけが non-Cliffordであるという量子計算上の重要な性質には触れない。 この性質は t-gate.html § 07 matrix-card の「Clifford + T で universal」と 対応するが、T† 単体ではエルミート共役として T と同じ非 Clifford 性を持ち続けることが量子コンパイラの 基底ゲート集合 (例: T と T† の両方を含む) の設計理由になっている。

改善案: page-lede か § 01 本文に「T† は T と同じく non-Clifford。Clifford + T 集合に必要な逆元」と 1 行追記し、T† の役割を読者に最初に植える。これがないと、「T† は T の逆」止まりで、なぜ Clifford 族 (S†) とは別扱いされるのかが伝わらない。

★ 批評 · § 06 回路グリッド上の配置
「T† 3 個の連続配置」モックは実際の量子コンパイラ出力と乖離する

現状のモックは T† を 1 つおきに 3 個並べる形だが、量子コンパイラの出力では T と T† が交互に出現する パターン (例: 位相補正、CNOT の位相シフト分解) が典型的。実シナリオで T と T† が並んだとき、 ユーザが両者を判別できるか / † グリフが視認できるかは、本ページの設計判断 (「字形差で順 / 逆を示す」) の妥当性を直接検証する場面なのに、ここでは検証されていない。

改善案: モックを 2 つに分け、(a) 現状の「T† 連続配置」(同種ゲートの繰り返し視認性検証) と (b) 「T / T† 交互配置」(順 / 逆の混在シナリオでの判別性検証) を並べる。 後者で判別性が低いことが確認できれば、Top Opportunities #5 の hover 強調策やテキストラベルの根拠になる。

§ 07意味論と設計判断

行列
T† = [[1, 0], [0, e-iπ/4]]
基底状態
T†|0⟩ = |0⟩
T†|1⟩ = e-iπ/4|1⟩
ブロッホ球
Z 軸まわりの −π/4 (−45°) 回転。T と逆向きに相対位相を巻き戻す。
関係
T†·T = I / (T†)2 = S† / (T†)4 = Z / T† = T7。非 Clifford ゲート。
  • T と本体を共有して字形差で順 / 逆を示す: T (順 π/4) と T† (逆 −π/4) は数学的には別の作用だが、ユーザにとっては「T の打ち消し」として理解される。色 / サイズ / 角丸を完全に揃え、右上の † グリフだけで差分を示す
  • 逆回転を色で表現しない: 「順 / 逆」を別色にすると、ホバー / ドラッグなどの状態色と衝突する。順 / 逆の識別は字形 († の有無) とヘルプ文に閉じる
  • † を superscript 位置に置く: 数式 T† の組版に倣い、T グリフの右上に小さく配置 (T の 52 % 縮尺)。T 字形の重心を本体中央に保ち、見た目の重心が右にずれないようにする
  • RZ(-π/4) と混同させない: T† は固定角 −π/4 の位相、RZ(θ) は任意角の回転ゲート。T† は文字 + † グリフ、RZ は 2 文字グリフで描き分ける
  • stroke を持たない: 本体色 cyan-400 が wire (ui-2) や背景 (bg-2) と十分区別できるため、枠線は足さない
  • span = 1 固定: T† は単一量子ビットだけに作用するため、表示ブロックや QFT のような span リサイズを持たない
★ 批評 · § 07 意味論と設計判断
matrix-card の「非 Clifford ゲート」が、代数関係と同じセル内に追記される構造になっている

matrix-card 「関係」セルには T†·T = I / (T†)2 = S† / (T†)4 = Z / T† = T7 / 非 Clifford ゲート が並列に詰め込まれている。最後の「非 Clifford」は代数関係ではなく 計算複雑性上の分類で、 前の 4 つの代数関係とは性質が異なる。同じセルに混ぜると、ユーザは「非 Clifford」を「T† = T7 の 補足説明」のように読み流してしまう。これは t-gate.html § 07 でも同じ構造的弱点。

改善案: matrix-card に「分類」セルを独立で立てる (「非 Clifford / Phase 族 / dagger」)。 この分類軸は他の Phase メンバ (S / S† は Clifford / Phase 族 / dagger なし or あり、P は Clifford 階層の連続化) との対比で T† の唯一性が浮かび上がる。matrix-card のレイアウト (4 列 grid) には追加 1 セル分の余裕がある。
