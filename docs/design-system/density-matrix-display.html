密度行列表示ブロック

span 内の量子ビットを測定せずに、局所的な混合状態 (reduced density matrix) ρ = Trrest(|ψ⟩⟨ψ|) を可視化する密度行列表示ブロック (表示ブロック の定義は AGENTS.md 用語集と design-system §01 参照)。 振幅表示ブロックが α = re + i·im 1 本を 2span セルで描くのに対し、本表示ブロックは ρij の 2span × 2span 全成分 を行列状に描く。 対角成分は 各測定結果の確率 P(|i⟩) = ρii、非対角成分は coupling / coherence ρij (絶対値 = 大きさ、偏角 = 相対位相)。 span 上限は 8 量子ビット (Quirk DensityMatrixDisplay と同じ。216 = 65 536 セルの正方行列、vec2<f32> で 512 KB を GPU storage で扱う上限)。 配色 (blue-200 fill / blue-400 disk border / tx-2 outline / tx needle) は振幅表示ブロック / 状態ベクトルパネルと完全に揃える (Quirk の #3F3 / #040 緑系は Flexoki に馴染まないため不採用)。 Quirk の DensityMatrixDisplayFamily (src/gates/DensityMatrixDisplay.js) と MathPainter.paintDensityMatrix を Flexoki + WebGPU + Qiskit Aer 二系統経路へ移植する仕様書。

§ 01 サイズ別の見た目 (1〜8 量子ビット、動くモック)

span 1〜8 の代表的な reduced density matrix を並べた参考レンダリング。matrix 寸法は n × n (n = 2span) の正方行列、本体寸法は size_px = 56 × span − 16 px の正方形 (確率表示ブロックの高さ公式と一致、振幅表示ブロックの幅 / 高さ公式とも対称)。 cell 寸法 (cellPx = size_px / n) は span が増えるごとに半減する: span 1 で 20 px、span 4 で 13 px、span 5 で 8.25 px、span 7 で 2.94 px、span 8 で 1.69 px。 cellPx に応じてレイヤを段階的に省略する (§ 05): cellPx ≥ 12 = outline + disk + needle / cellPx ∈ [3, 12) = outline + disk (needle 省略) / cellPx < 3 = heatmap (mag を alpha に潰す dense mode)。 対角 / 非対角ともに outline 円 + magnitude disk で描き、disk 半径は対角なら ρii (= 確率)、非対角なら |ρij|。対角は実数 (位相 0) なので needle のみ省略する。 各セルにマウスを乗せると Quirk と同じ tooltip 内容 (対角は Probability of |k⟩ / 非対角は Coupling of |row⟩ to ⟨col|) をポップアップ表示する。

純粋状態 vs 混合状態の見た目の違い

span 2 の例で、純粋状態 (Bell |Φ⁺⟩⟨Φ⁺|、ランク 1) と 最大混合状態 (I/4、ランク 4) を並べる。 純粋状態は対角と非対角の両方に値が並び、coupling が明確に見える。 最大混合状態は対角のみに 0.25 半径の小さな disk が均等に並び、非対角は全て 0 → off-diagonal が空になり対角の小さな円だけが残る 見た目になる。これが「混合度の視覚的指標」になる。

§ 02 パレットアイコン (mini preview)

パレットに並ぶ DensityMatrixDisplay アイコンは 40 × 40 px の静的 mini preview。 2×2 行列 (= span 1) を 純粋 |+⟩⟨+| の密度行列 として描く: 4 セルすべてに 0.5 半径の magnitude disk + outline 円、非対角 2 セルだけは追加で真上 needle (実数なので位相 0 = 真上)。 「対角 / 非対角ともに disk、非対角だけ needle が立つ」という本表示ブロックの統一されたセル描画を 1 アイコン内で提示し、密度行列特有の行列 (matrix) 形状を視認させる。 アイコン自体の外側に四角枠は描かず、4 つの円だけで密度行列表示ブロックだと分かるようにする。円周の外端はセル境界から 1.5 px だけ内側に置き、hover 枠と重ならない範囲で最大化する。 ホバー時は外側のゲートホバー枠だけ表示 (静的なので個別 cell ポップアップは出さない)。

§ 03 概要

役割span 内の量子ビットの局所的な混合状態 ρ = Trrest(|ψ⟩⟨ψ|) を可視化する表示ブロック (状態に影響しない)。純粋状態 / 混合状態の判別と、span 内外の entanglement の有無を 1 つの widget で読める点が振幅表示ブロックとの差。Quirk の Density Matrix Display と同じ意味
span1〜8 量子ビット (Quirk の Gate.buildFamily(1, 8, ...) と一致)。28 × 28 = 65 536 複素成分を扱う上限
matrix 寸法n × n (n = 2span)、row / col とも binary big-endian (row 0 = |0…0⟩、col 0 = ⟨0…0|)。ρii が対角 = 確率、ρij (i ≠ j) が非対角 = coupling
計算内容span に対応する subspace の縮約密度行列を control 条件で射影して返す。本番経路で GPU → CPU リードバックなし。外部 Qiskit Aer 経路ではバックエンド側で save_density_matrix(qubits=[…]) を呼び、JSON を web に返してから GPU buffer に upload する (§ 09)
シリアライズ ID"Density" (span 1)、"Density2".."Density8" (span 2..8)。Quirk の setSerializedId("Density" + span) と一致、span 1 だけ接尾辞なしの "Density" になるのも同じ
palette symbol"Density" (Quirk setSymbol("Density") に対応)
配置パレット 1 アイコンから drag-and-drop。配置後に上下のリサイズハンドルで span を 1..8 に変更 (§ 08)
nesting禁止 (表示ブロックの中に表示ブロックは置けない、Quirk と同じ "can't nest displays")
measure columnQuirk と同じく、列処理の後に display capture。span 内に measured wire を含む列では、measure された量子ビットの非対角成分が 0 に潰される (Quirk の decohereMeasuredBitsInDensityMatrix と同じ挙動)。詳細は § 05 参照
NaN handling正規化 (unity = Σ ρii) が 0 や NaN になる pathological ケース (controls が満たされない / 入力が崩れる) では ρ = NaN として中央に "NaN" を描く。Quirk の densityPixelsToMatrix と paintDensityMatrix の hasNaN 分岐に揃える

水平 slot 占有 (振幅表示ブロックと同モデル)

qni の水平 slot pitch は SLOT_SPACING = 56 px。密度行列表示ブロックは正方形なので width_px = size_px = (span − 1) × SLOT_SPACING + GATE_SIZE = 56 × span − 16 となり、 span 8 で 432 px (= 8 slot 分の幅を覆う) になる。slot 構造としては1 列消費、視覚的には span slot 分の幅をはみ出す (振幅表示ブロックの可変幅モデルと同じ採用。詳細は amplitude-display.html § 04 参照)。

  • URL round-trip (Quirk 互換) — JSON は {"cols":[["Density3"]]} のように単一 token。setWidth は表示列幅であり JSON 上の列消費ではない。decode 時に "Density<span>" を正規表現で読み、内部 slot index 1 つ分を占有するエントリとして登録 (shift / reserve なし)
  • placement / 衝突検出 — 振幅表示ブロックと同じくgate_rect の幾何交差で判定: 新規 density を slot N に置くとき、gate_rect (x..x + size_px, y..y + size_px) が既存 gate と交差するなら drop 拒否
  • resize handle — 上下のみ (span を変える)。幅は span の関数なので separate な width handle は不要 (§ 08)
  • drag / drop preview — drag 中は他ゲートと同じく purple-600 を背景に差し替え、内部の cell 描画 (outline / disk / needle) は通常時のまま維持する

§ 05 セル描画モデル (全セル統一、対角は needle のみ省略)

Quirk の paintDensityMatrix (src/draw/MathPainter.js) を Flexoki + 振幅表示ブロックの視覚言語へ移植する。 対角 / 非対角ともに同じ「outline 円 + magnitude disk」レイヤで描き、対角だけ needle を省くのがポイント。これにより:

  • 対角セル ρii = 実数の確率 P(|i⟩) ∈ [0, 1]。 outline 円 + magnitude disk の 2 層で描く。 disk 半径 = ρii × inner_radius (= P × inner_radius)、半径ゼロ (P = 0) なら disk を描かない。 needle は描かない: 対角は常に実数 (位相 0) なので needle が真上を向くだけになり情報量を持たず、視覚的ノイズになる。Quirk の Probability square (下から上に伸びる塗りバー) は採用せず、非対角と同じ disk 表現で統一する (確率の値は disk の面積として読める)。
  • 非対角セル ρij (i ≠ j) = 複素数の coupling。 振幅表示ブロックと同じ outline 円 + magnitude disk + disk 境界線 + phase needle の 4 層で描く。 mag = |ρij|、phase = arg(ρij)。 disk 半径 = mag × inner_radius、needle 方向 = (−sin(phase), −cos(phase)) で真上が phase 0。 境界線 / 配色は振幅表示ブロックの規約に従う (amplitude-display.html § 05 と完全共有)。
  • Hermitian 性 — 密度行列は ρij = conj(ρji) なので、上三角と下三角は位相が反転した対称。表示としても自動的に左下と右上の needle が鏡像になるため、ユーザーは行列の片側を読むだけで全体が読める (Quirk と同じ視覚言語)。対角は実数 (虚部 0) なので Hermitian 性も自動的に満たされる。
(1) back fill — セル背景。通常時は bg (#FFFCF0)。drag preview 中は matrix 外周のみ purple-600 に差し替え、内部の cell 描画 (outline / disk / needle) は通常時のまま
(2) outline 円 (全セル) — セル中央、半径 = cellPx/2 − stroke/2 − 1.5 px。stroke は振幅表示ブロックに合わせ、cellPx > 24 で 2 px、それ以下で 1 px。円周 stroke の外端をセル境界から 1.5 px 内側に置き、matrix 外枠と重ならない範囲で最大化する。描画条件: cellPx ≥ 3。mag > 1e-6 なら tx-2、≈ 0 なら ui-2。cell hover 時は outline 円を purple-400 に置き換える (振幅表示ブロックと同様)
(3) magnitude disk (全セル) — 中心 = セル中心、半径 = |ρij| × inner_radius。fill = blue-200 + inset 1 px blue-400 境界線。閾値: r > 0.3 で fill、r ≥ 1.5 で stroke も追加。対角は実部 = 確率 = 半径として描かれる
(4) phase needle (非対角のみ) — セル中心から方向 (−sin(phase), −cos(phase)) へ inner_radius の線分。tx stroke。描画条件: cellPx ≥ 12 かつ i ≠ j。対角は実数で位相 0 なので常に省略
(5) 外枠 — matrix 全体の外枠だけを ui-2 1 px で描く。cell 間の縦横区切り線は描かず、振幅表示ブロックと同じ円の余白でセル境界を読ませる

Quirk との差分: Quirk は対角に塗りバー (_traceProbabilitySquare) を採用しているが、本仕様は対角も非対角と同じ disk 表現に統一する。理由は (a) 1 つの行列内に「塗りバー + 円」の 2 種類の見た目が並ぶと視線が分散する、(b) 振幅表示ブロック / 状態ベクトルパネルが既に「disk = 確率の大きさ、needle = 位相」の語彙を確立しているので、密度行列もそれに乗せたほうが学習コストが低い、(c) 対角は実数なので needle を省くだけで「確率 = 円」と「coupling = 円 + needle」の差が自然に出る。 Quirk の _traceAmplitudeLogarithmCircle (log 強調用の補助円) は disk と冗長 (disk が小さくても outline 円が常に視認できる) なので不採用。小さい coupling は magnitude disk の大きさだけで表現し、ロガリズム強調は tooltip の log: ... dB 数値に集約する (§ 07)。

heatmap モード (cellPx < 3、span 7〜8)

cellPx が 3 px 未満では outline 円 / disk / needle が視覚的に潰れる。 各セルを 1 つの矩形塗りに潰し、alpha = √(|ρij| / max|ρ|) で濃淡を出す:

  • 対角 / 非対角の区別はせず、全セルに blue-200 を √スケール alpha で塗る (Quirk の d ≤ 2 フォールバックと同じ、lightgray → blue-200 へ色のみ差し替え)
  • matrix 全体の外枠だけは ui-2 1 px で残す。cell 間 grid は描かない
  • cell hover は引き続き有効: purple-400 2 px の正方形ringを描く (heatmap では outline 円が無いため、振幅表示ブロックの「outline 円を purple-400 で置換」ではなく cell rect の purple ring を採用)
  • 位相情報は heatmap では消える: span 7〜8 では tooltip だけが phase の供給源になる (cell hover 必須)

measure 済み量子ビットの decoherence

span 内に measure 済み wire が含まれる列では、Quirk の decohereMeasuredBitsInDensityMatrix と同じく measured bit が異なる (row, col) ペアの非対角成分を 0 に潰す: 

// row / col の measured bit pattern が一致しない非対角を 0 化。
// (Quirk DensityMatrixDisplay.js:107-124 と等価、qni 内部で GPU compute pass として組む)
for row in 0..n:
  for col in 0..n:
    if ((row ^ col) & is_measured_mask) != 0:
      rho[row, col] = 0  // 位相 coherence が古典化で失われる

視覚的には、measured wire 由来の非対角列 / 行が消えて、対角の塊が残る。これは「測定後の古典化された状態」と「未測定の量子重ね合わせ」の境界を hover 抜きで見分ける手がかりになる。 qni 側の lowering 順序は列処理の後に display captureなので、measure される直前の純粋振幅ではなく collapse 後の混合状態 が表示される (振幅表示ブロックの § 06 と同じ仕様判断)。

§ 06 実行前プレースホルダ (シミュレーション未実行の状態)

回路に密度行列表示ブロックを配置しただけで、まだシミュレーション (▶ Run) を実行していない段階で表示する仮の見た目。 GPU 経路の density_output / density_meta バッファがまだ書き込まれていないので行列値は存在せず、 従来の素朴な実装ではセル領域が真っ白に抜けて見え「壊れているのか配置できていないのか」が判別できない問題が出る。 この空白を 「実行待ちであることを伝えるプレースホルダ」 として明示的にデザインする。 振幅表示ブロック (amplitude-display.html § 01) / 確率表示ブロック (probability-display.html § 01) と同じ配色コンベンションに従う。

  • 背景 (placeholder fill) — purple-100 (#ECE1F3) の薄い紫で matrix 全体を塗る。本デザインシステムでは紫を「未確定 / 進行中」に充てており (drag preview = purple-600、hover ring = purple-400)、実行前の ρ も「0 (赤系) と 1 (青系) の中間に位置する未確定な値」として同じ紫系統で表す。色相は drag/hover で使う濃い紫よりさらに淡くし、「進行中アクション」と「結果待ち静止状態」を区別する
  • cell 構造ガイド — cell 間の grid は引かない。通常時と同じく、matrix 外枠だけで表示ブロックの領域を示す
  • outline 円 / disk / needle — 描かない。ρ の値が無いので「対角の確率」も「非対角の coupling」も意味を持たない
  • 外枠 — 通常時と同じ ui-2 1 px の外枠を引く
  • hover / tooltip — 実行前は cell 単位 popup を出さない (表示すべき数値が無い)。ゲート全体の hover ring (purple-400 4 px) と上下リサイズハンドルは通常時と同じく出す
  • 遷移 — 現行実装は Run 結果が届いたフレームでプレースホルダ層 (薄紫背景 + 外枠) から通常の probability + disk + needle 描画へ即時に切り替える。150 ms ease-out のクロスフェードは将来の改善候補

  • full / outline + disk モード — 対象 cell の outline 円周を purple-400 2 px に置き換える (対角 / 非対角ともに同じ outline 円を持つので扱いが統一される)。matrix 全体の hover ring は cell hover 中は消す (振幅表示ブロックの方針と同じ)
  • heatmap モード — cell が小さすぎて outline 円が無いので、cell 領域の正方形 ringを purple-400 2 px で囲む (Quirk の strokeRect ... 'orange', 2 と同じ位置、色だけ Flexoki へ置換)

§ 08 リサイズハンドル (span 1〜8)

振幅表示ブロック / 確率表示ブロックの上下ハンドルと chrome 仕様は完全に共有する (amplitude-display.html § 04 の resize handle 節 / probability-display.html § 11 参照)。 ハンドル単独の挙動だけ要点を再掲する:

  • 配置 — matrix の上下中央に 1 つずつ。top / bottom: −12 px (4 px hover ring + 2 px paper gap + 6 px height の合計 12 px 外側)
  • 幅 — JS で canvas 幅 (size_px) の 60% に動的にスケール、min 24 px (上限なし、span 8 = 432 px なら handle 幅 ≈ 259 px)
  • 初期状態 — opacity: 0、ゲート hover で奥から飛び出してくるマイクロインタラクション (フェードイン + 軽いバウンス: scale(0.7) → scale(1) in 250 ms cubic-bezier(0.34, 1.56, 0.64, 1))
  • default — cyan-400 ベース (ホバー枠 purple-400 と別色族で「リングの突起 ?」誤認を回避)
  • 個別 hover — cyan-600 + scale(1.15)、cursor は ns-resize
  • active drag — cyan-600 + scale(1.25)、固定
  • span clamp — drag の上限は span 8 (Quirk と同じ)、下限は span 1。span 1 から上方向 / span 8 から下方向にドラッグしても止まる
  • 左右ハンドルなし — width は span の関数 (56 × span − 16) なので独立した width handle は不要。高さハンドルの変更で同時に幅も変わる正方形リサイズ

§ 09 Qiskit / GPU 実装メモ (二系統経路)

密度行列表示ブロックは 2 つの計算経路を持つ: (a) WebGPU 内部実行 (qni 単体で動く既存経路、振幅 / 確率表示ブロックと同じ scheme) と (b) 外部 Qiskit Aer 経路 (qiskit-backend からの結果を受け取る経路、apps/qiskit-backend と統合)。 どちらも本番 UI 経路では GPU → CPU readback しない規約に従い、結果を GPU storage buffer に置いて render shader が直接 sample する。

(a) WebGPU 内部実行 (qni 単体、振幅表示ブロックと同パイプライン)

Quirk の densityDisplayStatTexture (DensityMatrixDisplay.js:44-71) を WebGPU compute pass 列へ移植:

  1. Control select + cycle — controls を満たす要素だけ詰めて span subspace を head に持ってくる (Quirk CircuitShaders.controlSelect + cycleAllBits)
  2. amplitudes → couplings — Quirk AMPLITUDES_TO_DENSITIES_SHADER と等価な compute kernel: ρij(rest) = ψi,rest · conj(ψj,rest) を各 rest 値ごとに計算し、出力 buffer に vec2<f32> で書き込む。要素数 = 2rest × 2span × 2span
  3. Partial trace (sum-fold) — rest 量子ビットについて sumFold で畳み込み、最終的に ρ: vec2<f32>[2span × 2span] の縮約密度行列が得られる
  4. unity 正規化 — unity = Σ ρii.real を reduce、ρ /= unity を全要素並列で適用 (Quirk densityPixelsToMatrix と等価)
  5. measured-bit decoherence — controls / lowering で得た is_measured_mask を渡して、(row ^ col) & mask != 0 な非対角を 0 に潰す compute pass (Quirk decohereMeasuredBitsInDensityMatrix と等価)
  6. render shader — 出力 storage バッファを fragment shader が直接 sample。outline / disk / needle / 外枠はすべて fragment shader 内の SDF で描く (振幅表示ブロックの amplitude_result シェーダと同型)

(b) 外部 Qiskit Aer 経路 (apps/qiskit-backend、実装済み)

外部 GPU 実行では、Web 側が配置済み Density Matrix 表示ブロックを outputs.densities に列挙し、qiskit-backend が QuantumCircuit.save_density_matrix(qubits, label=...) で縮約密度行列を保存する。応答は densities 配列で返り、各項目は gate_id / span / cells / unity を持つ。cells は行優先の [re, im] 配列で、サイズは 2span × 2span 複素数。

  • バックエンド側 — contract.py が outputs.densities を検証し、span 1〜8 / 最大 16 件を受け付ける。runners.py は各列のゲート適用直後に save_density_matrix を挿入し、densities[].cells へ変換する
  • Web 側要求 — apps/web/src/app/external_gpu/density.rs が {"gate_id", "column", "span", "base_bit"} を生成する。Control と同じ列に置いた Density Matrix 表示ブロックは、外部契約へ control_mask / control_value を追加するまで拒否する
  • Web 側描画 — 応答 JSON を Float32Array 相当の連続値へ平坦化し、DensityMatrixDisplayCallback が density_output / density_meta GPU バッファへ queue.write_buffer で転送する。転送後の描画は (a) と同じ DENSITY_RENDER_SHADER が担当する
  • 測定済み wire の注意 — 現在の外部経路は Aer の保存結果をそのまま表示する。測定済み wire の非対角を WebGPU 内部実行と完全一致させるための追加 decoherence pass は今後の改善候補
