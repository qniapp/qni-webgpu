密度行列表示ブロック

span 内の量子ビットを測定せずに、局所的な混合状態 (reduced density matrix) ρ = Trrest(|ψ⟩⟨ψ|) を可視化する密度行列表示ブロック (表示ブロック の定義は AGENTS.md 用語集と design-system §04 参照)。 振幅表示ブロックが α = re + i·im 1 本を 2span セルで描くのに対し、本表示ブロックは ρij の 2span × 2span 全成分 を行列状に描く。 対角成分は 各測定結果の確率 P(|i⟩) = ρii、非対角成分は coupling / coherence ρij (絶対値 = 大きさ、偏角 = 相対位相)。 span 上限は 8 量子ビット (Quirk DensityMatrixDisplay と同じ。span 8 は 65 536 セルの正方行列で、ヒートマップとして読む)。 配色 (blue-200 fill / blue-400 disk border / tx-2 outline / tx needle) は 振幅円 プリミティブに従い、振幅表示ブロック / 状態ベクトルパネルと完全に揃える (Quirk の #3F3 / #040 緑系は Flexoki に馴染まないため不採用)。 Quirk の DensityMatrixDisplayFamily (src/gates/DensityMatrixDisplay.js) と MathPainter.paintDensityMatrix の見た目を Flexoki の表示ブロックとして定義する。WebGPU / Qiskit Aer 経路の詳細は 実装仕様へ分離する。

★ 批評 · 全体所見
「N×N 行列を 1 widget に詰める」根本的なスケーラビリティ問題が § 05 表に押し込まれている

Flexoki Light 準拠、振幅表示ブロックとのセル描画統一、実装仕様との分離により、probability-display.html / amplitude-display.html と同等に見た目の仕様として読みやすい。 ただし本表示ブロックの固有の難しさは 「セル数が 22 × span = (振幅表示ブロックの 2 乗) で爆発する」こと。 span 1 で 4 セル、span 2 で 16 セル、span 4 で 256 セル、span 8 で 65 536 セル。同じ span でも振幅表示ブロックは 2span セルなので、密度行列表示ブロックは 常に振幅表示ブロックの 2 乗倍のセルを持つ。 これが「span 上限 8」(振幅は 16) の根本理由であり、§ 02 / § 05 では span 1〜6 の行列モードと span 7〜8 のヒートマップモードを分けて説明する。span 8 の 65 536 セルを 432 × 432 px 正方形に詰めると、個々の円ではなく濃淡分布として読む必要があるため、「N × N 行列を視覚化することそのものの限界」を仕様内で先に知らせる。

「対角 = 確率、非対角 = coherence」という 2 つの異なる意味を同じセル形状で描く判断も本表示ブロックの固有問題で、§ 06 で 「対角も非対角も outline 円 + magnitude disk、対角だけ needle 省略」と統一されている。 これは振幅表示ブロックとの語彙統一として優れているが、対角の ρii = 確率 と非対角の ρij = coupling は物理的に別の量 (確率は [0, 1]、coupling は複素数で大きさ ≤ 0.5) で、同じ「半径 = mag」表現にすると対角の disk は最大 1 まで膨らみ、非対角は最大 0.5 までと視覚的スケールが構造的に対角優位になる。Quirk は対角を probability bar、非対角を disk と形を変えて区別していたが、本仕様は語彙統一を優先する。§ 06 では、この利点と副作用をトレードオフとして明示する。

★ 批評 · 改善候補
ユーザー判断が必要な改善候補
  1. operation 前後の diff 表示 — 量子操作後の ρ の変化 (どの coupling が増減したか) は単一スナップショットでは読めない。「直前の ρ との差分表示モード」が将来価値を持つ可能性 (§ 06 後半 / 実装仕様の受け入れ条件参照)。

§ 02 サイズ別の見た目 (1〜8 量子ビット、動くモック)

span 1〜8 の代表的な reduced density matrix を並べた参考レンダリング。matrix 寸法は n × n (n = 2span) の正方行列、本体寸法は size_px = 56 × span − 16 px の正方形 (確率表示ブロックの高さ公式と一致、振幅表示ブロックの幅 / 高さ公式とも対称)。 cell 寸法 (cellPx = size_px / n) は span 3 以降で急速に縮む: span 1 で 20 px、span 4 で 13 px、span 5 で 8.25 px、span 7 で 2.94 px、span 8 で 1.69 px。 cellPx に応じてレイヤを段階的に省略する (§ 06): cellPx ≥ 12 = outline + disk + needle / cellPx ∈ [3, 12) = outline + disk (needle 省略) / cellPx < 3 = heatmap (mag を alpha に潰す dense mode)。 対角 / 非対角ともに outline 円 + magnitude disk で描き、disk 半径は対角なら ρii (= 確率)、非対角なら |ρij|。対角は実数 (位相 0) なので needle のみ省略する。 各セルにマウスを乗せると Quirk と同じ補足内容 (対角は Probability of |k⟩ / 非対角は Coupling of |row⟩ to ⟨col|) をポップオーバーで表示する。

純粋状態・中間混合・最大混合の見た目の違い

span 2 の例で、純粋状態 (Bell |Φ⁺⟩⟨Φ⁺|、ランク 1)、50% 混合 (0.5|Φ⁺⟩⟨Φ⁺| + 0.5I/4)、最大混合状態 (I/4、ランク 4) を並べる。 純粋状態は対角と非対角の両方に値が並び、結合が明確に見える。 中間混合では非対角 disk が半分に縮み、対角には小さな均一成分が混ざる。 最大混合状態は対角のみに 0.25 半径の小さな disk が均等に並び、非対角は全て 0 → off-diagonal が空になり対角の小さな円だけが残る 見た目になる。 補助テキストの Tr(ρ²) は純粋度で、1.0 に近いほど純粋、1/n に近いほど混合している。

★ 批評 · § 02 サイズ別の見た目
純粋状態の判別: rank=1 という構造が視覚化されていない

純粋状態 |ψ⟩⟨ψ| は rank 1、混合状態は rank > 1 という代数的事実は密度行列表示ブロックの主要な情報量だが、本仕様の disk 表現ではこの構造を直接読めない (rank は固有値分解しないと出てこない)。 Tr(ρ²) の補助値で純粋度の入口はあるが、残る改善余地は「純粋なら disk pattern が 1 つの outer product (列ベクトル × 行ベクトル) で書ける」という構造を hover で示唆すること。

§ 03 パレットアイコン (mini preview)

パレットに並ぶ DensityMatrixDisplay アイコンは 40 × 40 px の静的 mini preview。 2×2 行列 (= span 1) を 純粋 |+⟩⟨+| の密度行列 として描く: 4 セルすべてに 0.5 半径の magnitude disk + outline 円、非対角 2 セルだけは追加で真上 needle (実数なので位相 0 = 真上)。 「対角 / 非対角ともに disk、非対角だけ needle が立つ」という本表示ブロックの統一されたセル描画を 1 アイコン内で提示し、密度行列特有の行列 (matrix) 形状を視認させる。 アイコン自体の外側に四角枠は描かず、4 つの円だけで密度行列表示ブロックだと分かるようにする。円周の外端はセル境界から 1.5 px だけ内側に置き、hover 枠と重ならない範囲で最大化する。 ホバー時は外側のホバー枠だけ表示 (静的なので個別 cell ポップオーバーは出さない)。

本表示ブロックのアイコンは 2×2 行列 (span 1 の |+⟩⟨+|) で 4 つの disk を並べ、密度行列特有の行列形状を最初から提示する。 これは振幅表示ブロック (1 セル) や確率表示ブロック (4 行ガウシアン) より意図が明確で、設計判断として優れている (probability-display.html / amplitude-display.html § 03 の批評で「アイコンと配置後の形状ジャンプ」を問題視したのと対照的)。

一方で、本表示ブロックの本質的な力は span 4〜6 の 16×16 / 64×64 行列で off-diagonal coupling パターンを visualize することにあり、span 1 の 2×2 はもっとも単純な例にすぎない。 アイコンが span 1 (4 セル) なので、ユーザは「2×2 程度の小さい行列を見るゲート」と最初に学習し、span 4 まで上げる動機が弱い。 改善案: アイコンを 4×4 (span 2 の Bell) にして、対角四隅 + 中央 4 セルのcoupling patternを初期表現にする。span 4 で見える coupling 縞を span 2 のレベルで予告すると、ユーザの mental model が「行列のパターン認識」に寄る。

§ 04 概要

役割span 内の量子ビットの局所的な混合状態 ρ = Trrest(|ψ⟩⟨ψ|) を可視化する表示ブロック (状態に影響しない)。純粋状態 / 混合状態の判別と、span 内外の entanglement の有無を 1 つの widget で読める点が振幅表示ブロックとの差。Quirk の Density Matrix Display と同じ意味

matrix 寸法n × n (n = 2span)、row / col とも binary big-endian (row 0 = |0…0⟩、col 0 = ⟨0…0|)。ρii が対角 = 確率、ρij (i ≠ j) が非対角 = coupling
計算内容span に対応する subspace の縮約密度行列を control 条件で射影して表示する。計算経路の詳細は 実装仕様で扱う

measure columnQuirk と同じく、列処理の後に display capture。span 内に measured wire を含む列では、measure された量子ビットの非対角成分が 0 に潰される (Quirk の decohereMeasuredBitsInDensityMatrix と同じ挙動)。詳細は § 06 参照

§ 06 セル描画モデル (全セル統一、対角は needle のみ省略)

Quirk の paintDensityMatrix (src/draw/MathPainter.js) を Flexoki + 振幅表示ブロックの視覚言語へ移植する。 対角 / 非対角ともに同じ「outline 円 + magnitude disk」レイヤで描き、対角だけ needle を省くのがポイント。これにより:

  • 対角セル ρii = 実数の確率 P(|i⟩) ∈ [0, 1]。 outline 円 + magnitude disk の 2 層で描く。 disk 半径 = ρii × inner_radius (= P × inner_radius)、半径ゼロ (P = 0) なら disk を描かない。 needle は描かない: 対角は常に実数 (位相 0) なので needle が真上を向くだけになり情報量を持たず、視覚的ノイズになる。Quirk の Probability square (下から上に伸びる塗りバー) は採用せず、非対角と同じ disk 表現で統一する (対角セルだけは確率の値を disk の半径として読む)。
  • 非対角セル ρij (i ≠ j) = 複素数の coupling。 振幅表示ブロックと同じ outline 円 + magnitude disk + disk 境界線 + phase needle の 4 層で描く。 mag = |ρij|、phase = arg(ρij)。 disk 半径 = mag × inner_radius、needle 方向 = (−sin(phase), −cos(phase)) で真上が phase 0。 境界線 / 配色は振幅表示ブロックの規約に従う (amplitude-display.html § 06 と完全共有)。
  • Hermitian 性 — 密度行列は ρij = conj(ρji) なので、上三角と下三角は位相が反転した対称。表示としても自動的に左下と右上の needle が鏡像になるため、ユーザーは行列の片側を読むだけで全体が読める (Quirk と同じ視覚言語)。対角は実数 (虚部 0) なので Hermitian 性も自動的に満たされる。

対角と非対角のスケール差: 対角セルは確率 ρii ∈ [0, 1]、非対角セルは結合 |ρij| ≤ √(ρiiρjj) ≤ 0.5 を半径として描く。 同じ disk 表現に統一すると、振幅表示ブロック / 状態ベクトルパネルと読み方を共有できる一方で、対角セルの disk が視覚的に大きくなりやすい。 本仕様ではこのトレードオフを受け入れ、対角 = disk のみ、非対角 = disk + needle の違いで意味を分ける。

(1) back fill — セル背景。通常時は bg (#FFFCF0)。drag preview 中は matrix 外周のみ purple-600 に差し替え、内部の cell 描画 (outline / disk / needle) は通常時のまま
(2) outline 円 (全セル) — セル中央、半径 = cellPx/2 − stroke/2 − 1.5 px。stroke は振幅表示ブロックに合わせ、cellPx ≥ 24 で 2 px、それ未満で 1 px。円周 stroke の外端をセル境界から 1.5 px 内側に置き、matrix 外枠と重ならない範囲で最大化する。描画条件: cellPx ≥ 3。mag > 1e-6 なら tx-2、≈ 0 なら ui-2。cell hover 時は outline 円を purple-400 に置き換える (振幅表示ブロックと同様)
(3) magnitude disk (全セル) — 中心 = セル中心、半径 = |ρij| × inner_radius。fill = blue-200 + inset 1 px blue-400 境界線。閾値: r > 0.3 で fill、r ≥ 1.5 で stroke も追加。対角は実部 = 確率 = 半径として描かれる
(4) phase needle (非対角のみ) — セル中心から方向 (−sin(phase), −cos(phase)) へ inner_radius の線分。tx stroke。描画条件: cellPx ≥ 12 かつ i ≠ j。対角は実数で位相 0 なので常に省略
(5) 外枠 — matrix 全体の外枠だけを ui-2 1 px で描く。cell 間の縦横区切り線は描かず、振幅表示ブロックと同じ円の余白でセル境界を読ませる

Quirk との差分: Quirk は対角に塗りバー (_traceProbabilitySquare) を採用しているが、本仕様は対角も非対角と同じ disk 表現に統一する。理由は (a) 1 つの行列内に「塗りバー + 円」の 2 種類の見た目が並ぶと視線が分散する、(b) 振幅表示ブロック / 状態ベクトルパネルが既に「disk = 確率の大きさ、needle = 位相」の語彙を確立しているので、密度行列もそれに乗せたほうが学習コストが低い、(c) 対角は実数なので needle を省くだけで「確率 = 円」と「coupling = 円 + needle」の差が自然に出る。 Quirk の _traceAmplitudeLogarithmCircle (log 強調用の補助円) は disk と冗長 (disk が小さくても outline 円が常に視認できる) なので不採用。小さい coupling は magnitude disk の大きさだけで表現し、ロガリズム強調はポップオーバーの log P: ... dB 数値に集約する (§ 08)。

heatmap モード (cellPx < 3、span 7〜8)

cellPx が 3 px 未満では outline 円 / disk / needle が視覚的に潰れる。 各セルを 1 つの矩形塗りに潰し、alpha = √(|ρij|) で濃淡を出す:

  • 対角 / 非対角の区別はせず、全セルに blue-200 を √スケール alpha で塗る (Quirk の d ≤ 2 フォールバックと同じ、lightgray → blue-200 へ色のみ差し替え)
  • matrix 全体の外枠だけは ui-2 1 px で残す。cell 間 grid は描かない
  • セルホバーは引き続き有効: purple-400 2 px の正方形の枠を描く (ヒートマップでは outline 円が無いため、振幅表示ブロックの「outline 円を purple-400 で置換」ではなくセル矩形の purple の枠を採用)
  • 位相情報はヒートマップでは消える: span 7〜8 ではポップオーバーだけが phase の供給源になる (セルホバー必須)

測定済み量子ビットの見た目

span 内に測定済み wire が含まれる列では、測定済みビットが異なる (row, col) ペアの非対角成分を 0 として表示する。 視覚的には、測定済み wire 由来の非対角列 / 行が消えて、対角の塊が残る。これは「測定後の古典化された状態」と「未測定の量子重ね合わせ」の境界を hover 抜きで見分ける手がかりになる。 詳細な計算順序は 実装仕様 § 01を参照。

★ 批評 · § 06 セル描画モデル
Hermitian 性で上三角と下三角が「鏡像」になる冗長表示が情報量を 2 倍に膨らませている

本文は「Hermitian 性 → 上三角と下三角は位相が反転した対称、ユーザは片側を読むだけで全体が読める」と述べる。 これは正しいが、視覚的には全 n² セルが描かれているので情報密度に対するセル数は実質 n(n+1)/2。 span 5 で 1024 セル描いて実質 528 セル、span 8 で 65 536 セル描いて実質 32 896 セル。cellPx を 2 倍にできる空間が浪費されている。 改善案: 「下三角だけ描画し、対角と上三角を空にする (または薄く描く)」というモードを設ければ、同じ本体寸法で cellPx を ~1.4 倍にでき、span 6〜8 の視認性が劇的に上がる。Quirk は対称描画を採用しているが、qni-webgpu 独自の改善余地。

heatmap モードで位相情報が完全に消えるのに、本仕様で軽く扱われている

§ 06 のヒートマップモード説明で「位相情報はヒートマップでは消える: span 7〜8 ではポップオーバーだけが phase の供給源になる (セルホバー必須)」と 1 行で済まされているが、 これは本表示ブロックの「coherence を見る」という本来の目的が span 7〜8 で視覚的には消失することを意味する。 production 標準の描画 (span 7〜8 = heatmap) で位相が読めないなら、密度行列表示ブロックは span 6 までが事実上の上限とも言える。 改善案: (a) heatmap でも phase を hue で出す (HSV 表現、Flexoki に馴染まないが span 7+ 限定で example) / (b) span 7+ ではポップオーバー確認が必須であることを UI で明示 (本体の周囲に「Hover for phase」と注記を出す)。

operation 前後の差分表示が将来価値を持つ余地

密度行列は量子操作 (gate 適用、measurement) で どう変化するかが本質的な情報。 現状の本仕様はスナップショット (操作直後の ρ) しか描かず、ユーザは複数の widget を並べて目で diff を取る必要がある。 将来の改善余地として「直前の slot との差分モード」 (各セルに Δρij を描く)、「純粋からの距離」 (√(1 − Tr(ρ²)) を補助テキストで出す) などが考えられる。Quirk には無い機能で、qni-webgpu 独自の教育的価値を作れる。

§ 07 実行前プレースホルダ (シミュレーション未実行の状態)

回路に密度行列表示ブロックを配置しただけで、まだシミュレーション (▶ Run) を実行していない段階で表示する仮の見た目。 行列値がまだ存在しない段階でもセル領域が真っ白に抜けて見えないよう、この空白を 「実行待ちであることを伝えるプレースホルダ」 として明示的にデザインする。 振幅表示ブロック (amplitude-display.html § 02) / 確率表示ブロック (probability-display.html § 02) と同じ配色コンベンションに従う。

  • 背景 (placeholder fill) — purple-100 (#ECE1F3) の薄い紫で matrix 全体を塗る。本デザインシステムでは紫を「未確定 / 進行中」に充てており (drag preview = purple-600、ホバー枠 = purple-400)、実行前の ρ も「0 (赤系) と 1 (青系) の中間に位置する未確定な値」として同じ紫系統で表す。色相は drag/hover で使う濃い紫よりさらに淡くし、「進行中アクション」と「結果待ち静止状態」を区別する
  • cell 構造ガイド — cell 間の grid は引かない。通常時と同じく、matrix 外枠だけで表示ブロックの領域を示す
  • outline 円 / disk / needle — 描かない。ρ の値が無いので「対角の確率」も「非対角の coupling」も意味を持たない
  • 外枠 — 通常時と同じ ui-2 1 px の外枠を引く
  • ホバー / ポップオーバー — 実行前はセル単位ポップオーバーを出さない (表示すべき数値が無い)。ゲート全体のホバー枠 (purple-400 4 px) と上下リサイズハンドルは通常時と同じく出す
  • 遷移 — 現行実装は Run 結果が届いたフレームでプレースホルダ層 (薄紫背景 + 外枠) から通常の probability + disk + needle 描画へ即時に切り替える。150 ms ease-out のクロスフェードは将来の改善候補

★ 批評 · § 07 実行前プレースホルダ
amplitude/probability の placeholder と異なり「outline 円すら描かない」のは情報量を犠牲にしすぎ

本仕様の placeholder は 「背景 purple-100 + matrix 外枠」のみで、cell ガイドを描かない。 amplitude-display.html § 02 は「placeholder でも outline 円を全セルに描く」(これから何セルが並ぶかを示す)、probability-display.html § 02 は「行ガイド線を 2span − 1 本引く」(これから何行が並ぶかを示す) と決めている。 本表示ブロックだけが「matrix サイズすら placeholder で示さない」選択をしており、ユーザは Run 前に「これは 2×2 行列? 16×16 行列?」を判別できない。

本仕様は理由を「placeholder は全 span で背景の薄紫一色 + 外枠だけになる」と書くが、根拠は説明されていない。 想像できる理由は (a) 65 536 セルの outline 円を描くのは GPU 負荷が大きい、(b) cell 間の grid 線を描かない方針 (§ 05) と整合させる の 2 点だが、(a) は heatmap モード (span 7〜8) でも GPU で問題なく描画している以上説得力が弱く、(b) は cell 描画と placeholder ガイドを別 layer として扱える。 改善案: span 1〜4 (full モード) では outline 円を描く / span 5+ では空 のように cellPx 帯で判断する。これで「placeholder でも matrix のおおよその density が分かる」という情報量が span 4 までは保てる。

遷移演出が「即時切替」と書かれているのに、振幅/確率は 150 ms クロスフェード

本文に「現行実装は Run 結果が届いたフレームでプレースホルダ層から通常の描画へ即時に切り替える。150 ms ease-out のクロスフェードは将来の改善候補」と書かれている。 sibling の amplitude-display.html § 02 / probability-display.html § 02 は「150 ms ease-out クロスフェード」を採用済みで、本表示ブロックだけが即時切替と不揃い。 これは表示ブロック族のマイクロインタラクション一貫性を破る決定で、ユーザは「結果が来た瞬間」の視覚フィードバックを表示ブロックごとに別形式で受け取ることになる。 将来の改善候補として残されているが、優先度は高い (sibling と揃えるだけで unified UX になる)。

§ 08 ホバー / ポップオーバー

セルホバー時の詳細表示は、共通 ポップオーバー の吹き出し型外装を使う。 対角セルは確率、非対角セルは結合を表示し、外装・tail・影・画面端反転の規約は 密度行列表示ポップオーバー仕様を正とする。 このページではセルホバー時に本体側へ出る強調枠だけを定義する。

セルホバー時の枠

  • 行列モード — 対象セルの outline 円周を purple-400 2 px に置き換える。対角 / 非対角ともに同じ outline 円を持つので扱いが統一される。行列全体のホバー枠はセルホバー中は消す (振幅表示ブロックの方針と同じ)
  • ヒートマップモード — セルが小さすぎて outline 円が無いので、セル領域の正方形の枠を purple-400 2 px で囲む。Quirk の strokeRect ... 'orange', 2 と同じ位置で、色だけ Flexoki へ置換する

§ 09 リサイズハンドル (span 1〜8)

振幅表示ブロック / 確率表示ブロックの上下ハンドルとクロム仕様は完全に共有する (amplitude-display.html § 05 の resize handle 節 / probability-display.html § 12 参照)。 ハンドル単独の挙動だけ要点を再掲する:

  • 配置 — matrix の上下中央に 1 つずつ。top / bottom: −12 px (4 px ホバー枠 + 2 px の背景の空き + 6 px 高さ の合計 12 px 外側)
  • 幅 — JS で canvas 幅 (size_px) の 60% に動的にスケール、min 24 px (上限なし、span 8 = 432 px なら handle 幅 ≈ 259 px)
  • 初期状態 — opacity: 0、ホストホバーで奥から飛び出してくるマイクロインタラクション (フェードイン + 軽いバウンス: scale(0.7) → scale(1) in 250 ms cubic-bezier(0.34, 1.56, 0.64, 1))
  • default — cyan-400 ベース (ホバー枠 purple-400 と別色族で「リングの突起 ?」誤認を回避)
  • 個別 hover — cyan-600 + scale(1.15)、cursor は ns-resize
  • active drag — cyan-600 + scale(1.25)、固定
  • span clamp — drag の上限は span 8 (Quirk と同じ)、下限は span 1。span 1 から上方向 / span 8 から下方向にドラッグしても止まる
  • 左右ハンドルなし — width は span の関数 (56 × span − 16) なので独立した width handle は不要。高さハンドルの変更で同時に幅も変わる正方形リサイズ
★ 批評 · § 09 リサイズハンドル
span 上限 8 が「Quirk と同じ」だけで根拠が薄い (cellPx 1.69 px は本当に視認可能か)

span 上限 8 は Quirk 互換として自然だが、「視覚的に意味のある上限」とは別の問題である。 § 05 表で span 8 は cellPx = 1.69 px、ヒートマップモードで「位相情報は heatmap では消える」とまで書かれている。 位相が消えた密度行列は本表示ブロックの価値の半分を失うので、span 8 を許可する根拠はもっぱら「Quirk 互換」だけになる。 改善案: span 6 (cellPx 5.0、outline + disk が見える) を実用上限とし、span 7〜8 は「heatmap モード専用」として警告を出す。または span 8 のリサイズで widget を ~3 倍 (cellPx ~5) にスケールするオプションを用意する (本体寸法を 1080 px に伸ばすトレードオフ)。

「上下ハンドルだけ = 正方形維持」が他表示ブロックと違うハンドル動作

確率表示ブロック / 振幅表示ブロックの上下ハンドルは「span を変える = 高さだけ変える」だが、本表示ブロックは「span を変える = 高さと幅両方が変わる」(正方形維持)。 ユーザは sibling のハンドル動作を学習しているので、本表示ブロックで上下ドラッグして左右にも本体が広がるのは予想外の動きになる。 改善案: 上下ハンドルだけでなく 4 隅 (上下左右) すべてにハンドルを置く。正方形維持の制約は保ちつつ、「どの隅をつかんでもサイズが変わる」と形状が正方形だと最初から伝わる。 または現状の上下ハンドルの形を「正方形を示すアイコン (□)」に変えて、視覚的に「これは正方形リサイズ」と予告する。
