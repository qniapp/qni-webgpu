測定ゲート (Measurement)

量子ビットを Z 基底で射影測定し、結果に応じて状態ベクトルを収縮させる非ユニタリ操作。 見た目は cyan-400 のゲート本体を持たない 透明な 40 × 40 px 領域 + purple-600 のメーター。 測定後はメーターを wire と同じ ui-2 に落とし、GPU が直接描く red-600 の 0 / blue-600 の 1 だけを重ねる。

★ 批評 · 全体所見
「測定」という唯一の量子→古典変換の不可逆性が、視覚仕様で十分に強調されていない

H ページの全体所見と同じく、本仕様は Flexoki Light に厳密で、purple-600 のメーター、ui-2 への退色、 赤 / 青のディジット重ね合わせなど、寸法 / 配色 / 字形のすべてに根拠が書かれている。 特に 「未測定 = purple-600 (中間状態)」「測定後 = ui-2 (退色) + 結果ディジット (赤 / 青)」という二相モデルは、 測定が「実行された / されていない」をユーザに即座に伝える優れた構造。

一方で、測定ゲートは qni-webgpu のゲート群で唯一「量子情報 → 古典ビット」の変換を行う不可逆操作であり、 |0⟩ / |1⟩ オペレーションと同じく非ユニタリだが、 状態を破壊するのではなく 状態から情報を抜き取る点で意味論が大きく異なる。 この不可逆性 (情報を一度抜いたら、後続列で元の重ね合わせには戻せない) は、Quirk が半円の "メーター" アイコンを採用した 根本的な理由だが、本仕様ではメーターは「purple-600 で描く」という配色判断だけに集約され、 「後続列との古典 wire (二重線) 表記」「測定後の量子状態が確率分布の混合に変わったことの可視化」などの 事柄が明示的に触れられていない。

★ 批評 · Top Opportunities
影響度の大きい改善候補 (各論は本文中の批評ブロックに展開)
  1. 測定後の古典 wire (二重線) 表記の有無を仕様で確定 — 教科書 / Qiskit drawer / Quirk では測定後の wire を二重線にして「これは古典ビット」と区別するが、本仕様は wire 表記の変化に触れていない (§ 03 / § 05 参照)。
  2. 「不可逆性」が視覚的にユーザに伝わっているか — メーター色を ui-2 へ退色させる方針は良いが、「測定が起きた = 後続の重ね合わせが壊れた」ことを示す要素 (例: 後続スロットへの subtle indicator) があるかは不明 (§ 04 / § 06 参照)。
  3. § 04 状態バリアントが 4 状態 (既定 / ホバー / ドラッグ / 測定後) で過密 — H 系の 3 状態に対し、Measurement だけ data-outcome という直交軸が追加され、4 状態のキャプションも文字数が揃わない (§ 04 参照)。
  4. § 03 「wire マスク 4 px」の根拠と他ゲートとの比較 — wire を切る ad-hoc な処理だが、Spacer / Write は wire マスクを使わない。なぜ Measurement だけが必要かの言語化が薄い (§ 03 参照)。
  5. § 02 配色テーブルに「ホバー枠」が回路 / パレットで分岐するのに、その分岐が 1 行に圧縮されている — 「回路上では 2 px の線だけ。パレット上は Gate palette に従う」と備考で書き分けているが、これは |0⟩ / |1⟩ / Spacer と共通の問題で、テーブル構造を見直す価値 (§ 02 参照)。

§ 01概要 (見た目と用途)

測定ゲートは、回路の途中で量子ビットを古典ビットへ読み出す操作。コード上の識別子は GateKind::Measurement、URL 用トークンは "Measure"。H / X / Rz のような可逆な回転ではなく、 サンプル結果 0 または 1 を選び、その基底へ状態を射影して後続列へ渡す。

既定
purple-600 メーター
ホバー
purple-400 の枠
測定済み 0
ui-2 + red-600
測定済み 1
ui-2 + blue-600

パレット上と未計算の回路上では purple-600。測定結果が GPU の measurement_aux_buffer に入った後だけ、 メーターを ui-2 にして結果ディジットを強調する。

★ 批評 · § 01 概要
「測定ゲート」呼称が、量子情報理論の「ゲート (ユニタリ作用)」と用語的に衝突する

本仕様は page-title から本文まで一貫して「測定ゲート」と呼ぶが、量子情報理論において「ゲート」は通常ユニタリ作用を指し、 非ユニタリな射影測定は「測定」「観測」とは呼んでも「ゲート」とは呼ばない。 |0⟩ / |1⟩ オペレーションが「ゲート」 vs 「operation」の呼称揺れを抱えていたのと同じ問題で、 本仕様も GateKind::Measurement という型と "Measure" という URL トークン、UI 上の「測定ゲート」表記の 3 つを並べているが、 用語論的な正確さを読者に問われたときに即答できる根拠は薄い。

改善案: 本ゲートが「Quirk 互換のために慣習的に "Measurement gate" と呼ばれているが、厳密には非ユニタリ projector」であることを page-lede か § 01 冒頭で 1 文明示する。また、UI 表記としては「測定ゲート」のままでも構わないが、breadcrumb の親が 「量子ゲート」になっている点 (write0 / write1 / spacer も同じ) は、qni-webgpu の用語体系として 「量子操作」に統一するか、unitary / non-unitary を分けたカテゴリにするかを再検討したい。

本テーブルは 5 行で 3 つの直交軸 — (1) メーター色の時間的変化 (未測定 → 測定後)、 (2) 結果ディジット (0 / 1)、(3) 場所別ホバー枠 (回路 / パレット) — を縦に並べているが、 いずれも独立した軸で、現状の「用途」列に圧縮されている。 加えて「ホバー枠」行の備考に 「回路上では 2 px の線だけ。パレット上は Gate palette の共通ホバー枠に従う」と 2 種類のチョーキング (回路 / パレット) を 1 行に詰め込んでおり、h-gate.html § 02 の「ロール / 状態の軸圧縮」批評と 同じ問題を別軸で抱えている。

改善案: テーブルを 「ロール / 文脈 (回路 or パレット) / 状態 (未測定 or 測定後) / Flexoki トーン / hex / 備考」の 6 列に再構成。これで「測定後のメーターを ui-2 に退色させる」「結果 0 / 1 で色が変わる」「ホバー枠は文脈で変わる」が 交差なくソートできる。透明マーカ系ゲート (Write0 / Write1 / Spacer / Measurement) で共通の問題なので、 親仕様 transparent-marker-gates.html (仮) を作って配色テーブルの軸定義を共有するとよい。

★ 批評 · § 03 ジオメトリ
「wire マスク 4 px」が ad-hoc な根拠で、測定後の古典 wire 表記が仕様に存在しない

本仕様で「wire マスクは左右 4 px だけ広く背景でマスクする」と書かれているが、なぜ 4 px なのか、なぜ Spacer や Write は wire マスクを使わないのに Measurement は必要なのかが明示されていない。 実装側 (apps/web/src/icons/gate_glyphs.rs) では draw_meter_icon がメーター弧と針を描くため、 wire が弧の内側を通ると針と視覚干渉する。だが「なぜ 4 px なのか」(2 px や 6 px ではダメな根拠) は本仕様にない。

加えて、教科書 / Qiskit drawer / Quirk では 測定後の wire を二重線で描き、 「ここから先は古典ビット」と区別する慣習がある。これは「測定が量子 → 古典の変換である」という意味論の最も重要な視覚要素の 1 つだが、 本仕様には wire 二重線の言及がなく、§ 05 の slot-mock を見ても測定前後の wire が同じ ui-2 単線で続いている。 改善案: 「本仕様では古典 wire (二重線) を採用するかどうかを意図的に保留している」と書くか、 採用するなら本ページに wire 仕様も含めて統合する。これは wire 仕様 (もし別仕様で存在するなら) と相互参照すべき課題。

§ 04状態バリアント

測定ゲートは、本体色をドラッグ中に変えない。透明領域 + メーターという形を保ち、意味色は「未測定 purple」「測定後 red / blue」に限定する。

2 px stroke

パレットのホバーは外側 purple-400 + 内側 paper の二重枠、回路上のホバーは本体外側 4 px に置く 2 px の線だけ。 回路上で内側を塗るとコネクタや wire を消すため、透明ゲートでは線だけに統一する。

★ 批評 · § 04 状態バリアント
既定 / ホバー / ドラッグ / 測定後の 4 状態が異なる軸で並んでおり、構造が読みにくい

本章は 4 つの状態モックを横並びで見せているが、よく見ると「① 既定 ② ホバー ③ ドラッグ」は data-state 軸 (UI 操作状態)、 「④ 測定後」は data-outcome 軸 (実行結果の有無)と性質の違う 2 つの軸を 1 つのストリップに並列に並べている。 H / Rz の状態バリアントは UI 操作状態 1 軸の 3 状態だけで完結するが、Measurement だけは結果軸が加わるため、 本来は 3 × 2 = 6 マスの直交表で示すべき情報を 1 行に圧縮している。

改善案: § 04 を 2 段階に分割する — 上段「UI 操作状態 (3 状態)」、下段「実行結果 (未測定 / 0 / 1)」。 これで「④ 測定後 結果を重ねる」と書いてある現在の表記が、「未測定 / 測定後 0 / 測定後 1」と 3 つの結果として並び、 測定の不可逆性 (一度測定すると ② ホバーの紫色には戻らない) も時系列で示せる。

補足: caption 文字数も揃っておらず (「① 既定 未測定」「② ホバー 2 px stroke」「③ ドラッグ 色変化なし」「④ 測定後 結果を重ねる」)、 モック下のキャプションが 2 行 / 3 行 / 2 行 / 2 行と凹凸する。Tailwind スケール統一の本プロジェクトとしては、 caption 高さも揃えたい (例: 3 行統一)。

§ 05回路グリッド上の配置

スロット中心に 40 px のメーターを置き、wire はゲート直下だけ背景で短く切る。結果ディジットは GPU の描画コールバックで後から重ねる。

うっすら入っている縦線は説明用のスロット境界。実 UI では wire とゲートだけが見える。 測定後もゲート位置は変えず、結果だけを重ねるため、後続列との読み順が安定する。

★ 批評 · § 05 回路グリッド配置
測定後の wire 継承と後続ゲートとの関係が UI 上で見えない

slot-mock では「未測定」「測定後 0」「測定後 1」を 1 本の wire に並べているが、 測定が起きた後の後続 wire が「古典化」されているかが UI 上では一切区別されない。 既存の量子回路エディタの慣習では、測定後は wire が二重線になったり、後続のゲートが「古典制御ゲート」に 変わったりするが、本仕様は「ゲート位置は変えず、結果だけを重ねる」と書かれているだけで、 後続列の意味論がどう変わるかが触れられていない。

加えて、Quirk では測定後の量子ビットに対して X / Y / Z ゲートを置くと「古典制御による反転」として解釈される (Deferred Measurement Principle)。 qni-webgpu でも同じ意味論を取るのか、それとも測定後の wire には他のゲートを置けないのか、本仕様からは判断できない。 改善案: § 05 に 「測定後の後続列で許される操作」を 1 段落追加するか、 制御ゲート 仕様と相互参照して「測定結果は古典制御の source としてどう使われるか」を明示する。

§ 06意味論と実装契約

計算
列ごとに pZero を GPU で求め、決定論的乱数で 0 / 1 をサンプルする。
収縮
選ばれた基底へ状態を射影し、√p で再正規化して後続列へ渡す。
描画
本番経路で CPU 読み戻ししない。結果ディジットは measurement_aux_buffer.z を GPU が読む。
  • 角丸本体を持たない: 回転ゲートではなく読み取り操作なので、cyan-400 の塗りつぶしゲートと視覚的に分ける。
  • 未測定色は purple-600: 0 / 1 のどちらにも属さない中間状態として扱い、結果の赤 / 青と衝突させない。
  • 測定後メーターを中性化する: 読み取るべき情報はディジットなので、メーターは wire と同じ ui-2 へ退かせる。
  • wire を短く切る: メーターの内部を横線が通ると針と競合するため、左右 4 px だけ広く背景でマスクする。
  • span = 1 固定: 1 つの測定ゲートは 1 量子ビットだけを測定する。複数量子ビット測定は各 wire に 1 個ずつ置く。
★ 批評 · § 06 意味論と実装契約
「semantics」「GPU 描画契約」「設計判断」が 1 章に詰め込まれている

本章は semantic-grid 3 マス (計算 / 収縮 / 描画) と、設計判断リスト 5 項目を抱えているが、 「計算 (確率からのサンプル)」「収縮 (再正規化)」が量子情報の semantics、 「描画 (CPU 読み戻ししない)」「wire を短く切る」が GPU / UI 実装契約、 「角丸本体を持たない」「測定後メーターを中性化する」が視覚デザイン判断と、3 つの異なる関心事が同居している。 h-gate.html § 07 が「8 項目平等並び」を批評されたのと同型の問題。

改善案: 章を 3 つに分割するか、リスト内で (a) 量子 semantics / (b) 描画契約 (GPU-only) / (c) 視覚デザイン判断 の サブ見出しを切る。特に「本番経路で CPU 読み戻ししない」は qni-webgpu の 最重要ルール である GPU-only 原則そのもので、この一行がリスト内に紛れているのは存在感が薄い。 本章冒頭で「測定ゲートは GPU-only の代表例である」と一段昇格させて書くと、 他ゲート仕様にも波及する重要原則として扱える。

補足: semantic-grid の 3 マスは情報密度が低く、特に「収縮」マスは「選ばれた基底へ状態を射影し、√p で再正規化」と テキストだけで、ブロッホ球での図解や状態ベクトルの数式表現がない。matrix-card 形式は概念整理には良いが、 「これだけ読めば測定の semantics が分かる」レベルには到達していない。
