# X 軸検出器・Y 軸検出器

`XDetector` と `YDetector` は、Quirk と同じ ID で回路 JSON と URL に保存する標本測定の回路要素である。パレットでは Z Detect-Control-Reset の右隣に配置する。

## 測定結果と射影

制御がない場合の結果と固有状態の対応を示す。

| 検出器 | クリックなし（表示 0、固有値 +1） | クリック（表示 1、固有値 −1） |
| --- | --- | --- |
| `XDetector` | \|+⟩ = (\|0⟩ + \|1⟩)/√2 | \|−⟩ = (\|0⟩ − \|1⟩)/√2 |
| `YDetector` | \|+i⟩ = (\|0⟩ + i\|1⟩)/√2 | \|−i⟩ = (\|0⟩ − i\|1⟩)/√2 |

制御がなければ、測定後の状態は結果に対応する固有状態への射影となる。検出器は状態をリセットしない。入力がすでにその軸の固有状態なら、結果は確定し、状態は変化しない。入力が |0⟩ なら、両軸ともクリック確率は 1/2 である。

制御がなければ、X 軸は `H → Measurement → H`、Y 軸は `S† → H → Measurement → H → S` に分解できる。Measurement は既存の GPU 上の Z 軸標本測定と状態の射影を表す。Quirk は Y 軸の測定前に √X、測定後にその逆変換 √X† を適用する。本実装の分解も同じ射影を与える。S†、H の順に適用すると |−i⟩ が |1⟩ に移るため、負の Y 軸、つまり |−i⟩ でクリックする。

## 同じ列の制御

Control / Anti Control が同じ列にあるときは、「制御条件を満たす、かつ変換後の対象ビットが 1」という条件を全状態に対して測定する。クリック確率は、この条件に該当する部分空間の重みである。制御条件を満たす部分空間だけで確率を正規化する処理ではない。パリティ制御も同じ列の制御条件に含める。

クリック時は条件に該当する部分空間のみを残す。クリックしない場合はその補空間を残すため、制御条件を満たさない振幅と、制御条件を満たす変換後の対象ビット 0 の振幅とのコヒーレンスを保つ。両結果とも残った状態を正規化する。基底変換と逆変換そのものは制御を付けずに行う。

列の処理順序は、パリティ制御の基底変換と集約、検出器の基底変換、列の通常の演算と標本測定、検出器の逆変換、表示ブロックによる取得、パリティ制御の集約と基底変換の解除である。既存の Measurement は従来どおり同じ列の制御を無視する。

## GPU 実装と外部実行

確率の集計、標本抽出、射影、正規化は WebGPU の計算シェーダで行う。結果は既存の測定結果用バッファに保持し、描画シェーダが直接読み取って 0/1 を表示する。本番経路に CPU での量子状態計算や GPU から CPU への読み戻しはない。乱数は既存の Measurement と同じくゲート ID を種にするため、同じ回路の再計算では結果が再現する。

外部 Qiskit 実行でも両検出器に対応する。制御がない場合は、基底変換、Qiskit の回路途中の測定、逆変換を適用する。制御付きの場合は、対象・制御・反制御に Kraus 演算子 `{P, I-P}` を適用する。P は「すべての制御条件を満たし、変換後の対象ビットが 1」の部分空間への射影であり、Aer が試行ごとに結果を標本抽出する。対象と制御・反制御の合計は 8 量子ビット以内とする。パリティ制御との組み合わせにも対応し、パリティの集約後に検出器の基底変換を行う。集約先の 1 量子ビットも制御数に含める。

WebGPU と同じく、検出器の基底変換は Swap・通常の演算・QFT より前に、測定はそれらの後に行う。その後、検出器の逆変換、表示ブロックによる取得を行う。最終ヒストグラムは、検出器の結果ではなく回路末尾の Z 基底測定を集計する。

既存の Measurement と同様に、WebGPU と Qiskit では乱数の扱いが異なる。WebGPU はゲート ID を種にしてゲートごとに 1 回の結果を表示するが、Qiskit は試行ごとに標本抽出する。このため、外部実行の確率・密度行列・ブロッホベクトルなどの平均表示は、複数の測定結果の混合を表す。

測定変数を設定する `Measure>name` と異なり、検出器には測定変数の接尾辞を付けない。
