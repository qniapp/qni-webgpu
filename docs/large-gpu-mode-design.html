方針 — 自動切替ではなく、明示切替

Local / GPU の切替を、現在の実行形態が常に分かる場所に置く。配置は画面設計で決める。Local は手元 WebGPU の即時表示、GPU は外部 GPU への明示実行。Local は 16量子ビットで編集上限を止め、GPU の 17量子ビット以上では Local 側を選択不可にする。

Local

手元の WebGPU で即時更新

  • 16量子ビット以下で使う通常モード。
  • ドラッグやドロップの直後に再計算する。
  • 本番経路では GPU から CPU へ読み戻さない。
  • 17量子ビット目の追加は受け付けず、Local の上限を越えた状態を作らない。

明示的に
選ぶ
GPU

外部 GPU へ明示的に実行

  • 1量子ビットでも選べる。qni-gl と同じく「GPU 版として実行」を明示できる。
  • 自動再計算、ホバー中のプレビュー再計算、ドラッグ中の再計算を止める。
  • 返すのは全状態ベクトルではなく、要約、標本、指定した振幅だけにする。
2

操作感 — GPU 実行中であることを明確に見せる

GPU モードでは通信、待ち行列、回路変換、GPU 計算、結果抽出が入る。手元の WebGPU の「触るたび即時更新」と同じ見せ方にしてはいけない。小さな回路でも、GPU モードを選んだら実行ボタンを押す流れに統一する。

状態をはっきり表示する

  • Local: 16量子ビット以下を手元で即時更新。
  • Local 上限到達: 16量子ビット。17量子ビット目の追加は不可。
  • GPU: 未実行。まだ結果がない。

状態表示 — 外部 GPU では状態ベクトル画面を廃止する

筋が良いのは、17量子ビット以上では「状態ベクトルを見る画面」から「実行結果を見る画面」へ切り替えること。全確率分布のヒストグラムも 2^N 件になり得るので、既定にはしない。

廃止

全状態ベクトル表示

  • 振幅と位相を全基底状態ぶん描く表示は、32量子ビットでは意味的にも転送量的にも破綻する。
  • 「見えている範囲だけ問い合わせる」方式も、状態ベクトル画面を残す限り期待値を誤解させる。
既定

測定結果の集計

  • 試行回数を指定して実行し、出たビット列と回数だけ返す。
  • 返る行数は最大でも試行回数ぶん。4096回なら多くても 4096 行。
  • 測定ゲートがない回路では、表示用に「最後に全量子ビットを測った場合」の標本を取る。
  • 量子計算機らしい「実行結果」として自然。
補助

限定的な問い合わせ

  • 一部の量子ビットだけの周辺分布。
  • 上位 k 件の頻出ビット列。
  • 指定した状態番号の振幅、指定した観測量の期待値。
表示既定にするか理由
状態ベクトル全体しない振幅・位相が 2^N 件。転送も理解も破綻。
厳密な確率分布しない確率だけでも 2^N 件。32量子ビットなら float32 生データで 16 GiB。
試行結果から作るヒストグラムする最大行数が試行回数で抑えられる。4096回なら JSON でも数百 KiB 程度。
一部量子ビットの周辺分布する表示対象を 1〜8量子ビット程度に絞れば、2^k 件で済む。
指定した振幅任意デバッグ用途。状態番号を明示し、件数と返却サイズに上限を置く。
期待値・忠実度など任意大きな状態を返さず、少数の数値に畳み込める。

結論: 外部 GPU モードでは、下部の状態ベクトルパネルを 実行結果パネル に差し替える。既定タブは「測定ヒストグラム」。次に「周辺分布」「指定振幅」「観測量」「ログ」を置く。振幅表示は主役ではなく、上限付きの調査機能にする。

qni-gl 調査 — 取り入れる点と避ける点

取り入れる

表示中の振幅だけ要求する発想

  • 画面側は visibleQubitCircleIndices を amplitudeIndices として送る。
  • 実行サーバーは requestType=circuit/export を持つ。
  • GPU 実行は AerSimulator(method="statevector") + device="GPU" + cuStateVec_enable=True。
  • ローカル開発では qiskit-cpu-dev runner で Qiskit 経路だけ確認できる。これは WebGPU の CPU fallback ではない。
  • ABCI では Open OnDemand で GPU 資源上にアプリを起動する。
避ける

全状態ベクトルを作ってから絞り込む流れ

  • save_statevector で状態ベクトル全体を結果へ保存している。
  • dict(enumerate(amplitudes)) で全振幅を Python の辞書にしている。
  • その後に amplitudeIndices で絞り込む。32量子ビットではここで破綻する。
  • service worker が手元のシミュレータで状態ベクトルを複製する無駄もあり、qni-webgpu では禁止。
../qni-gl/backend/src/qni/qiskit_runner.py: AerSimulator の GPU 設定、save_statevector、全状態ベクトルの列挙。
../qni-gl/backend/src/qni/backend.py: _filter_amplitudes の考え方は良いが、絞り込みが遅すぎる位置にある。
../qni-gl/frontend/src/state-vector-renderer.ts: 見えている円だけを持つ表示方式は採用候補。
../qni-gl/abci_ood/*.yml: ABCI はジョブ投入 API ではなく、GPU ノード上の対話アプリ起動。

入出力仕様 — 状態そのものではなく観測した値を返す

実行形態
  - Local: 手元 WebGPU。16量子ビット以下を常時更新
  - Local 上限到達: 16量子ビット。17量子ビット目の追加は不可
  - GPU: 外部 GPU。未実行 / 再実行が必要 / 待機中 / 実行中 / 完了 / 失敗 / 中止

実行依頼
  - 回路のハッシュ
  - 量子ビット数
  - 途中停止する列（任意）
  - 直列化した回路
  - 乱数種（任意）
  - 欲しい結果の種類

返せる結果
  - 測定ヒストグラム: 試行回数を指定。返却行数は最大でも試行回数ぶん
  - 一部量子ビットの周辺分布: 対象量子ビットを指定
  - 上位 k 件のビット列: k と実行回数を指定
  - 振幅: 状態番号の一覧を指定。最大 4k〜16k 件
  - Bloch ベクトル: 対象量子ビットを指定
  - 期待値: Pauli 文字列などを指定
  - 返さないもの: 全状態ベクトル、全確率分布

実行結果
  - 実行番号
  - 実行先名（例: qiskit-aer-gpu / ABCI）
  - 経過時間
  - 返却バイト数
  - 上限で切り詰めたかどうか
  - 結果本体

実装順 — 安全な順番

順番実装検証
1Local / GPU 切替と実行モード状態を追加する。配置は UI モックで決める。外部 GPU は模擬実装だけ。単体テスト: Local / GPU の状態遷移。GPU は 1量子ビットでも選べる。
2Local では 17量子ビット目を追加できないようにし、GPU で 17量子ビット以上になったら Local を選択不可にする。GPU モードでは実行バー、再実行表示、中止ボタンを出す。Playwright: Local は 16量子ビットで止まる。17量子ビット以上の GPU 回路では Local に戻れない。
3外部 GPU 実行依頼を直列化する。全状態ベクトル要求を作れない型にする。契約テスト: 返却上限、全件返却なし。
4模擬の外部 GPU 結果表示を作る。状態ベクトルパネルを実行結果パネルへ差し替え、測定ヒストグラムを既定にする。画面スクリーンショットとラベル確認。
5実際の qiskit-aer-gpu 実行サーバーへ接続する。まず標本、集計、指定振幅だけ。小さな回路で一致確認。実行サーバー不在時のエラー確認。
6ABCI/OOD または実行サービスへ接続する。認証、進捗確認、時間切れ、中止を扱う。検証環境で疎通。CPU 代替なし。

設計規則: 実行モードはユーザーが明示的に選ぶ。Local は手元 WebGPU の即時表示、GPU は大規模実行。手元 WebGPU の本番経路は GPU 上で完結させ、外部 GPU の結果は上限付きの問い合わせとして別扱いにする。
