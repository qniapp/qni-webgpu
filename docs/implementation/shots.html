Shots 実装仕様

外部 GPU 実行（Qiskit Aer バックエンドを使う経路）の測定ショット数を usize の裸値ではなく、Shots という値オブジェクトで扱うための仕様。 バックエンドの契約と同じ「1 以上、上限以下」という不変条件を Rust 側の型へ閉じ込め、不正なショット数をネットワーク往復の前に弾く。

§ 01 背景と目的

外部 GPU 実行のペイロード生成 qiskit_run_payload / qiskit_run_payload_with_display_outputs（external-gpu-model クレート）は、測定ショット数を shots: usize で受け取り、JSON へ埋め込む。 バックエンド側（apps/qiskit-backend の contract.py）は 1 <= shots <= MAX_SHOTS（MAX_SHOTS = 100_000）を検証し、外れると ContractError にする。

つまりショット数には「1 以上、上限以下」という契約上の不変条件があるが、現状それを守るのはバックエンドだけである。 Rust 側は生の usize を渡すだけなので（呼び出し元は 1024 をハードコード）、不正なショット数はネットワークを往復してから初めて弾かれる。

Shots は「測定ショット数」だけを表す値オブジェクトにする。 範囲を生成時に検証し、上限はバックエンドの MAX_SHOTS と同期させる。 これにより、ドメイン駆動設計（DDD）の観点で重要な不変性、自己検証、等価性をショット数へ適用する。

  • ショット数は 1 以上、上限以下である（上限はバックエンドの MAX_SHOTS と同期させ、片方だけ変えない）
  • ショット数・量子ビット数・結果側の回数を同じ usize で混在させない

§ 02 ドメインモデル

型名Shots
配置先apps/web/crates/external-gpu-model/src/lib.rs。クレート公開型なので pub を維持する
意味外部 GPU 実行の測定ショット数
不変条件1 <= value <= Shots::MAX。Shots::MAX はバックエンドの MAX_SHOTS（100_000）と同じ値
既定値Shots::DEFAULT = 1024（現在のハードコード値）
保持する値NonZeroUsize。フィールドは非公開にする
対象範囲qiskit_run_payload / qiskit_run_payload_with_display_outputs の shots 引数、外部 GPU 実行要求を組み立てる呼び出し元
対象外量子ビット数（QubitCount）、ヒストグラムの観測回数のような結果側の数値

想定 API

#[derive(Clone, Copy, Debug, PartialEq, Eq, PartialOrd, Ord, Hash)]
pub struct Shots(NonZeroUsize);

#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum ShotsError {
    Zero,
    AboveMax { value: usize, max: usize },
}

impl Shots {
    /// バックエンドの MAX_SHOTS と同期させる上限。
    pub const MAX: usize = 100_000;
    /// 既定のショット数（現行のハードコード値）。
    pub const DEFAULT: Shots = /* Shots(1024) */;

    pub fn try_new(value: usize) -> Result<Self, ShotsError>;
    pub fn get(self) -> usize;
}

try_new は 0 を Err(ShotsError::Zero)、上限超えを Err(ShotsError::AboveMax { value, max }) で弾く。エラー設計は QubitCount の Zero / AboveCapacity に揃える。 Shots::MAX はバックエンドの MAX_SHOTS と同じ値にし、定義の近くに同期する旨をコメントで明記する。 get() はペイロード JSON へ数値を埋め込む境界だけで使う。

§ 03 DDD 上の性質

性質仕様禁止事項
不変性 生成後に内部値を変更しない。別のショット数が必要なら新しい Shots を作る 公開フィールド、&mut usize を返すメソッドを作らない
自己検証 生成時に 1 <= value <= MAX を保証する。範囲外は ShotsError にする 呼び出し側で shots の範囲チェックを重複実装しない。バックエンドだけに検証を任せない
等価性 内部のショット数値で比較する。同じ値の Shots は等しい 生成元や呼び出し文脈でショット数の等価性を判定しない
型の一貫性 ショット数を受け渡す Rust API は Shots を使う。量子ビット数や結果側の回数の usize と混在させない 新しいショット数引数を usize のまま追加しない

§ 04 組み込み方

ペイロード生成

qiskit_run_payload と qiskit_run_payload_with_display_outputs の shots: usize 引数を shots: Shots へ変更する。 関数内では shots.get() で JSON へ数値を埋め込む。出力 JSON の形式（"shots":1024）は変えない。

呼び出し元

外部 GPU 実行要求を組み立てる app/external_gpu/app_adapter.rs のハードコード 1024 は Shots::DEFAULT にする。 将来ショット数を可変にする場合も、入口で Shots::try_new を通してから渡す。

バックエンドとの契約同期

Shots::MAX はバックエンド（apps/qiskit-backend/src/qni_qiskit_backend/contract.py の MAX_SHOTS）と同じ値にする。 Shots による検証は契約の前段チェックであり、Python 側の 1 <= shots <= MAX_SHOTS 検証はそのまま残す（境界の二重防御）。

§ 05 境界と変換規則

境界形式変換不正値の扱い
ペイロード JSON整数 "shots":Nshots.get() で数値化する値オブジェクト生成済みなので追加検証は不要
呼び出し元既定値またはユーザー入力既定は Shots::DEFAULT、可変入力は try_new範囲外は ShotsError
Qiskit バックエンドJSON の整数Python 側の契約検証で 1 <= shots <= MAX_SHOTS を確認する範囲外なら ContractError

公開 JSON の形式（"shots":N）は変えない。 型による保護は Rust 側の前段で効かせる。

§ 06 移行方針

  1. Shots と ShotsError を external-gpu-model クレートに追加し、Shots::MAX をバックエンドの MAX_SHOTS に合わせる
  2. qiskit_run_payload / qiskit_run_payload_with_display_outputs の shots 引数を Shots へ変更し、内部で get() を使う
  3. 呼び出し元のハードコード 1024 を Shots::DEFAULT にする
  4. ショット数を受け取るクレート公開 API に裸の usize が残っていないことを rg で確認する

後方互換の別名や古い入口は残さない。 変更後は usize 引数のままショット数を受け取る関数を新設しない。

§ 07 受け入れ条件

  1. 有効なショット数を生成できる — Shots::try_new(256).map(Shots::get) が Ok(256) になることを確認する
  2. 0 を拒否する — Shots::try_new(0) が Err(ShotsError::Zero) になることを確認する
  3. 上限超えを拒否する — Shots::try_new(Shots::MAX + 1) が Err(ShotsError::AboveMax { value: 100_001, max: 100_000 }) になることを確認する
  4. 既定値が 1024 — Shots::DEFAULT.get() が 1024 になることを確認する
  5. 等価性が値で決まる — 同じ値の Shots 同士が等しいことを確認する
  6. JSON 形式が変わらない — Shots::DEFAULT を渡したペイロードに "shots":1024 が含まれることを確認する
  7. 裸の usize ショット数が残らない — qiskit_run_payload 系がすべて Shots を受け取ることを確認する
