ColumnControls 実装仕様

1 つの回路列が持つ制御条件を、control_mask: u32 と control_value: u32 の裸の 2 値ではなく、ColumnControls という 1 つの値オブジェクトで扱うための仕様。 「どのワイヤが制御か」と「そのうち 1 を要求するのはどれか」という 2 本のビットマスクを束ね、両者の関係という不変条件を型へ閉じ込める。

§ 01 背景と目的

現行実装では、列ごとの制御条件を control_mask と control_value という 2 本の u32 ビットマスクで表し、常に対で引き回している。 control_mask は制御ワイヤ全体（Control と AntiControl の両方）のビット、control_value は値 1 を要求するワイヤ（Control のみ）のビットを表す。 AntiControl は control_mask だけ立て、control_value は立てない（simulation_plan/linearize.rs の列走査）。

この 2 本には「control_value のビットは必ず control_mask の部分集合である」という不変条件がある。 裸の u32 対では、この関係を型で保証できず、gate_params_controlled / phase_params / rx_params / ry_params / rz_params の引数順を取り違えても気付けない。 さらに、CCZ 化（制御だけの列）、SWAP 分解への制御の合流、QFT の外部制御除去といった操作が、各所のビット演算として散らばっている。

ColumnControls は「1 つの回路列の制御条件」だけを表す値オブジェクトにする。 2 本のマスクは非公開にし、生成と更新を add_control / add_anti_control などの操作へ閉じ込め、不変条件を常に満たす。 これにより、ドメイン駆動設計（DDD）の観点で重要な不変性、自己検証、等価性を制御条件へ適用する。

  • control_value のビットは常に control_mask の部分集合である
  • 制御ワイヤの追加は QubitBit 単位で行い、生のビット演算を呼び出し側へ漏らさない
  • GPU へ渡す GateParams の 2 つの u32 フィールドは、境界で ColumnControls から取り出す

想定 API

#[derive(Clone, Copy, Debug, Default, PartialEq, Eq)]
pub(crate) struct ColumnControls {
    mask: u32,
    value: u32,
}

impl ColumnControls {
    /// 制御なしの列（mask = 0, value = 0）。
    pub(crate) const NONE: Self = Self { mask: 0, value: 0 };

    /// 制御ワイヤを 1 本追加する（mask と value の両方を立てる）。
    pub(crate) fn add_control(&mut self, bit: QubitBit);
    /// 反制御ワイヤを 1 本追加する（mask のみ立てる）。
    pub(crate) fn add_anti_control(&mut self, bit: QubitBit);

    /// 指定ビットを足した新しい制御条件を返す（不変のまま 1 本追加）。
    pub(crate) fn with_control(self, bit: QubitBit) -> Self;
    /// 指定ビットを mask と value の両方から外した新しい制御条件を返す。
    pub(crate) fn without(self, bit: QubitBit) -> Self;
    /// 値 1 を要求する制御ワイヤだけを残した純制御集合（反制御を落とす）。
    /// CCZ 化で、反制御を除いた Z の制御を作るのに使う。
    pub(crate) fn controls_only(self) -> Self;
    /// 指定マスク内のビットを mask と value の両方から外す（QFT スパン内の制御除去用）。
    pub(crate) fn restricted_outside(self, span_mask: u32) -> Self;

    /// 制御が 1 本もないか（`if control_mask == 0` の置き換え）。
    pub(crate) fn is_uncontrolled(self) -> bool;
    /// 値 1 を要求する制御ワイヤの本数（CCZ 化の 2 本以上判定用）。
    pub(crate) fn control_count(self) -> u32;
    /// 値 1 を要求する制御ワイヤのうち最上位のビット（CCZ の Z 対象選択用）。
    pub(crate) fn highest_control(self) -> Option<QubitBit>;

    /// GPU 境界（GateParams / SimulationOp）へ渡す生の値。
    pub(crate) fn mask(self) -> u32;
    pub(crate) fn value(self) -> u32;
}

生のビット演算（1u32 << bit、|=、& !）は ColumnControls の内部だけに閉じ込め、呼び出し側へ漏らさない。 mask() / value() は GateParams 生成や SimulationOp への格納など、GPU 境界へ出る直前だけで使う。

§ 03 DDD 上の性質

性質仕様禁止事項
不変性 列走査で値を組み立てる間は add_control / add_anti_control で更新し、確定後は変更しない。SWAP・CCZ・QFT の派生は with_control / without / restricted_outside で新しい値を計算する 公開フィールド、&mut u32 を返すメソッド、内部の 2 本を個別に書き換える API を作らない
自己検証 すべての操作は value & !mask == 0 を保つ。add_anti_control は mask のみ、add_control は両方を立てる 呼び出し側で value だけを単独で立てない。mask を外すときに value を残さない
等価性 2 本のマスクの値で比較する。同じ mask / value を持つ ColumnControls 同士は、どの列で生成されたかに関わらず等しい 列番号やゲート ID、生成順で制御条件の等価性を判定しない
型の一貫性 制御条件を受け渡す Rust ドメイン API は ColumnControls を 1 引数で使う。control_mask / control_value を 2 引数で並べない 新しい制御条件引数を (u32, u32) や 2 本の u32 のまま追加しない

§ 04 組み込み方

列走査での組み立て

simulation_plan/linearize.rs の列走査では、control_mask / control_value という 2 本のローカル変数を ColumnControls 1 本に置き換える。 GateKind::Control は add_control(bit)、GateKind::AntiControl は add_anti_control(bit) を呼ぶ。 bit は QubitBit として求める（wire からの変換は WireIndex / QubitBit 側に閉じる）。

ゲート行列の構築

gate_params_controlled / phase_params / rx_params / ry_params / rz_params は、control_mask: u32, control_value: u32 の 2 引数を controls: ColumnControls の 1 引数へ変更する。 関数内では controls.mask() / controls.value() で GateParams の u32 フィールドへ書き込む。 制御なしと制御ありで分岐していた if control_mask == 0 は controls.is_uncontrolled() にする。

SWAP 分解と CCZ 化

SWAP3 段の CNOT へ列の制御を合流させる。controls.with_control(swap_partner_bit) で各 CNOT の制御を作る
CCZ 化controls.control_count() >= 2 で多重制御 Z を出す条件を判定する。Z の対象ビットは controls.highest_control() で選び、controls.controls_only().without(target) で反制御を落としつつ対象を除いた制御を作る（反制御ビットは Z の制御に含めない）

QFT への制御の引き回し

qft_external_controls は QFT スパン内のワイヤに付いた制御を除いた外部制御を返す。 controls.restricted_outside(qft_span_mask) でスパン内ビットを除外する。 QFT 内部の制御位相回転では、外部制御に内部制御ビットを足すため external.with_control(qft_control_bit) を使う。

表示ブロックの捕捉

SimulationOp::CaptureBloch / CaptureProbability / CaptureAmplitude / CaptureDensity が持つ control_mask / control_value の 2 フィールドは、controls: ColumnControls の 1 フィールドへ変更する。 これらの表示ブロックは列の制御を受けて条件付きで状態を捕捉するため、組み立て済みの ColumnControls をそのまま持たせる。

§ 05 境界と変換規則

境界形式変換
GPU（GateParams）#[repr(C)] の control_mask: u32 / control_value: u32WGSL シェーダの入力レイアウトは変えない。ColumnControls から mask() / value() で取り出して詰める
SimulationOpディスパッチ用の中間表現表示ブロック系のバリアントは ColumnControls を保持し、GPU ディスパッチ直前に mask() / value() を読む
URL / 外部 GPU JSON制御は "•" / "◦" のトークンとして列内に並ぶ制御条件はビットマスクとしては直列化しない。ColumnControls は実行計画の内部表現にとどめる

GateParams は GPU へ渡す #[repr(C)] の固定レイアウトなので、内部の u32 フィールド自体は変えない。 型による保護は実行計画を組み立てる Rust ドメイン層の中で効かせ、GPU 境界では mask() / value() という明示的な取り出し点を置く。

§ 06 移行方針

  1. ColumnControls を apps/web/src/gates/controls.rs に追加し、gates から再公開する
  2. gate_params_controlled / phase_params / rx_params / ry_params / rz_params の control_mask, control_value 引数を controls: ColumnControls へまとめる
  3. linearize.rs の列走査ローカル変数 control_mask / control_value を ColumnControls へ置き換え、Control / AntiControl の処理を add_control / add_anti_control にする
  4. SWAP 分解、CCZ 化、QFT への制御の引き回しのビット演算を with_control / without / controls_only / restricted_outside / highest_control / control_count へ移す
  5. SimulationOp の表示ブロック系バリアントの 2 フィールドを controls: ColumnControls へ変更し、GPU ディスパッチ側を mask() / value() 経由にする
  6. 制御条件を受け取る Rust ドメイン API に control_mask / control_value の 2 引数や裸の u32 対が残っていないことを rg で確認する

後方互換の別名や古い 2 引数版は残さない。 変更後は (control_mask, control_value) の対で制御条件を受け取る関数を新設しない。

§ 07 受け入れ条件

  1. 制御なしを表せる — ColumnControls::NONE が is_uncontrolled() で真になることを確認する
  2. 制御がマスクと値の両方を立てる — 空の制御条件へ add_control(bit) した結果の mask() と value() が同じビットになることを確認する
  3. 反制御がマスクのみを立てる — 空の制御条件へ add_anti_control(bit) した結果の value() が 0 で mask() にビットが立つことを確認する
  4. 不変条件を保つ — 任意の操作後に value() & !mask() == 0 が成り立つことを確認する
  5. 制御本数を数えられる — 制御 2 本を足した制御条件の control_count() が 2 になることを確認する
  6. 最上位の制御を選べる — 複数の制御を足した制御条件の highest_control() が最上位ビットを返すことを確認する
  7. スパン内の制御を除外できる — restricted_outside(span_mask) がスパン内ビットを mask と value の両方から外すことを確認する
  8. 反制御は CCZ の制御に入らない — 反制御を含む列で CCZ 化したとき、Z の制御に反制御ビットが含まれないことを確認する（既存の linearize テストを ColumnControls ベースへ移す）
  9. GPU 形式が変わらない — ColumnControls 経由で構築した GateParams の control_mask / control_value が従来と同じ値になることを確認する
  10. 裸の u32 対が残らない — gate_params_controlled / phase_params / rx_params / ry_params / rz_params と SimulationOp の表示ブロック系が ColumnControls を受け取ることを確認する
