01

コンテナと GPU 実行環境

qni-gl の Dockerfile は CUDA / cuQuantum / Qiskit Aer GPU ビルドを 1 イメージにまとめている。qni-webgpu では WebAssembly 配信と Qiskit GPU バックエンドを同じ配備単位に閉じ込める。

P0実装済み

本番 Dockerfile を追加する

CUDA ベースイメージ、Rust / Trunk / Node / Python、nginx、Qiskit Aer GPU、cuQuantum、cuTensor を含める。Web は trunk build --release の成果物だけを配信する。

完了条件: docker build と docker run --gpus all で Web UI と /health が応答する。
P0実装済み

Python 依存関係を固定する

apps/qiskit-backend に本番用の依存関係定義を置く。qiskit-gpu は device="GPU" と cuStateVec_enable=True を必須にし、失敗時に CPU へ逃がさない。

完了条件: 新規環境で依存関係を入れ直し、PYTHONPATH=apps/qiskit-backend/src python3 -m unittest discover apps/qiskit-backend/tests が通る。
P0実装済み

本番ランナーを qiskit-gpu に固定する

本番配備では mock と qiskit-cpu-dev を要求から選べないようにする。通信確認用のモック実行は開発・スモークテストだけに限定し、本番の成功判定には使わない。

完了条件: 本番設定で runner を省略しても qiskit-gpu だけが使われる。
P0実装済み

起動スクリプトを作る

コンテナ起動時に Qiskit バックエンドを本番向けに起動し、nginx を前面に出す。qni-gl の docker-entrypoint.sh 相当だが、Vite 開発サーバは使わない。

完了条件: 1 コマンドで静的 Web、/run、/health が起動する。
02

静的配信・リバースプロキシ・認証

現行 Web は既定で http://127.0.0.1:4184/run を直接呼ぶ。ABCI と Basic 認証では、Web と API を同一オリジンに寄せる構成が必要。

P0実装済み

nginx 設定を追加する

静的ファイルを配信し、/run と /health を Qiskit バックエンドへ転送する。Open OnDemand の /node/<host>/<port>/ 配下でも動くように、Trunk の公開パスと生成後の bootstrap.js の読み込みパスも検証する。

完了条件: Web UI の Run GPU が同一オリジンの /run へ要求を送る。
P0実装済み

.htpasswd 認証を環境変数で制御する

qni-gl の固定 userA/passA ではなく、環境変数またはシークレットから生成する。未設定時に認証を無効化するか、起動失敗にするかを明記する。

完了条件: 認証あり / なしの両方を curl で確認できる。
P1実装済み

バックエンド URL 注入方法を整理する

bootstrap.ts の __qniQiskitBackendUrl 初期値を配備形態に合わせる。相対パス既定にすると、認証付き配備で扱いやすい。

完了条件: 開発環境と本番環境で URL の上書き手順が分かれている。

qni-gl には abci_ood 一式がある。qni-webgpu では CUDA コンテナと WebAssembly 配信を前提に作り直す。

P0実装済み・実機未検証

manifest.yml、form.yml、submit.yml.erb、template、view.html.erb を作る。GPU 資源、ABCI グループ、コンテナイメージ、認証設定を入力できるようにする。

完了条件: ABCI の Sandbox Apps からジョブを投入し、接続リンクで Web UI が開く。
P0実装済み・実機未検証

Singularity / Apptainer 用定義を作る

Docker イメージを ABCI 上で使うための変換手順または定義ファイルを用意する。qni-gl の Node/Vite 用定義はそのまま流用しない。

完了条件: ABCI 上でイメージ作成、ジョブ起動、/health 確認まで通る。
04

外部 GPU API と qni-gl 互換の不足

qni-webgpu の外部 GPU 経路は、安全のため多くのゲートを拒否している。ABCI 本番前に、必要な互換範囲を明確にし、GPU 実行だけで実装する。

P0未着手

qni-gl 相当のゲート対応を洗い直す

qni-gl は制御付き H/Y/Z/√X/S/S†/T/T†、SWAP、測定、制御 Z、書き込みゲートを Qiskit に変換している。現行外部 GPU 経路の拒否理由と、実装優先度をゲートごとに決める。

完了条件: 対応 / 非対応 / 後回しを表にし、UI の失敗表示と一致させる。
P0未着手

測定結果の契約を決める

qni-gl は各ステップの measuredBits を返す。qni-webgpu はヒストグラムと表示ブロック結果が中心。測定ゲートを外部 GPU で使う場合の応答形式を決める。

完了条件: 測定ゲートありの API テストが追加される。
P1未着手

QASM3 書き出しの要否を決める

qni-gl は requestType=export で QASM3 を返す。qni-webgpu で UI 導線を残すなら、外部バックエンドまたは Web 側で同等機能を設計する。

完了条件: 採用 / 非採用と実装場所が決まる。
P1未着手

実行キャッシュを検討する

qni-gl の CachedQiskitRunner 相当が必要か確認する。キャッシュする場合は、回路 JSON、出力要求、shots、seed、ランナーをキーに含める。

完了条件: 採用時はキャッシュ無効化条件のテストがある。
