# 外部 GPU API 互換方針

このメモは、ABCI 配備前に qni-gl と qni-webgpu の外部 GPU API の差分を固定するためのもの。
本番経路は `qiskit-gpu` のみを許可し、CPU 代替実行は用意しない。

## ゲート対応

| 分類 | qni-webgpu の方針 | 備考 |
| --- | --- | --- |
| 単一量子ビットゲート | 対応 | `H` / `X` / `Y` / `Z` / `X^½` / `S` / `S†` / `T` / `T†` / `P` / `Rx` / `Ry` / `Rz` を Qiskit 回路へ変換する。 |
| 制御付き単一量子ビットゲート | 対応 | 制御と反制御を Qiskit の制御命令へ変換する。 |
| パリティ制御 | 対応 | `zpar` / `xpar` を可逆的に一番上の対象へ集約し、通常の制御・反制御と AND で組み合わせる。補助量子ビットは使わない。伸縮可能なブロックの範囲内のパリティ制御は除外する。操作・測定・表示値の保存後に集約を解除する。詳細は[パリティ制御の外部実行](../sample-parity.md#外部-gpu-実行-qiskit)を参照する。 |
| サンプル表示ブロック | 非対応 | 含む回路は外部 GPU 実行の開始前に拒否する。 |
| 書き込みゲート | 対応 | `\|0>` / `\|1>` と制御付き書き込みを扱う。事前の基底追跡で安全に変換できない場合は失敗させる。 |
| `Swap` | 対応 | 2 個の `Swap` を入れ替えとして扱い、制御付き `Swap` も制御付き X 分解で扱う。 |
| `QFT` / `QFT†` | 対応 | 同じ列の制御と反制御を、QFT 分解後の各操作へ外部制御として適用する。QFT の `span` 内で本体と重なる制御記号は、外部制御から除外する。 |
| 測定 | 対応 | 測定ゲートは Qiskit の古典ビット測定へ変換する。同じ列の制御は qni / WebGPU 本体と同じく無視する。WebGPU はゲート ID を種として各測定で 1 回だけ標本抽出するが、Qiskit は試行ごとに標本抽出する。外部の確率・密度行列・ブロッホベクトルは試行集団の平均になる。振幅表示だけは `save_amplitudes` が返す 1 試行分の保存振幅で、試行平均でも混合状態の振幅でもない。 |
| 測定変数・条件付きゲート | 対応 | `Measure>name` の各書き込みに専用の古典ビットを用意し、`H` / `X` / `Y` / `Z` / `X^½` / `S` / `S†` / `T` / `T†` の条件を `if_test((clbit, 1))` で実行する。量子ビットごとの古典ビットを流用しないため、再測定でも別の変数の値が変わらない。前の列までの最新の書き込みを参照し、同じ列では一番下の測定が次の列以降の値になる。未設定ならゲートを省略する。制御・反制御も条件内で適用する。測定と同様に試行ごとに分岐し、確率・密度行列・ブロッホベクトルは試行平均、振幅は 1 試行分を表示する。事後選択は分岐後の試行を選別する。変数用ビットは棄却判定にも公開ヒストグラムにも含めない。詳細は[条件付きゲート](../web.md#条件付きゲート)を参照する。 |
| X 軸検出器・Y 軸検出器 | 対応 | 制御なしは基底変換・回路途中の測定・逆変換、制御付きは Kraus 演算子 `{P, I-P}` で射影する。対象と制御・反制御の合計は 8 量子ビット以内。パリティ制御とも組み合わせられ、集約先も制御数に含める。試行ごとの標本抽出と平均表示の違いは[検出器の仕様](../axis-detectors.md#gpu-実装と外部実行)を参照する。 |
| Z Detect-Control-Reset | 対応 | 列の先頭で制御なしの Z 基底測定を行い、同じ列の操作・X 軸検出器・Y 軸検出器・条件付き表示では Control として扱う。Measurement はこの制御も無視する。表示ブロックの値を保存した後に対象をリセットし、後続の操作がなければ最終ヒストグラムの対象ビットは 0 になる。QFT の範囲が対象と重なる場合は、WebGPU の `\|0⟩` 書き込み（`Write0`）と物理的なリセットが等価にならないため拒否する。パリティ制御と組み合わせる場合は、Z 基底測定を集約前、リセットを表示値の保存後かつ集約解除前に行う。Measurement と同様に、WebGPU はゲート ID を種にしてゲートごとに 1 回だけ標本抽出するが、Qiskit は試行ごとに標本抽出する。このため外部実行の確率・密度行列・ブロッホベクトルの平均表示は複数の測定結果の混合を表す。 |
| 事後選択 | 対応 | `\|0⟩⟨0\|` / `\|1⟩⟨1\|` / `\|+⟩⟨+\|` / `\|-⟩⟨-\|` ごとに、棄却条件を補助量子ビットへ書き込んで専用の古典ビットへ測定し、結果 0 の試行だけを残す。対象は測定しないため、制御条件を満たさない分岐のコヒーレンスを保つ。表示ブロックはその列までの事後選択をすべて通過した試行でだけ保存する。生存率は返さない。有限試行数による取りこぼしや `1e-12` の閾値との違いは[事後選択の仕様](../postselection.md#外部-qiskit-実行)を参照する。 |
| 表示ブロック | 対応 | Bloch / Probability / Amplitude / Density Matrix は同じ列の制御・反制御とパリティの集約先を条件付き表示の `control_mask` / `control_value` として出力要求へ渡す。Bloch は対象と制御の合計を 8 ビット以内、Probability は保存対象の span と表示外制御の合計を 16 ビット以内、Density Matrix は保存対象の span と表示外制御の合計を 8 ビット以内に制限する。 |
| 全状態ベクトル / 全確率分布 | 非対応 | 大きな GPU 結果を本番経路で返さない。表示ブロック単位の有界な結果だけを返す。 |

## 測定結果の契約

qni-gl の `measuredBits` は採用しない。qni-webgpu の外部 GPU API は、量子結果として以下を返す。
`status` / `runner` / `qubits` / `shots` / `truncated` などのメタデータは従来どおり返す。

- `histogram`: shots 全体の測定結果。事後選択を含む回路では、すべての事後選択を通過した試行だけを数える。このとき `shots` は試行した回数のままで、ヒストグラムの合計は残った試行数 (0 もありうる) になる。事後選択用・測定変数用の古典ビットはビット列に含めず、同じ公開ビット列の件数を合算する。
- `amplitudes` / `bloch` / `probability` / `densities`: 表示ブロック単位の有界な結果。残った試行が 1 回も保存に到達しなかった表示ブロックには `defined: false` を付ける。

測定ゲートを含む回路でも、段階ごとの測定ビット列は返さない。
UI が必要とする量子結果はヒストグラムと表示ブロック結果で足りるため、`measuredBits` 互換は初期 ABCI 対応の範囲外とする。

## QASM3 書き出し

qni-gl の `requestType=export` に相当する QASM3 書き出しは、ABCI 初期対応では採用しない。
理由は次のとおり。

- 現行 UI に QASM3 書き出し導線がない。
- 本番配備の主目的は `Run GPU` の実行と表示ブロック結果の返却である。
- QASM3 は実行結果ではなく成果物出力であり、GPU 実行経路とは別の設計として扱う方が安全。

将来採用する場合は、外部 GPU 実行 API ではなく、別の明示的な書き出し API または Web 側の保存機能として設計する。

## 実行キャッシュ

qni-gl の `CachedQiskitRunner` 相当は、ABCI 初期対応では採用しない。
サーバはステートレスに保ち、同じ要求でも毎回 Qiskit Aer GPU を実行する。

採用しない理由は次のとおり。

- キャッシュキーに回路 JSON、出力要求、shots、seed、ランナー、Qiskit / CUDA 版を含める必要があり、運用上の不整合が起きやすい。
- 表示ブロック結果は有界な出力に絞っており、まずは正しさと失敗時の切り分けを優先する。
- ABCI のジョブ実行では、複数利用者間で結果を共有しない方が安全。

将来採用する場合は、明示的な無効化条件とキャッシュ命中 / 不命中のログを先に追加する。
