ProbabilityDistribution 実装仕様

外部 GPU 実行（Qiskit Aer バックエンドを使う経路）から受け取る測定確率分布を、裸の Arc<[f32]> ではなく ProbabilityDistribution という値オブジェクトで扱うための仕様。 「長さが 2 のべき乗・GPU バッファ枠以下・各要素が有限かつ単位区間内」という不変条件を JSON 取り込みの境界で一度だけ検証して閉じ込め、不正な確率配列が GPU バッファへ書き込まれるのを防ぐ。

§ 01 背景と目的

外部 GPU 実行では、Qiskit が算出した測定確率分布が JSON で返り、parse_probability_upload_batch_impl（apps/web/src/app/external_gpu/probability.rs）が各測定結果の確率を f64 から f32 へ変換して Arc<[f32]> に詰める。 この配列は ExternalProbabilityUpload に保持され、probability_display.rs で bytemuck::cast_slice により GPU の確率バッファへ転送される。

従来この配列は裸の Arc<[f32]> で、確率分布としての妥当性が型にも実行時にも保証されていなかった。 具体的には、NaN・±Inf・負値・1 超過の要素や、想定外の長さ（2 のべき乗でない、または GPU バッファの 1 スロット枠を超える長さ）がそのまま GPU バッファへ流れ込みうる状態だった。 長さの一部（2^span 個ちょうど取り込む）はパース側で守られていたが、要素の値域はまったく検証されていなかった。

ProbabilityDistribution は「外部 GPU から受け取る 1 スロット分の測定確率分布」だけを表す値オブジェクトにする。 不変条件を生成時に検証し、確率の値が GPU バッファへ届く前に不正を弾く。 これにより、ドメイン駆動設計（DDD）の観点で重要な不変性・自己検証・等価性を確率分布へ適用する。

  • 確率分布の長さは 2 のべき乗（2^span）で、GPU バッファの 1 スロット枠（MAX_PROBABILITY_OUTCOMES）以下である
  • 各要素は有限で、丸め誤差を考慮した単位区間内（おおむね 0.0..=1.0）にある
  • 確率分布の配列を、スロット番号・観測結果インデックス・要素数などの裸の数値と混在させない

§ 02 ドメインモデル

型名ProbabilityDistribution
配置先apps/web/src/gpu/probability_distribution.rs。クレート内型なので pub(crate) を維持する
意味外部 GPU（Qiskit）から受け取る、確率表示スロット 1 つ分の測定確率分布
不変条件空でない / 長さが 2 のべき乗 / 長さが MAX_PROBABILITY_OUTCOMES 以下 / 各要素が有限かつ -UNIT_TOLERANCE ..= 1.0 + UNIT_TOLERANCE の範囲内
保持する値Arc<[f32]>。フィールドは非公開にする
許容誤差UNIT_TOLERANCE = 1e-3。f64 から f32 への変換やバックエンドの丸めで生じる微小な逸脱（例: 1.0000001）を弾かないための余裕
対象範囲ExternalProbabilityUpload.probabilities のフィールド型、JSON 取り込みの生成点、GPU 書き込みの消費点
対象外確率表示ブロックの種別（GateKind::ProbabilityDisplay）、スロット番号（SlotIndex<Probability>）、span や表示個数、GPU バッファ上の f32（Rust の型が届かない）

実装 API

#[derive(Clone, Debug, PartialEq)]
pub(crate) struct ProbabilityDistribution {
    values: Arc<[f32]>,
}

const UNIT_TOLERANCE: f32 = 1e-3;

#[derive(Clone, Copy, Debug, PartialEq)]
pub(crate) enum ProbabilityDistributionError {
    Empty,
    NotPowerOfTwo { len: usize },
    TooManyOutcomes { len: usize, max: usize },
    OutOfUnitRange { index: usize, value: f32 },
}

impl ProbabilityDistribution {
    pub(crate) fn try_new(values: Arc<[f32]>) -> Result<Self, ProbabilityDistributionError>;
    pub(crate) fn as_slice(&self) -> &[f32];
}

try_new は長さ（空・2 のべき乗・上限）を順に検証し、続いて各要素の有限性と値域を検証する。 長さの上限 MAX_PROBABILITY_OUTCOMES（2^16）は apps/web/src/gpu/params.rs の定数を参照し、これにより GPU 書き込み時に隣のスロットを破壊しない安全性も型で担保する。 as_slice() は GPU バッファへ書き込む境界だけで使い、bytemuck::cast_slice へそのまま渡せる生の &[f32] を返す。

§ 03 DDD 上の性質

性質仕様禁止事項
不変性 生成後に内部の配列を変更しない。別の分布が必要なら新しい ProbabilityDistribution を作る 公開フィールドや、内部配列への可変参照を返すメソッドを作らない
自己検証 生成時に長さと各要素の値域を保証する。不正は ProbabilityDistributionError にする 消費側で長さや値域のチェックを重複実装しない。外部バックエンドの応答を無検証で信頼しない
等価性 内部の確率配列の値で比較する。同じ配列を持つ ProbabilityDistribution は等しい スロット番号や生成元の文脈で分布の等価性を判定しない
型の一貫性 確率分布を受け渡す Rust API は ProbabilityDistribution を使う。スロット番号や要素数の u32 / usize と混在させない 新しい確率分布フィールドや引数を裸の Arc<[f32]> のまま追加しない

§ 04 GPU-only 制約との関係

量子状態のシミュレーション（測定確率の算出）は GPU の compute shader 側で完結させ、CPU では計算しない（GPU-only ルール）。 この値オブジェクトはそのルールに抵触しない。try_new がするのは「外部バックエンドが算出済みの数値が分布として妥当か」という入力検証であって、状態ベクトルから確率を再計算する処理ではないからである。

確率の値が CPU を通過するのは、外部 GPU 実行の結果を JSON で受け取って GPU バッファへ転送する一瞬だけである。 as_slice() が返す生の &[f32] を bytemuck::cast_slice でそのまま書き込むため、コピーを増やさず GPU バッファのレイアウトも従来どおり保たれる。

確率の値が現れる箇所本値オブジェクトの扱い
外部 GPU（Qiskit）取り込み境界対象。生成点で検証し、運搬・消費を ProbabilityDistribution で型付けする
GPU バッファ上の f32（本番描画）対象外。Rust の型が届かない。描画は shader が直接バッファを sample する
テスト専用 readback（read_probability_distributions_impl）対象外。本番では発生しない例外経路で、JS の Float32Array へ抜けるため生の &[f32] のままにする
静的パレットツールチップの |amp|²（gates/info.rs）対象外。固定振幅から描く図示用で、量子状態ではない
apps/tui の測定確率対象外。apps/web とは別の CPU シミュレータで、GPU-only ルールの管轄外

§ 05 組み込み方

生成点（JSON 取り込み）

parse_probability_upload_batch_impl は、2^span 個の確率を Vec<f32> に集めたあと ProbabilityDistribution::try_new(Arc::from(..)) で構築する。 検証に失敗した場合は .ok()? でバッチ全体を None にし、不正な確率分布を 1 スロットでも含む応答は取り込まない（この関数のほかの検証失敗と同じ扱い）。

消費点（GPU 書き込み）

ProbabilityDisplayCallback は upload.probabilities.as_slice() を bytemuck::cast_slice に渡し、GPU の確率バッファへ書き込む。 書き込みのオフセットや挙動は従来と変わらない。

運搬

ExternalProbabilityUpload.probabilities のフィールド型を Arc<[f32]> から ProbabilityDistribution へ変更する。 ExternalProbabilityUploadBatch 経由でアプリ状態へ運ぶ経路はこの型を透過的に運ぶだけで、追加の検証は不要。

§ 06 境界と変換規則

境界形式変換不正値の扱い
応答 JSONprobabilities 配列（f64 要素）f64 を f32 へ変換し try_new に通す長さ・値域違反は ProbabilityDistributionError、バッチは None
GPU バッファ書き込み連続した f32as_slice() を bytemuck::cast_slice に渡す生成済みなので追加検証は不要
テスト readbackJS の Float32ArrayGPU バッファを直接読み出す（本番外）本値オブジェクトは介在しない

公開 JSON の形式は変えない。 型による保護は Rust 側の取り込み境界で効かせる。

§ 07 移行方針

  1. ProbabilityDistribution と ProbabilityDistributionError を apps/web/src/gpu/probability_distribution.rs に追加し、gpu モジュールから再エクスポートする
  2. ExternalProbabilityUpload.probabilities を Arc<[f32]> から ProbabilityDistribution へ変更する
  3. JSON 取り込みの生成点を try_new 経由にし、失敗時は .ok()? でバッチを弾く
  4. GPU 書き込みの消費点を as_ref() から as_slice() へ変更する
  5. 確率分布を受け渡す箇所に裸の Arc<[f32]> が残っていないことを rg で確認する

後方互換の別名や古い入口は残さない。 変更後は Arc<[f32]> のまま確率分布を受け取るフィールドや関数を新設しない。

§ 08 受け入れ条件

  1. 有効な分布を生成できる — 長さ 2 の [0.25, 0.75] が Ok になることを確認する
  2. 下限の長さを受理する — 長さ 1（2^0）が Ok になることを確認する
  3. 上限の長さを受理する — ちょうど MAX_PROBABILITY_OUTCOMES 個が Ok になることを確認する
  4. 空を拒否する — 長さ 0 が Err(Empty) になることを確認する
  5. 2 のべき乗でない長さを拒否する — 長さ 3 が Err(NotPowerOfTwo) になることを確認する
  6. 上限超えを拒否する — MAX_PROBABILITY_OUTCOMES の 2 倍が Err(TooManyOutcomes) になることを確認する
  7. 非有限・範囲外を拒否する — NaN / 1.5 / -0.5 がそれぞれ Err(OutOfUnitRange) になり、報告されるインデックスが正しいことを確認する
  8. 許容誤差内を受理する — 1.0 および 0.0 をわずかに超える/下回る値が許容誤差内なら Ok になることを確認する
  9. 値を取り出せる — as_slice() が元の配列を返すことを確認する
  10. 裸の Arc<[f32]> が残らない — 確率分布の運搬がすべて ProbabilityDistribution を経ることを確認する
