QubitBit 実装仕様

GPU の量子状態計算が使うビット位置（q0=LSB、リトルエンディアン）を、u32 の裸値ではなく QubitBit という値オブジェクトで扱うための仕様。 ビット位置という意味を型へ閉じ込め、1u32 << bit のビットマスク生成を 1 か所へ集約する。

§ 01 背景と目的

現行実装では、GPU へ渡す量子ビット番号を bit / qubit_bit / base_bit / target_bit という名前の u32 で表す。 これは q0=LSB のリトルエンディアンのビット位置で、最上段ワイヤ q0 が最下位ビット（LSB）に対応する。エディタのワイヤ番号（上から下へ 0 始まり）とは一致する（Quirk と同じビット順）。 値は WireIndex からの変換、または制御マスクの最上位ビット抽出（CCZ の対象選択）、表示ブロックのスパン上端から生まれる。

ビット位置からは 1u32 << bit でビットマスクを作り、simulation_plan/linearize.rs や ColumnControls の各所で制御マスクへ合流させる。 SimulationOp には gate_id / output_slot / bit といった意味の異なる u32 が同居しており、裸の u32 では取り違えを型で防げない。 さらに 1u32 << bit が各所に散らばっている。

QubitBit は「q0=LSB のビット位置」だけを表す値オブジェクトにする。 値は非公開にし、ビットマスク生成をメソッドへ閉じ込める。 これにより、ドメイン駆動設計（DDD）の観点で重要な不変性、自己検証、等価性をビット番号へ適用する。

  • ビット位置は WireIndex::to_qubit_bit などの変換から生まれ、量子ビット数の範囲内に収まる
  • ビットマスク生成は mask() に集約し、1u32 << bit を呼び出し側へ書かない
  • ビット位置・ゲート ID・スロット番号を同じ u32 で混在させない

§ 02 ドメインモデル

型名QubitBit
配置先apps/web/src/qubit_bit.rs を新設し、lib.rs から再公開する（QubitCount と並ぶ量子ビット番号の基盤型）
意味GPU の量子状態計算が使うビット位置（q0=LSB、リトルエンディアン）。最上段ワイヤ q0 が最下位ビット（LSB）に対応する
範囲0 以上、量子ビット数未満。GPU 上限の 32 量子ビットでは 0..=31
保持する値u32。フィールドは非公開にする
生成元WireIndex::to_qubit_bit（ワイヤ番号からの恒等変換）、ColumnControls::highest_control（数値が最大の制御ビット）、表示ブロックのスパン上端（wire）
対象範囲GateParams.bit、SimulationOp の qubit_bit / base_bit、CCZ の対象ビット、QFT 展開の対象・制御ビット
対象外エディタのワイヤ番号（WireIndex）、列番号（CircuitColumnIndex）、GPU バッファのスロット番号（SlotIndex）

想定 API

#[derive(Clone, Copy, Debug, PartialEq, Eq, PartialOrd, Ord, Hash)]
#[repr(transparent)]
pub(crate) struct QubitBit {
    value: u32,
}

impl QubitBit {
    pub(crate) const fn new(value: u32) -> Self;
    pub(crate) const fn as_u32(self) -> u32;

    /// このビット位置だけを立てたビットマスク（`1u32 << bit` の集約）。
    pub(crate) fn mask(self) -> u32;
}

new(u32) は基本のコンストラクタ。QubitBit は外部入力を直接受けず生成元の変換から作られるため、WireIndex のような try_from_i64 や専用エラー型は持たない。 ビット位置が量子ビット数の範囲内（≤ 32）に収まることは生成元（WireIndex::to_qubit_bit の範囲ガード、制御マスクの最上位ビット抽出、範囲判定済みの表示ブロック）が保証し、mask() の 1u32 << value もこの範囲に依存する。 as_u32() は GateParams や SimulationOp の u32 フィールドへ詰める、GPU 境界へ出る直前だけで使う。

§ 03 DDD 上の性質

性質仕様禁止事項
不変性 生成後に内部値を変更しない。別のビット位置が必要なら新しい QubitBit を生成する 公開フィールド、&mut u32 を返すメソッドを作らない
自己検証 ビット位置が量子ビット数の範囲内であることを生成元で保証する。mask() はその範囲（< 32）に依存する 呼び出し側で 1u32 << bit を直接書かない。範囲外のビット位置で mask() を呼ばない
等価性 内部のビット位置値で比較する。同じビット位置の QubitBit は等しい ゲート ID、スロット番号、ワイヤ番号でビット位置の等価性を判定しない
型の一貫性 ビット位置を受け渡す Rust ドメイン API は QubitBit を使う。SimulationOp のビット位置フィールドと、ゲート ID・スロット番号の u32 を区別する 新しいビット位置引数やフィールドを u32 のまま追加しない

§ 04 組み込み方

ワイヤ番号からの生成

WireIndex::to_qubit_bit(qubits) は Option<QubitBit> を返す。 simulation_plan/linearize.rs と app/external_gpu/*.rs の wire as u32 は、この変換でビット位置を得る形へ統一する（WireIndex 実装仕様を参照）。

ビットマスクへの合流

1u32 << bit はすべて bit.mask() へ置き換える。 制御マスクへの合流は ColumnControls の add_control / add_anti_control / with_control が QubitBit を受け取って内部で mask() を使う。

制御マスクの最上位ビット

CCZ 化で Z の対象を選ぶビット位置（31 − control_value.leading_zeros()）は、ColumnControls::highest_control() が Option<QubitBit> で返す。 呼び出し側はこの QubitBit をそのまま対象ビットに使い、without で制御から外す。

表示ブロックのスパン上端

確率・振幅・密度行列の表示ブロックが使う base_bit は、最上段ワイヤ（wire）のビット位置で、これは表示スパンに含まれる最下位ビットに当たる。wire.to_qubit_bit(qubits) で得る。 この計算地点で QubitBit を作り、SimulationOp の base_bit フィールドへ QubitBit として持たせる。 スパンは GateSpan、ワイヤは WireIndex として別々に扱う。

§ 05 境界と変換規則

境界形式変換
GPU（GateParams）#[repr(C)] の bit: u32WGSL シェーダの入力レイアウトは変えない。QubitBit から as_u32() で詰める
SimulationOpディスパッチ用の中間表現qubit_bit / base_bit フィールドを QubitBit にし、GPU ディスパッチ直前に as_u32() を読む
WireIndexエディタのワイヤ番号WireIndex::to_qubit_bit(qubits) でビット番号（q0=LSB、恒等対応）へ変換する

GateParams は GPU へ渡す #[repr(C)] の固定レイアウトなので、内部の u32 フィールド自体は変えない。 型による保護は実行計画を組み立てる Rust ドメイン層の中で効かせ、GPU 境界では as_u32() という明示的な取り出し点を置く。

§ 06 移行方針

  1. QubitBit を apps/web/src/qubit_bit.rs に追加し、再公開する
  2. WireIndex::to_qubit_bit と ColumnControls::highest_control の戻り値を QubitBit にする
  3. 1u32 << bit の全箇所を bit.mask() へ置き換える
  4. SimulationOp の qubit_bit / base_bit フィールドと、ビット位置を渡すヘルパの引数を QubitBit へ変更する
  5. 表示ブロックのスパン上端 base_bit を QubitBit で生成する地点を 1 か所に保つ
  6. GPU ディスパッチ側（GateParams.bit への代入）だけ as_u32() を使う
  7. ビット位置を受け取る Rust ドメイン API に裸の u32 が残っていないことを rg で確認する

後方互換の別名や古い入口は残さない。 変更後は u32 のままビット位置を受け取る関数やフィールドを新設しない。

§ 07 受け入れ条件

  1. ビット位置を保持できる — QubitBit::new(2).as_u32() が 2 になることを確認する
  2. ビットマスクを生成できる — QubitBit::new(0).mask() が 0b1 に、QubitBit::new(2).mask() が 0b100 になることを確認する
  3. 等価性が値で決まる — 別々に生成した QubitBit::new(1) 同士が等しいことを確認する
  4. 異なるビット位置は等しくない — QubitBit::new(1) と QubitBit::new(2) が異なることを確認する
  5. ワイヤ番号から生成できる — 3 量子ビットで WireIndex::ZERO.to_qubit_bit(3) が QubitBit::new(0) になることを確認する
  6. GPU 形式が変わらない — QubitBit 経由で構築した GateParams.bit が従来と同じ値になることを確認する
  7. 裸の u32 ビット位置が残らない — SimulationOp の qubit_bit / base_bit と、ビット位置を渡すヘルパが QubitBit を受け取ることを確認する
