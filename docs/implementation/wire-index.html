WireIndex 実装仕様

回路エディタの量子ビットワイヤ番号を usize の裸値ではなく、WireIndex という値オブジェクトで扱うための仕様。 上から下へ 0 始まりで数えるワイヤ番号という意味を型へ閉じ込め、GPU 側のビット番号（q0=LSB、リトルエンディアン）への変換と範囲判定を 1 か所へ集約する。

§ 01 背景と目的

現行実装では PlacedGate.wire: usize を中心に、ドラッグ中のスナップ先ワイヤ、ステップ展開の対象ワイヤ、外部 GPU 経路の表示出力対象が、同じ意味のワイヤ番号として使われている。 ワイヤは画面の上から下へ 0, 1, 2, … と数える。 GPU 側の量子状態計算は最上段ワイヤ q0 を最下位ビット（LSB）とするリトルエンディアンのビット番号を使うため、ワイヤ番号とビット番号は一致する（bit = wire の恒等対応）。Quirk と同じビット順である。

この対応の範囲判定は simulation_plan/linearize.rs と app/external_gpu/*.rs に十数か所散らばっており、いずれも「wire が量子ビット数の範囲内である」という前提に依存する。 裸の usize では、ワイヤ番号と配列添字・スロット番号・ビット番号の取り違えを型で防げず、範囲判定のオフバイワン誤りも検出できない。

WireIndex は「回路エディタのワイヤ番号」だけを表す値オブジェクトにする。 値は非公開にし、ビット番号（q0=LSB）への変換と範囲判定をメソッドへ閉じ込める。 これにより、ドメイン駆動設計（DDD）の観点で重要な不変性、自己検証、等価性をワイヤ番号へ適用する。

  • ワイヤ番号は常に 0 以上の整数で、先頭ワイヤは WireIndex::ZERO で表す
  • ビット番号への変換は to_qubit_bit に集約し、範囲判定（wire < qubits）を呼び出し側へ書かない
  • ピクセル座標から暗黙にワイヤ番号を作らず、スナップ確定時に明示的に変換する

想定 API

#[derive(Clone, Copy, Debug, Default, PartialEq, Eq, PartialOrd, Ord, Hash)]
#[repr(transparent)]
pub(crate) struct WireIndex {
    value: usize,
}

#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub(crate) enum WireIndexError {
    Negative,
    Overflow,
}

impl WireIndex {
    pub(crate) const ZERO: Self = Self { value: 0 };

    pub(crate) const fn new(value: usize) -> Self;
    pub(crate) fn try_from_i64(value: i64) -> Result<Self, WireIndexError>;
    pub(crate) const fn as_usize(self) -> usize;

    /// 量子ビット数の範囲内か（`wire < qubits` ガードの置き換え）。
    pub(crate) fn is_within(self, qubits: QubitCount) -> bool;
    /// ビット番号（q0=LSB、リトルエンディアン）へ変換する。範囲外なら None。
    /// (ワイヤ番号とビット番号は一致する恒等対応。範囲判定だけをここに閉じ込める)
    pub(crate) fn to_qubit_bit(self, qubits: QubitCount) -> Option<QubitBit>;
    /// 下方向へ delta 本ずらしたワイヤ（スパン内・QFT 展開のワイヤ走査用）。
    pub(crate) fn offset(self, delta: usize) -> Self;
}

new(usize) は Rust の型がすでに 0 以上を保証するため失敗しない。 負数や対象環境の usize に収まらない整数が混ざりうる URL 復元や将来の JavaScript 連携では try_from_i64 を使う。 to_qubit_bit は範囲判定を行ってビット番号（恒等対応）を返し、結果が None のときは GPU へ出さない。 as_usize() はピクセル座標計算や配列添字など、境界層へ出る直前だけで使う。

§ 03 DDD 上の性質

性質仕様禁止事項
不変性 生成後に内部値を変更しない。ワイヤ移動は古い値を書き換えず、新しい WireIndex を計算して PlacedGate.wire へ代入する 公開フィールド、set_value、&mut usize を返すメソッドを作らない
自己検証 生成時に 0 以上かつ usize に収まることを保証する。外部入力から負数を受け取った場合は Err(WireIndexError::Negative) にする。範囲判定（wire < qubits）は is_within / to_qubit_bit に集約する 呼び出し側で wire >= qubits を重複実装しない。負数を 0 に丸めない
等価性 内部のワイヤ番号値で比較する。別々に生成した同じ番号の WireIndex は等しい ゲート ID、ピクセル座標、生成元でワイヤ番号の等価性を判定しない
型の一貫性 ワイヤ番号を受け渡す Rust ドメイン API は同じ型を使う。wire・配列添字・スロット番号・ビット番号を同じ usize で混在させない 新しいワイヤ番号引数を usize のまま追加しない

§ 04 組み込み方

配置済みゲート

PlacedGate.wire は usize から WireIndex に変更する。 PlacedGate::new のワイヤ引数も WireIndex にする。 grid_pos がピクセル座標を求めるときだけ wire.as_usize() を使う。

ビット番号への変換

simulation_plan/linearize.rs と app/external_gpu/*.rs に散らばる gate.wire as u32 は、すべて gate.wire.to_qubit_bit(qubits) へ置き換える。 to_qubit_bit は範囲判定を行ってビット番号（恒等対応）を返すため、1 量子ビットの対象ビットを求める箇所はこれ 1 つで済む。

一方、表示ブロックのように対象ビットがスパンの上端（base_bit = wire）で決まる箇所では、変換を伴わない範囲判定だけが要るので is_within を使う。 表示ブロックの収集前に置かれた if display.wire >= qubits { continue; } と、外部 GPU 経路のフィルタ gate.wire < qubits がこれに当たる。 QFT 展開でワイヤを下へ走査する gate.wire + idx は gate.wire.offset(idx) にし、その後 to_qubit_bit でビット番号へ変換する。

ドラッグとスナップ

layout/snap.rs の candidate_wire / wire_index など、ピクセル位置から求めた候補ワイヤは、スナップ先として確定する段階で WireIndex::new(index) に変換する。 LiveDragSnap::Slot.wire / LiveDragSnap::Insert.wire は WireIndex にする。

必要ワイヤ数とスパン

required_qubit_count や URL 復元では、ゲートが占めるワイヤ範囲 [wire, wire + span) の下端（wire + span）を使って必要なワイヤ数を求める。 この計算は wire.as_usize() と GateSpan を組み合わせて行い、ワイヤ番号とスパンを別々の値オブジェクトとして保つ。

§ 05 境界と変換規則

入口 / 出口形式変換不正値の扱い
URL 復元配列添字 / 行番号 usizeWireIndex::new(row)配列添字なので負数は発生しない
ピクセル座標スナップ計算の候補ワイヤ usizeスナップ確定時に WireIndex::new(index)範囲外候補はスナップ対象から除外する
GPU ビット番号QubitBit（q0=LSB、リトルエンディアン）wire.to_qubit_bit(qubits)範囲外は None。GPU へ出さない
外部 GPU 表示出力Rust の値オブジェクトJSON 生成時だけ as_usize() で数値化する値オブジェクト生成済みなので追加検証は不要

公開 JSON の形式は変えない。 型による保護は Rust ドメイン層の中で効かせ、ピクセル座標・GPU ビット番号・JSON の各境界に明示的な変換点を置く。

§ 06 移行方針

  1. WireIndex と WireIndexError を app/circuit_model/wire_index.rs に追加し、再公開する
  2. PlacedGate.wire と PlacedGate::new のワイヤ引数を WireIndex へ変更する
  3. wire as u32 の全箇所を wire.to_qubit_bit(qubits) へ、wire >= qubits / wire < qubits のガードを is_within へ置き換える
  4. ドラッグのスナップ先、挿入対象、LiveDragSnap のワイヤを WireIndex へ広げる。ピクセルから求めた候補は確定地点で変換する
  5. QFT 展開のワイヤ走査を offset ＋ to_qubit_bit に置き換える
  6. ワイヤ番号を受け取る Rust ドメイン API に裸の usize が残っていないことを rg で確認する

後方互換の別名や古い入口は残さない。 変更後は usize 引数のままワイヤ番号を受け取る関数を新設しない。

§ 07 受け入れ条件

  1. 先頭ワイヤを表せる — WireIndex::ZERO.as_usize() が 0 になることを確認する
  2. 0 以上の値を生成できる — WireIndex::new(2).as_usize() が 2 になることを確認する
  3. 負数を拒否する — WireIndex::try_from_i64(-1) が Err(WireIndexError::Negative) になることを確認する
  4. 等価性が値で決まる — 別々に生成した WireIndex::new(1) 同士が等しいことを確認する
  5. ビット番号へ変換する — 3 量子ビットで WireIndex::ZERO.to_qubit_bit(3) が最下位ビット（0）に対応することを確認する
  6. 範囲外は変換しない — WireIndex::new(3).to_qubit_bit(3) が None になることを確認する
  7. 範囲判定ができる — WireIndex::new(3).is_within(3) が false になることを確認する
  8. 下方向のずらしができる — WireIndex::ZERO.offset(2).as_usize() が 2 になることを確認する
  9. URL 復元でワイヤ番号が保存される — 2 段目のワイヤに置いたゲートの wire が WireIndex::new(1) になることを確認する
  10. 裸の usize ワイヤ引数が残らない — PlacedGate::new、grid_pos、スナップ確定、LiveDragSnap、ステップ展開、外部 GPU 経路が WireIndex を受け取ることを確認する
