GateSpan 実装仕様

ゲートが縦方向に占めるワイヤ本数（スパン）を usize の裸値ではなく、GateSpan という値オブジェクトで扱うための仕様。 「1 以上」という不変条件を型へ閉じ込め、種類別の上限とワイヤ残数で切り詰める処理を 1 か所へ集約する。

§ 01 背景と目的

現行実装では PlacedGate.span: usize で、ゲートが縦に占めるワイヤ本数を表す。 通常の 1 量子ビットゲートは常に 1。確率・振幅・密度行列の表示ブロックと QFT / QFT† は、ホバーで現れるハンドルでスパンを伸縮できる。 スパンには「1 以上」という不変条件と、種類別の上限がある（確率・振幅は 16、密度行列は 8、QFT は量子ビット数まで。GateKind::max_resizable_span）。

この切り詰めは各所に散らばっている。 simulation_plan/linearize.rs と app/external_gpu/*.rs は span.clamp(1, 16).min(qubits − wire)（密度行列は 8）と書き、エディタ側の clamp_span_to_qubit_capacity は max_resizable_span を呼ぶ。 前者（linearize.rs / external_gpu）がハードコードする 16 / 8 は、後者の max_resizable_span のロジックを暗黙に複製している。 裸の usize では、0 という不正なスパンや、上限の取り違えを型で防げない。

GateSpan は「ゲートのスパン」だけを表す値オブジェクトにする。 内部値を NonZeroUsize で持って「1 以上」を型で保証し、切り詰めを clamped_for へ集約する。 これにより、ドメイン駆動設計（DDD）の観点で重要な不変性、自己検証、等価性をスパンへ適用する。

  • スパンは常に 1 以上で、1 量子ビットゲートは GateSpan::SINGLE で表す
  • 種類別の上限とワイヤ残数による切り詰めは clamped_for に集約する
  • ピクセル幅の計算へ出る境界だけで get() を使う

想定 API

#[derive(Clone, Copy, Debug, PartialEq, Eq, PartialOrd, Ord, Hash)]
pub(crate) struct GateSpan {
    value: NonZeroUsize,
}

#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub(crate) enum GateSpanError {
    Zero,
}

impl GateSpan {
    /// 1 量子ビットゲートのスパン（= 1）。
    pub(crate) const SINGLE: Self = /* NonZeroUsize::new(1) */;

    pub(crate) fn try_new(value: usize) -> Result<Self, GateSpanError>;
    pub(crate) fn get(self) -> usize;

    /// 種類別の上限と利用可能ワイヤ数で切り詰めた新しいスパンを返す。
    /// `GateKind::max_resizable_span(available_wires)` を上限に使い、
    /// `span.clamp(1, 16).min(qubits − wire)` 系をここに集約する。
    pub(crate) fn clamped_for(self, kind: GateKind, available_wires: usize) -> Self;
}

try_new は 0 を Err(GateSpanError::Zero) で弾く。 clamped_for は種類別の上限（max_resizable_span）とワイヤ残数（利用可能ワイヤ数 available_wires）の両方を 1 回で適用し、結果は常に 1 以上になる。 ワイヤ残数は飽和減算で求め（0 以上）、ステップ展開では qubits − wire、エディタ側では capacity − wire を渡す。 get() はピクセル幅の計算や行数の算出など、境界層へ出る直前だけで使う。

§ 03 DDD 上の性質

性質仕様禁止事項
不変性 生成後に内部値を変更しない。伸縮や切り詰めは古い値を書き換えず、新しい GateSpan を計算して PlacedGate.span へ代入する 公開フィールド、&mut usize を返すメソッドを作らない
自己検証 生成時に 1 以上であることを NonZeroUsize で保証する。0 は Err(GateSpanError::Zero) にする。上限の切り詰めは clamped_for に集約する 呼び出し側で span.clamp(1, 16) や .max(1) を重複実装しない。0 を 1 へ暗黙に丸めるコードを各所に置かない
等価性 内部のスパン値で比較する。別々に生成した同じスパンの GateSpan は等しい ゲート ID やピクセル幅でスパンの等価性を判定しない
型の一貫性 スパンを受け渡す Rust ドメイン API は GateSpan を使う。ワイヤ本数・列幅・行数の usize と混在させない 新しいスパン引数を usize のまま追加しない

§ 04 組み込み方

配置済みゲート

PlacedGate.span は usize から GateSpan に変更する。 PlacedGate::new のスパン引数も GateSpan にし、1 量子ビットゲートは GateSpan::SINGLE を渡す。

切り詰めの集約

simulation_plan/linearize.rs と app/external_gpu/*.rs の span.clamp(1, 16).min(qubits − wire)（密度行列は 8）、ホバープレビューの gate.span.clamp(1, 16) は、すべて span.clamped_for(kind, qubits − wire) へ置き換える。 エディタ側の clamp_span_to_qubit_capacity は span.clamped_for(kind, capacity − wire) にする。 これで種類別の上限はすべて GateKind::max_resizable_span 1 か所に集約され、16 / 8 のハードコードが消える。

伸縮ハンドル

span_resize.rs / drag_controller/resize.rs がドラッグ量から求めた新しいスパン候補は、GateSpan::try_new(candidate) で値オブジェクトにし、clamped_for で上限へ収める。 SpanResizeDrag.start_span も GateSpan にする。

ピクセル幅と表示ブロックのスパン下端

layout/geometry.rs の gate_width_cols / gate_size / amplitude_grid_dims / amplitude_grid_rect / density_matrix_width_cols は GateSpan を受け取り、ピクセル計算の内部だけで get() を使う。 一方、ステップ展開では表示ブロックのスパン下端 base_bit = qubits − wire − span を、WireIndex と GateSpan を組み合わせて求め、結果を QubitBit として扱う。

§ 06 移行方針

  1. GateSpan と GateSpanError を apps/web/src/gates/span.rs に追加し、再公開する
  2. PlacedGate.span と PlacedGate::new のスパン引数を GateSpan へ変更し、1 量子ビットゲートは GateSpan::SINGLE にする
  3. span.clamp(1, 16).min(...) / span.clamp(1, 8).min(...) / span.max(1) / clamp_span_to_qubit_capacity の切り詰めを clamped_for へ統一する
  4. 伸縮ドラッグのスパン候補と SpanResizeDrag.start_span を GateSpan へ変更する
  5. layout/geometry.rs のスパンを取るピクセル幅関数を GateSpan 受け取りにし、内部で get() を使う
  6. スパンを受け取る Rust ドメイン API に裸の usize が残っていないことを rg で確認する

後方互換の別名や古い入口は残さない。 変更後は usize 引数のままスパンを受け取る関数を新設しない。

§ 07 受け入れ条件

  1. 1 量子ビットを表せる — GateSpan::SINGLE.get() が 1 になることを確認する
  2. 1 以上の値を生成できる — GateSpan::try_new(5).map(GateSpan::get) が Ok(5) になることを確認する
  3. 0 を拒否する — GateSpan::try_new(0) が Err(GateSpanError::Zero) になることを確認する
  4. 等価性が値で決まる — 別々に生成した GateSpan::try_new(3) 同士が等しいことを確認する
  5. 確率表示の上限は 16 — GateSpan::try_new(20) を確率表示ブロック・ワイヤ残数 32 で clamped_for した結果が 16 になることを確認する
  6. 密度行列の上限は 8 — GateSpan::try_new(20) を密度行列表示ブロック・ワイヤ残数 32 で clamped_for した結果が 8 になることを確認する
  7. ワイヤ残数で切り詰める — GateSpan::try_new(10) をワイヤ残数 3 で clamped_for した結果が 3 になることを確認する
  8. URL 復元でスパンが保存される — 5 ワイヤ分の確率表示ブロックを復元した span が GateSpan::try_new(5) になることを確認する
  9. 裸の usize スパン引数が残らない — PlacedGate::new、gate_width_cols、clamp_span_to_qubit_capacity、伸縮ドラッグ、ステップ展開が GateSpan を受け取ることを確認する
