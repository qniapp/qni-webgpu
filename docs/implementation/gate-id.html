GateId 実装仕様

配置済みゲートの同一性を表す番号を u32 の裸値ではなく、GateId という値オブジェクトで扱うための仕様。 ゲートはエンティティであり、その「どのゲートか」だけを GateId が担う。一意な採番は GateIdAllocator へ集約する。

§ 01 背景と目的

配置済みゲートは、位置・スパン・角度といった可変な属性を持つエンティティである。 これらの属性が変わってもゲートとしての同一性は保たれ、それを PlacedGate.id: u32 で識別する。 ドラッグ対象の特定、伸縮ハンドルの対応付け、角度エディタの対象、GPU の表示出力スロットの対応付けは、すべてこの番号で行う。

番号は QniApp::next_gate_id: u32 をカウンタにして採番し、URL 復元時には衝突しない次番号を引き継ぐ。 同一性の判定（gate.id == drag.id）、列内の決定的な並び替え（a.id.cmp(&b.id)）、スロット辞書の検索（gate_id をキーにした探索）に使われる。 SimulationOp や GPU 計画には gate_id / output_slot / bit といった意味の異なる u32 が同居しており、裸の u32 では取り違えを型で防げない。

GateId は「ゲートの同一性」だけを表す値オブジェクトにする。 採番は GateIdAllocator に閉じ込め、next_gate_id += 1 を各所へ書かない。 これにより、ドメイン駆動設計（DDD）の観点で、エンティティの同一性を型として明確にする。

  • ゲートの属性（位置・スパン・角度）が変わっても id は変えない
  • 採番は GateIdAllocator に集約し、同じ番号の二重発行を防ぐ
  • ゲートの同一性・スロット番号・ビット番号を同じ u32 で混在させない

§ 02 ドメインモデル

型名GateId（同一性）と GateIdAllocator（採番器）
配置先apps/web/src/app/circuit_model/gate_id.rs を新設し、circuit_model.rs と app.rs から再公開する
意味GateId は配置済みゲートの同一性。GateIdAllocator は一意な GateId を順に発行するカウンタ
保持する値GateId は u32、GateIdAllocator は次に発行する u32。いずれもフィールドは非公開にする
性質GateId は値オブジェクトとして等価性・順序・ハッシュを内部値で定める（Eq / Ord / Hash）。ゲート自体はエンティティ
対象範囲PlacedGate.id、DragState.id、SpanResizeHandle.gate_id、SpanResizeDrag.gate_id、AngleAffordance.gate_id、AngleEditor.gate_id、SimulationOp の gate_id、スロット辞書のキー、外部 GPU 経路の表示出力 gate_id
対象外GPU のビット番号（QubitBit）、スロット番号（SlotIndex）、回路ライブラリのエントリ ID（CircuitId）

想定 API

#[derive(Clone, Copy, Debug, PartialEq, Eq, PartialOrd, Ord, Hash)]
#[repr(transparent)]
pub(crate) struct GateId {
    value: u32,
}

impl GateId {
    pub(crate) const fn from_u32(value: u32) -> Self;
    pub(crate) const fn as_u32(self) -> u32;
}

#[derive(Clone, Copy, Debug)]
pub(crate) struct GateIdAllocator {
    next: u32,
}

impl GateIdAllocator {
    /// 採番の起点（現行 `next_gate_id` の初期値に合わせる）。
    pub(crate) const fn new() -> Self;
    /// 一意な GateId を 1 つ発行し、カウンタを進める。
    pub(crate) fn allocate(&mut self) -> GateId;
}

from_u32 は、URL 復元やテストで明示的に GateId を作る入口で使う。通常のゲート追加は GateIdAllocator::allocate で採番する。 Ord の導出により sort_by_key(|gate| gate.id) で列内の決定的な並び替えができ、Eq / Hash の導出によりスロット辞書のキーに使える。 as_u32() はデバッグ表示やテストの照合など、必要な境界だけで使う。

§ 03 DDD 上の性質

性質仕様禁止事項
不変性 GateId は生成後に変更しない。ゲートの属性（位置・スパン・角度）が変わっても id は変えない GateId に &mut u32 を返すメソッドや公開フィールドを作らない
自己検証 一意性は GateIdAllocator が採番時に保証する。URL 復元は順に発行し、衝突しない採番器を引き継ぐ 呼び出し側で next_gate_id += 1 を直接書かない。採番器を経由せずに同じ番号を二重発行しない
等価性 GateId の内部値で同一性を判定する。gate.id == drag.id はこの値で比較する ピクセル座標、配列位置、生成順序でゲートの同一性を判定しない
型の一貫性 ゲートの同一性を受け渡す Rust ドメイン API は GateId を使う。スロット番号・ビット番号の u32 と区別する 新しい同一性引数やフィールドを u32 のまま追加しない

§ 04 組み込み方

同一性フィールド

PlacedGate.id、DragState.id、SpanResizeHandle.gate_id、SpanResizeDrag.gate_id、AngleAffordance.gate_id、AngleEditor.gate_id、SimulationOp の gate_id、外部 GPU 経路の表示出力要求の gate_id を GateId へ変更する。 同一性の比較（gate.id == drag.id など）は導出した Eq でそのまま動く。

採番

QniApp::next_gate_id: u32 を GateIdAllocator に置き換える。 ドラッグ開始でパレットゲートを実体化する let new_id = app.next_gate_id; … app.next_gate_id += 1;（drag_controller/start.rs）は app.gate_ids.allocate() にする。

並び替えと検索

列内の決定的な並び替え sort_by(|a, b| a.id.cmp(&b.id))（linearize.rs / external_gpu/*.rs）は sort_by_key(|gate| gate.id) にできる。 position(|gate| gate.id == gate_id) の検索もそのまま GateId の比較で動く。

スロット辞書

gpu_plan_state.rs と gpu/params.rs の bloch_slot(gate_id) / measurement_slot(gate_id) / slot_for_gate(gate_id) など、gate_id をキーにスロット番号を引く辞書は、キーを GateId にする。 返り値のスロット番号は SlotIndex として別に扱う。

§ 05 境界と変換規則

境界形式変換
URL 復元解析中に順に振る番号GateIdAllocator で順に allocate() し、採番器を引き継ぐ
スロット辞書GateId をキーにした HashMap / 探索GateId の Eq / Hash をそのまま使う
デバッグ / テスト数値from_u32 / as_u32 で出入りする

ゲートの同一性番号は URL や外部 GPU JSON にはそのまま直列化しない（URL 復元時に採番し直す）。 GateId は実行時の内部識別子にとどめ、型による保護を Rust ドメイン層の中で効かせる。

§ 06 移行方針

  1. GateId と GateIdAllocator を apps/web/src/app/circuit_model/gate_id.rs に追加し、再公開する
  2. PlacedGate.id をはじめ、同一性を表すフィールドと引数をすべて GateId へ変更する
  3. QniApp::next_gate_id: u32 を gate_ids: GateIdAllocator フィールドに置き換え、採番を allocate() へ集約する
  4. URL 復元（url_circuit/decode.rs）は採番器で順に発行し、戻り値を (Vec<PlacedGate>, GateIdAllocator) にする
  5. スロット辞書のキーと、並び替え・検索を GateId ベースにする
  6. ゲートの同一性を受け取る Rust ドメイン API に裸の u32 が残っていないことを rg で確認する

後方互換の別名や古い入口は残さない。 変更後は u32 のままゲートの同一性を受け取る関数やフィールドを新設しない。

§ 07 受け入れ条件

  1. 同一性を保持できる — GateId::from_u32(3).as_u32() が 3 になることを確認する
  2. 等価性が値で決まる — 同じ番号の GateId 同士が等しく、異なる番号は等しくないことを確認する
  3. 採番が一意で単調 — 1 つの GateIdAllocator から続けて allocate() した 2 つの GateId が互いに異なることを確認する
  4. 並び替えに使える — GateId を Ord で並べたとき採番順になることを確認する
  5. 辞書キーに使える — GateId をキーにした HashMap で値を出し入れできることを確認する
  6. URL 復元で衝突しない採番を引き継ぐ — 復元したゲート群の後に allocate() した GateId が既存のどれとも重複しないことを確認する
  7. 裸の u32 同一性が残らない — PlacedGate.id、DragState.id、SimulationOp の gate_id、スロット辞書のキーが GateId を使うことを確認する
