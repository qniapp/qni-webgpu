Quirk サンプル回路の移植候補

Quirk（Craig Gidney 作の量子回路シミュレータ）の組み込みサンプル回路を qni-webgpu のサンプルへ取り込めるかを調べた結果。 どの回路がそのまま（トークンの書き換えだけで）追加でき、どれが新しいゲートを足して初めて追加できるかを、Quirk 標準の 10 サンプルについて区分する。

§ 01 背景と目的

Quirk と qni-webgpu はどちらも回路を {"cols":[[...]]} という同じ形の JSON で表す。 一見すると Quirk のサンプルをそのまま貼り付けて移植できそうだが、実際には次の 3 つの落とし穴があり、「読み込めた」ことと「意味が正しい」ことは別である。

  1. 確率表示ブロックの ID が違う。 Quirk は確率表示を Chance / Chance5 と書くが、qni は Probability / Probability5 を使う。Quirk の Chance をそのまま貼ると、qni 側では確率表示ブロックとして認識されない。
  2. デコーダは未知のトークンを読み飛ばす。 qni のデコーダ（token_to_gate）は知らないトークンに出会うと、エラーにせずそのゲートを捨てて残りを読み込む。未対応のゲートが混じっていても回路自体は開けてしまうが、捨てられたゲートのぶん意味が壊れる。忠実に移植するには、登場する全ゲートが対応済みであることが前提になる。
  3. Quirk の ~xxxx カスタムゲート。 Quirk のサンプルは ~xxxx という独自 ID のゲートを多用する。多くは恒等行列にラベルを付けただけの注釈なので削除して差し支えないが、一部（Grover の Oracle など）は実体のあるサブ回路を持つ。qni にネストした回路を 1 ゲートに畳む機能はないため、恒等ラベルは削除し、実体のあるものは中身を列として展開する必要がある。

落とし穴 2 は特に注意が要る。未対応ゲートを含む Quirk 回路を貼り付けても画面にはそれらしく描画されるため、欠落に気づきにくい。 移植時は登場トークンを 1 つずつ qni のゲート語彙（§ 02）と突き合わせる。

Quirk にあって qni に無い主な系統は次のとおり。これらを使うサンプルは新ゲートの追加が前提になる。

  • X^¼ / X^-¼ など X・Y のルート族
  • |0⟩⟨0| など — ポストセレクション（事後選択）
  • +=A / *A / *BToAmodR / inputA / setR など — 算術・モジュラー演算と入力レジスタ
  • Counting — 時間で値が進む入力レジスタ
  • e^-iYt / X^t など — 時間依存ゲート

§ 03 トークンの書き換えで吸収できる差分

Quirk と qni の差分の多くは、新しいゲートを足さずトークンを書き換えるだけで吸収できる。 次の対応で済むものは、ゲート語彙そのものは足りている。

~xxxx（恒等行列のラベル）削除不要（ユニタリは恒等のため）

位相ゲート P の行列は diag(1, e^{iθ}) で、角度パーサは任意分母の π/n を受理する（apps/web/src/gates/angle.rs で確認）。 そのため Z の高次ルート（Z^⅛ 以降）はすべて P(π/n) で表せる。Quirk の Z^t は diag(1, e^{iπt}) なので、Z^½ は位相 π/2（＝S）、Z^¼ は π/4（＝T）、Z^⅛ は π/8 に対応する。 制御位相は、同じ列の別ワイヤに • を置くだけで掛かる（制御位相は対称なので対象と制御の役割は入れ替えてよい）。

§ 04 Quirk 標準サンプルの移植判定

Quirk のメニューにある標準 10 サンプルを、追加に要する手間で 3 区分に分けた。 ~xxxx ラベルの削除と § 03 のトークン書き換えは、いずれの区分でも前提とする。

区分 A — 新ゲート不要（トークン書き換えとラベル削除のみ）

対称性の破れ（Symmetry Breaking）H • ◦ X Swap X^½ Measure ChanceChance→Probability と恒等ラベルの削除だけ。実ゲートはすべて対応済み
遅延選択量子消しゴム（Delayed Choice Eraser）H • X QFT7 Measure X^½ Chance7Chance7→Probability7 と恒等ラベルの削除。QFT も対応済み
量子テレポーテーション（Teleportation）H • X Measure Z Bloch ＋ 時間依存の状態準備送る状態を作る e^-iYt / X^t を固定の状態準備（Ry など）に置き換える。中核は対応済み

§ 05 すでに qni にあるもの

次の 2 つは、Quirk から移植するまでもなく、qni に同等のサンプルやゲートがすでにある。

Groverqni に grover-search サンプル（5 量子ビット）が実装済み。Quirk 版は拡散変換に ⊖（X 軸制御）を使うが、qni 版は H → 多重制御 X → H（多重制御 Z と等価）の形で同じ拡散を組んでいるため、⊖ なしで成立している
QFTqni はネイティブの QFT<n> ゲートを持ち、qft-4 サンプルもある。Quirk の手動 QFT は Counting と Z の高次ルートを使うが、qni のサンプルは H と制御位相回転（P(π_2) / P(π_4) / P(π_8)）、および末尾のビット反転 Swap へ分解した形で持っている。ネイティブの QFT<n> ゲートも同じ分解で展開し、末尾のビット反転 Swap で出力順を戻して真の離散フーリエ変換になる。ビット順は qni の流儀（上のワイヤが最上位ビット。Quirk は逆）なので、同じ位置にマークを置いても干渉縞の本数は Quirk と変わる（遅延選択量子消しゴムはこの差を吸収するためマーク位置を q6 にしている）

§ 06 推奨アクション

すぐ追加できる（新ゲート不要）

区分 A のうち、対称性の破れと遅延選択量子消しゴムの 2 つは、トークンの書き換えだけで忠実に追加できる。 テレポーテーション・超高密度符号化・量子加算は、入力や状態準備を固定値へ簡略化すれば追加できる。

費用対効果の高い基盤改善

デコーダ（token_to_gate）に Chance→Probability、Z^½→S、Z^¼→T、Z^⅛→P(π_8) … というデコード時のエイリアスを足すと、Quirk の URL をそのまま貼り付けて読み込めるようになる。 新しい GateKind は増やさず、トークンの対応表に行を足すだけで済む。

新ゲートの追加候補（優先順）

  1. ⊖ / ⊕（X 軸の制御）— Grover や蒸留の拡散変換を素直に書けるようになる汎用機能
  2. |0⟩⟨0| など — ポストセレクション
  3. X^¼ ほか — X・Y のルート族
  4. モジュラー算術（*BToAmodR ほか）— ショアのアルゴリズム向け。最も大きな工事
