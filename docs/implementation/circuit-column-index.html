CircuitColumnIndex 実装仕様

回路上の列番号を usize の裸値ではなく、CircuitColumnIndex という値オブジェクトで扱うための仕様。 0 始まりの列番号という不変条件を型へ閉じ込め、URL 復元、ドラッグ、描画、GPU 実行計画、外部 GPU 経路（Qiskit Aer バックエンドを使う経路）で同じ意味の値として扱う。

§ 01 背景と目的

現行実装では PlacedGate.column: usize を中心に、URL の cols 配列添字、ドラッグ中のスナップ先、ステッププレビュー、外部 GPU 経路の表示出力に含まれる column JSON 値が同じ意味の列番号として使われている。 一方で、状態表示のグリッド列、密度行列の列、CSS の列数など、同じ column / col という語を持つ別概念も多い。 裸の usize では、これらの混入を型で防げない。

CircuitColumnIndex は「回路モデル内の 0 始まり列番号」だけを表す値オブジェクトにする。 値は非公開にし、生成時に検証し、比較は値そのもので行う。 これにより、ドメイン駆動設計（DDD）の観点で重要な不変性、自己検証、等価性を列番号へ適用する。

  • 列番号は常に 0 以上の整数である
  • 最初の列は CircuitColumnIndex::ZERO で表す
  • ピクセル座標や表示グリッド列から暗黙に列番号を作らない
  • 外部境界では数値 JSON を維持し、Rust ドメイン層へ入る時点で値オブジェクトへ変換する

想定 API

#[derive(Clone, Copy, Debug, Default, PartialEq, Eq, PartialOrd, Ord, Hash)]
#[repr(transparent)]
pub(crate) struct CircuitColumnIndex {
    value: usize,
}

#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub(crate) enum CircuitColumnIndexError {
    Negative,
    Overflow,
}

impl CircuitColumnIndex {
    pub(crate) const ZERO: Self = Self { value: 0 };

    pub(crate) const fn new(value: usize) -> Self;
    pub(crate) fn try_from_i64(value: i64) -> Result<Self, CircuitColumnIndexError>;
    pub(crate) const fn as_usize(self) -> usize;

    pub(crate) fn checked_add(self, delta: usize) -> Option<Self>;
    pub(crate) fn saturating_sub(self, delta: usize) -> Self;
}

new(usize) は Rust の型がすでに 0 以上を保証しているため失敗しない。 外部入力、テスト補助、将来の JavaScript 連携など、負数や対象環境の usize に収まらない整数が混ざりうる入口では try_from_i64 を使う。 checked_add と saturating_sub は列移動で必要な場合だけ使う名前付き演算であり、暗黙の Add<usize> 実装は持たせない。 as_usize() は配列添字、JSON 生成、egui の座標計算など、境界層へ出る直前だけで使う。

§ 03 DDD 上の性質

性質仕様禁止事項
不変性 生成後に内部値を変更しない。列移動や挿入による変更は、古い値を書き換えるのではなく新しい CircuitColumnIndex を計算して PlacedGate.column へ代入する 公開フィールド、set_value、&mut usize を返すメソッドを作らない
自己検証 値オブジェクトの生成時点で 0 以上、かつ usize に収まることを保証する。外部入力から負数を受け取った場合は Err(CircuitColumnIndexError::Negative) にする Rust ドメイン層の呼び出し側で if column >= 0 を重複実装しない。JSON や TypeScript 境界の形式検証は維持する。負数を 0 に丸めない
等価性 識別子ではなく内部の列番号値で比較する。CircuitColumnIndex::new(2) 同士は同じ値であり、どこで生成されたかは等価性へ影響しない ポインタ同一性、ゲート ID、生成元、ピクセル座標で列番号の等価性を判定しない
型の一貫性 回路列番号を受け渡す Rust ドメイン API は同じ型を使う。関数ごとに usize、slot、step を混在させない 新しい回路列番号引数を usize のまま追加しない

§ 04 組み込み方

配置済みゲート

PlacedGate.column は usize から CircuitColumnIndex に変更する。 PlacedGate::new の列引数も CircuitColumnIndex にし、呼び出し側で列番号の意味を明示する。 URL 復元のように enumerate() から得た添字を使う場合は、CircuitColumnIndex::new(col_idx) で変換する。

ドラッグと挿入

LiveDragSnap::Slot.column、LiveDragSnap::Insert.column、DragState.original_column は CircuitColumnIndex にする。 insert_gate_at_column は insert_index: CircuitColumnIndex を受け取る。 SlotSnap.index や InsertSnap.index のような探索途中の配列添字は、回路列番号として確定する地点で CircuitColumnIndex へ変換する。 挿入によって後続ゲートを右へずらす場合は checked_add を使い、あふれが起きる値は受け入れない。 左へ詰める処理は現行の saturating_sub の意味を値オブジェクト側へ閉じ込める。

描画と座標計算

PlacedGate::grid_pos と gate_rect_at_grid は CircuitColumnIndex を受け取る。 ピクセル座標へ変換する箇所だけ column.as_usize() を使う。 nearest_slot_index が返す配列添字は、スナップ先として採用する段階で CircuitColumnIndex::new(index) に変換する。

URL と外部 GPU 経路

URL 復元cols.iter().enumerate() の col_idx を CircuitColumnIndex::new(col_idx) に変換して PlacedGate へ渡す
URL 生成gate.column.as_usize() で cols 配列の添字へ変換する。JSON の cols 配列形式は変えない
外部 GPU 表示出力Rust 側の ExternalAmplitudeRequest.column などは CircuitColumnIndex にし、JSON 生成時だけ数値へ戻す
Qiskit バックエンドPython 側は JSON 境界なので int のままにし、既存どおり 0 <= column < len(columns) を検証する

実行計画

ColumnAnalysis は回路列番号をキーにする経路で CircuitColumnIndex を扱う。 描画専用の配列添字を残す場合は、circuit_column と slot_index のように名前を分け、値オブジェクトへの変換点を明示する。 WebGPU へ渡すバッファ構造体には列番号を直接入れないため、シェーダや量子状態計算の経路は変更しない。

§ 05 境界と変換規則

入口入力変換不正値の扱い
URL cols配列添字 usizeCircuitColumnIndex::new(col_idx)配列添字なので負数は発生しない
MCP qni_place_gateJavaScript の number公開境界の形式検証として TypeScript 側の column >= 0 は維持する。Rust ドメインへ入れる経路ができた場合は try_from_i64 を使う負数、小数、無限大、NaN は拒否する
外部 GPU 経路の表示出力要求Rust の値オブジェクトJSON 生成時に as_usize() で数値化する値オブジェクト生成済みなので追加検証は不要
Qiskit バックエンドJSON の整数Python 側の契約検証で 0 <= column < len(columns) を確認する範囲外なら ContractError にする

値オブジェクトを導入しても、公開 JSON の形式は変えない。 {"column":1} は引き続き数値として送受信する。 型による保護は Rust ドメイン層の中で効かせ、境界層では明示的な変換点を置く。

§ 06 移行方針

  1. CircuitColumnIndex と CircuitColumnIndexError を追加する
  2. PlacedGate.column と PlacedGate::new の列引数を CircuitColumnIndex へ変更する
  3. URL 復元、テストデータ、ドラッグ開始時の既定列を CircuitColumnIndex::ZERO または CircuitColumnIndex::new(...) へ置き換える
  4. 挿入、ステッププレビュー、列解析など、回路列番号として確定した引数を CircuitColumnIndex へ広げる。探索途中の配列添字は変換点を明示する
  5. URL 生成、描画座標、配列添字、JSON 生成の境界だけ as_usize() を使う
  6. 回路列番号を受け取る公開的な Rust ドメイン API に裸の usize が残っていないことを rg で確認する

後方互換の別名や古い入口は残さない。 変更後は usize 引数のまま回路列番号を受け取る関数を新設しない。

§ 07 受け入れ条件

  1. 0 始まりを表せる — CircuitColumnIndex::ZERO.as_usize() が 0 になることを確認する
  2. 0 以上の値を生成できる — CircuitColumnIndex::new(3).as_usize() が 3 になることを確認する
  3. 負数を拒否する — CircuitColumnIndex::try_from_i64(-1) が Err(CircuitColumnIndexError::Negative) になることを確認する
  4. 等価性が値で決まる — 別々に生成した CircuitColumnIndex::new(2) 同士が等しいことを確認する
  5. 異なる列は等しくない — CircuitColumnIndex::new(1) と CircuitColumnIndex::new(2) が異なることを確認する
  6. 順序付けが列順と一致する — CircuitColumnIndex::new(1) < CircuitColumnIndex::new(2) になることを確認する
  7. あふれを検出できる — usize::MAX を保持する列へ checked_add(1) した場合に None になることを確認する
  8. 左詰め操作が 0 未満へ落ちない — CircuitColumnIndex::ZERO.saturating_sub(1) が CircuitColumnIndex::ZERO になることを確認する
  9. URL 復元で列番号が保存される — {"cols":[[1],["H"]]} を復元した H の列が CircuitColumnIndex::new(1) になることを確認する
  10. URL 生成の形式が変わらない — CircuitColumnIndex::new(1) のゲートを含む回路が従来どおり cols 配列の 2 番目に出力されることを確認する
  11. 外部 GPU JSON の形式が変わらない — 表示出力要求の column が従来どおり数値で直列化されることを確認する
  12. 裸の usize 回路列引数が残らない — PlacedGate::new、grid_pos、gate_rect_at_grid、insert_gate_at_column、shift_trailing_gates_after_width_change、ステッププレビュー状態、外部 GPU 経路の表示出力要求が CircuitColumnIndex を受け取ることを確認する
