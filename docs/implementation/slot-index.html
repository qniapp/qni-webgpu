SlotIndex 実装仕様

GPU バッファのスロット番号を u32 の裸値ではなく、家族（バッファ種別）ごとに型を分けた SlotIndex<F> という値オブジェクトで扱うための仕様。 家族の異なるスロットの取り違えと、スロット番号・ゲート ID・ビット番号の混同を型で防ぎ、家族別の採番を SlotAllocator<F> へ集約する。

§ 01 背景と目的

GPU の表示出力やステップキャッシュは、種別ごとに別々のストレージバッファを持つ。 simulation_plan/linearize.rs は、ブロッホ・測定・確率・振幅・密度行列・ステップスナップショットの 6 つの家族について、それぞれ独立したカウンタ（bloch_slot / measurement_slot / probability_slot / amplitude_slot / density_slot / next_snapshot_slot）で u32 のスロット番号を採番する。 gpu_plan_state.rs は家族ごとに HashMap<gate_id, slot>（bloch_slots など）を持ち、対応するバッファのスロットを引く。

スロット番号は家族ごとに別々のアドレス空間である。 にもかかわらず、SimulationOp には output_slot / aux_slot / gate_id / bit といった意味の異なる u32 が同居しており、裸の u32 ではブロッホスロットを測定バッファへ渡すような家族の取り違えも、スロット番号とゲート ID の混同も型で防げない。

SlotIndex<F> は「ある家族 F のスロット番号」だけを表す値オブジェクトにする。 家族はファントム型のマーカーで区別し、採番を SlotAllocator<F> に閉じ込める。 これにより、ドメイン駆動設計（DDD）の観点で、家族別のアドレス空間と採番の一意性を型として明確にする。

  • スロット番号は家族 F ごとに別の型で、家族をまたいで代入できない
  • 家族別の採番は SlotAllocator<F> に集約し、slot += 1 を各所へ書かない
  • スロット番号・ゲート ID・ビット番号を同じ u32 で混在させない

§ 02 ドメインモデル

型名SlotIndex<F>（スロット番号）と SlotAllocator<F>（家族別の採番器）
配置先apps/web/src/gpu/slot.rs を新設し、gpu から再公開する（スロットは GPU バッファを指すため）
意味家族 F のストレージバッファ内の位置。F はバッファ種別を表すマーカー
家族Snapshot / Bloch / Measurement / Probability / Amplitude / Density のゼロサイズマーカー
保持する値u32 と PhantomData<F>。値フィールドは非公開にする
対象範囲SimulationOp の output_slot / aux_slot、家族別カウンタ、gpu_plan_state.rs の家族別 HashMap の値
対象外ゲートの同一性（GateId）、GPU のビット番号（QubitBit）、量子ビット数

想定 API

use std::marker::PhantomData;

pub(crate) struct SlotIndex<F> {
    value: u32,
    _marker: PhantomData<F>,
}

pub(crate) struct SlotAllocator<F> {
    next: u32,
    _marker: PhantomData<F>,
}

impl<F> SlotIndex<F> {
    pub(crate) const fn new(value: u32) -> Self;
    pub(crate) const fn as_u32(self) -> u32;
}

impl<F> SlotAllocator<F> {
    pub(crate) const fn new() -> Self;
    /// 家族 F の一意なスロットを 1 つ発行し、カウンタを進める。
    pub(crate) fn allocate(&mut self) -> SlotIndex<F>;
}

// 家族マーカー（ゼロサイズ）。
pub(crate) enum Snapshot {}
pub(crate) enum Bloch {}
pub(crate) enum Measurement {}
pub(crate) enum Probability {}
pub(crate) enum Amplitude {}
pub(crate) enum Density {}

PhantomData<F> により F は実体を持たず、SlotIndex<Bloch> と SlotIndex<Measurement> はコンパイル時に別の型になる。 Clone / Copy / PartialEq / Eq / Hash は F に依存せず（HashMap の値・キーとして使えるように）手動実装で付ける。 as_u32() は GPU バッファの添字やシェーダへの割り当てなど、GPU 境界へ出る直前だけで使う。

§ 03 DDD 上の性質

性質仕様禁止事項
不変性 SlotIndex は生成後に変更しない。次のスロットは SlotAllocator から発行する SlotIndex に &mut u32 を返すメソッドや公開フィールドを作らない
自己検証 家族の一意性は SlotAllocator<F> が採番時に保証する。家族の取り違えはファントム型で生成時に防ぐ 呼び出し側で slot += 1 を直接書かない。SlotIndex::new で家族をまたいだ番号を作らない
等価性 同じ家族 F 内で内部のスロット番号値により比較する 家族の異なるスロットを等価比較しない（型が違うので比較できない）
型の一貫性 スロット番号を受け渡す Rust ドメイン API は SlotIndex<F> を使う。家族・ゲート ID・ビット番号の u32 を区別する 新しいスロット番号引数やフィールドを u32 のまま追加しない

§ 04 組み込み方

家族別の採番

linearize.rs の 6 つのカウンタ（bloch_slot / measurement_slot / probability_slot / amplitude_slot / density_slot / next_snapshot_slot）を、対応する SlotAllocator<F> に置き換える。 bloch_slot += 1 などの採番は allocate() にする。

ディスパッチ表現

SimulationOp の各バリアントの output_slot / aux_slot を、家族付きの SlotIndex<F> にする。 SnapshotState.output_slot は SlotIndex<Snapshot>、CaptureBloch.output_slot は SlotIndex<Bloch>、MeasureReduceSample.output_slot と MeasureCollapse.aux_slot は SlotIndex<Measurement>、確率・振幅・密度行列も同様に対応する家族にする。

スロット辞書

gpu_plan_state.rs の家族別 HashMap<gate_id, slot>（bloch_slots など）は、値を家族付きの SlotIndex<F>、キーを GateId にする。 スロットを引く bloch_slot(gate_id) などは Option<SlotIndex<Bloch>> を返す。

GPU 境界

シェーダへの割り当てやバッファ添字へ渡すときだけ as_u32() を使う。 WebGPU のバッファレイアウトとシェーダは変更しない。

§ 05 境界と変換規則

境界形式変換
GPU バッファ / シェーダバッファ添字・バインドの u32バッファレイアウトは変えない。SlotIndex から as_u32() で取り出す
SimulationOpディスパッチ用の中間表現output_slot / aux_slot を SlotIndex<F> にし、ディスパッチ直前に as_u32() を読む
スロット辞書家族別 HashMapキーを GateId、値を SlotIndex<F> にする

WebGPU のバッファレイアウトとシェーダは #[repr(C)] や WGSL の固定形式なので変えない。 型による保護は実行計画を組み立てる Rust ドメイン層の中で効かせ、GPU 境界では as_u32() という明示的な取り出し点を置く。

§ 06 移行方針

  1. SlotIndex<F> / SlotAllocator<F> と 6 つの家族マーカーを apps/web/src/gpu/slot.rs に追加し、再公開する
  2. linearize.rs の 6 つのカウンタを家族別の SlotAllocator に置き換え、採番を allocate() へ集約する
  3. SimulationOp の output_slot / aux_slot を家族付きの SlotIndex<F> へ変更する
  4. gpu_plan_state.rs の家族別 HashMap の値を SlotIndex<F>・キーを GateId にし、gpu/params.rs のスロットフィールドと slot_to_gate_id 逆引きも SlotIndex<F> にする
  5. GPU ディスパッチ側（バッファ添字・バインド）だけ as_u32() を使う
  6. スロット番号を受け取る Rust ドメイン API に裸の u32 が残っていないことを rg で確認する

後方互換の別名や古い入口は残さない。 変更後は u32 のままスロット番号を受け取る関数やフィールドを新設しない。

§ 07 受け入れ条件

  1. スロット番号を保持できる — Bloch 家族の SlotIndex を new(2) で作り as_u32() が 2 になることを確認する
  2. 家族別に採番が単調 — 1 つの SlotAllocator<Bloch> から続けて allocate() した 2 つのスロットが 0 と 1 になることを確認する
  3. 家族をまたいで代入できない — SlotIndex<Bloch> を SlotIndex<Measurement> が必要な箇所へ渡せないことを確認する（型エラー）
  4. 同じ家族内で等価性が値で決まる — 同じ家族・同じ番号の SlotIndex 同士が等しいことを確認する
  5. 辞書の値に使える — HashMap<GateId, SlotIndex<Bloch>> で値を出し入れできることを確認する
  6. 裸の u32 スロット番号が残らない — SimulationOp の output_slot / aux_slot と家族別 HashMap の値が SlotIndex<F> を使うことを確認する
