QubitCount 値オブジェクト 実装仕様

量子ビット数を生の usize / int / number で引き回す代わりに、 ドメイン駆動設計（DDD）の値オブジェクトとして扱うための実装仕様。 「1 以上であること」と「実行モードごとの上限」を型と生成境界で表し、 WebGPU 内部実行、外部 GPU 実行、Qiskit バックエンドの契約を同じ言葉でそろえる。

§ 01目的と非目的

目的

  • QubitCount は量子レジスタの量子ビット数を表す値オブジェクトであり、常に 1 以上である。
  • QubitCapacity は実行モードごとに受け入れられる最大量子ビット数を表す値オブジェクトである。
  • ローカル WebGPU 内部実行の上限は QubitCapacity::local() == 16 とする。
  • 外部 GPU 実行の上限は QubitCapacity::external_gpu() == 32 とする。
  • 量子ビット数に依存する配列長、ビット反転、Qiskit の量子ビット引数は、すべて QubitCount から派生させる。

非目的

  • QubitCount 自体へ実行モードを埋め込まない。同じ 17 は外部 GPU では有効だが、ローカル WebGPU では無効であるため、値そのものと上限判定は分ける。
  • 回路エディタが見た目として最低 2 本のワイヤを表示する規則は、量子レジスタの不変条件ではない。必要なら VisibleWireCount など別の値として表す。
  • 表示ブロックの span、ゲートの対象ワイヤ、Qiskit のビット順序は QubitCount の責務に含めない。必要になった時点で別の値オブジェクトとして定義する。

§ 02値オブジェクトの定義

名前責務不変条件
QubitCount 量子レジスタの量子ビット数。状態数 2^n、ワイヤ範囲、外部 GPU 要求の qubits を導く元値。 1 <= value
QubitCapacity 実行モードごとの最大量子ビット数。QubitCount を受け入れられるかを判定する。 1 <= max。定数は local = 16、external_gpu = 32
QubitCountError 生成または上限判定に失敗した理由を境界で返す。UI と API はこの理由を表示用文言へ変換する。 Zero、AboveCapacity { count, capacity } を区別する

Rust の形

#[derive(Clone, Copy, Debug, Eq, PartialEq, Ord, PartialOrd, Hash)]
pub(crate) struct QubitCount(NonZeroUsize);

#[derive(Clone, Copy, Debug, Eq, PartialEq)]
pub(crate) struct QubitCapacity(NonZeroUsize);

impl QubitCount {
    pub(crate) fn try_new(value: usize) -> Result<Self, QubitCountError>;
    pub(crate) fn try_for_capacity(
        value: usize,
        capacity: QubitCapacity,
    ) -> Result<Self, QubitCountError>;
    pub(crate) fn get(self) -> usize;

    // ローカル実行の状態ベクトル長 2^n。ローカル容量を超える n は QubitCountError。
    pub(crate) fn local_state_count(self) -> Result<usize, QubitCountError>;
    // GPU バッファ / GateParams 用の u32 版（同じくローカル容量で検証する）。
    pub(crate) fn local_state_count_u32(self) -> Result<u32, QubitCountError>;
}

impl QubitCapacity {
    pub(crate) const fn local() -> Self;        // 16
    pub(crate) const fn external_gpu() -> Self; // 32
    pub(crate) fn contains(self, count: QubitCount) -> bool;
}

状態ベクトル長 2^n の算出は、ローカル容量を検証する local_state_count() / local_state_count_u32() メソッドへ集約する。 名前に local を残すのは、修飾のない state_count() を QubitCount へ持たせると、外部 GPU では有効な 32 量子ビットでもローカル状態ベクトルを確保できるように読めてしまうためである。 GPU 実行計画（linearize_ops）と GateParams が使う 1u32 << qubits は local_state_count_u32() に置き換え、各所に散らばる 1u32 << qubits を 1 本化する。

Python / TypeScript の境界

  • Qiskit バックエンドでは RunRequest.qubits を QubitCount 相当の frozen dataclass にする。JSON から読む場所だけが int を受け取り、以降は値オブジェクトを渡す。
  • Playwright 補助の TypeScript では branded type または小さなオブジェクトを使い、createQubitCount(raw) を通さない値を受け取らない。
  • 言語ごとの表現は違ってよいが、境界で検証して内部へ不正値を入れない、という不変条件は同じにする。

§ 03実行モードと上限

実行モード上限意味失敗時の扱い
ExecMode::Local QubitCapacity::local() = 16 WebGPU 内部の状態ベクトル、ブロッホ表示、測定、確率表示、振幅表示、密度行列表示をフレーム内で扱う上限。 17 以上はローカル実行不可。UI は外部 GPU への切り替えを促す。
ExecMode::Gpu QubitCapacity::external_gpu() = 32 外部 Qiskit Aer 経路へ送信できる量子ビット数の上限。 33 以上は回路編集または実行要求を拒否する。

ExecMode は QubitCapacity を返すだけにする。 ExecMode が生の usize を返すと、呼び出し側が 16 / 32 の意味を知らないまま比較できてしまうため、上限の意図が失われる。 

impl ExecMode {
    pub(crate) fn qubit_capacity(self) -> QubitCapacity {
        match self {
            ExecMode::Local => QubitCapacity::local(),
            ExecMode::Gpu => QubitCapacity::external_gpu(),
        }
    }
}

§ 04既存コードへの対応方針

Web アプリ

  • required_qubit_count() は QubitCount を返す。配置済みゲートが無い場合は、ドメイン上の最小値 1 と、エディタ表示上の最小ワイヤ数 2 を混ぜない。
  • state_qubits() はローカル実行用に QubitCount::try_for_capacity(raw, QubitCapacity::local()) を通す。
  • external_execution_qubits() は外部 GPU 用に QubitCount::try_for_capacity(raw, QubitCapacity::external_gpu()) を通す。
  • layout_qubits() は見た目のワイヤ本数なので、QubitCount と同一視しない。ドラッグ中に 1 本増やす処理は表示都合の派生値として扱う。
  • linearize_ops、circuit_columns_to_json、collect_*_requests は生の usize ではなく QubitCount を受け取る。
  • linearize_ops と GateParams の状態数 1u32 << qubits は QubitCount::local_state_count_u32() を通す。メソッド自体は容量超過を Result で弾くが、これらはローカル実行経路のみで state_qubits() がローカル容量を保証するため、ここでの算出は常に成功する。

外部 GPU / Qiskit バックエンド

  • Web 側は外部 GPU 実行要求を組み立てる直前まで QubitCount を保持し、JSON の qubits へは qiskit_run_payload_with_display_outputs を呼ぶ最後の境界で get() した値だけを書き込む。
  • contract.py は payload["qubits"] を読んだ直後に QubitCount を生成し、QubitCapacity.external_gpu() で上限を検証する。
  • runners.py の QuantumCircuit(request.qubits, request.qubits)、qiskit_basis_order、probability_qargs、density_save_qargs は値オブジェクトから取り出した値だけを使う。
  • バックエンドのエラー文言は qubits must be an integer in [1, 32] の意味を維持する。ただし内部では Zero と AboveCapacity を分けておく。

TUI（端末 UI）

  • TUI の qubit_count(state) は QubitCount を返す候補である。ただし現在の TUI は CPU シミュレーションを含むため、WebGPU 本番経路と同時に整理する。

§ 05境界と変換規則

境界入力変換後備考
URL 回路 JSON 列配列の長さと配置済みゲート QubitCount URL は量子ビット数を明示しない。必要量子ビット数を復元してから生成する。
外部 GPU 要求 JSON { "qubits": number } QubitCount 受信直後に 1..=32 を検証し、以降は生の整数を要求オブジェクトに保持しない。
GPU uniform / storage QubitCount u32 GPU へ書き込む直前だけ u32 へ変換する。変換失敗は起きない範囲に制限済み。
Qiskit API QubitCount int QuantumCircuit や qargs へ渡す最後の境界でだけ整数化する。

§ 06受け入れ条件

  1. 最小値 — QubitCount::try_new(0) が Zero を返すことを 1 ケース 1 アサーションで確認する。
  2. 1 は有効 — QubitCount::try_new(1) が成功することを 1 ケース 1 アサーションで確認する。
  3. ローカル上限 — QubitCount::try_for_capacity(17, QubitCapacity::local()) が AboveCapacity を返すことを確認する。
  4. 外部 GPU 上限 — QubitCount::try_for_capacity(32, QubitCapacity::external_gpu()) が成功し、33 は失敗することを別テストで確認する。
  5. URL 復元 — 17 本目のワイヤにゲートがある URL は、ローカルでは不可、外部 GPU では有効な QubitCount として扱われることを確認する。
  6. 外部 GPU 要求 JSON — 外部 GPU 要求 JSON の qubits が値オブジェクトから生成され、回路列の最大ワイヤ数以上になることを確認する。
  7. バックエンド契約 — { "qubits": 0 } と { "qubits": 33 } が契約エラーになることを Python unittest で分けて確認する。
  8. 生整数の封じ込め — ドメイン内部の新規関数は usize / int / number の量子ビット数を直接受け取らず、境界と GPU / Qiskit への最終変換だけで整数へ戻す。
  9. 状態数メソッド — 16 量子ビットで local_state_count() が 65_536・local_state_count_u32() が 65_536u32 を返し、外部 GPU 容量の 32 量子ビットでは local_state_count() が AboveCapacity を返すことを別テストで確認する。
