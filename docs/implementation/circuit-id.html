CircuitId 実装仕様

回路ライブラリのエントリ識別子を、現状の型エイリアス pub type CircuitId = String; から、検証を持つ newtype の値オブジェクトへ昇格するための仕様。 「空でない識別子」という不変条件を型へ閉じ込め、保存名や回路 JSON といった他の String との取り違えを防ぐ。

§ 01 背景と目的

現行の circuit-library-model クレートは pub type CircuitId = String; という型エイリアスでエントリ識別子を表す。 エイリアスは名前を付けただけで、String そのものと区別されない。 CircuitEntry は id / name / circuit_json がいずれも String なので、rename(id: &str, name: &str) のように同じ &str を 2 つ取る関数で引数を取り違えても、コンパイラは検出できない。

さらにエイリアスは不変条件を一切強制しない。 識別子はサンプルが固定文字列、ユーザー作成は採番されるが、空文字列も型としては許され、現に CircuitEntry::default() は空の id を作る。 空の識別子は「どのエントリも指さない」不正な状態であり、本来は型で表現できなくすべきものである。

CircuitId を、String を内側に持つ newtype の値オブジェクトへ昇格する。 「空でない」を生成時に検証し、保存名や回路 JSON とは別の型にする。 これにより、ドメイン駆動設計（DDD）の観点で重要な不変性、自己検証、等価性を識別子へ適用する。

  • 識別子は空でない文字列である
  • 識別子・保存名・回路 JSON を同じ String で混在させない
  • 保存形式（JSON の文字列）は変えず、逆シリアライズの時点で検証する

想定 API

#[derive(Clone, Debug, PartialEq, Eq, Hash, Serialize, Deserialize)]
#[serde(try_from = "String", into = "String")]
pub struct CircuitId(String);

#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum CircuitIdError {
    Empty,
}

impl CircuitId {
    pub fn try_new(value: impl Into<String>) -> Result<Self, CircuitIdError>;
    pub fn as_str(&self) -> &str;
}

impl TryFrom<String> for CircuitId { /* try_new */ }
impl From<CircuitId> for String { /* 内部の String を返す */ }

try_new は空文字列を Err(CircuitIdError::Empty) で弾く。 #[serde(try_from = "String", into = "String")] により、JSON では従来どおり素の文字列として読み書きしつつ、逆シリアライズの時点で try_new の検証を通す。シリアライズ側は into 属性が From<CircuitId> for String を使う。serde(transparent) は検証を挟めないため使わない。 as_str() は比較や JavaScript 連携（DOM ストレージ）など、文字列として扱う境界で使う。

§ 03 DDD 上の性質

性質仕様禁止事項
不変性 生成後に内部値を変更しない。識別子の変更は新しい CircuitId を作って差し替える 公開フィールド、&mut String を返すメソッドを作らない
自己検証 生成時に空でないことを保証する。空文字列は Err(CircuitIdError::Empty) にする。逆シリアライズも try_from で同じ検証を通す 呼び出し側で if id.is_empty() を重複実装しない。空 id を持つ CircuitEntry を作らない
等価性 内部の文字列値で比較する。entry.id == active_id はこの値で比較する 保存名やピクセル位置で識別子の等価性を判定しない
型の一貫性 識別子を受け渡す API は CircuitId を使う。保存名・回路 JSON の String と区別する 新しい識別子引数を String や &str のまま追加しない

§ 04 組み込み方

エントリとライブラリ

CircuitEntry.id、CircuitOrigin::Sample.origin_id、CircuitLibrary.active_id を CircuitId にする。 識別子で比較・検索するライブラリ操作（set_active / delete_by_id / rename / find_canonical_sample / duplicate_active など）は、引数と戻り値を CircuitId または &CircuitId にする。 これで id と name の取り違えを型で防ぐ。

空 ID の既定値

現在 CircuitEntry::default() は空の id を作る。 CircuitId は空を許さないため、この既定値を見直す。 このプロジェクトは後方互換の保持を残さない方針なので、誤解を生む空 ID の Default 実装は削除するか、呼び出し側で実際に採番した CircuitId を渡す形へ移行する。

JavaScript 連携

apps/web/src/circuit_library.rs は DOM ストレージとの間で識別子を JavaScript の文字列としてやり取りする。 JavaScript から受け取った文字列は CircuitId::try_new で値オブジェクトにし、書き出すときは as_str() で文字列へ戻す。 採番（format!("ckt_{millis}_{suffix:06x}")）の結果も try_new を通して CircuitId にする。

§ 06 移行方針

  1. pub type CircuitId = String; を CircuitId newtype と CircuitIdError へ置き換える
  2. CircuitEntry.id / CircuitOrigin::Sample.origin_id / CircuitLibrary.active_id を CircuitId にする
  3. 識別子を比較・検索・受け渡しするライブラリ操作の引数と戻り値を CircuitId / &CircuitId へ広げる
  4. 空 id を作る CircuitEntry::default() を見直す（削除または採番済み CircuitId を渡す形へ）
  5. JavaScript 連携の入口で try_new、出口で as_str() を使う。serde 属性で JSON 形式を保つ
  6. 識別子を受け取るクレート公開 API に裸の String / &str が残っていないことを rg で確認する

後方互換の別名や古い入口は残さない。 pub type CircuitId = String; は削除し、識別子を String のまま受け取る関数を新設しない。

§ 07 受け入れ条件

  1. 空でない識別子を生成できる — CircuitId::try_new("ckt_1") の as_str() が "ckt_1" になることを確認する
  2. 空文字列を拒否する — CircuitId::try_new("") が Err(CircuitIdError::Empty) になることを確認する
  3. 等価性が値で決まる — 同じ文字列の CircuitId 同士が等しく、異なる文字列は等しくないことを確認する
  4. JSON 形式が変わらない — CircuitId を含む CircuitEntry が従来どおり {"id":"…"} の素の文字列でシリアライズされることを確認する
  5. 逆シリアライズで検証する — id が空文字列の JSON を CircuitEntry へ逆シリアライズすると失敗することを確認する
  6. 取り違えを型で防ぐ — 識別子を取るライブラリ操作に保存名の String をそのまま渡せないことを確認する（型エラー）
  7. 裸の識別子 String が残らない — CircuitEntry.id、active_id、識別子を取るライブラリ操作が CircuitId を使うことを確認する
