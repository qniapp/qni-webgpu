# スマホ縦向きの画面構成 (縦レイアウト)

スマホを縦に持ったときの画面構成 (縦レイアウト) の仕様と実装の要点をまとめる。
現時点では単体アプリだけが対象で、埋め込み (`startEmbed`) は従来どおり横レイアウトで表示する。
寸法の単位は論理 px。

## 切り替えの条件

キャンバスの論理サイズが次の両方を満たすとき、縦レイアウトにする。

- 幅が `SCREEN_SM` (640) 未満
- 高さが幅以上

| 機種・状態 | 論理サイズ | レイアウト |
| --- | --- | --- |
| iPhone 縦 | 390×844 | 縦 |
| iPhone 横 | 844×390 | 横 |
| iPad 縦 | 768×1024 | 横 |
| 細いデスクトップウィンドウ | 500×800 | 縦 |
| 低いデスクトップウィンドウ | 500×300 | 横 |

- 判定は `CircuitOrientation::for_canvas` (`apps/web/src/layout/orientation.rs`) の純粋関数で行う。
- `QniApp::update_orientation` がフレームの先頭で 1 回だけ判定し、`QniApp::orientation` に保持する。
- ゲートのドラッグ中、スパンのリサイズ中、角度エディタの表示中、回路のパン中は判定を据え置く。モバイルキーボードや URL バーで高さが変わっても、操作の途中でレイアウトが変わらない。
- 上部メニューの折りたたみは向きとは別に毎フレーム判定する。横レイアウトでも、幅が足りない場合はボタン幅と間隔を詰める。

## 画面構成

390×844 では上から次の順に並ぶ。

| 領域 | 位置 | 内容 |
| --- | --- | --- |
| ツールバー | 上端、高さ 44 | 回路ピッカー、Undo / Redo、Clear、複製、ロック、Tutorial リンク、実行モード切り替え |
| 状態パネル | ツールバーの 8 下 | 見出しと状態ベクトルの円表示。幅は画面幅から左右 16 ずつ引いた値 |
| 回路帯 | 状態パネルの 16 下からパレットの 16 上まで | 縦向きの回路 |
| パレットのカルーセル | 下端から 16 上、高さ 96 | `‹`、4 項目、`›`、ページドット |

- 縦レイアウトのツールバーは、左右の余白と項目の間隔を詰め、アイコンボタンの幅を 24 にする。回路名の表示幅は 24 に制限し、長い名前は省略する。Tutorial リンクと実行モード切り替えの左右の余白も小さくする。390 px では、Local モードと GPU モードの待機中に全項目が 1 行に収まる。GPU の実行状態があるときは左右の項目群の間隔を 8 px 以上確保するため、Tutorial をその他メニューへ移す。さらに狭い幅では実行モード切り替えもメニューへ移す。Pages 版は切り替えを表示しない。詳しくは[上部メニューの幅への追従](web.md#上部メニューの幅への追従)を参照する。
- GPU モードでは実行ボタンも並び、実行状態は色付きの丸で示す。その丸のツールチップでは状態の説明に加え、完了時は実行時間、失敗時はエラーの詳細を確認できる。
- 状態パネルは位置が固定で、ドラッグでの移動と四隅のリサイズはできない。
- 状態パネルの表示領域 (見出しの下で円を並べる部分) の高さは、「格子の自然な高さ + 32」を画面高の 4 分の 1 以下に抑えた値にする (ただし `STATE_VIEWPORT_MIN_HEIGHT` を下回らない)。格子はこの幅と高さに収まるよう縮小する。表示領域の中のパンとズームは従来どおり使える。
- 状態パネルの列数の初期値は、横レイアウトの既定値を上限として、パネル幅に自然なサイズで収まる最大の値にする。たとえば 2 量子ビットは 4×1、3 量子ビットは 4×2 になる。ユーザーが列数を選び直した場合は、その値を保つ。
- `index.html` は `100dvh` を使い、スマホのブラウザで URL バーが出入りしても画面の高さに合わせる。

## 縦向きの回路

回路空間 (x が時間、y がワイヤ) はそのまま使い、画面座標との変換だけを `CircuitProjection` (`apps/web/src/layout/projection.rs`) にまとめている。

```text
横レイアウト: screen = origin + (x, y)
縦レイアウト: screen = origin + (-y, x)
```

- 縦レイアウトは横レイアウトを 90° 時計回りに回したもので、鏡映を含まない。時間は上から下へ進み、量子ビット 0 が右端、量子ビットが増えると左へ伸びる。
- `QniApp::circuit_projection` が唯一の差し込み口になる。描画 (ワイヤ、ステップの区切り線、ゲート、接続線、表示ブロック、ラベル) とヒットテスト (`gate_input.rs` での画面座標から回路空間への変換) の両方がこの変換を使う。
- ドラッグ、スナップ、ドロップ、ステップ選択の判定は回路空間で動くため、横レイアウトと同じコードを使う。
- 文字とゲートの絵柄は回転させない。アンカー点と矩形だけを写し、その中に正立で描く。
- 測定ゲートの下でワイヤを消す範囲や、挿入中のプレビューの前後で描画を分ける境界は、時間軸の向きに合わせて切り替える。
- 量子ビットのラベルは `q0` の形で各ワイヤの上端に置く。
- 角度ラベル (P / Rx / Ry / Rz) と測定の変数名は、ゲートの下 (次のステップとの隙間) に置く。
- コメントブロックは範囲の左右を縦罫線で囲み、ラベルを範囲の左外側に上端をそろえて置く。ラベルを押すと正立した編集欄が開く。範囲を変更するハンドルは上下の辺に表示する。
- 振幅表示ブロックと密度行列表示ブロックは、写した矩形にシェーダが正方形のセルを収める。値はすべて GPU から描く。
- 各行を縦に積む GPU の描画は横長の矩形では潰れるので、2 ワイヤ以上にまたがる確率表示ブロックとサンプル表示ブロックは値を含まない本体だけを描く。CPU 側で値を計算する代替表示は作らない。
- スパンのリサイズハンドルは縦レイアウトでは出さない。

## パレットのカルーセル

- 1 ページに 4 項目を並べる。フルパレットは横レイアウトの読み順 (1 段目、2 段目、表示ブロック、コメントブロック) で 39 個を区切り、10 ページになる。算術ゲート (+1 / −1) は Rz の直後、4 ページ目に並ぶ。
- `‹` `›` で前後のページへ移る。両端では止まり、端の矢印は薄い色になる。ページドットを押すとそのページへ移る。1 ページに収まるときは矢印とドットを出さない。
- ゲートを押してそのまま回路へドラッグすると配置できる。マウスとタッチのどちらでも使える。
- ページ番号 (`QniApp::palette_page`) は表示用の状態で、URL や保存データには書かない。
- 寸法: ゲート 48、ゲート間 16、矢印の押せる範囲 48、ドット 8 (間隔 8)、カードの角丸は `ROUNDED_XL`。
- 縦レイアウトではパレットのツールチップを出さない。

## タッチとマウスの操作

縦レイアウトでは次のように操作する。

- 回路の何もない場所を押して動かすと、回路を時間軸の方向へパンする。指とマウスのどちらでも使え、マウスホイールも同じ方向にスクロールする。
- ステップの選択は離した時点で確定する。押した位置から動かした場合はパンとして扱い、選択は変えない。細いデスクトップウィンドウでのマウス操作も同じ扱いにする。
- 回路帯の外 (状態パネルやパレットの下) に隠れたゲートとステップは、押しても反応しない。

次の対応は横レイアウトにも共通する。

- ブラウザは 1 回のタップで `pointerdown` と `touchstart` の両方を送る。eframe のパッチでタッチの `pointerdown` を無視し、押下イベントを egui の入力キューに 1 回だけ積む (`apps/web/vendor/eframe/PATCHES.md`)。
- `touchcancel` ではクリックを発生させず、進行中のドラッグとポインタの押下状態を解除する。回路編集中のドラッグは開始前の回路へ戻す。取消後も次のタップを受け付ける。

## テスト

- Rust の単体テスト
  - `layout/orientation.rs`: 判定の境界
  - `layout/projection.rs`: 回路空間と画面の往復、回転であること
  - `layout/palette_carousel.rs`: ページ構成とヒットテスト
  - `layout/geometry.rs`: 縦レイアウトの余白
  - `render/state_panel_layout/geometry.rs`: 状態パネルの位置と大きさ
  - `app/drag_controller/vertical_tests.rs`: 画面座標でのドラッグとドロップ、ページ送り、ステップ選択、パン、描画位置のスナップショット
- Playwright: `apps/web/tests/web-mobile-portrait.spec.ts` (390×844、`hasTouch` と `isMobile` を有効にする)
  - 縦レイアウトの判定、ページ送り、マウスとタッチでのドラッグ配置、GPU 経由の状態ベクトル、パン、ステップ選択、横向きの判定
  - 空の回路、ベル回路、パレットの 2 ページ目のスクリーンショット
- テスト用フック `__qniLayoutJson` は、向き、回路帯、各セルの中心、カルーセルの矩形とページ番号を公開する。座標だけで、量子状態の値は含まない。
