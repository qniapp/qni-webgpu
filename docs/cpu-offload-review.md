# CPU処理の棚卸しとGPU移行優先度

目的: 現行実装で CPU に残っている処理を整理し、GPU に寄せる優先度を明確化する。  
このドキュメントは、他の Codex に作業を依頼する際の指示書として使う。

## 現状のCPU依存ポイント

主に `apps/web/src/main.ts` に集中している。

- 状態ベクトルの **読み戻し**（GPU → CPU）
  - `computeStateVector` で GPU 計算後に `readbackBuffer.mapAsync` して結果を CPU に戻している。
- 図形の **頂点展開**
  - `addRect/addLine/addText` で CPU 側で三角形リストを生成している。
- 文字描画の **レイアウト計算**
  - `addText` で文字の UV と座標を CPU 側で計算している。
- フォントアトラスの **生成**
  - `createFontAtlas` が CPU でビットマップを組み立てている（初回のみ）。
- デバッグ用の **フレーム読み戻し**
  - `__debugPixel` や `__frameDataUrl` 用の読み戻し・RGBA変換が CPU 側。

## 最新実装の再確認（指摘）

- **状態ベクトルの読み戻し（テスト用）**
  - `window.__captureStateVector` が true の場合、GPU → CPU に読み戻す。
- **状態ベクトル表示はGPU側で生成（限定パターン）**
  - GPU の stateVector バッファを読み、既知の出力パターンに応じて文字列を生成している。
- **図形インスタンスの構築**
  - 線・矩形のインスタンス配列は CPU で作成している。
- **文字列の入力準備**
  - 文字コード配列とテキスト用ユニフォームを CPU で作成している。
- **フォントアトラスの生成**
  - フォントビットマップは CPU で生成し GPU に転送している（初回のみ）。

## 影響

- 計算そのものは GPU 化されているが、表示に関わる処理は CPU 依存が残る。
- 状態ベクトル表示は GPU 計算結果に連動するようになったが、表示パターンは限定されている。

## GPU移行の優先度

影響が大きく、GPU 化の効果が高い順に整理する。

### P1: 状態ベクトルの読み戻し廃止（部分対応）

- 現状: GPU → CPU → 文字列化 → 頂点生成
- 目標: GPU 内の `StateVector` バッファを直接描画シェーダで参照
- メリット: CPU が数値→文字列の処理から解放される

現状:
- 通常実行では読み戻しを行わないように変更済み（テスト時のみ読み戻し）。
- GPU の stateVector から固定パターンの文字列を生成する方式に移行。

### P2: 文字描画のGPU化（レイアウト最小化）（部分対応）

- 現状: 文字列を CPU でレイアウトし頂点化
- 目標: CPU は「文字コード列 + 基準位置」だけ渡す
- 実装案: GPU で `textIndex` を参照し UV を計算する

現状:
- 状態ベクトル文字列とゲートラベルは GPU で UV/配置を計算するように変更済み。
- CPU 側は文字コード列と基準位置のみを渡している。

### P3: 図形描画のGPU化（インスタンス化）（部分対応）

- 現状: 線・矩形を CPU で三角形化
- 目標: GPU で quad を生成するインスタンス描画に移行
- 実装案: `DrawInstances` を GPU に渡し、頂点シェーダ側で展開

現状:
- 線と矩形はインスタンス描画に移行済み（vertex shader で quad を生成）。
- CPU はインスタンス配列のみを作る。

### P4: フォントアトラスの生成最適化

- 現状: CPU でビットマップ生成 → GPU に転送
- 目標: 固定テクスチャにしてビルド時に埋め込む／初回転送だけに限定
- 備考: 1回だけなので優先度は低い

### P5: デバッグ読み戻しの整理

- 現状: ピクセル読み戻しは一時停止（描画完了は `onSubmittedWorkDone` で確認）
- 目標: テスト限定に残す／本番は無効化
- 備考: Playwright の検証が目的なら現状維持でもよい

## 移行時の注意点

- Compute と Render の同期設計を明確にする（1フレーム内で完結させる）。
- GPU 内データの検証方法（読み戻し or 専用デバッグパス）を用意する。
- TDD 前提なので、GPU 化ごとに Playwright テストを更新する。

## 他の Codex に依頼する際の指示例

- 「P1: 状態ベクトルの読み戻しをやめ、描画側が GPU バッファを直接読む形にして」
- 「P2: 文字描画を GPU 側に寄せるため、文字コード列の転送方式を設計して」
- 「P3: 既存の addRect/addLine をインスタンス描画に置き換えて」
