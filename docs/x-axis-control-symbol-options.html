X 軸制御 / Y 軸制御 — 記号デザイン候補

Quirk には X 軸制御 (制御 量子ビットが |+⟩ のとき発火) と Y 軸制御 (|i⟩ のとき発火) があり、それぞれ ⊕ / ⊗ という独自記号で描画される。 一方世間一般の量子回路には専用記号が存在しない: 教科書 / 論文 / IBM Quantum / Azure Quantum は全て ─H─•─H─ の Hadamard サンドイッチ展開で書く。 qni-webgpu に同様のゲートを入れるなら記号を 1 から設計する必要があるので、 候補を 6 案並べて Pros / Cons を比較する。

§ 01 背景: なぜ専用記号が要るのか

X 軸制御は本質的に「制御 量子ビットを H で挟んだ Z 制御」と等価。展開して描けば既存記号だけで足りる ので、わざわざ専用記号を導入するコストは高い。一方 Quirk のように1 記号で表すと次の利点がある:

  • 列内の制御を 1 セルに収められる (展開すると H ゲート 2 個 + 制御 1 個 = 3 セル使う)
  • 制御 / アンチ制御のペアと並列に並ぶ → ツールバーの「control 系」グルーピングが自然
  • URL 互換: Quirk 回路を import するなら何らかの記号が要る

欠点は業界標準ではないこと。学習者は「⊕ って何?」となり、毎回 tooltip を読まされる。 qni-webgpu は教育用途も意識するので、記号デザインで「H サンドイッチを思い出させる」方向にすると親切。

採用しない選択肢も検討

  • 採用しない: ユーザに H · • · H を毎回書いてもらう。教科書と一致、教育効果 ◎、UI の複雑度を増やさない
  • 採用するが本ページの記号案を使う: 利便性 ◎、要記号デザイン

以下は「採用する」を前提とした記号デザイン候補。

§ 02 記号デザイン候補 (X 軸制御版)

全候補とも 40 × 40 px ゲートセルの中央に 1 つのコントロール印を描く。実寸 (1×) と 4× zoom を併記。 アンチ制御版 (|−⟩ で発火) も右に並べて対称性を確認できるようにした。

A. Quirk 互換 (⊕)

cross-in-circle
control
anti-control
  • Quirk URL を import したときに記号が同じ
  • シンプル幾何 (円 + 直線 2 本) で 1 px グリッドに乗る
  • 業界標準じゃない記号を qni-webgpu でも踏襲する形 → 学習負荷は据え置き
  • 「⊕ = X 軸」が直感的じゃない (XOR や Pauli X と混同しやすい)
代替案 Quirk URL 互換性を最優先するなら採用。

B. 円に X 文字

letter-in-dot
control
anti-control
  • 「X 軸」が文字で明示される → 業界外の人にも読める
  • Y 軸版は同じパターンで「Y 文字」、拡張一貫
  • •/○ の通常制御と並べても族として読める (黒丸 / 中に文字)
  • 円が大きくなる (r=7) ので通常制御 (r=5) より重く見える
  • 1× だと X が判読しにくい (Geist Mono 9 px はギリギリ)
推奨 初学者にも読める。Quirk URL は serialize 時にマッピングで対応。

C. H サンドイッチ表記

hadamard-bracketed
control
anti-control
  • 「H で挟まれた制御 = X 基底制御」の物理をそのまま視覚化 — 教育効果が一番強い
  • 記号を覚える必要なく、量子計算の知識から直接読める
  • Y 軸版なら H の代わりに S† / S など、対応するベース変換ゲートを書く
  • 記号が縦に間延びする (上下に小文字 H)
  • Y 軸版は S†·•·S 風になり、対称性が崩れて読みにくい (S と S† は別記号)
代替案 教育用途を最大化したいとき。ツールバー的には大きい。

D. 色で基底を分離

basis-as-color
X control (blue)
X anti (blue, hollow)

別基底用の色割り当て (案): Z = 黒 (現状) / X = blue-400 / Y = red-400 (orange / green も可)

  • 形が完全に統一 (●/○) — 認知負荷が低い、グリッドに乗る
  • 色で基底を一瞬で識別、横並びの control 列が美しい
  • 色覚多様性の問題: 緑赤色弱・青黄色弱だと判別不能、AAA 非対応
  • 白黒印刷で消える
  • 「基底 = 色」のマッピングを覚えなくちゃいけない → tooltip 必須
非推奨 色覚アクセシビリティの観点で単独採用は不可。形 + 色の併用ならアリ。

E. ●ˣ (上付きラベル)

dot-with-superscript
control
anti-control
  • 「通常制御 = ●」に基底文字をラベルとして付け足す形 — 既存知識との連続性が高い
  • 1 ピクセル単位で軽量 (Option B より小さい円)
  • 上付きが小さくて 1× だと X がほぼ点にしか見えない (Geist Mono 8 px)
  • SVG ラスタライズでアンチエイリアシングがにじむと文字が崩れる (egui rasterize で要検証)
  • 「●ˣ vs ●ʸ」のラベル切替だけだと、列を縮めたとき判別困難
非推奨 縦長レイアウトに合わない。zoom しないと読めない。

F. 菱形 ◇ + 内部記号

diamond-frame
control
anti-control
  • 通常制御 (円) と形そのものが違う → 一瞬で「これは別物」と判別できる
  • 菱形は量子情報界で他のゲートとぶつからない (回路図で頻出しない形)
  • 新規形状の導入 — 学習負荷が増える (3 つ目の形を覚える)
  • 1 px グリッドに乗らない斜辺、レンダリングがにじみやすい
  • 「●/○/◆/◇」と並べると形が増えて雑然
非推奨 形を増やすと control 系の見た目が壊れる。

§ 04 推奨と次のステップ

第一候補: B. 円に X 文字

  • 「●/○ の制御族」と一貫した円形を保ちつつ、中に基底ラベル X / Y を入れる
  • 業界外の人にも「X 軸に関する制御」が読める (Quirk の ⊕ より直感的)
  • Quirk URL 互換: Quirk の ⊕/⊗ serialized id とは内部マッピングで対応 (UI 上は B 形式、URL は ⊕)

第二候補: C. H サンドイッチ表記 — 教育効果を最重視する場合。チュートリアルモードでだけ C 表記、通常編集モードは B 表記、のような切替も検討に値する。

採用しない選択肢も忘れず: 専用ゲートを入れない場合、ユーザは H + • + H を手で書く。 qni-webgpu はまず採用するか / しないかの判断からユーザに確認すべき。

採用後にやること

  • ゲート定義に GateKind::XControl / GateKind::XAntiControl / 同 Y 版を追加
  • icon rasterize (`icons/gate_body.rs` 系) で SVG 経路をリファレンスに描画
  • WGSL shader への影響 (制御解釈): 既存の Z 制御を「H サンドイッチで包む」操作を回路コンパイル側で挿入する
  • URL シリアライズ: Quirk 互換のため ⊕ / ⊖ / ⊗ / (/) を保持 (UI 描画とは分離)
  • tooltip: 「X 軸制御 — 制御 量子ビットが |+⟩ 状態のとき発火 (Hadamard 基底)」のような短い説明を必ず添える
