# 制御条件と算術ゲートの形式検証

Kani 0.68.0 で、実際の Rust コードの制御条件・算術パラメータと、WGSL から転記した添字計算を検証する。
既存の単体テストでは列挙しにくい、対象範囲と制御の全組み合わせを扱うために Kani を使う。

## 実行方法

リポジトリのルートで、初回のみ Kani 0.68.0 を準備する。
Kani はホスト上で専用の nightly を使い、プロジェクトの stable や wasm32 向けのビルドとは独立して動作する。

```bash
cargo install --locked kani-verifier --version 0.68.0
cargo kani setup
```

Kani の準備に時間がかかるため、当面は CI に追加しない。検証は次の 1 コマンドで行う。

```bash
bash apps/web/scripts/verify-kani.sh
```

`pnpm -C apps/web run verify:kani` でも同じ検証を行う。
実ソースの全ハーネスの成功と、各ハーネスに対応する故障版の失敗を確認した場合だけ終了コードが 0 になる。
故障版は一時コピーだけを書き換え、対象のハーネスだけを実行する。終了時に一時ファイルを削除する。
`KANI_LOG_DIR` を指定すると、正常版と故障版のログをそのディレクトリに保存できる。

## 検証する性質と壊れた場合の影響

- **制御の保存**: `ColumnControls::restricted_outside` は範囲内の制御だけを消し、範囲外の `mask` と `value` を変えない。
  壊れると、QFT や算術ゲートが本来と異なる基底状態に作用する。
- **置換**: 算術ゲートの逆引き添字は状態配列の範囲内にあり、異なる出力添字を同じ入力添字に対応させない。
  壊れると、振幅の重複や欠落が生じる。
  有限の同じ添字集合内で単射なので、全単射でもある。
- **局所性**: 対象範囲外のビットは不変で、制御成立時の範囲内は `field - amount` を `2^span` で剰余した値になり、制御不成立時は恒等写像になる。
  壊れると、別の量子ビットを書き換えたり、加減算の方向を誤ったりする。
- **逆写像**: 同じ対象範囲・制御で `amount = 1` と `amount = u32::MAX` の逆引きを合成すると元の添字に戻る。
  壊れると、加算を減算で取り消しても元の状態に戻らない。
- **計画の前提条件**: 実コードで生成した対象マスクが正しい幅を持ち、量子ビット数内に収まり、渡す制御が対象範囲と重ならない。
  壊れると、制御付き算術ゲートで置換の前提が失われる。

## 実コードとの対応

依存ライブラリのない独立クレート `apps/web/verification/kani` が、実際の `controls.rs`、`qubit_bit.rs` と `simulation_plan/arithmetic_field.rs` の `ArithmeticField` を取り込む。
`simulation_plan/linearize.rs` の算術分岐はこの抽出モジュールを使う。

添字写像は製品では `apps/web/src/gpu/shaders/arithmetic.wgsl` にだけ存在する。
ハーネス内の転記は、WGSL の `u32` 減算と同じ折り返しを `wrapping_sub` で表す。
実行スクリプトはシェーダの対応箇所の一致を確認し、変更された場合は証明前に停止する。
これは WGSL の直接検証や転記の自動的な意味同値証明ではない。対応関係のレビューも必要である。

## 上限と前提

制御保存の証明は任意の `u32` の `mask`、`value`、`span_mask` を扱い、前提は `value & !mask == 0` だけである。
連続範囲に限定せず、全 32 ビットを対象とする。

算術の証明は次の範囲を扱う。

- 量子ビット数 `n` は `1..=16`。これは `LOCAL_MAX_QUBITS` に対応し、状態数 `2^n` は `u32` に収まる。
  外部 GPU の上限 32 はローカル状態配列の容量ではない。
- 対象の先頭 `wire` は `0..n`、幅 `span` は `1..=n-wire`。
  `linearize.rs` が行う `GateSpan::clamped_for` による切り詰め後の値を前提とする。切り詰め関数自体の証明ではない。
- 制御ビットは下位 `n` ビット内にあり、`value` は `mask` の部分集合。
  計画の証明では範囲内の制御も入力に含め、実コードによる除去を検証する。
  添字写像の証明では対象範囲外の制御だけを使う。
- 添字は `0..2^n`、加減算の量は `1` または `u32::MAX`。
  置換の証明では異なる 2 個の記号的な添字を使い、全添字を配列やループで列挙しない。

各ハーネスはアサーションを 1 つだけ持つ。ループの展開上限による打ち切りはない。

## 故障検出と対象外

故障注入では、実 Rust の制御除去・対象マスク・減算量と、転記内の添字計算を意図的に壊す。
正常版の 5 ハーネスと、計画の前提条件に対応する 2 件を含む 6 件の故障版を実行する。
スクリプトは置換箇所が一意であること、Kani の非 0 終了、対応する `Failed Checks:` 行の完全一致、`VERIFICATION:- FAILED` と失敗数を確認する。
コンパイルエラーだけでは故障検出の成功にならない。

振幅の数値精度、GPU 実行・バッファ配置・並列処理、WGSL コンパイラ、回路全体の順序、QFT、他の `ColumnControls` メソッド、wasm32 専用コードは対象外である。
計画全体や呼び出し側の有効な入力の生成まで証明したものではなく、既存の Rust・GPU テストを置き換えない。
変更時の判断と再検証の手順は、プロジェクト内の [検証スキル](../.agents/skills/verify-kani/SKILL.md) を参照する。
