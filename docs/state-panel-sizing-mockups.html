状態ベクトルパネル — サイズ案 (qubit 数のスケーリング)

現状は qubit 数が増えるとパネル自体が拡大していく方式 (qni と同じ)。1〜4 qubit ではきれいだが、8 qubit を超えると見苦しく、16 qubit で画面に収まりません。代替を 3 つ並べます。各案で 2 / 8 / 16 qubit 時の見た目を比較できるようにしてあります。

A 案

固定パネルサイズ + 円を auto-fit で縮小

パネルのサイズを固定して、qubit 数が増えるほど円のサイズだけが小さくなります。UI は最も単純。低 qubit 数ではゆったり、16 qubit ではほぼ「ヒートマップ」になり個別の値は読めなくなりますが、状態のパターンは把握できます。リサイズハンドル (G-2 で議論) と組み合わせると、ユーザーは詳細を見たいときにパネルを大きくするだけ。

2 qubits → 4 cells
2 qubits4 × 1 = 4 states
8 qubits → 256 cells
8 qubits32 × 8 = 256 states
16 qubits → 65536 cells
16 qubits256 × 256 = 65536 states
B 案

固定パネル + pan / zoom (ゲームマップ風)

パネルは固定サイズ、内側はビューポートとして grid 上の一部だけを表示します。ドラッグで pan、Ctrl+ホイールで zoom、右下にミニマップで位置を表示。低 qubit 数では拡大率を 1.0 に固定して全体が収まる挙動。詳細インスペクション能力は最強ですが、操作が増えるぶん UI 複雑度は最大。

2 qubits → 全体表示
2 qubits4 × 1 = 4 states
8 qubits → ビュー + zoom
8 qubits32 × 8 = 256 states
16 qubits → ビュー + zoom
16 qubits256 × 256 = 65536 states
C 案

qubit 数で表示モード切替 (円 ↔ ヒートマップ)

ある qubit 数 (たとえば 7 以上) になったら、円表示をやめてヒートマップに切り替える案。各セルは「位相 = 色相 / 振幅 = 明度」の点で、円より情報密度が高く、大きい状態数でもパターンが読めます。低 qubit では従来の円を維持。ヘッダー帯にモード切替トグルを置いて手動で切り替えることも可能 (右下のトグル)。

2 qubits → 円
2 qubits 4 × 1 = 4 states circleheat
8 qubits → 自動でヒートマップに
8 qubits 32 × 8 = 256 states circleheat
16 qubits → ヒートマップ専用
16 qubits 256 × 256 = 65536 states circleheat

3 案の比較

  • A 案 — 固定パネル + auto-fit: UI が最もシンプル。リサイズハンドル (G-2) と相性が良く、高 qubit ではユーザーがパネルを引き伸ばして個別 value を見る運用が成立。実装コストも低い (現状の grid layout を fixed-panel に切り替えるだけ)。
  • B 案 — pan/zoom: 詳細インスペクションが最強。一方で zoom コントロール / ミニマップ / pan ジェスチャの実装が増える。タッチ操作も別途検討必要。教育用途では「全体を見渡す」体験のほうが優先かも。
  • C 案 — モード切替: 表示密度の本質的な解。円とヒートマップを両方実装する必要があり最も重い。ただし「位相 = 色」のヒートマップは美しく、14+ qubit の状態を一望するには最適 (qni 以外のシミュレータでもよく採用)。

個人的なおすすめは A 案: G-2 のリサイズハンドル前提なら、追加実装はほぼ「panel size を固定し、grid を auto-fit にする」だけ。B / C は power-user 向けの拡張として後で追加することもできます。
