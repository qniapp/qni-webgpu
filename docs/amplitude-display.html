振幅表示ブロック

span 内 量子ビットを測定せずに、状態ベクトルの複素振幅 (大きさ + 位相) を可視化する振幅表示ブロック (`表示ブロック` の定義は AGENTS.md 用語集と design-system §01 参照)。 確率表示ブロックが |α|² (周辺確率) を線形バーで描くのに対し、本表示ブロックは α = re + i·im を outline 円 + 振幅 disk + 位相 needle の 3 層で描く。 span 上限は 16 量子ビット (Quirk と同じ。216 = 65 536 outcomes、状態ベクトル ≈ 512 KB を GPU storage で扱う上限)。 配色 (blue-200 fill / tx-2 outline / tx needle) は状態ベクトルパネルと完全に揃える (state.rs の cell_contribution)。 Quirk の AmplitudeDisplayFamily (src/gates/AmplitudeDisplay.js) を Flexoki + WebGPU へ移植する仕様書。

§ 01 サイズ別の見た目 (1〜16 量子ビット、動くモック)

span を 1〜16 (上限) 全部並べた参考レンダリング。outcome 数 n = 2span を w × h グリッド (w = n === 2 ? 2 : 1 << floor(log2(n)/2)) に配置する。 位相の原点 (needle の向き) は state panel と同じ「phase = 0 = 真上」 (cell 中心からの方向 = (−sin(phase), −cos(phase)))。 各セルにマウスを乗せると、Quirk と同じ tooltip 内容 (ket、val、mag² と phase) をポップアップ表示する。 cell 寸法 (cellPx) が小さくなるにつれてレイヤを段階的に省略する。閾値 (§ 05 参照): cellPx ≥ 12 = needle + outline + disk / cellPx ∈ [3, 12) = outline + disk / cellPx < 3 = heatmap。cell 間の区切り線は描かず、matrix 全体の外枠だけを描く。 production の cellPx は § 04 表参照、span 16 でも最小 3 px なので heatmap は production では発生しない。下のモックは表示の都合で 320 px に scale down しているので、mock では span 13〜16 が cellPx ≤ 2 となり heatmap mode に入る。

可変幅 (56 × cols − 16 px) 採用に伴う実装タスク

現行 qni-webgpu のゲートは resizable span でも幅 40 px 固定 (例: 確率表示ブロックも 40 px)。本仕様の振幅表示ブロックは 2D 行列の縦横バランスを保つため span に応じた可変幅 (cols = 2〜16、width_px = (cols − 1) × SLOT_SPACING + GATE_SIZE = 56 × cols − 16、96 〜 880 px) を採用する。 これは現行 gate_visible_rect() / hit-test / drag-drop / hover ring と整合しないので、以下を併せて実装する:

  • gate_visible_rect() — gate の width_cols を返すよう拡張、x..x + width_px を bounding rect とする (width_px = (cols − 1) × SLOT_SPACING + GATE_SIZE)。振幅表示ブロック以外は cols = 1 を返して既存挙動 (width_px = GATE_SIZE = 40) を維持。
  • hit-test (palette → circuit drop) — drop 時に新規 amplitude の gate_rect (width = 56 × cols − 16) と既存 gate rect が幾何交差しないかを確認、交差なら drop 拒否 (詳細は下の「placement / 衝突検出」参照、probability / QFT の resizable と同じセマンティクス)。
  • drag / drop preview — drag 中の影 / プレビューも width_px × height_px で描く。drag 中の matrix 背景は他ゲートの drag preview と同じ purple-600 にするが、outline 円の内側の白地は bg のまま残し、振幅 disk / outline / needle の色も通常時のまま変えない。回路 slot に snap して GPU の live 値が出る前も、palette から出した Amps1 は同じ GPU 表示シェーダの強制ゼロ描画インスタンスとして mag = 0 の空セル 2 つを描く。drop target highlight も同寸。
  • hover 表示 — Amplitude の cell hover は正方形枠を描かず、対象 outcome の outline 円周だけを purple-400 に置き換える。ゲート全体の矩形 hover ring は cell hover 中には出さない。
  • resize handle — 上下のみ (height = span を変える)、左右の幅は span の関数なので separate な width handle は不要。
  • 列衝突検出 — gate の右端列まで衝突判定を広げる。width_px 範囲内の他ゲートと gate_rect ∩ gate_rect 幾何交差で重ならない位置にのみ配置可。
  • URL round-trip (Quirk 互換) — JSON は {"cols":[["Amps3"]]} のように単一 token。setWidth は表示列幅であって JSON 上の列消費ではない。 採用モデル: 「JSON col index = qni 内部 slot index」 (1:1 対応、shift 一切なし)。 decode:
    1. JSON の各 col 配列を読み、wire k の cell が "Amps3" なら span = 3 を正規表現で抽出
    2. cols = (span === 1 ? 2 : (span % 2 === 0 ? span : ceil(span/2))) で表示列幅を導出
    3. amplitude gate は qni 内部で JSON col index 1 つ分の slot を占有するエントリとして登録する。後続 slot を予約しない、shift しない
    4. 表示時に「右側 cols − 1 個の slot 範囲」に視覚的にはみ出すが、これは描画レイヤだけの話で slot 構造には反映しない
    encode:
    1. 各 qni slot を順に走査して JSON col 配列を出す。amplitude gate は "Amps<span>" の単一 token を該当 col に書くだけ
    2. shift / 圧縮なし。slot index がそのまま JSON col index になる
    衝突検出は decode/encode の責務ではなく、placement 時に幾何的に行う (次項)。
  • 水平 slot 占有モデル — qni の水平 slot pitch は SLOT_SPACING = 56 px (確率表示ブロックと同じ。40 px ではない)。amplitude の幾何幅は垂直の (span − 1) × LINE_GAP + GATE_SIZE と対称に width_px = (cols − 1) × SLOT_SPACING + GATE_SIZE = 56 × cols − 16。slot 構造としては 1 列消費 (上記 decode/encode と一致)、視覚的には cols slot 分の幅を覆う。
  • placement / 衝突検出 (幾何ベース) — slot index の比較ではなく、gate_rect の幾何交差で判定する: 新規 gate を slot N に置くとき、その gate_rect (x_left..x_left + width_px, y_top..y_top + height_px) と既存 gate の rect が交差していたら drop 拒否。amplitude の場合 width が広いので、右側 cols − 1 個分の slot 範囲に既存 gate があれば交差で検出される。
    この方式なら cols 可変 × cols=1 ゲート混在も、矩形交差だけで一貫して扱える。逆に slot index 単純比較は wide gate に対して破綻するので採用しない。

上記が困難なら fallback: 幅 40 px 固定 × 高さ可変 (確率表示ブロックと同じ) にして、2D matrix を 1 列の縦並び に潰す。情報は保持されるが Quirk のような bit-pattern 視覚化は失う。本仕様はまず可変幅で実装することを推奨、難しければこの fallback に切り替える。

§ 05 セル描画モデル (state panel と同じ 3 層)

qni-webgpu の状態ベクトルパネル (apps/web/src/gpu/shaders/state.rs) と 同じ 3 層モデルを 1:1 で踏襲する: outline 円 + 振幅 disk + 位相 needle。 Quirk の確率正方形 / 対数円は冗長 (disk の半径 = mag、面積 ∝ mag² で確率値も読める) なので不採用。 α = re + i·im, mag = |α| = √prob。

(1) back fill — セル背景。通常時は bg (#FFFCF0)。drag preview 中だけ円の外側を purple-600 (#5E409D) に差し替え、outline 円の内側の白地と disk / outline / needle 色は維持する
(2) outline 円 — セル中央、半径 = cellPx/2 − stroke (matrix 外枠へ食い込まないよう 1px slack を取る)。stroke は cellPx ≥ 24 で 2 px、それ未満で 1 px。描画条件: cellPx ≥ 3。 mag > 1e-6 なら tx-2 (state panel の state_outline)、≈ 0 なら ui-2 (state_outline_zero)。cell hover 時は正方形枠ではなく、この outline 円周を purple-400 で上書きする。
(3) 振幅 disk — 中心 = セル中心、半径 r = mag × inner_radius (= mag × (cellPx/2 − stroke)、mag = 1 で outline の内側ギリギリまで広がる)。 blue-200 fill (state panel の state_fill、Quirk #8FF と等価)。 加えて blue-400 (確率表示ブロックのバー右端と同じ) でinset の 1 px 境界線を引く: ① 半径 r で fill ② 半径 r − 0.5 で stroke。stroke の外端が r に一致するので視認性は上がるが disk 面積は変わらない。閾値: r > 0.3 で fill、r ≥ 1.5 で stroke も追加
(4) phase needle — セル中心から方向 (−sin(phase), −cos(phase)) = (−im/mag, −re/mag) へ長さ inner_radius の線分。 tx stroke (outline と同じ太さ: cellPx ≥ 24 で 2 px、それ未満で 1 px)。 描画条件: cellPx ≥ 12。それ未満では省略 (cellPx ∈ [3, 12) は outline + disk、cellPx < 3 はモック限定 heatmap)。 位相 0° = 真上、反時計回りに π/2 (= 左)、π (= 下)、−π/2 (= 右)。 state panel cell_contribution wgsl と一致 (let dir = vec2(-sin(phase), -cos(phase)))
(5) frame — matrix 全体の外枠だけを ui-2 1 px で描く。cell 間の区切り線は描かない (円と円の間は bg のまま)

state panel との差分: 色トークン (blue-200 fill / tx-2 outline / tx needle) と disk 半径計算式 (mag × inner_radius) は state.rs の cell_contribution() と同一。ただし以下の点で異なる:

  • cell を矩形 grid で密に並べる (state panel は cell 間に 3 px gap あり)
  • disk に blue-400 の inset 境界線 (1 px) を追加 (state panel は disk fill のみ、境界線なし)
  • outline 表示条件: mag > 1e-6 で tx-2 / ≈ 0 で ui-2。10 量子ビット 一様振幅 (prob = 1/1024) のような小さいが非ゼロの振幅も non-zero outline として扱う
  • layer 合成順序: 本仕様は frame → outline → disk → needle (state panel は fill → needle → outline 合成)。cell 間の区切り線は描かない
  • phase lock cell の別マーカーは引かない (state panel は phase lock 概念がない、本仕様も Quirk の赤マーカーを不採用)

擬似コード (Rust + wgsl 構造)

// shader (fragment) — 1 cell につき (state.rs の cell_contribution と同形)
const STROKE: f32 = 2.0;
const half_stroke: f32 = STROKE / 2.0;
fn render_cell(re: f32, im: f32, cell_uv: vec2<f32>, cell_size: f32) -> vec4<f32> {
    let mag = sqrt(re*re + im*im);
    let p   = re*re + im*im;
    let r_outline = cell_size / 2.0 - 2.0;
    let r_inner   = r_outline - half_stroke;
    let r_cell    = distance(cell_uv * cell_size, vec2(cell_size/2.0));
    var col = BG;                                                      // (1) back

    // (2) outline (常時描画、mag で stroke 色だけ切替)
    let outline_color = select(UI_2, TX_2, mag > 1e-6);
    if (abs(r_cell - r_outline) < half_stroke) { col = outline_color; }

    // (3) disk (mag > threshold なら塗る)
    if (mag * r_inner > 0.5 && r_cell <= mag * r_inner) {
        col = BLUE_200;
    }
    // (4) needle: 同じ fragment shader 内で SDF。cell center から (-sin(phase), -cos(phase)) × inner_radius
    //     への線分との signed distance を計算、stroke 幅以下なら TX で塗る (§ 08 参照)。
    // (5) frame: matrix 全体の外枠だけを ui-2 1 px で塗る。cell 間の区切り線は描かない。
    //     全レイヤ CPU vertex buffer は不要、すべて fragment shader 完結。
    return vec4(col, 1.0);
}

§ 06 phase lock + incoherent state

phase lock — 主要振幅を位相基準に

GPU パイプライン (§ 08) は最大振幅を持つ outcome の index (phaseLockIndex) を返す。 その index の振幅の位相 θ = atan2(im, re) を全 ket から e−iθ で打ち消し、 phase lock 後の振幅は実数正 + 虚部ゼロに正規化される。これで「全体に同じ位相を掛けたとき見た目が変わらない」 = 量子状態の物理的等価性を視覚化に反映する。

phase lock cell に別マーカーは引かない。state panel と同じく needle が真上 (位相 0) を向いている cell を見れば自然に lock 位置がわかる、というのが基本方針。 Quirk 原版の赤い水平線 + 'fixed' ラベルは (a) needle 方向との視覚的衝突 (Quirk は phase 0 = 右、本仕様は phase 0 = 上)、(b) state panel に同等マーカーが無いため UI が分散する、の 2 点で不採用。 span == 回路全体の 量子ビット数 のときだけは phase lock を無効にする (「全体相」を持つ意味がないため、Quirk 同挙動)。 実装は AmplitudeCapture uniform の phase_lock_enabled flag で制御する: ColumnAnalysis が span == total_qubits を検出して phase_lock_enabled = 0 に set し、shader 側は phase_lock_index = sentinel を書き、stage 8 で θ = 0 扱い (正規化のみで位相回転なし)。詳細は § 08 stage 7/8 参照。

incoherent state — entangled で振幅未定義

span 内 量子ビットが span 外と entangled しているとき、純粋状態としての振幅は定義できない (reduced density matrix のみ計算可能)。 Quirk は coherence 指標 quality = denormalizedQuality / unity / incoherentUnity を計算し、 quality < 0.99 で incoherent と判定する。

  • matrix は ket ではなく incoherentKet = sqrt(reduced_diag) (実数のみ) を描く
  • outline 円は通常通り描く (情報量を保持)、disk は alpha 0.45 で薄塗り「振幅未定義 / 確率のみ」を示す
  • phase needle は描かない (虚部が無いので位相は 0、線が意味を持たない)
  • ゲート下に "incoherent" を red-600 でフェードイン (1 − indicatorAlpha 透明度)
  • ホバー popup は "Probability of |ket⟩ [entangled with other qubits]" と raw % / log dB のみ (val / phase は出さない)

measure 済み列での挙動 (Quirk と仕様が異なる)

qni と Quirk で capture 順序が異なる:

  • Quirk: 列処理の前に display capture → measure された 量子ビットがあっても collapse 前の純粋振幅を表示。「deferred measurement」の解釈で、ゲート下に "(w/ measure defer)" / "(assuming measurement deferred)" を red-600 でフェードイン。
  • qni: 列処理の後に display capture (既存 CaptureProbability と同じパス) → measure された 量子ビットは collapse 後の古典状態として扱われる。表示される ket は post-measure 状態の振幅 (=ある outcome に collapse した後の確定状態、span 内に measured wire があれば確率 1 の単一 outcome になる)。

本仕様では「post-measure state を素直に表示する」を採用。ゲート下の "incoherent" 以外の補足テキストは出さない (Quirk の "(w/ measure defer)" 系を真似ない)。Quirk と数値再現性を取る場合は別途 capture 順序の入れ替え (lowering で display を column 先頭に移動) が必要だが、本仕様では未採用。

§ 08 GPU パイプライン (GPU-only、毎フレーム readback 無し)

Quirk の amplitudeDisplayStatTextures() + JS 側 processOutputs() を WebGPU compute shader 列に完全移植する。Quirk が JS で行う unity 正規化 / quality 計算 / phaseLockIndex 選択 / phase 回転 も全部 GPU compute pass にする (AGENTS.md の GPU-only ルールに従い、毎フレームの readback は禁止)。 入力: state_ket: storage<vec2<f32>> (state vector、各要素 = 複素振幅)、capture: AmplitudeCapture uniform (下記)。 出力: すべて GPU storage buffer に書き込み、render shader が直接 sample する。

capture uniform (CaptureProbability の amplitude 版)

現行 CaptureProbability は base_bit / span / output_slot のみで control 情報を持たない。 Amplitude では Quirk と同じ control-conditional 表示を行うため、capture uniform を拡張する: 

struct AmplitudeCapture {
    base_bit:           u32,   // span 内 量子ビットの起点 (CaptureProbability と同じ)
    span:               u32,   // 1..=16
    output_slot:        u32,   // 結果 buffer の書き込み slot
    control_mask:       u32,   // どの state_index bit が control 条件の対象か
    control_value:      u32,   // 期待値 (該当 bit が 1 なら |1⟩ 期待、0 なら |0⟩ 期待)
    phase_lock_enabled: u32,   // 0 = 無効 (θ=0、回転なし) / 1 = 有効 (Quirk 互換、決定論的 max)
    total_qubits:       u32,   // 回路全体の 量子ビット数。span == total_qubits なら ColumnAnalysis で
                                // 自動的に phase_lock_enabled = 0 にセット (§ 06 「span == 全量子ビット」例外)
};

bit 順序: control_mask / control_value はqubit_bit (= state_index の bit position) 単位で指定。 qni-webgpu の state_index は qubit big-endian (state_index = bq−1 bq−2 ... b1 b0、wire 0 が top wire) なので、 wire 番号と bit position は qubit_bit = qubits − 1 − wire で変換する (qni 既存の変換と一致)。 uniform に書く値は wire 番号ではなく変換後の qubit_bit: 

// ColumnAnalysis 側で wire → qubit_bit 変換してから uniform を組む。
// 例: qubits = 5、wire 1 を |1⟩ control にする場合:
//   qubit_bit = 5 - 1 - 1 = 3
//   control_mask  |= 1 << 3;
//   control_value |= 1 << 3;   // |1⟩ 期待
// wire 1 を |0⟩ control (anti-control) にする場合:
//   control_mask  |= 1 << 3;
//   control_value |= 0 << 3;   // (= no-op)、|0⟩ 期待

shader 内では既存 base_bit と同じセマンティクスで (state_index & control_mask) == control_value な要素のみを集約対象とする。 control_mask = 0 なら無条件 (現行 確率表示ブロック同等)。controls 統合はこの uniform 1 つで完結する。

compute pipeline (10 stage、すべて GPU storage 内で完結)

stage処理出力 buffer
1Control select + cycle — controls を満たす要素だけ詰めて、span subspace を head に持ってくる (Quirk CircuitShaders.controlSelect + cycleAllBits)ket_just_after_cycle: vec2<f32>[2^involved]

phaseLockIndex の選び方 (Quirk 互換: 決定的最大)

Quirk の _processOutputs_pickPhaseLockIndex() は m > best * 10000 な「10000 倍ジャンプしないと更新しない」探索を行う: 

var best: f32 = 0.0;
var result: u32 = 0u;
for (k = 0u; k < n; k++) {
    let m = dot(ket[k], ket[k]);
    if (m > best * 10000.0) { best = m; result = k; }
}

真の最大ではなく「圧倒的に大きい最初の outcome」を選ぶ。利点は (a) 振幅が拮抗するときは index 0 を保ち画面のチラつき (異なるフレームで lock 先がコロコロ変わる) を抑える、(b) 浮動小数の僅差を安定して扱える、こと。 qni でもこの Quirk-compatible な決定論的探索を採用する (真の argmax は意図的に使わない)。

Render shader (毎フレーム描画、readback 無し)

矩形 cell grid を fragment shader で描く (確率表示ブロックの STATE_RENDER_SHADER と同じパターン)。 入力 storage buffer (ket / incoherent_ket / quality / phaseLockIndex) を直接 sample。 quality < 0.99 の判定も fragment shader 内で行う (incoherent fallback 切替) — CPU 分岐ではない。 needle 線・matrix 外枠・outline 円・disk・disk 境界線はすべて1 dispatch の draw call で出す:

  • outline 円 / disk / disk 境界線: fragment shader で SDF (signed distance) 計算、ブレンド合成
  • 背景 / matrix 外枠: 同じ fragment shader 内で背景 layer として塗る。cell 間の区切り線は描かない
  • needle: fragment shader 内で SDF で描く。各 fragment で「自分が属する cell の amp = (re, im) を amplitude_result.ket[k] から sample」→「needle 線分 (center → (-sin(phase), -cos(phase)) × inner_radius) との signed distance を計算」→ stroke 幅以下なら TX 色で塗る。専用 vertex buffer は持たない ので、振幅 / 位相が変わるたび rebuild する必要がない (毎 recompute で amplitude_result が更新されれば、render shader が自動的に新しい needle を描く)。

CPU は vertex buffer を作らない。ゲート配置 (cell サイズ) が変わったときに更新する vertex は cell quad の四隅と uv だけ (各セル fragment shader が cell index を知るための instance buffer 相当)。これは ゲート placement / resize 時だけ rebuild。

Popup の値も GPU 描画 (readback 無し、glyph atlas + overlay shader)

ホバー popup の数値 (coherent では val / mag² / phase の 3 行、incoherent では raw / log の 2 行) は本番 UI 経路なので、GPU-only ルールに従いreadback しない。 代わりに glyph atlas + overlay render pass で GPU 上で文字を直接合成する (確率表示ブロックのポップアップと同じ方針)。 coherent / incoherent の分岐は overlay fragment shader 内で quality < 0.99 を判定して切り替える (擬似コードは下記)。

必要なリソース

  • glyph_atlas: texture_2d — pre-rendered grid: ASCII 数字 0..9、記号 + − . i %、単位 °、ラベル val / mag² / phase (coherent 用)、raw / log (incoherent 用、確率表示ブロックのポップアップと完全共有) と dB 単位。Geist Mono で 1 行高 16 px、各 glyph 16×16 px の正方 grid に焼く (起動時 1 度のみ)
  • amplitude_result — § 08 の compute pass 出力 storage buffer (ket / incoherent_ket / quality / phase_lock_index)。fragment shader は quality < 0.99 で incoherent_ket を読み、それ以外は ket を読む
  • popup_uniform: PopupRenderInput — hovered cell の index hovered_k: u32、popup screen 位置 popup_pos: vec2<f32>、表示 / 非表示 flag

overlay render pass

ホバー判定は CPU で行う (マウス座標 → cell index)、その index を popup_uniform に書くだけ。値そのものは GPU 内のまま: 

// fragment shader (popup overlay) — coherent と incoherent で表示内容を切替
@fragment
fn fs_popup(@location(0) uv: vec2<f32>) -> @location(0) vec4<f32> {
    if (popup.hovered_k == 0xffffffffu) { discard; }
    let k: u32 = popup.hovered_k;
    let q: f32 = amplitude_result.quality;

    var glyph_uv: vec2<f32>;
    if (q < 0.99) {
        // incoherent: raw % と log dB の 2 行のみ (val / phase は出さない)。
        // incoherent_ket[k] は sqrt(prob) なので raw_prob = (incoherent_ket[k])².
        let sqrt_p: f32 = amplitude_result.incoherent_ket[k];
        let raw_p: f32 = sqrt_p * sqrt_p;                       // 0..1
        // log10(x) = log(x) * 0.4342945。raw_p = 0 のときは log(0) = -inf になるので、
        // 専用 sentinel (NEG_INF: f32 = -3.4e38) を渡し、compute_glyph_uv_incoherent 側で
        // "−∞ dB" の glyph 並びへ分岐する。
        let log_db: f32 = select(log(raw_p) * 4.342945, NEG_INF, raw_p <= 0.0);
        glyph_uv = compute_glyph_uv_incoherent(k, uv, raw_p, log_db);
    } else {
        // coherent: val (re / im) / mag² / phase の 3 行。
        let amp: vec2<f32> = amplitude_result.ket[k];
        let mag2: f32 = dot(amp, amp);
        let phase_deg: f32 = atan2(amp.y, amp.x) * 180.0 / PI;
        glyph_uv = compute_glyph_uv_coherent(k, uv, amp, mag2, phase_deg);
    }
    return sample_glyph_atlas(glyph_uv);
}

compute_glyph_uv_coherent / compute_glyph_uv_incoherent は同じ glyph atlas を sample するが、 ラベル glyph (val / mag² / phase vs raw / log) と行レイアウトが異なる。incoherent 側の raw / log ラベルと整形ロジックは 確率表示ブロックのポップアップと完全共有 (shaders/glyph_format.wgsl)。

確率表示ブロックのポップアップとの共有

確率表示ブロックのポップアップの既存 glyph atlas + format callback パターンを再利用する:

  • glyph atlas 本体 — 既に 確率表示ブロックのポップアップで実装済み (shaders/glyph_atlas.wgsl)。ASCII 数字・+ − . i % °・固定ラベル文字を共有。Amplitude 用に追加するのは val / mag² / phase のラベル glyph のみ。
  • format helper — 確率表示ブロックのポップアップで format_percent(p, decimals) / format_db(p) 等が既にある。Amplitude は 新規に 以下を追加:
    • format_complex(re, im, decimals) — "0.50000 + 0.30000i" 形式。sign / 整数桁 / 小数桁 / "i" 記号 を順に glyph に逆引き。
    • format_signed_deg(deg, decimals) — "+30.96°" 形式。format_percent に sign prefix を足したものと同等構造。
  • log10 の WGSL fallback — WGSL には log10 が無いので log10(x) = log(x) / log(10.0) (= log(x) * 0.4342945) を glyph_format.wgsl 内に inline 定義。確率表示ブロックのポップアップの dB 表示でも同じ式が必要なので、Probability/Amplitude 共有 helper として置く。
  • atan2 は WGSL builtin なので追加実装不要。

確率表示ブロックのポップアップが既に動いていれば、振幅表示ブロックのポップアップの glyph 描画は「format 関数 2 つ追加 + label glyph 3 つ追加」だけで済む見込み。 fragment shader 内で完全な printf を実装するわけではなく、確率表示ブロックのポップアップの既存パイプラインに乗せる前提。

readback はテスト専用 API に限定: read_amplitude_cell(gate_id, k) は #[wasm_bindgen] で JS テストから呼ぶ async API としてのみ提供 (Playwright で val / mag² / phase の正しさを確認する用途)。本番 UI 経路からは一切呼ばれない。 これは AGENTS.md の例外条項 (テストハーネス向けの on-demand readback) に該当。
