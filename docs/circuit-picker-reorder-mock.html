Circuit picker reorder

回路一覧をマウスでつかんで上下にドラッグして並び替える機能。 submenu の Move up / Move down はそのまま残す (キーボード派や 1 段ずつ動かしたい時の代替) ─ ドラッグはマウスでまとめて再配置したい時の primary な手段。ドロップダウンの幅 / 影 / 角丸 / その他の挙動は実装済みの picker と同じ。差分はドラッグハンドル無しの whole-row live reorder のみ。

§ 01 ドラッグの 3 状態 (ライブ並び替え)

Idle (普通) → Hover (掴める合図 = cursor: grab) → Dragging (掴んだ行そのものが pointer に追従、他の行は data swap で隣の slot に瞬時に移動)。 ゴーストも drop indicator も elevated shadow も無し。dragged 行は Flexoki ui グレーだけで示し、 それ以外の行は live-reorder されたあとの位置で静止する。

右端の例: GHZ state が「上に向かって動いてる途中」のスナップショット。 Bell state と QFT 4-qubit は既に live-reorder で位置が確定済み (QFT が 2 番目に上がっている)。 GHZ 行は Flexoki ui グレーのまま pointer に追従。release した時点でその index が確定される。

§ 02 ドラッグ機構の解剖

ドラッグハンドルは導入しない ─ 行のどこを掴んでも drag に入る。 kebab だけは drag 対象外 (kebab クリックで submenu を開く挙動を維持)。 drag 中は 掴んだ行そのものが pointer に追従し、隣接する行のセンターを 跨ぐ瞬間に entries 配列で swap して即座に再 render する。 Create new circuit の footer は drag target から除外。

part挙動 / トークン
drag start 行の mousedown + 移動距離 ≥ 4 px で drag 開始 (egui だと response.drag_started() 相当)。閾値以下のクリックは選択 / kebab open など本来の挙動。
cursor 行 hover で grab、drag 中は grabbing。kebab hover では pointer。
dragged 行の描画 その行自身に transform: translateY() を当てて pointer に追従させる。 background: var(--ui) (グレー塗り) + z-index: 5 で 「これがいま掴まれている行」を示す。浮かす shadow は付けない。 ゴーストクローンは作らない、source は薄くしない。
動きは Y 軸のみ: translateX は常に 0。pointer の X が動いても無視。
Y はドロップダウン内側にクランプ: pointer が dropdown の外に行っても translateY は [panel_pad, dropdown_height - panel_pad - row_height] の範囲内に止まる。
他の行 drag 中は 非 dragged 行はすべて paper bg (白)。 アイテムの bg は基本「ホバー時 = bg-2」「ドラッグ中 = ui」のイベント由来の変化のみで、 アクティブ行も resting state では bg を持たない (font-weight 500 だけで「いま編集中」を示唆)。 これで dragged 行のグレーが視覚的に唯一のアクセントになる。
live swap 毎 mousemove で dragged 行の visual center (= pointer.y - ghostOffsetY + row.height/2) を計算し、 1 つ上 / 1 つ下の行の center を跨いだら entries 配列で隣同士を swap し、 state.drag.idx を ±1 して再 render。swap した瞬間に dragged 行の natural top が 36 px ずれるが、 translateY を再計算して visual position は連続。
他の行 (live swap) live swap が起きたとき、押し出される行は FLIP アニメーションで 旧位置から新位置へ 80 ms ease でスライドする ─ 単純な snap だと「いま何が動いたか」が読みづらいので。 FLIP: swap 前に rect を記録 (First) → swap + 再 render (Last) → 旧位置との差を translateY で打ち消す (Invert) → 次フレームで transition 有効化 + transform 解除で 0 へアニメーション (Play)。 dragged 行は除外 (cursor 追従が遅延するのを避けるため transition: none)。
kebab 除外 kebab 上の mousedown は drag を開始しない (event を kebab handler に渡す)。kebab は drag handle ではなく submenu trigger。
auto scroll dropdown が scrollable で、カーソルが dropdown rect の上下 24 px 以内に入ったら 60 fps で 6 px/frame スクロール (entries が多い時用、今は entries 少ないので第 1 弾では実装不要)。
release data は drag 中に live swap で既に並び替え済み。mouseup では transform をクリアして state.drag = null するだけ。active_id は id で保持してるので index ズレなし。
Esc cancel drag 開始時に state.entries を snapshot しておき、Esc 押下で復元 + state.drag = null + 再 render。
submenu との両立 submenu の Move up / Move down は据置 ─ キーボード代替 / 1 段ずつ動かしたい時用。drag は飛ばし移動の primary path。別行の drag が始まったら開いている submenu は閉じる。同じ kebab trigger を再クリックしたときも submenu は閉じる。

§ 03 実装プロトタイプ — 掴んで上下に動かす

各行を mouse でつかんで上下に移動 → dragged 行自身が pointer に追従し、隣接行の center を跨ぐと live swap で即時に並び替わる。 Esc でキャンセル。kebab は drag されない (クリックすると "kebab clicked" alert)。 Create new circuit は drag 対象外。

§ 04 実装仕様 (Codex 用リファレンス)

既存 picker への差分 — drag-reorder の追加だけ。

  1. 状態 ─ PickerState::Open に drag 中 sub-state を追加: 
    pub(crate) enum DragState {
    Idle,
    Pending { entry_index: usize, started_pos: Pos2 },
    Active  {
        entry_index: usize,         // dragged 行の現在の data index (live swap で変わる)
        pointer_offset_y: f32,      // pointer.y - row.top at drag start (= cursor とのオフセット)
        original_entries: Vec,  // Esc cancel 用の snapshot
    },
}
    Pending → Active への昇格は pointer 移動距離 ≥ 4 px。 Pending 中に mouseup なら通常の click として扱う (select)。
  2. 各 item 行 の egui::Sense::click_and_drag() に変更。 response.drag_started() で DragState::Pending。 response.drag_delta().length_sq() > 16.0 で Active に昇格 (このとき entries を snapshot)。 response.drag_released() で DragState::Idle に戻すだけ — data は既に live swap で確定済み。 ui.input(|i| i.key_pressed(Key::Escape)) で cancel (snapshot から復元)。
  3. kebab は drag 対象外 ─ kebab 用の inner Response が Sense::click() のままで、その上のクリックは行の drag を起こさない (egui は inner widget のクリックを優先する)。
  4. dragged 行の描画 ─ dragged 行 (= active.entry_index) を描くときに:
    ・本来の Y 位置: natural_top = row_rects[idx].top()
    ・欲しい visual Y: wanted_top = clamp(pointer.y - pointer_offset_y, dropdown.min_top, dropdown.max_top) でドロップダウン内側にクランプ (min_top = dropdown.inner_top、max_top = dropdown.inner_bottom - row_h)
    ・両者の差を translateY 相当で吸収して描画する。 egui で外向きに位置だけずらすには、行の draw 時に ui.allocate_space を natural rect で取った後、 painter.with_clip_rect を外して painter.add(Shape::translate(...)) で natural rect の中身を wanted_top - natural_top px だけ Y シフトして描き直す方式。 またはその行だけ別 Area で描く (Area::new(...).order(Order::Foreground).fixed_pos(pos2(natural_left, wanted_top))) でも可。
    X 軸はロック: translateX は常に 0、pointer.x は無視。 背景は ui グレー: dragged 行だけ Frame.fill = colors.toolbar_hover_bg (Flexoki ui)、 他の行は colors.surface (paper) のまま。elevated shadow は付けない。
    他の行は全部 paper bg: アイテムの bg はそもそも hover (bg-2) と drag (ui) でのみ 色が付く。active 行も resting state は paper のまま (font-weight 500 だけで識別)。drag 中は他の行の hover bg を transparent に抑制するだけで、active styling は触らなくて済む。
    egui だと if drag_active && !is_dragged { skip hover_bg paint } の 1 行で実現。
  5. swap アニメーション (FLIP) ─ live swap で押し出される側の行を即 snap せず、 80 ms の ease で旧位置から新位置にスライドさせる。egui だと ctx.animate_value_with_time(row_id, target_y, 0.08) を行ごとに動かす方式:
    ・swap 直前に old_y[entry_id] = row_rect.top を記録
    ・swap 後の 新位置を target_y として登録
    ・描画時に current_y = animate_value_with_time(target_y) を使って target_y - current_y 分の translateY シフトで描く
    ・dragged 行はこの animation 系から除外 (cursor 追従が滑らかさで遅れないように)
  6. live swap ロジック ─ 各フレームで dragged 行の visual center が 隣接行の center を跨いだら entries 内で swap し、active.entry_index を ±1 する: 
    let visual_center = wanted_top + row_height / 2.0;
let idx = active.entry_index;

// 上に swap
if idx > 0 {
    let above_center = row_rects[idx - 1].top() + row_height / 2.0;
    if visual_center < above_center {
        library.entries.swap(idx - 1, idx);
        active.entry_index -= 1;
        // pointer_offset_y は不変 (cursor とのオフセットは行の data idx に依存しない)。
        // 次フレーム描画で natural_top が 36 px 上にずれ、translateY も自動で +36 補正される。
    }
}
// 下に swap
if idx < entries.len() - 1 {
    let below_center = row_rects[idx + 1].top() + row_height / 2.0;
    if visual_center > below_center {
        library.entries.swap(idx, idx + 1);
        active.entry_index += 1;
    }
}
    ループは 1 swap / frame だが、フレームレート (60 fps) で十分追従する。 高速な flick で複数 swap が必要なら while ループで複数回 swap する版に。
  7. release ─ mouseup / drag_released() で: DragState::Idle に戻す + library.bump_updated_at() を 1 回呼ぶ。 data は live swap で既に最終状態なので、追加の reorder 処理は不要。 active_id は entry id で保持してるので変わらない。
  8. Esc で cancel ─ DragState::Active 中の Esc キーで: library.entries = original_entries.clone() で snapshot 復元、 DragState::Idle に戻す。dragged 行が元位置に戻る (Esc の瞬間は jump、要望なら別 PR で transition を)。 bump_updated_at() は呼ばない (実質変更なしなので)。
  9. auto scroll ─ entries 件数が dropdown max-height (320 px) を超えないうちは 本 PR では実装しない。スクロール対応が要る段階で別 PR。
  10. submenu の Move up / Move down は touched しない。 既存実装 (entries の隣接 swap) と drag-reorder は独立で並存。
  11. cursor アイコン: ・行 hover → CursorIcon::Grab
    ・DragState::Pending / Active 中 → CursorIcon::Grabbing
    ・kebab hover → CursorIcon::PointingHand
    ui.output_mut(|o| o.cursor_icon = ...) で設定。
  12. Tests ─ tests/egui-web-circuit-picker-reorder.spec.ts を新規:
    ・3 件目を 1 件目の上にドラッグ → 順序が [3, 1, 2] に
    ・1 件目を末尾にドラッグ → 順序が [2, 3, 1] に
    ・drag 中 Esc → 順序維持
    ・kebab クリックは drag を起こさず submenu を開く (回帰防止)
    ・同じ kebab を再クリック → submenu が閉じる
    ・submenu open 中に別行 drag を開始 → submenu が閉じる
    Playwright の mouse.down() / mouse.move() / mouse.up() で本物のマウス操作を実行。

Acceptance

  1. 行を mouse で掴んで上下にドラッグできる。dragged 行そのものが cursor に追従し (ui グレー塗りのみ)、ゴーストや drop indicator や elevated shadow は出さない。
  2. dragged 行は Y 軸のみ追従。カーソルが横に動いても dropdown 列から外れない。
  3. dragged 行は ドロップダウン内側にクランプ。pointer が dropdown の外に出ても row は panel 内に止まる。
  4. アイテムの bg が色付くのは hover 時 (bg-2) と drag 中 (ui) の 2 イベントだけ。active 行も resting state では paper bg のままで、font-weight 500 だけで identify する。drag 中は他の行の hover も抑制され、dragged グレーが唯一のアクセント。
  5. dragged 行の center が隣接行の center を跨ぐと、押し出される行が 80 ms の ease で旧位置から新位置にスライド (FLIP アニメーション)。dragged 行は除外で cursor を 1:1 追従。
  6. release は単に drag state クリア (data は live swap で既に最終状態)。active な entry の id は変わらない (= active 表示も維持)。
  7. Esc で drag をキャンセル、順序維持。
  8. kebab をクリックしても drag は始まらず、submenu が開く (既存挙動の回帰なし)。同じ kebab をもう一度クリックすると閉じる。
  9. dropdown は topbar 直下に隙間なく開く (state vector aspect dropdown と同じ接続感)。
  10. submenu が開いている状態で別行の drag を始めたら submenu は閉じる。
  11. submenu は右側表示 / 画面右端での左 flip とも、親行の上辺 Y と同じ px に揃う。
  12. submenu の Move up / Move down は引き続き動く。
  13. cursor が行 hover で grab、drag 中で grabbing。
  14. cargo clippy --target wasm32-unknown-unknown --all-targets -- -D warnings 通過、cargo fmt --check クリーン。
  15. snapshot tests は drag 中の中間 frame をキャプチャしない (flaky 防止) ─ before / after だけ。
