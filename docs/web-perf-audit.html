Gate ごとの queue.submit — encoder が分裂

apps/web/src/gpu.rs:2126–2289  (StateVectorCallback::prepare, recompute branch)

SimulationOp の各 ApplyGate / CaptureBloch / MeasureReduceSample / MeasureCollapse ごとに create_command_encoder → begin_compute_pass → dispatch_workgroups → queue.submit(Some(encoder.finish())) を独立に発行。N gate なら N 回 submit となり、CPU↔GPU の IPC ラウンドトリップが N 倍になる。

書き戻しが必要な依存があるわけではなく、同一 encoder 内なら順序は保たれる。1 個の encoder にバッチして 1 回 submit すれば、IPC コストは N → 1 に縮む。深い回路ほど効く。

Fix ループ外で encoder を 1 つ生成し、各 gate の compute pass を順に追記。 queue.write_buffer も StagingBelt あるいは ring buffer に置き換えると、各 gate の params 更新が encoder 内 copy として畳み込める。最後にまとめて queue.submit。

毎フレームの params write_buffer — dirty flag 不在

gpu.rs:2092 (state) · 1929/1934 (bloch) · 2000/2005 (measurement)

|0…0⟩ 初期化を CPU で確保 → upload

gpu.rs:2111

recompute のたびに vec![[0.0f32, 0.0f32]; state_count] を CPU で確保し、state_buffers[0] に queue.write_buffer。Qubit 数 N のとき 2N·8 byte を毎回 PCIe / IPC 越しに転送。

GPU 上で完結させるべき値 (CLAUDE.md §1)。

Fix 専用の compute shader で state_buffers[0] をゼロ初期化し、index 0 のみ (1.0, 0.0) を書く dispatch を 1 回行う。CPU 確保もアップロードも消える。
