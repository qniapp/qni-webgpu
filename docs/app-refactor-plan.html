update()576 行 → コーディネータ + 9 helper

現在の update() は責務が直列に書かれているだけ。各セクションを fn process_* として impl QniApp に切り出し、 update() 本体は順に呼ぶだけにする。

update() のセクション → 呼び出し先 helper

  1. frame_start + ScrollArea pre-input gate (state panel rect 計算 → wheel をパネル上で吸う設定) → compute_state_panel_input_gate [state_panel.rs]
  2. ScrollArea で circuit 描画 → そのまま (handle_input と draw_circuit は既に分割済み、ここからは呼ぶだけ)
  3. aspect_index sync + state_layout 計算 + clamp 系 → そのまま (state_layout は既に render::state_panel_layout 経由)
  4. strip drag → process_state_panel_strip_drag [state_panel.rs]
  5. viewport pan → process_state_panel_viewport_pan [state_panel.rs]
  6. Ctrl+wheel zoom → process_state_panel_zoom [state_panel.rs]
  7. aspect dims (wheel + click) → process_aspect_dims [state_panel.rs]
  8. aspect popover (row click + outside-close + ESC) → process_aspect_popover [state_panel.rs]
  9. resize handles (4 隅 hit rect + cursor + drag) → process_resize_handles [state_panel.rs]
  10. GPU recompute (sim_ops + bloch_slots / measurement_slots 更新) → process_gpu_recompute [app.rs に残す、self の sim 系を更新するだけ]
  11. draw_palette / draw_state_vector / draw_drag_preview → そのまま (render 側へ呼ぶだけ)
  12. FPS HUD → draw_fps_hud [app.rs に残す or 別 mod]
  13. drag repaint scheduling → schedule_drag_repaint [gate_input.rs]

切り出し後の update() は~80 行のコーディネータになります。各 helper は引数で必要なものを受け取り、 self の関連 field を更新するだけ。

手順段階的に分割 (5 step)

  1. scaffold: app/ ディレクトリ + 空の state_panel.rs / gate_input.rs + mod 宣言。空 mod のままビルド確認。
  2. gate_input.rs へ移動 — handle_input + schedule_drag_repaint。pub(super) → pub(crate)。cargo check → スナップショット差分ゼロ。
  3. state_panel.rs (helper 系) へ移動 — clamp_state_viewport_size, begin/apply/end_resize_drag, active_resize_corner。update() からの呼び出しはそのまま。
  4. update() の切り出し — 9 個の process_* method を app/state_panel.rs に新規追加し、update() 本体からそれぞれの section を呼び出しに置き換え。各 process_* 追加ごとに小さく commit すると bisect が効きやすい。
  5. 最終 cargo check + Playwright snapshot + ファイル行数チェック (全部 500 行以下を確認)。

難所: update() を helper に切り出すとき、各 process_* で 必要な引数の絞り込みが必要。state_layout, screen_rect, aspect_qubits, dims_hit 等を helper 間で共有するために、コーディネータ側で 1 回計算して使いまわす形にする。

設計なぜ "state_panel" と "gate_input" で切るのか

  • 独立した責務: state panel と gate-drag-to-place は完全に別の UI 要素。混在してたのは update() に直列で書いてただけ。
  • update() がコーディネータになる: 「ScrollArea → state panel interactions → resize handles → GPU recompute → draw → FPS HUD → repaint scheduling」という毎フレームの全体フローが一望できる状態を保つ。詳細は helper に隠す。
  • 修正の局所性: 「aspect popover のクリック処理を変えたい」→ state_panel.rs の process_aspect_popover 単独。「ゲートが配置位置にスナップする条件を変えたい」→ gate_input.rs の handle_input 単独。手を入れるファイルが一意。
  • テスト容易性: process_* helper はそれぞれ &mut self + 引数を受け取って戻り値なし、なので将来 mock UI に対する単体テストが書きやすい。
